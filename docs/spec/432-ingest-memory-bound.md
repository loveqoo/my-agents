## 결정(구남님 승인 — A+B)

### A. 배치 단위 흘려보내기([[cap-the-raw-source-not-the-buffer]] — 누적 원천에 상한)

`_embed_chunks`+`_persist_chunks` 전량 경로를 `_embed_persist_batched`로 교체:
EMBED_BATCH(128)마다 **임베딩→Chunk insert→flush→참조 해제(expunge)** — 벡터·ORM 상주가 배치
1개로 유계. 청크 문자열 목록은 유지(업로드 캡 25MB로 이미 유계 — 지배 항 아님).

- **트랜잭션은 하나(원자성 유지)**: flush는 Postgres로 밀 뿐 커밋이 아니다 — 중간 실패 시 전체
  롤백(반쪽 문서 없음, 기존 계약 동일).
- **재인덱싱 경합 차단(스펙 312 codex F1)은 조건부 UPDATE를 말미로 이동해 유지**: flush된 청크는
  커밋 전까지 불가시라, 커밋 직전 조건부 UPDATE(`status != 'reindexing'`) rowcount=0이면 raise→
  전체 롤백 — 스왑 밖 청크가 커밋되는 P0 데이터 손실은 여전히 불가능. **선행 배치의 이득**: 종전
  선행-UPDATE는 임베딩 HTTP 내내 컬렉션 행 잠금을 쥐어(트랜잭션이 길어지면) 재인덱싱 CAS·동시
  인제스트가 분 단위 블록 — 말미 UPDATE는 잠금을 커밋 직전 찰나만 쥔다.
- 차원 검증(가드2: RAG_EMBED_DIMS·c.dims)은 배치마다 동일 적용.

### B. 동시 인제스트 세마포어

`_execute_ingest` 본문을 `asyncio.Semaphore(RAG_INGEST_CONCURRENCY, 기본 2)`로 감쌈 — 대기 중
문서는 status=parsing(UI 폴링에 자연 표시). spawn 자체는 무변경(다른 배경 작업 무영향).
