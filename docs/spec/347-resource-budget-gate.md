# 347 — 자원 예산 게이트 (기준 수립: "무엇을 얼마나 소모하나"를 상시 측정)

## 왜 (진단 — 개별 누수가 아니라 **계층의 맹점**)

스펙 346(체크포인트 무한 누적)의 진짜 교훈은 "체크포인트를 안 지웠다"가 아니다. **기능 테스트는
전부 초록이었다** — 아무도 "행이 몇 개 쌓이나"를 묻지 않았기 때문이다. 우리 검증은 지금까지
**"동작하는가"만 물었고 "무엇을 얼마나 소모하는가"는 한 번도 안 물었다.**

전수 감사(deep-reasoner, 2026-07-15) 결과 같은 형태가 **5건 더** 나왔다 — 쓰기 경로만 있고 회수 경로가
아예 없는 테이블(`accesstoken`·`approvals`·`eval_runs`/`eval_case_results`·`batch_runs`·`memory_snapshots`).
개별로 고치면 **다음에 추가되는 테이블에서 또 샌다.** 그래서 먼저 **자를 만든다.**

## 설계 — 두 축

### A. 회수 정책 대장(정적) — "이 테이블은 누가 치우나"를 **선언하게 강제**
`api/resource_policy.py`에 테이블별 정책 레지스트리를 둔다. 모든 우리 소유 테이블은 셋 중 하나로
**반드시 분류**된다:

- `RECLAIMED` — 회수 경로 있음. **누가** 치우는지 명시(배치 잡 이름 · CASCADE · 관문 함수).
- `BOUNDED` — 자라지 않음(싱글톤·읽기 전용 카탈로그·관리자 페이스 자원). 사유 명시.
- `USER_DATA` — 사용자 자산이라 임의 삭제 금지. 보존정책은 관리자 설정(그 설정이 **어디**인지 명시).

**게이트**: `models.py`의 테이블 집합 == 레지스트리 키 집합. 새 테이블을 만들고 분류를 빠뜨리면
**테스트가 실패**한다 — 이것이 이 스펙의 복리다(사람의 기억이 아니라 게이트가 기억한다).

**허수 방지**: `RECLAIMED`가 가리키는 회수 주체가 **실재**해야 한다 — 배치 잡 이름은 `batch.jobs.JOBS`에
있어야 하고, CASCADE는 FK의 `ondelete`가 실제로 CASCADE여야 한다. (없는 청소부를 가리키는 선언은
"치운다"는 거짓말이다.)

### B. 성장 예산(동적) — 실제로 돌려서 **행 증가를 잰다**
대표 오퍼레이션을 실행하고 **잔여 행 증가**를 예산과 대조한다. 예산 초과 = 실패.

| 오퍼레이션 | 예산(잔여 행 증가) |
|---|---|
| 채팅 1턴 | `messages` +2 · `checkpoints`/`writes`/`blobs` **+0** · 그 외 0 |
| 로그인 1회 | `accesstoken` +1 (**만료 행은 0** — 349에서 회수 도입 후 상향 없음) |
| 에이전트 CRUD 1회 | 관리자 페이스(예산 없음, 관찰만) |

이 표가 랄프 루프의 **자**다. 누수를 고칠 때마다 예산이 초록으로 바뀌고, 새 누수는 빨강으로 뜬다.

## 이 게이트가 드러낼 것(=후속 스펙의 작업 목록)

레지스트리를 정직하게 채우면 **회수 주체가 없는 테이블이 그대로 드러난다**. 그것들이 348~ 이후의 일감:
- **348 배치 가동 경로** — 청소 잡이 있어도 **돌리는 프로세스가 없다**(`batch_runs` 0행 = 이 서비스가
  생긴 이래 배치가 한 번도 안 돌았다). 회수 경로를 아무리 잘 만들어도 **손이 없으면 죽은 코드**다.
  → 게이트에 "가동" 축을 추가(설치 ≠ 가동, memory `installed-guard-isnt-covering-guard`).
- **349 accesstoken 회수** (로그인당 1행, 만료 행 영구 잔류 — 실측 누수 중)
- **350 approvals 보존정책 + 무제한 폴링** (삭제 경로 0 · 플레이그라운드가 전체 목록을 2.5초마다)
- **351 eval_runs/eval_case_results 보존** (버전 활성화마다 자동 3런)
- **352 mem0 장기기억 회수 기본값** (턴마다 쓰는데 통합 배치는 기본 OFF)
- **353 RAG 인제스트 메모리** (5만 행 × 1024차원 전량 적재 ≈ 1.6GB **추정** — **실측 먼저**)
