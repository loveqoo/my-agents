# 167 — 문구·평이함 감사 (검증 축3)

## 배경
축2·축1 골격을 축3에 적용: UI 문구가 일반인도 이해할 수준인지 전수 점검. 자가검증은 관대(내가 쓴
문구는 내가 안다 → 사각). 처방: **루브릭(합격선 글로 박제) + 적대적 리뷰어("IT 모르는 일반인" 연기)**.

## 대상(전수)
사용자 노출 문자열만 — 개발자 주석 제외. 추출 패턴:
- 프롭: `placeholder`·`title`·`label`·`okText`·`cancelText`·`description`·`tooltip` 한글 값.
- 알림: `setToast(...)`·`message.{success,error,warning,info}(...)` 한글.
- JSX 텍스트 노드: 태그 사이 한글 카피(버튼·설명·빈상태·배지).
- 메뉴/네비 라벨(AdminShell), Alert `message`/`description`.
파일 상위: AgentsView·BlocksView·BatchView·CollectionsView·EvalView·ProviderModelView·DebugChat·OverridePanel·Inspector.

## 루브릭(리뷰어가 각 문자열에 적용) — `copy-rubric.md`
문제 유형:
1. **전문용어(jargon)**: 비개발자가 모를 IT/내부 용어가 **설명 없이** 노출. 예: 임베딩·벡터·스냅샷·
   브로커·오케스트레이션·페이로드·인제스트·청크·런타임·토큰·프로바이더·차원. (도메인 필수어는 툴팁/괄호
   설명이 있으면 통과 — 무조건 배척 아님. "설명 없이 처음 마주치면 막히나"가 기준.)
2. **오탈자·맞춤법·띄어쓰기**.
3. **불명확·비평이**: 한 문장이 너무 길거나 내부 개념 전제, 이중부정, 수동태 남발.
4. **일관성**: 같은 개념을 다른 단어(예: 지식/컬렉션/벡터 테이블, 초안/미반영).

각 발견: `파일:라인 · 원문 · 유형 · 심각도(막힘/거슬림/사소) · 개선 제안`. 리뷰어는 "IT 모르는 일반인이
이 화면만 보고 막히나"로 판정. **관대 금지 — 애매하면 flag하고 심각도로 구분**.

## 실행
deep-reasoner(read-only, 판단형)에 위임 — 위 패턴으로 사용자 문자열 grep+루브릭 채점. 심각도순 랭킹 반환.
메인이 적대 트리아지(진짜 개선 vs 도메인 필수/취향) → **막힘·오탈자 우선 수정**(fast-worker 또는 메인),
거슬림은 선별, 취향은 보류. 수정 후 재추출로 회귀 확인.
