# 141 — 평가 5탄: 모델별 비교 실행 + 격자 뷰

## 배경 / 왜
사용자: "똑같은 문제에 대해 지정된 모델별로 테스트 — 적합한 모델 선정에 필요." 조사(learning 141)
확인: 업계 표준 = "고정 데이터셋 × 가변 구성(모델)" 비교. 결정: **격자(promptfoo식)까지** 간다.

## 설계
1. **스키마**: eval_runs에 `model_name`(String 120, null=에이전트 기본 모델)·`group_id`(UUID,
   비교 실행 묶음, index) 추가. 마이그레이션 1건.
2. **러너**: eval_run_agent에 overrides 파라미터 → `_load_context(agent_pk, None, overrides)`.
   모델 오버라이드는 기존 화이트리스트 경로 재사용(cfg["model"]→레지스트리 해석, 스펙 025/134).
3. **실행 API**: RunStartIn에 `models: list[str]`(선택, 최대 6, kind=agent 전용 — rag에 주면 400).
   - **이름 사전 검증**: 각 이름이 레지스트리 chat 모델에 존재해야 함 — _load_context는 미존재
     이름을 기본 모델로 만회하므로(스펙 089와 같은 함정) 여기서 안 막으면 **다른 모델로 조용히
     시험**된다 → 400.
   - N개면 group_id 하나로 EvalRun N개 생성(각 model_name 박제) 후 **한 태스크에서 순차 실행**
     (로컬 LLM 과점유 방지). 중복 게이트·좀비 sweep은 기존 그대로 적용됨.
4. **UI**:
   - 문제집 드로어(agent): 모델 **다중 선택**(레지스트리 chat 모델) — 0개면 기존 단일 실행(에이전트
     기본 모델), N개면 비교 실행. 실행 이력에 모델 태그 컬럼.
   - **새 탭 "모델 격자"**: 비교 그룹 선택(최근 그룹 목록) → 표: 행=문제, 열=모델, 셀=통과/실패
     (+점수·클릭 시 성적표). **"다른 결과만" 필터**(promptfoo Different — 모델 간 결과가 갈리는
     행만). 열 하단에 모델별 점수 합계.

## 검증
- 단위: 미존재 모델 400·rag+models 400·models 7개 400·그룹 N런 생성·model_name/group_id 박제.
- 통합(실 모델): 같은 provider를 다른 이름으로 임시 등록해 2모델 격자 → 두 런 ok·격자 데이터 정합.
- e2e(fast-worker): 모델 2개 선택→비교 실행→격자 탭(행×열·Different 필터)·스샷. codex 간이.

## 비목표 (OUT)
- 프롬프트(페르소나) 축 격자(모델 축만 — 오버라이드 구조상 후속 확장 용이), 병렬 실행, 그룹 간 비교.
