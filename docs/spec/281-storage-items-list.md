# 281 — 저장 항목 리스트(확장 가능) + 비영속 승인 제약 명시

> 280(대화 저장 이동)을 사용자 재검토로 대체: ①"대화는 저장 대상 중 하나 — 상태가 늘어도 확장
> 가능해야" ②"비영속이면 승인도 기록 안 하는데 승인 오버라이드가 나오는 게 맞나?"

## 측정 (비영속 × 승인)
- 비영속이 승인 필요 도구를 호출하면 **실행 거부**(fail-closed, chat.py:1290 — 승인 대기는 DB
  기록·재개가 필요한데 비영속=쓰기 0, 스펙 237 게이트).
- 따라서 비영속에서 승인 오버라이드의 의미가 반전: 강화(승인 필요)=그 도구 사용 불가,
  **완화('승인 없음', 관리자만 저장)=승인 기본 도구를 비영속에서 쓸 유일한 레버**. → 숨기면 레버
  소실. **노출 유지 + 제약 명시**가 정답.

## 변경
1. **저장 항목 리스트(step ①, 저장 방식 아래)** — 280의 단일 '대화 저장' Field 대체:
   - 영속: "저장 항목" 리스트 — 행=[Switch·이름·한 줄 설명]. 현재 1행(대화 내용), 구조가 리스트라
     기억 추출·승인 기록·트레이스 등 **행 추가만으로 확장**.
   - 비영속: 리스트 소멸 → "저장 항목 없음 — 아무것도 기록하지 않습니다" + **승인 제약 안내**
     ("승인 필요 도구는 실행 거부 — '승인 없음' 오버라이드(관리자)만 예외").
2. **승인 오버라이드 본문(step ②)**: 비영속이면 제약 문구 선행("승인 대기를 만들 수 없어 승인 필요
   도구는 실행 거부 — '승인 없음'만 사용 가능하게 함").
3. 저장 데이터(persistHistory)·백엔드 무변경.

## 완료 조건
1. 영속: '저장 항목' 리스트에 '대화 내용' 행(토글) — off 저장 왕복 persistHistory=false(e2e).
2. 비영속: 리스트 소멸·"저장 항목 없음"+승인 제약 문구(e2e). 영속 복귀 시 리스트 복원.
3. step ② 승인 아이템(도구 선택 후): 비영속이면 제약 문구 노출(e2e).
4. tsc 0 + 279 무회귀 + verify-280 갱신(불변식: 저장 방식 아래 위치·왕복 유지).
