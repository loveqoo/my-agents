# 268 — 노드별 RAG(컬렉션)·메모리: 캐싱 회상 프록시 (구현 완료)

> 상태: **done**(2026-07-10 사용자 승인 후 구현·검증). P2 프록시 설계는 사용자 안(2026-07-10).

## 현재 상태 (제약의 뿌리)
- **RAG**: 플랫폼이 배선된 컬렉션 *전체*를 하나의 `search_documents` 도구로 묶어 빌드(runtime.
  build_rag_tool) → 노드는 이 단일 도구를 켜고 끌 수만 있음. 컬렉션 구분 불가.
- **메모리**: 회상(mem0 검색)은 플랫폼이 턴 시작에 1회 수행해 **에이전트 페르소나에 합침** → 노드형은
  노드가 각자 프롬프트를 쓰므로 이 경로를 안 타 회상이 노드에 닿지 않음(259 정직 기록).

## 제안

### P1 — 노드별 RAG: 컬렉션별 검색 도구로 쪼갠다
- 플랫폼(chat.py)이 노드형 에이전트에 한해 **컬렉션마다 검색 도구 1개**를 빌드: 이름
  `search_documents__<컬렉션>`(_safe_name 규칙 재사용 — 265 이름 체계 그대로).
- UI 노드 도구 선택지: "문서 검색 (컬렉션 전체)" 대신 **"문서 검색 · docs-kb"** 처럼 컬렉션별 항목.
- 풀 파생: vectorTables = 노드들이 참조한 컬렉션 합집합(기존 파생 로직 확장).
- 하위호환: 구저장 `search_documents`(민이름)는 기존 전체-컬렉션 도구로 계속 해석(무회귀). 엔진은
  이름 필터 그대로라 **무변경** — 변경은 플랫폼 도구 빌드 + UI 옵션 두 곳.
- 효과: "검색 노드는 A컬렉션만, 검증 노드는 B컬렉션만" 가능. ragMinScores도 컬렉션별이라 자연 정합.

### P2 — 노드별 메모리: **캐싱 회상 프록시** (사용자 설계, 2026-07-10)
"1회 조회→노드 매핑" vs "노드별 키워드 조회"의 양자택일을 없앤다 — **노드는 각자 조회하고, 프록시가
키워드로 캐싱**한다. 같은 키워드 조회는 캐시 반환(비용 자연 수렴=1회), 다른 키워드는 자연히 개별 조회.

- **MemoryRecallProxy**(턴 스코프): `memory.search`를 감싸는 캐시. 키=(회상 키워드), 값=히트 목록.
  수명 = 한 턴(요청) — 턴을 넘겨 캐시하면 새 기억이 안 보이므로 금지.
- **주입 방식**: 브로커 선례 그대로 — 플랫폼이 **recall_scope를 미리 고정**한(RBAC — 노드가 스코프
  변경 불가) 호출가능 프록시를 `AgentBuildContext`에 주입. 엔진은 주입물만 호출(085 U2 유지).
- **노드 설정**: `memories: string[]`(기억 블록 선택 — 회상 받을 노드) + 회상 키워드 모드:
  `사용자 입력`(기본 — 모든 기본 노드가 캐시 공유=사실상 턴 1회) / `이 노드의 입력`(노드가 받는
  마지막 메시지로 조회 — 노드별 키워드, 예: 앞 노드 결과로 재검색).
- **관측(보너스)**: 프록시가 조회마다 (노드, 키워드, 건수, 캐시 히트 여부)를 trace에 기록 — 조회
  행위 계측(082) 공짜 획득, 인스펙터 노드 행에 표면(266 규율: 기록+표면).
- 풀 파생: 에이전트 memories = 노드 선택 합집합(도구 파생과 동형).
- 효과: 259의 "memories 소비 선언했으나 미사용" 정직성 흠 해소 + 노드별 키워드까지 v1에서 해결
  (별도 v2 불필요 — 프록시가 두 방식을 통일).

## 구현 스케치 (승인 후)
- chat.py: 노드형이면 rag_collections를 컬렉션별 도구로 분리 빌드 + **MemoryRecallProxy 생성·주입**
  (recall_scope 고정, 캐시 턴 스코프, trace sink 연결) + 노드 memories 파생 검증.
- runtime(AgentBuildContext): `memory_recall` 주입 슬롯(브로커와 형제).
- pipeline.py: 노드 memories/키워드 모드 정규화 + 노드 실행 직전 프록시 호출 → "# 관련 기억" 블록을
  그 노드 시스템 프롬프트에 덧붙임.
- NodeListEditor: 도구 옵션에 컬렉션별 항목 + "기억" 선택(+키워드 모드) 한 줄 추가(267 간결 기조).
- 검증: 단위(캐시 히트/미스·스코프 불변·주입 노드 한정) + 실모델 e2e(두 노드 다른 컬렉션 검색·
  키워드 모드별 회상) + 인스펙터 표면(266 규율 — 기록+표면).

## 검증 계획 요약
발화 필수 단언(151): 노드1이 A컬렉션만·노드2가 B컬렉션만 검색함을 호출 기록의 컬렉션 스코프로 단언.
메모리는 (a) 같은 키워드 2노드 → 검색 1회+캐시 히트 1회(프록시 카운터), (b) 키워드 모드 다른 노드 →
검색 2회, (c) 회상 블록이 선택 노드의 프롬프트에만 존재, (d) 스코프가 플랫폼 고정값과 일치(노드가
못 바꿈)를 단언.
