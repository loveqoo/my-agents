# 200 — '능력 부여' UI 개편 (스펙 199 진단의 구현)

## 배경
스펙 199 진단: 유저 메뉴 '능력 부여(정책)' 카드가 설계자도 헷갈릴 만큼 어려움 — P1 자유입력(이름
타이핑), P2 `capability:…` 코드 노출, P3 역할/유저 혼재, P4 맥락 부족. 사용자 결정(2026-07-07):
"수정을 해봅시다."

추가 발견(P5): 능력 종류가 코드상 6종(mcp·rag·agent·memory·memwrite·memedit)인데 UI엔 3종만 —
member에게 '기억' 능력을 UI로 부여할 방법이 없다.

## 설계 (프론트만 — 백엔드 정책 API 무변경)

### D. 도입 문장 (P4)
카드 상단: "능력이란 에이전트가 쓸 수 있는 도구(MCP)·지식(RAG 컬렉션)·하위 에이전트·기억입니다.
admin은 모두 쓸 수 있고, member는 여기서 열어준 능력만 쓸 수 있습니다."

### C. 대상 분리 (P3)
Segmented(또는 Radio) **"역할에게(권장) | 특정 유저에게"** → 아래 Select엔 해당 목록만. 선택 시
효과 한 줄: 역할 = "이 역할의 모든 유저에게 적용" / 유저 = "이 유저에게만 적용".

### 종류를 사람 말로 (P2 일부 + P5)
`mcp`→"도구 (MCP 서버)" · `rag`→"지식 (RAG 컬렉션)" · `agent`→"하위 에이전트" ·
`memory`→"기억 검색" · `memwrite`→"기억 저장" · `memedit`→"기억 수정/삭제". 6종 전부 노출.

### A. 자유입력 → 카탈로그 선택 (P1, 핵심)
종류 선택 시 이름 Input 대신 **등록된 자원 Select**:
- 도구: MCP 서버 목록(목록 API 확인 — `/blocks` 또는 `/mcp-servers` GET).
- 지식: `listCollections()` → name.
- 하위 에이전트: `listAgents()` → **주의: broker `_cap_resource`가 agent는 cap_id(`agt_…`)를 쓴다 —
  부여 name이 무엇과 매칭되는지 구현 시 브로커 판정 코드로 확정**(이름을 넣었는데 id로 판정하면
  영영 안 맞는 무효 부여가 됨. 확정 후 Select value를 판정 키와 일치시킴).
- 첫 옵션 "전체 — 모든 {종류}"(name 없음 = kind-레벨). 기억 3종은 리소스가 내부 고정(`user`)이라
  이름 Select 자체를 숨김(kind-레벨만).

### B. 코드 숨기고 문장으로 (P2)
- 미리보기: `capability:mcp:calc` → "**member 역할**에게 **도구 'calc'** 사용을 허용합니다."
  코드는 문장 아래 작은 회색(또는 툴팁)으로 유지(디버깅·감사 로그 대조용).
- 부여 목록 테이블: object 코드 Tag → "도구 · calc" / "지식 · docs-kb" / "모든 도구" 식 사람 말.
  코드는 툴팁.

## 후속 (2026-07-07, 사용자 요청)
- **유저 목록·능력 부여 탭 분리** — 한 화면 세로 나열은 유저가 늘면 불편. antd Tabs로 '유저 목록' /
  '능력 부여' 분리, '유저 추가' 버튼은 유저 탭에서만 노출. e2e에 탭 검증 3항목 추가(21/21).

## RBAC 경계 (트리거 판정)
- **쓰기 입구 무변경**: grantPolicy/revokePolicy 백엔드 그대로(admin 전용 `require("users","manage")` +
  `capability:` 객체 경계 + 감사 로그). 새 쓰기 입구 0.
- UI 카탈로그 선택은 **표시층 화이트리스트**일 뿐 인가 아님(직접 API 호출은 여전히 임의 name 가능 —
  기존과 동일, 스키마 경계는 `capability:*` prefix 검증뿐). 백엔드 존재 검증 추가는 OUT(스펙 148
  rename 가드와 얽힘 — 참조 무결성 축으로 별도).

## 검증
- e2e: ① 종류별 카탈로그 옵션이 실제 등록 자원과 **개수 일치**(측정), ② 부여 → 목록에 사람 말 표시
  → 회수 왕복, ③ 기억 종류는 이름 Select 없음, ④ 문장 미리보기 정확성. tsc0 · 스샷(회고 183 교훈:
  배치·위계 눈 확인).
- agent 부여 실효성: 부여 후 브로커 판정 키와 일치하는지(구현 중 확정한 키로) 확인.

## 경계
- 백엔드 존재 검증·rename 시 정책 참조 갱신은 OUT(위 RBAC 절).
- 승인 정책(툴 approval)과는 별개 축 — 이 화면은 "누가 쓰나"만.
