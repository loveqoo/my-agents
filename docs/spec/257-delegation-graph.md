# 스펙 257 — 조율형 위임 구조(DAG) 시각화 (사용자 지시)

## 배경 (2026-07-09, 256 v2 직후)

깊이 N이 되면서 위임이 계층 구조가 됐다. 사용자: "재귀 가능성을 막아야 — 결국 DAG처럼. 조율형이면
에이전트 DAG 구조를 보여주는 방식이 필요."

**런타임 층은 이미 DAG 보장**: 호출 체인(방문 집합)이 모든 실행 경로의 재방문을 차단 → 어떤 실행도
비순환. 남은 문제는 **설정 층** — A→B, B→A로 저장하는 것 자체는 가능(런타임이 끊을 뿐)해서, 구조가
보이지 않으면 사용자는 순환 설정을 알아챌 수 없다.

## 변경

### DelegationGraph 공용 컴포넌트 (admin)
- 클라이언트에서 전체 에이전트의 capabilities로 그래프 조립(agent cap = 콜론 없는 bare id).
- 루트(해당 조율형)부터 들여쓰기 트리로 전개: 노드 = 이름 + 태그(조율형/로컬·A2A/서빙 여부) +
  비-agent 능력 요약(도구 N·문서 N·기억).
- **순환(back-edge) = 경로 기준 탐지**해 빨간 "↩ 순환 — 실행 시 자동 차단" 마커(설정은 저장돼 있어도
  런타임이 끊는다는 사실을 정직하게). 다이아몬드(공유 노드)는 재전개(작은 그래프 전제), 깊이 표시 캡 8.

### 배치 2곳
1. **에이전트 상세 — 구성 탭**: 조율형이면 "위임 구조" 하위 섹션(저장된 활성 config 기준).
2. **플레이그라운드 — 오버라이드 서랍 2단계**: "맡길 것" 아래 접기(Collapse) — **편집 중인 값(draft
   capabilities) 기준** 미리보기(체크를 바꾸면 구조가 즉시 반영 — 적용 전 확인).

## 검증
- 시드: A(조율)→B(조율)→C(직접) + C→A 순환 설정 → 상세 구성 탭 트리에 3단 전개 + C 아래 A에
  순환 마커. 오버라이드 2단계에서 체크 변경 시 그래프 반영. 양 뷰포트 오버플로 0.

## 검증 결과 (2026-07-09)
- e2e 6/6: 상세 구성 탭 그래프(3단 전개 a→b→c·순환 마커 b→a·조율형/로컬 태그) + 오버라이드 서랍
  미리보기(draft 기준 — 체크 해제 시 "위임 대상 없음" 즉시 반영).
- 육안 발견 1건 동시 수정: 구성 표 "위임 대상"이 raw id(agt_…) 노출 + 그래프와 중복 → 그래프가
  canonical, 표에는 비-에이전트 능력(mcp:/rag:)만 "위임 능력"으로.
- 재귀 계층 정리: 런타임=체인(모든 실행 경로 비순환 보장, 256 v2) / 설정=순환 저장 가능하되
  시각화에 빨간 마커 — 두 층이 함께 "DAG처럼" 동작함을 사용자가 눈으로 확인 가능.
