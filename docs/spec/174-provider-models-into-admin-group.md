# 174 — 프로바이더·모델 메뉴를 "관리자" 그룹으로 이동

## 배경 (메뉴 감사)
"관리자" 그룹 5개(유저·배치·평가·허용호스트·설정)는 전부 서버 라우터에서 `require(...,"manage/run")`으로
관리자 강제 — UI만 숨기는 게 아니라 실제 게이트. 그룹핑↔인가 일치, 보안 함정 없음.

**역방향 불일치 하나**: **프로바이더·모델**(`key: 'models'`)은 *상단(전원 표시)*인데, 생성/수정/삭제가
전부 관리자 전용(`dependencies=[_manage]`, providers.py·model_registry.py; 비관리자 403·보기만).
"관리 기능인데 관리자 그룹 밖"이라 일반 사용자에겐 눌러도 못 만지는 메뉴 → 오해.

사용자 결정(AskUserQuestion): **관리자 그룹으로 이동**.

## 안전성 (기능 무회귀)
- 메뉴를 숨겨도 에이전트 폼·RAG 생성 폼의 **모델 선택은 무영향** — 목록은 `GET /models`(마운트 `_auth`,
  로그인만; 변이만 `_manage`)로 읽으므로 메뉴 가시성과 무관.
- 라우트/뷰 자체는 그대로. 메뉴 항목의 *그룹·가시성*만 변경(비관리자는 `user.is_superuser` 블록 밖이라
  미표시). 5개 기존 항목과 동일 게이트 메커니즘.

## 딜리버러블 (프론트만)
`admin/src/admin/AdminShell.tsx` `menuItems`:
- `{ key: 'models', ... }`를 상단에서 제거, "관리자" 그룹 `children` 첫 항목으로 이동.
- 그룹 주석에 프로바이더·모델 추가(서버 강제 근거 유지).

## 검증
- tsc clean. 브라우저(admin): "관리자" 그룹에 프로바이더·모델 노출·상단엔 없음. 클릭 시 뷰 정상.
- 비관리자 미표시는 기존 5개와 동일한 `is_superuser` 게이트라 코드 논리로 확인(별도 유저 없이).

## OUT
- 라우트 접근 가드 추가(이미 서버 `_manage`로 강제 — 메뉴 숨김은 방어심화일 뿐).
- 빌딩 블록 내 권한(permissions) 등 더 세밀한 재분류(별도 축).
