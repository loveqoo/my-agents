# 스펙 237 — 비영속 에이전트의 도구 경계 (DB 쓰기 도구만 금지)

## 배경 (스펙 235 OUT → 사용자 결정 2026-07-08)

235의 "쓰기 0" 계약은 앱 DB 적재를 막았지만, 도구 자체의 부작용은 못 막는다(codex R2). 금지 범위를
묻자 사용자 결정: **"직접 DB에 쓰기와 연결된 도구만 금지. MCP는 보통 내부 DB를 안 쓴다고 가정(허용).
DB 읽기는 상관없음 — RAG 조회 가능."**

즉 전부 금지(순수 추론 강제)가 아니라 **쓰기 경계만** 긋는다:
- **허용**: MCP 도구(외부 호출 — 내부 DB 무관 가정)·RAG 조회(읽기)·능력 중 읽기 계열(rag:·memory:·agent:)
- **금지**: 기억 저장/수정 능력(`memwrite:`·`memedit:` — 우리 DB에 직접 쓰는 유일한 도구 표면)
- **기억 회상(config.memories)**: 도구가 아니라 플랫폼 선처리 — 235 결정(비영속=전면 off) **유지**.
  읽기라 이 원칙상 허용 여지가 있으나 235에서 stateless 계약으로 확정했고 이번 결정은 도구 축에 한정
  (원하면 후속 재론).

## 변경

1. **저장 게이트(agents.py create/update)** — `ephemeral=true`인데 `capabilities`에 `memwrite:`/`memedit:`
   계열이 있으면 **422**("비영속 에이전트에는 기억 저장·수정 능력을 연결할 수 없습니다"). 조용한 무시
   금지(회고 214) — 입구에서 명시적으로.
2. **런타임 방어층(chat.py ctx)** — 과거 저장분·우회 대비: ephemeral이면 ctx.capabilities에서
   memwrite/memedit 항목을 걸러낸다(fail-closed, 저장 게이트가 정본).
3. **승인형 도구 정직화** — 비영속은 체크포인터가 없어(235) 승인(HIL)형 도구가 interrupt 시점에 실패한다.
   암호 같은 예외 대신 **명시 안내**("비영속 에이전트는 승인이 필요한 도구를 사용할 수 없습니다")로
   표면화(214 조용한 실패 금지).
4. **폼 안내** — 비영속 ON이면 조율형 능력 피커의 "기억에 저장" 항목이 저장 시 거부됨을 안내
   (구현 난도에 따라 비활성 또는 안내 문구 — 서버 422가 최종 게이트).

## 실측 발견 (구현 중 — 235 가정 반증)

승인형 도구를 비영속 에이전트로 **직접 트리거해 보니**, 체크포인터가 None인데도 interrupt가 발생해
`_create_approval`이 **세션+Approval 행을 썼다** — 235의 "체크포인터 없으면 구조적 미도달" 가정(codex·자체
추론 일치)이 틀렸고, verify_235 E6은 승인형 도구 셀을 안 돌려 vacuous 초록이었다. 계약 위반 실경로.
→ 변경 3(승인 게이트)이 사후 정직화가 아니라 **실 봉합**이 됐다. 235 문서·회고 213에 정정 기록.

## 검증 (완료 2026-07-08)
- **verify_237 8/8**: T1·T2 저장 422(생성·수정) / T3 ephemeral+MCP+RAG 저장 허용 / T4 RAG 조회 실발동
  +그 턴 전 테이블 Δ0(읽기가 쓰기 0을 안 깸) / T5 승인형 도구 → 명시 에러+Approval·세션 Δ0(위 발견의
  회귀 가드) / T6 DB 직접 변조 레거시(ephemeral+memwrite)도 Δ0(런타임 방어층).
- verify_235·verify_233 무회귀, tsc 0.
- codex 적대 4건 판정:
  - **#1 버전 승격(activate/revert) 게이트 밖** → **수정**: 두 경로에 `_enforce_ephemeral_boundary` 추가
    ("저장 상태로 존재 불가" 불변식). fork는 초안 생성이라 activate 게이트가 커버.
  - **#2 과거 승인 resolve 시 Approval 행 UPDATE** → **문서화 경계**: 그 행 자체의 라이프사이클 마감이며
    "채팅 1턴 쓰기 0" 계약 밖(재개 후 신규 영속은 _persist 게이트가 차단).
  - **#3 우리 API를 감싸는 MCP** → **의도된 잔여 위험**(사용자 결정: "MCP는 내부 DB 안 쓴다고 가정").
    기계 보장이 필요해지면 도구 메타 `writes_app_db` 표식 축이 후속 후보.
  - **#4 cap id 정규화(대소문자·공백)** → **저위험 문서화**: 브로커 `_kind_of`도 exact prefix라 변형
    문자열은 실행 자체가 deny-by-default(우회 불가). UI 숨김-해제 모순은 "선택돼 있으면 노출"로 기해결.

## 완료 조건 (충족)
- DB 쓰기 도구(memwrite/memedit)는 비영속에 연결 불가(입구 422 + 버전 승격 게이트 + 런타임 필터).
  읽기(도구·RAG)는 비영속에서 정상 동작하며 쓰기 0 유지. 승인형 도구 실패가 설명된다.
