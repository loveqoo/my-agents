# 스펙 250 — UI 중복 표현 전수 스캔 + 전반 검토

## 배경 (사용자 지시, 2026-07-09)

디자인의 날(246~249)에서 중복 표현을 5회 지적받음(초안 태그·초안 라벨·+새 대화·인스펙터 버튼·
시스템 프롬프트 버튼) — 전부 "컴포넌트를 고립적으로 만들고 화면 단위 확인 생략"이 뿌리(회고 227).
사후 처방이던 "추가 전 grep"을 **전수 스캔**으로 확장: 전 화면에서 같은 상태/같은 동작이 두 번
이상 표현되는 곳을 찾는다.

## 방법 (검증 사다리 — 자가검증 회피)

1. **deep-reasoner 코드 스캔**(타자): admin/src 뷰 트리에서 "한 화면에 같은 상태 배지/라벨/기능
   입구가 2회 이상" 후보를 file:line으로 열거. 판정 기준 = 회고 225의 중복 분류(상태 표현 중복 /
   기능 입구 중복 / 라벨-제목 중복).
2. **기계 텍스트 스캔**(메인): 화면별 innerText에서 동일 라인 반복 검출(테이블 행 반복 등 자연
   반복은 제외 휴리스틱) — 코드 스캔이 놓치는 런타임 조합 중복 보완.
3. **육안 확정**(메인): 후보를 스크린샷으로 참/거짓 판정 — 도구가 좁히고 육안이 확정(회고 133).

## 산출물
- 판정된 중복 목록(위치·종류·canonical 제안) — 수정은 사용자 선별 후.
- 중복 외 전반 검토 소견(문법 위반: 3층 위계·값=상태·탭 규칙 등).

## 완료 조건
- 전 화면(14 + 주요 오버레이) 커버, 후보 전건 육안 판정 완료.
