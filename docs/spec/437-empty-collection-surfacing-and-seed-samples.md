전수 조사(2026-07-31, 실모델 재현) 결과 **기능은 전 유형 정상**이었다:
단순형 2종=MCP 도구 bound 4·호출 성공 + RAG 배선·검색 호출 정상 / 노드형=도구 4회 호출 /

## 결정(구남님 승인 — A+B. C(acme 잔재 정리)는 범위 밖)

### A. 빈 컬렉션 표면화 — 조용한 빈 상태 제거

1. **런타임(관문 — 전 유형 공통)**: `build_rag_tool`의 무히트 경로에서, 대상 컬렉션이 **전부 문서
   0건**이면 "관련 문서를 찾지 못했습니다" 대신 **"컬렉션(X·Y)이 비어 있습니다 — 문서를 업로드해야
   검색할 수 있습니다"**를 도구 결과로 반환(모델이 사용자에게 정직하게 전달). 판정은 무히트일 때만
   1회 count 쿼리(히트 경로 비용 0). calls_sink 기록에도 같은 사유.
2. **에이전트 편집 폼**: RAG 픽커·노드 문서 옵션 라벨에 빈 컬렉션이면 `(비어 있음)` 접미.
3. 컬렉션 목록은 이미 status=empty 표시 — 무변경.

### B. 시드 샘플 문서 — 초기화 직후에도 검색이 바로 동작

`seed.py`가 데모 컬렉션 3종에 **소형 샘플 문서를 직접 적재**(HTTP 없이):
- 벡터=`mock_remote._det_embedding`(결정적, 1024) — 세 컬렉션 모두 mock-embed 바인딩이라 질의
  임베딩(mock 라우트)과 같은 공간, 검색이 결정적으로 동작. 부팅 중 자기 HTTP 호출 불가 제약 회피.
- Document(status=ready) + **DocumentBlob(원본 보존 — 편집·재청킹·435 재시도 계약 유지)** +
  청크(`rag_ingest.chunk_text`, 컬렉션 파라미터) + 카운트 갱신.
- 내용: docs-kb=헬프센터 도움말 샘플, team-notes=팀 노트(배포 절차 포함 — 전수 조사의 질의가 바로
  히트), product-titles=상품 타이틀 샘플. 각 1문서 소형.
- 설명 문구 화석 교정(3종 모두 "샘플 적재됨 — 교체·추가 업로드 가능"류로 정직화).
- seed_if_empty 경로라 기존 DB 무영향(빈 DB 첫 부팅에만).
