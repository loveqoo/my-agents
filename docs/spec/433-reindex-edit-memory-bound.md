# 스펙 433 — 재인덱싱·문서편집 임베딩 유계화(432 OUT 씨앗 마감)

## 발단

스펙 432가 인제스트를 유계화(피크 Δ+1.75GB→+196MB)하며 **같은 부류 두 경로를 OUT**으로 남겼다:
재인덱싱(reindex_core)과 문서편집(documents.py)이 여전히 전량 임베딩·전량 누적이다. 규모는
재인덱싱이 **더 크다**(컬렉션 전체 — 인제스트는 문서 1개).

**현재 구조**(코드 실측):

| 경로 | 누적 대상 | 규모 |
|---|---|---|
| 재인덱싱-모델교체(`_do_reindex` not chunk_change) | 전 청크 text + **전 벡터** | 컬렉션 전체 |
| 재인덱싱-재청킹(`_do_reindex` chunk_change) | `rebuilt`에 **전 문서의 청크+벡터** | 컬렉션 전체(최악) |
| 문서편집(`update_document_content`) | `old_map`(문서 전 청크 text→**벡터**) + 새 벡터 | 문서 1개(업로드 캡 25MB) |

## 불변식(먼저) — 무중단 원자 스왑은 건드리지 않는다

스펙 313: 재인덱싱·편집은 **한 트랜잭션 원자 스왑**이라 동시 검색이 옛것/새것만 보고 반쪽을 안 본다
(MVCC). 432와 같은 결론: **커밋을 쪼개지 않고**(원자성 유지) 배치마다 flush+expunge로 **파이썬 상주만**
유계화. 스왑 커밋 1회·실패 시 전체 롤백은 그대로.

## 결정

### A. 재인덱싱-모델교체: 배치 임베딩→UPDATE
`select(id, text)` 스냅샷은 유지(텍스트는 벡터의 ~1/16 — 지배항 아님), EMBED_BATCH(128)마다
`embed → UPDATE 128행 → 벡터 참조 해제`. 마지막에 Collection.embedding_model_id UPDATE + 커밋 1회.

### B. 재인덱싱-재청킹: `rebuilt` 누적 소멸(문서 단위 흘려보내기)
`DELETE 전 청크` 먼저 → **문서마다** 추출→청킹→(배치)임베딩→insert→flush→expunge → 마지막 Collection
UPDATE + 커밋 1회. `rebuilt` 리스트 제거.
- **순서 변경의 정직한 대가**: 종전은 "전량 계산 후 첫 쓰기"라 계산 중 실패 시 *쓰기 자체가 없었다*.
  이제는 DELETE가 먼저라 실패 시 **롤백에 의존**(결과 동일: 원 상태 온전, 반쪽 없음). 432와 같은 계약.

### C. 문서편집: 전 벡터 맵 소멸(텍스트 집합 + 배치별 조회)
- 재사용 판정을 **텍스트 집합만으로**: `select(Chunk.text)`(벡터 컬럼 미조회) → `reused/reembedded`
  통계 불변식(codex 331 P2: occurrence 기준)은 그대로 계산.
- 배치마다: 그 배치의 재사용 텍스트 벡터를 **DB에서 조회**(`WHERE text IN (…)`) + 미보유 텍스트만
  임베딩 → insert → flush → expunge.
- **정직한 변경**: 종전 "임베딩 호출은 문서 전체에서 유일화 1회" → **배치 내 유일화**로 축소. 배치를
  가로지르는 동일 신규 텍스트는 두 번 임베딩될 수 있다(같은 텍스트=같은 벡터라 정합성 무영향,
  비용만 미미 증가). 통계(reused/reembedded)는 occurrence 기준이라 불변.

## OUT(경계)

- 재인덱싱-모델교체의 **텍스트 스냅샷 전량 보유**(벡터 대비 소항 — 페이징은 잠금 전제 재검토 필요, 후속).
- 편집 vs 편집 last-write-wins(스펙 331 기존 경계 — 변경 없음).
- 긴 단일 트랜잭션의 연결 점유·FK 경합(432와 동일 경계, 재인덱싱은 이미 status 잠금으로 배타).
- **취소(CancelledError) 시 reindexing 상태 고착**(codex 433 P2, **선재** — 배치화가 만든 문제 아님):
  데이터는 롤백돼 옛 청크가 온전하지만 `except Exception`이 CancelledError를 안 잡아 status를 error로
  못 바꾼다 → 재기동(부팅 스윕)까지 편집·인제스트·재인덱싱이 409. 가용성 경계(데이터 손실·반쪽 없음).
  회수 주체를 부팅 스윕 외에 두는 건 별개 후속.
- 편집의 배치별 재사용 벡터 조회가 **연결 1개 추가 사용**(별도 읽기 세션 — 배치마다 열고 닫음).
