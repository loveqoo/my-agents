# 323 — 가짜 "단기(세션)" 메모리 타입 제거 + mem0 스코프 설명

## 배경 / 동기

사용자 지적(2026-07-13): 메모리 타입 카탈로그의 **"단기(세션)"은 가짜다 — 당장 지워라. 그리고 mem0 동작
설명을 추가하라.**

`단기(세션)`(=`SHORT_TERM_MEMORY`)은 **죽은 라벨**이었다: 백엔드 `memory_enabled()`가 무시하고(실제 단기는
`historyDepth`가 소유), 프론트는 도처에서 `.filter(m => m !== SHORT_TERM_MEMORY)`로 걸러내며, 카탈로그엔
"타입"으로 떠서 "장기 기억 (mem0)"과 나란히 보여 **혼란만 준다**(사용자: "장기기억에도 단기(세션)이 있는
줄"). 실제로 "장기기억의 단기 모드"는 mem0가 `userId` 유무로 자동 결정하는 것(별개 개념).

## 설계 / 실행

### 1) 가짜 타입 제거 (백엔드 + 데이터)

- **seed.py**: `MEMORY_TYPES`에서 `단기(세션)` 튜플 삭제. `AGENTS`의 `memories`에서 `단기(세션)` 제거(5곳).
- **DB(현 dev)**: `memory_types` 행 삭제 + 모든 `agent_versions.config`의 `memories`(에이전트·노드 레벨)에서
  `단기(세션)` 스트립(17개 버전). config JSON 재귀 청소.

### 2) 프론트 죽은 코드 제거 (전체 정합)

- `mockData.ts`의 `SHORT_TERM_MEMORY` 상수 + 7파일의 필터 사용처(~11곳) 제거. 타입이 사라지면 필터는
  no-op이자 삭제된 개념 참조라 함께 걷어낸다: `(x||[]).filter(m => m !== SHORT_TERM_MEMORY)` → `(x||[])`,
  import 제거. tsc/build로 무회귀 확인.

### 3) mem0 동작 설명 추가

- 에이전트 폼 **"장기 기억" 필드**에 mem0 스코프 자동결정 설명(긍정문): "userId가 있으면 세션을 넘어
  기억하고, 없으면 이번 세션에만 유지합니다." (카탈로그 "장기 기억 (mem0)" body엔 이미 있으나, 정작 켜는
  화면엔 없어 안 보였던 것.)

## 범위 밖 (OUT)

- historyDepth(진짜 단기) 동작 변경 — 그대로. 삭제는 가짜 라벨만.
- mem0 스코프를 명시 선택으로 바꾸기(지금은 userId 자동) — 설명만 추가, 동작 변경은 별건.
- "장기 기억 (mem0)" 타입 — 유지(진짜).

## 검증

- 카탈로그 메모리 타입 1개("장기 기억 (mem0)")만 남음(DB 조회). agent_versions config에 `단기(세션)` 0.
- 에이전트 상세/폼 메모리 표시 무회귀(가짜 라벨 사라져도 진짜 장기 기억 태그 정상).
- 에이전트 폼 "장기 기억" 필드에 스코프 설명 렌더(스크린샷).
- tsc/build·ruff/mypy 클린. `SHORT_TERM_MEMORY` grep 0.

## 완료 조건

- `단기(세션)` 카탈로그·시드·DB·프론트에서 완전 소멸(grep 0).
- 에이전트 폼 장기 기억 필드에 mem0 스코프 설명 표시.
- 메모리 표시·선택 무회귀. metrics-fast/tsc 클린.
