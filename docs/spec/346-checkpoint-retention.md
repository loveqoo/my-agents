# 346 — 체크포인트 누적 종식 (쓰기 축소 + 턴 종료 폐기 + TTL 스윕)

## 배경 (실측, 2026-07-14)

초기화 전 dev DB: **messages 520행 vs checkpoints 10,191행 / checkpoint_writes 14,423행**(20~30배).
`AsyncPostgresSaver`(HIL 승인 게이팅, 스펙 041)가 남기는 행인데 **삭제 경로가 코드에 아예 없다**.
세션이 끝나도, 승인이 해소돼도 잔류한다.

### 근인은 두 겹이다

1. **슈퍼스텝마다 1행** — 기본 `durability="async"`는 매 스텝 경계에서 체크포인트를 쓴다.
   (실측: 3노드 그래프 1회 실행 = checkpoints 3 / writes 3 / blobs 3)
2. **`thread_id`가 턴마다 고유** — `chat.py:445` `f"{ext_agent_id}:{session_id}:{token_hex(4)}"`.
   세션-안정이 아니라 **턴별**이다(세션-안정으로 두면 매 턴 전체 히스토리를 넘겨야 해서 그렇게 설계됨).
   따라서 **턴이 끝나면 그 스레드는 영원히 아무도 안 읽는다** — 지금 쌓이는 건 대화 이력이 아니라
   **끝난 턴의 시체**다. 체크포인트의 유일한 독자는 HIL 재개(승인 대기·ask/form 폼 대기)뿐이다.

## 사용자 아이디어 검토: "행을 늘리지 말고 컬럼/자식 테이블을" → **기각(사유 기록)**

LangGraph에 정확히 그 설계가 **이미 있다**: `ShallowPostgresSaver` — PK가 `(thread_id, checkpoint_ns)`라
스레드당 1행을 UPSERT로 덮어쓰고, 블롭도 채널당 1행이다. 그런데 둘 다 걸린다.

- **폐기 예정**: `"ShallowPostgresSaver is deprecated as of 2.0.20 and will be removed in 3.0.0.
  Use AsyncPostgresSaver instead, and invoke the graph with durability='exit'."` — 라이브러리 자신이
  대체재를 지목한다.
- **더 중요: 그걸 써도 우리 문제는 안 풀린다.** 스레드당 1행이어도 `thread_id`가 턴별 고유라
  **턴당 1행이 영구 누적**된다. 덮어쓰기는 *한 스레드 안의* 이력만 줄일 뿐, **죽은 스레드를 치우지 못한다.**

→ 아이디어의 방향(쓰기 축소)은 `durability="exit"`으로 **지원되는 방법으로** 취하고, 진짜 원인
(죽은 스레드)은 **삭제**로 친다.

## 주춧돌 실측 (설계 전 검증 — 회고 315/316 교훈: 근거를 결론보다 먼저 잰다)

| 실험 | 결과 |
|---|---|
| 기본(`async`) 완주 | checkpoints **3행** |
| `durability="exit"` 완주 | checkpoints **1행** |
| **`exit` + interrupt** | **체크포인트 남음(1행)** · `interrupted=True` |
| `exit` + interrupt 후 **별 실행으로 재개** | **성공**(n=111 = 1+10+100) → **HIL 안 죽는다** |
| `checkpoint_id` 형식 | **UUID version=6**(시간 인코딩) → **나이 산출 가능** |
| `adelete_thread(tid)` | 3스레드 전부 0행 → **삭제 경로 실재** |

## 처방 — 레버 3개 (사용자 결정: 두 레버 다 + TTL 24시간)

### L1. `durability="exit"` — 발생원(쓰기 횟수)
그래프 실행 지점(`chat.py` 스트리밍, `chat_approval` 재개)에 `durability="exit"`. 턴당 3~7행 → **1행**.
(learning 049: 삭제는 증상 처방 — 발생원을 같이 고친다.)

### L2. 턴 종료 시 스레드 폐기 — **관문 한 곳**
`checkpointer.discard_thread(thread_id)` 단일 함수. **보존 조건**(둘 중 하나면 남긴다):
- **승인 대기**: `Approval.status='pending'` AND `Approval.checkpoint == thread_id`
- **산출물 폼 대기**: `_PENDING_ARTIFACT`가 그 스레드를 가리킴(스펙 188)

그 외에는 삭제. 호출 지점은 **턴이 끝나는 곳 전부**: 채팅 스트림 종료(정상·에러·클라 끊김 = `finally`),
승인 재개 완료. (회고 316: 횡단 정책은 관문 한 곳에 — 잡별로 두면 새 호출부에서 샌다.)

### L3. TTL 스윕 — 크래시·방치가 남긴 고아 (배치, 24시간)
**기존 배치 서비스에 잡 추가**(`checkpoint-cleanup`, cron 설정 + `dry_run` — 새 스케줄러 금지, 스펙 038/049).
나이 = `checkpoint_id`(UUIDv6)의 타임스탬프. 대상:
- **고아**: 승인·폼 대기가 아닌데 남아 있는 스레드(= L2를 못 탄 크래시 턴) → 삭제
- **방치된 승인 대기**: `requested_at`이 TTL(24h)을 넘긴 pending 승인 →
  **승인을 `status='expired'`로 만료 표시한 뒤** 스레드 삭제

> **조용한 삭제 금지**: 체크포인트만 지우면 그 승인은 UI에 pending으로 남은 채 재개만 실패한다
> (회고 038의 적대 리뷰가 잡은 바로 그 결함 — "pending approval 삭제로 resume 고아"). 승인의 상태와
> 체크포인트의 수명은 **한 트랜잭션에서 같이 움직인다.**

### 안전 장치
- **파괴적 노브엔 바닥**(learning 037): TTL이 `None`/0/음수면 **정리 안 함**(0을 delete-all로 매핑 금지).
  cron NULL이면 미등록(기존 계약).
- **dry-run 먼저**(스펙 050): 스윕은 `dry_run=True`로 대상만 집계·표본 반환.
- **진행 중 턴 보호**: 나이 문턱(24h)이 분 단위 진행 턴을 절대 못 건드린다. 추가로 L2의 보존 조건을
  스윕도 **동일 술어**로 재사용한다(가드는 한 술어로 모든 입구에 — learning 050).

## 완료 조건 (측정 가능)

- **C1** 10턴 대화(승인 없음) 후 `checkpoints` 행 = **0**(현재 30) — 시체가 안 남는다.
- **C2** 턴당 체크포인트 쓰기 = **1**(현재 3) — `durability="exit"` 실측.
- **C3** HIL 승인 왕복: interrupt 시 스레드 **보존** → 승인 후 재개 성공 → 재개 완료 후 그 스레드도 **0행**.
  (verify_041 무회귀 + 삭제 시점 단언)
- **C4** 산출물 폼(ask/form) 대기 스레드는 다음 입력까지 **보존**(스펙 188/190 무회귀).
- **C5** TTL 스윕 dry-run: 24h 미만 스레드 **0건 대상**, 방치 승인만 대상으로 집계.
- **C6** 만료 처리: TTL 넘긴 pending 승인은 `status='expired'`(조용한 삭제 0) — UI '처리됨'에 노출.
- **C7** codex 적대 검토(파괴 경로 — 인가·경합·비가역) 지적 반영.
- 무회귀: verify_041(HIL)·188/190(폼)·스위트·lint/mypy.

## 결과 (2026-07-15 실행)

- **관문**(`checkpoint_retention.release_thread`) + **스윕**(`sweep`) 신설. 호출 지점은 채팅 스트림의
  `finally`(정상·에러·클라 끊김 전부)와 승인 재개 완료 — 두 곳뿐(그래프 실행 지점이 그 둘뿐임을 전수 확인.
  평가·A2A 서빙은 `checkpointer=None`이라 애초에 안 쓴다).
- **`durability="exit"`** 두 지점에 적용. 실측(라이브 HTTP): 폼 대기 스레드의 체크포인트 **1행**(기존 3행).
- **배치 잡** `checkpoint-cleanup`(TTL 24h·매시) + admin 배치 탭 + `expired` 승인 표기.

### codex 적대 검토가 잡은 P1 — **"핀이 있나"가 아니라 "턴이 정말 끝났나"**
처음 규칙은 *보존 조건(승인 행·폼 포인터)이 있으면 남긴다*였다. 그런데 **핀은 interrupt 이후에 심긴다**
(승인 행 커밋 · `_PENDING_ARTIFACT` 등록). 그 사이에 클라이언트가 끊기면 `finally`가 먼저 돌고,
핀이 아직 없으니 **멈춘 그래프를 지운다** — 아직 아무도 안 가리키지만 **일시정지 상태 자체가 재개의
근거**다. → `release_thread(paused=bool(interrupts))`로 판정 기준을 바꿨다(멈춘 채면 핀 무관하게 보존,
진짜 버려졌으면 TTL이 24h 뒤 회수 — **파괴보다 누수 쪽으로 기운다**). R11/R11b/R11c로 핀.
그 외 codex: 멀티워커 폼 재개 409(**기존 한계** — `_PENDING_ARTIFACT` 프로세스 로컬, 백로그 k8s P2) ·
`ts` 없는 행 누수(내가 선제 발견 → `unknown_age`로 요약에 노출, 파괴 대신 가시화) · 모델 주석 갱신.
