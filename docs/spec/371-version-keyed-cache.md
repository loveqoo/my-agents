# 371 — 복합 버전 키 캐시 (스펙 367-D: 매턴 재구성 비용 분할 상환)

## 왜 (368 베이스라인이 겨냥점을 확정)

매턴 그래프 재구성 비용의 실측(스펙 368, `make perf-build`):

| 축 | 실측 | 판정 |
|---|---|---|
| MCP 디스커버리 | 서버당 ~11ms(순차), **동시8에서 ~5배 증폭**(mcp=3: 166ms p50/201ms p95) | **1순위 — 벽의 정체** |
| graph(클라이언트+compile) | 웜 ~1.6ms wall / 0.50ms CPU(95% CPU·동기 루프 블록) | 2순위(CPU 축) |
| memory/rag/broker | 0 | 매턴 정당(캐시 대상 아님) |

369/370이 캐시를 건전하게 만들었다: 블록 버전 payload는 **불변**(append-only), pins가 실행 버전을
못박음 → **캐시 키가 불변 콘텐츠를 가리켜 무효화 로직이 필요 없다.**

## 설계

### D1 — MCP 도구 사양 캐시 (1순위, 벽 제거)

- **무엇을**: `build_mcp_tools`의 `client.get_tools(server)` 결과(**raw 도구 객체**) — 매턴 HTTP
  디스커버리가 사라진다. per-turn 래핑(`_wrap_mcp_tool`: calls_sink·승인 리졸버 클로저)은 **캐시하지
  않고 매턴 재수행**(순수 파이썬, ~0ms) — 실측으로 raw 도구가 per-turn 상태를 안 물고 있음을 확인.
- **키**: `(서버 name, 블록 version, auth 지문)`.
  - 369 불변성 덕에 `(name, version)`만으로 콘텐츠가 유일 — 오픈 버전·스크래치·미리보기·오버라이드
    전부 자연 적중(에이전트별 키보다 공유가 큼). pin 없으면 head의 현재 version 번호(그 버전 콘텐츠도 불변).
  - **auth 지문**(토큰 sha256 앞 8자): raw 도구가 연결 설정(auth 헤더)을 내장하므로, 키에 넣어
    **로테이션 = 새 키**(옛 토큰 잔존 사용 봉인). 지문은 로그·응답에 안 실림.
- **정책**: 프로세스-로컬 LRU(상한 ~256 엔트리)·TTL 무한(콘텐츠 불변) — 단일 uvicorn 전제(멀티워커면
  워커별 캐시, 정합엔 무해·중복만). SSRF 가드: miss에서만 연결이 일어나므로 기존 지점 그대로,
  hit는 아웃바운드 0. URL 변경=새 블록 버전=새 키라 가드 우회 없음. 호출 시 리다이렉트 가드
  (mcp_http_client_factory)는 도구 실행마다 여전히 적용.
- **정합 경계**: pin된 도구 목록이 원격 서버 실상과 다를 수 있음 — 그게 pin의 의미(제거된 원격 도구
  호출은 기존 graceful error 경로). 재탐색(rediscover)은 새 블록 버전 → 새 키(자동 반영).

### D2 — 모델 클라이언트 풀 (커넥션 재사용)

- `build_chat_openai`를 `(base_url, api_key 지문, model_id, params 해시)` 키 LRU로 풀링 —
  ChatOpenAI/httpx 클라이언트 재사용(async-safe). 근거는 빌드 비용(0.14ms)이 아니라 **실 프로바이더
  TLS 커넥션 재사용**(mock 루프백 사각지대 — 회사 환경 확인 항목, 368 결론 유지). 키 로테이션=새 키.
- 위치: packages/agent/src/agent/model.py(빌더가 있는 곳) — 상한 ~64.

### D3 — 그래프 캐시: 팩토리 설계 (구남님 설계 확정, 2026-07-16)

랭그래프 그래프는 원래 무상태·동시성 안전 — 지금 캐시 못 하는 유일한 이유는 **우리가 요청별 상태를
생성 시점에 구워 넣고 있기 때문**(트레이스 sink 클로저·프롬프트+회상 baked-in). 순서:

1. **인스턴스 무상태화 리팩터** (생성자 주입 → 호출 인자):
   - 트레이스 sink: 클로저 대신 **랭그래프 정식 per-call 통로(RunnableConfig.configurable)**로 도구가
     호출 시점에 수신 — 명시적 파라미터 전달(MDC식 암묵 아님), 재개 경계도 프레임워크가 나름.
   - 프롬프트+회상: `create_agent(system_prompt=None)`으로 짓고 **호출별 선두 SystemMessage**로 주입
     (`system_prompt`는 str만 지원 — 콜러블 미지원 실측). 단일 system이면 템플릿 충돌 없음 —
     **스파이크 선실증**(HIL 재개 시 중복 없음 포함) 후 진행.
2. **팩토리**: `graph_factory(...)` 하나가 생성을 감추고 인스턴스만 돌려준다 — **호출부는 신규/캐시본
   구분을 모른다**. "우회" 개념 없음(구남님 확정, 2026-07-16): 오버라이드는 ①호출마다 바뀌는 것
   (프롬프트·temperature)=**호출 파라미터**(config 딕셔너리)로, ②그래프 구조를 바꾸는 것(도구 집합·
   모델)=**팩토리 키에 포함** — 오버라이드 턴도 자기 키로 캐시된다. 키 = 빌드 결정 요소의 지문
   (모델 정체·도구 집합(서버,버전,auth 지문)·impl) — agent_version_id는 키 계산의 지름길.
   단순형부터(노드형/조율형은 후속). HIL 체크포인터는 전역 인스턴스라 공유 무해.

- 이득: 턴당 ~0.5ms CPU + 동기 compile의 이벤트 루프 블록 제거(처리량 천장). 무상태화는 그 자체로
  구조 개선(요청 상태와 실행기의 분리 — 367 구성/호출 분리의 완성).
