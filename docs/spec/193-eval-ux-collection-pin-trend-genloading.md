# 193 — 평가 UX 개선 3건 (RAG 컬렉션 고정 · 성적 추이 구분 · 생성 로딩)

## 배경 (실사용 문의 — 이미지 2장)
문제집(타겟팅 검색 정확도 체크) 실사용에서 3건:
1. **RAG 문제집 실행 시 "시험 칠 RAG 컬렉션 선택"을 매번 고른다** — 잘못됨. 문제집(골든 케이스)은
   특정 컬렉션 문서(`sql_filter_key.jsonl` 등)를 전제로 만들어져 **그 컬렉션 전용**인데, 시스템은 그
   연결을 저장하지 않아 실행마다 고르게 한다. 대신 (에이전트 문제집처럼) 실행 구성을 고르고 싶다.
2. **성적 추이 섹션이 골든 문제 목록과 UI가 비슷해 구분이 어렵다** — 배경색이라도 달라야.
3. **문제집 생성 시 에이전트가 자동으로 문제를 만드는 중임을 유저가 모른다** — 10개쯤 만드는 중이라는
   걸 블링크/로딩 표시로 알려줘야.

## 사용자 결정 (2026-07-06)
- 요구1 방향: **컬렉션을 문제집에 고정**(추천 선택). 문제집을 만들 때 정한 컬렉션을 기억 → 실행 시 다시
  안 고름. **RAG 검색엔 챗 모델 축이 없다**(러너는 `search_collections([collection], query)`뿐,
  `eval_runner.py:132` — 정확도는 컬렉션=문서+임베딩이 정함). 사용자 보충: **"임베딩 모델은 한 번
  정하면 수정하지 않는다"** → 컬렉션이 곧 고정 대상이라 모델 선택은 도입하지 않음.
- 요구2·3: 명확 → 확정.

## 설계

### P1 — RAG 문제집에 대상 컬렉션 고정 (백엔드 스키마 + 실행 UI)
현재: `EvalDataset`은 `kind`(agent|rag)만 저장, 실행마다 `collection_id`를 param으로 받음
(`eval_routes.py:280,424`). 문제집↔컬렉션 연결이 없다.
- **스키마**: `EvalDataset.collection_id`(nullable FK, kind=rag용) 추가. **마이그레이션 주의**:
  손수 리비전 ID는 앞선 스펙 슬롯과 **조용히 충돌**([[hand-authored-migration-ids-collide-silently]]) —
  `alembic revision`로 생성하고 헤더-only 그래프 검증(단일 head·중복 0·고아 0).
- **저장 입구**:
  (a) "컬렉션에서 생성"(`generateEvalDataset`, 스펙 142) — 이미 `collection_id`를 받으니 **생성 시
      dataset에 그대로 저장**(1회 스탬프).
  (b) "새 문제집"(kind=rag 수동) — 생성 모달에 **컬렉션 Select 추가**(rag일 때만), 저장.
  (c) 구버전(collection_id 없는 rag 문제집) — 첫 실행 시 고른 컬렉션을 dataset에 **기억**(lazy 저장)
      → 이후 고정. (마이그레이션 backfill은 불가 — 어느 컬렉션인지 시스템이 모름.)
- **출력**: `DatasetOut.collection_id`/`collection_name` 노출(round-trip 3지점 — 입력·출력·직렬화).
- **실행 UI**(`DatasetDrawer`): isRag면 컬렉션 Select 대신 **고정된 컬렉션 이름 표시**(칩) + 실행 버튼.
  collection_id 미저장(구버전)이면 폴백으로 Select 노출(고르면 저장). `startEvalRun`은 저장값 사용.
- **하위호환**: 실행 API는 `collection_id`를 계속 받되, dataset에 저장값 있으면 그것을 기본/우선.

### P2 — 성적 추이 시각 구분 (순수 UI)
성적 추이 박스와 골든 케이스 카드가 **둘 다 흰 배경 + 1px border + radius 8**(EvalView 241·279)이라
동일해 보인다. 성적 추이 박스에 **옅은 배경색**(예 `var(--geekblue-1)`)+테두리색+아이콘(추이)으로
"요약 패널"임을 시각 분리. 케이스 카드는 그대로(흰색=개별 문제).

### P3 — 자동 문제 생성 진행 표시 (목록 로딩 + 폴링)
현재: `generateEvalDataset`(컬렉션 생성)·`suggestEvalCases`(AI 출제)는 즉시 반환하고 **백그라운드로
문제를 채움**, 진행은 `description`에 텍스트로만 박제(스펙 142/143) → 목록에서 능동적 표시 없음.
- **생성 상태 노출**: `DatasetOut`에 `generating: bool`(+가능하면 `gen_target: int|null`=목표 문제 수).
  백엔드 생성 경로가 시작 시 True·완료/실패 시 False로 세팅(description 박제와 별개 구조 신호 — 파싱
  취약성 회피). 최소 변경이면 description 마커 파싱으로 폴백하되 **구조 필드 우선**.
- **antd `Skeleton`으로 "채워지는 중" 시각화**(사용자 제안 2026-07-06): 드로어 케이스 목록에서 생성
  중이면 이미 채워진 케이스는 **실제 카드**로, 아직 안 온 나머지(≈`gen_target - case_count`, 모르면
  3개 고정)는 **`<Skeleton active>` 카드**(케이스 카드와 같은 박스 골격 — 제목/문단 라인 shimmer)로
  자리표시. 폴링으로 case_count가 오르면 Skeleton이 실제 카드로 **하나씩 교체**되어 "문제가 써지는 중"이
  눈에 보인다. 스피너 배지보다 "콘텐츠 작성 중"을 직관 전달(사용자 원안: "콘텐츠 로딩 이미지").
- **목록 표시**: 생성 중 문제집 행엔 **"문제 생성 중…" 배지**(작은 스피너) — 목록에선 배지, 드로어를
  열면 Skeleton 카드(무게 배분: 목록은 가볍게, 상세는 풍부하게).
- **폴링**: 생성 중 문제집이 하나라도 있으면 목록을 **2.5s 간격 자동 새로고침**(전부 완료되면 정지 —
  좀비 폴링 방지). 드로어 안에서도 생성 중이면 케이스 목록 폴링(Skeleton→실카드 전환).
- 생성 모달/버튼: "생성 시작" 후 성공 메시지에 "목록에서 진행이 보입니다"로 안내 갱신.

## 검증 (사다리)
- **단위**: (P1) DatasetOut round-trip에 collection_id 보존·rag 실행이 저장 컬렉션 사용·구버전 lazy
  저장. (P3) generating 상태 세팅/해제(시작 True→완료 False→실패 False, fail-closed).
- **e2e**: (P1) rag 문제집 생성→컬렉션 고정 표시→실행 시 컬렉션 안 고르고 버튼만→성적표. (P2) 성적 추이
  박스 배경색 diff(스샷). (P3) "컬렉션에서 생성"→목록에 "생성 중" 스피너→폴링으로 case_count 증가→완료 시
  스피너 사라짐(스샷 2장). 브라우저 실검증(사용자 원칙).
- **무회귀**: 기존 평가 e2e(137·140·142·143)·admin tsc 0·137 러너 무회귀.

## RBAC 경계 (트리거 판정)
- **트리거**: EvalDataset은 `owner_id` 있는 유저별 데이터. 단 이번 변경은 **소유권 판정을 바꾸지 않음** —
  collection_id 저장/사용은 기존 dataset CRUD·실행 게이트(스펙 178 P3 can_manage) **owner 스코프 내**,
  새 쓰기 입구 0(dataset update 경로에 필드 하나). 실행 시 저장 컬렉션 접근은 기존 RAG 실행 게이트가
  담당(admin/owner). generating 상태는 읽기 표시(공개 읽기 유지). → **명시만**(경계 무이동).

## 경계
- RAG "모델 비교"는 미도입(임베딩=컬렉션 고정, 사용자 확인). 여러 컬렉션 비교는 후속(원하면 별도).
- 구버전 rag 문제집 backfill 불가(대상 컬렉션 미상) → 첫 실행 lazy 저장으로 흡수.
- gen_progress 정밀 카운트(N/M)는 백엔드 진행 노출 범위에 따름 — 최소는 generating bool + 스피너.
