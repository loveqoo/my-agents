# 스펙 245 — 에이전트 상세 풀페이지 승격 + 전 화면 복잡도 진단

## 배경 (사용자 2026-07-08)

"기능이 많이 들어가면서 서비스가 어려워지고 있다 — 에이전트 상세만 봐도 많은 내용. 파악하고 개편 필요."
진단: 상세 드로어(640px)에 결이 다른 4개 관심사(구성/버전·배포/공개·연동/운영) **12블록**이 한 스크롤로
누적 — 기능별로 정당하게 들어왔지만 전체 배치를 재설계한 적 없음(239 폼 개편 전과 동일 병).

합의(AskUserQuestion): **풀페이지 승격** + **상세부터 개편하되 전 화면 복잡도 전수 진단 병행**.

## 변경

### P1 — 에이전트 상세 풀페이지
- 목록 클릭 → 드로어 대신 **전용 페이지**(목록 대체 렌더 + "← 목록" 뒤로가기. 라우터 없이 view 내부
  상태 유지 — 기존 detailId 패턴 재사용).
- 좌측 **섹션 네비**(antd Anchor/Menu) + 넓은 본문, 관심사별 5섹션:
  1. **개요** — 이름·상태(서빙 vN/설정실패)·환경·모델·페르소나(+stale)·세션 수 + 주요 행동(편집·복제·삭제·플그로 대화)
  2. **구성** — 메모리·채팅 히스토리·벡터 테이블·MCP·에이전트 지식(mem0)
  3. **버전·배포** — 초안 카드(diff·테스트·활성화)·버전 이력(+운영 칩)·"편집은 초안" 안내
  4. **공개·연동** — 공개 범위 전환·A2A 스위치·A2A 식별자
  5. **운영** — 피드백 수확·버전 미상 피드백 (버전별 지표는 3의 이력 칩)
- code/external 에이전트도 같은 페이지 그릇(내용은 기존 Code/ExternalAgentDetail 재사용) — 클릭 동작
  일관성.
- 모바일: 섹션 네비를 상단 가로 스크롤로 축약(antd responsive).

### P2 — 전 화면 복잡도 전수 진단 (병행 산출물)
- `tests/browser/complexity-audit.mjs`: 전 메뉴 순회하며 **스크롤 높이·최상위 블록 수·컨트롤(버튼/입력)
  수** 실측 → scorecard. 순위표로 다음 개편 후보 도출(.dev/backlog에 기록) — "어렵다"를 수치로.

  전부 페이지에서 동작(기능 검증 — 겉만 옮기고 깨지는 것 방지). 기존 상세 의존 e2e/감사 갱신.
- tsc 0. 복잡도 진단 실행 결과 보고.

## 완료 조건
- 에이전트 상세가 관심사별 섹션이 있는 페이지가 되고, 어떤 기능도 잃지 않는다. 전 화면 복잡도 순위표가
  나와 다음 개편 우선순위가 정해진다.

- 브라우저 9/9 ×2회: 드로어 아님(풀페이지+뒤로가기)·5섹션·구성 이전 완료·네비 점프·초안 활성화 실동작·
  A2A 스위치·수확 섹션·목록 복귀. tsc 0.
