# 344 — 감사값 UI 노출: "누가 만들고 누가 고쳤나"를 화면에서

## 배경 (사용자, 2026-07-14)

스펙 343으로 감사 4컬럼이 27테이블에 쌓이기 시작했지만 **화면엔 하나도 안 보인다** — 지금은 psql로만
볼 수 있어 "audit이 가능해야 한다"는 요구의 절반이다. 값이 보이지 않으면 감사가 아니다.

### 합의된 2갈래 (AskUserQuestion, 2026-07-14)

| 질문 | 결정 |
|---|---|
| 노출 지점 | **상세 하단 메타 줄 + 목록 1컬럼**(수정 시각·수정자, 툴팁에 전체 4값) |
| 범위 | **관리 리소스 전반** — 에이전트·컬렉션/문서·MCP·모델/프로바이더·페르소나·노드템플릿·평가 데이터셋 |

## 전제: actor 공간은 **열려 있다** (사용자, 2026-07-14)

> "이 서비스에 등록된 유저는 전체 유저의 **부분집합**이다. 회사로 치면 전체 회사원이 고객이고,
> 여기 등록된 유저는 그중 **관리인**이다. 그래서 감사 컬럼을 FK로 하지 않았다 — **추후 채팅 중에
> 유저 아이디가 들어올** 것이기 때문이다."

감사 컬럼의 값 공간은 지금(`admin` 등 관리자 이메일 로컬파트 · `system` · `unknown`)이 전부가 아니라,
곧 **미등록 최종 사용자 ID**가 합류한다. 이것이 UI에 강제하는 것:

1. **`user` 테이블 조인·프로필 링크를 전제하지 않는다** — 표시 이름을 유저 테이블에서 찾으면
   미등록 사용자에서 전부 빈칸이 된다. **문자열 그대로** 보여준다(아바타·멘션 UI 금지).
2. **출처가 섞인다** — 같은 컬럼에 관리자와 고객이 함께 들어온다. 지금 화면에서 "사람 이름처럼
   보이는 값"을 전부 관리자로 읽게 만들면, 고객 ID가 합류하는 순간 **화면이 조용히 거짓말**을 한다.
   → 지금은 `system`/`unknown`만 시각 구분하되, **주체 종류 표기의 자리를 비워둔다**(후속에서
   관리자/고객/시스템 3분류 배지). 지금 관리자 전용 라벨(예: "관리자 admin")을 박지 않는다.
3. **누출 경계가 더 중요해진다** — 감사값에 고객 ID가 들어오면 외부 노출 경로(A2A 카드·서빙 MCP)로
   새는 것은 내부 계정명 누출을 넘어 **고객 식별자 누출**이다. 아래 검증 2번을 필수로 둔다.

## 설계 원칙 — 감사는 **배경**이다

집중 대상은 리소스의 정체(이름·상태)지 감사값이 아니다(memory `design-focus-before-layout`).
따라서 목록은 **컬럼 1개만** 늘린다(4개가 아니라). 나머지 3값은 툴팁/상세로 밀어 **가림**을 만든다.

- **목록**: `수정` 컬럼 하나 — `2시간 전 · admin`(상대시간 + 수정자). 툴팁에 4값 전체(절대시각 포함).
- **상세/편집 드로어**: 하단에 한 줄 — `admin이 생성 · 2026-07-14 18:03 / system이 수정 · 2시간 전`.
- **`system`·`unknown`은 시각적으로 구분**한다(사람 아님/이력 없음이 사람 이름처럼 보이면 안 됨) —
  옅은 회색 + 툴팁 설명("배경 작업"·"감사 도입 이전").

## 백엔드 (선행 — 지금 API가 감사값을 **안 내려준다**)

- `schemas.py`에 `AuditOut` 믹스인(`created_at`/`updated_at`/`created_by`/`updated_by`) 추가.
- 대상 Out 스키마가 상속: `AgentOut`·`CollectionOut`·`DocumentOut`·`McpServerOut`·`ProviderOut`·
  `ModelOut`·`PersonaOut`·`NodeTemplateOut`·`EvalDatasetOut`. 직렬화기(`serializers.py`)는 통과만.
- **누출 점검**: 감사값에 이메일 로컬파트가 들어간다(스펙 343) — 로그인 사용자만 보는 관리 화면이라
  현 인증 경계(전 라우터 `current_principal`) 안이다. **A2A/서빙 MCP 등 외부 노출 경로에는 실리지
  않음**을 테스트로 못박는다(외부에 내부 계정명이 새면 안 된다).

## 프론트 (공유 컴포넌트 하나로 — 화면마다 다시 그리지 않는다)

- `admin/src/admin/AuditMeta.tsx`:
  - `<AuditCell audit={row} />` — 목록 셀(상대시간 + 수정자, 툴팁 4값).
  - `<AuditFooter audit={obj} />` — 상세/편집 하단 메타 줄.
- 상대시간 포맷은 기존 `admin/src/admin/format.ts`를 재사용(새 유틸 금지 — 드리프트 0).

## 검증

1. **API 계약**: 대상 9개 Out에 4필드가 실제로 실려 나오는지 HTTP 응답으로 단언(스키마 선언이 아니라
   **응답 실물**).
2. **누출 핀**: A2A 에이전트 카드·서빙 MCP 응답에 `created_by`가 **없음**을 단언(외부에 계정명 비노출).
3. **UI 기능 검증**(memory `ui-verification-must-be-functional` — 스샷 한 장으로 완료 선언 금지):
   Playwright로 ① 목록에 수정 컬럼이 뜨고 **실제 값**(방금 만든 리소스 = `admin`)이 보이는지,
   ② 상세 드로어 하단 메타 줄, ③ 배경 작업으로 갱신된 문서가 `system`으로 뜨는지(343의 경계가
   화면에 그대로 드러나는지) — 셋 다 **DB 실측값과 대조**.
4. lint/tsc/기존 게이트 무회귀.

## 결과 (2026-07-14 실행)

- **백엔드**: `schemas.AuditOut` 믹스인 → 7개 Out(Agent·Collection·Document·McpServer·Provider·Model·
  Persona) + `DatasetOut`. 직렬화기는 `serializers.audit_of()` 한 헬퍼로 주입(드리프트 0).
  `/blocks`는 dict를 직접 조립하므로 `blocks._audit_json()`으로 4카테고리 전부(페르소나·메모리·
  임베딩·MCP)에 실었다.
- **프론트**: `admin/AuditMeta.tsx` 공유 조각(`AuditCell` 목록 셀 · `AuditFooter` 상세 하단 ·
  `Actor` — `system`/`unknown`은 옅은 이탤릭 + 뜻 툴팁). 목록은 **컬럼 1개만** 늘렸고, BlocksView는
  기존 "수정일"(시각만) 자리를 **승격**해 컬럼 수를 유지했다.
- **검증**: **VERIFY344_OK 12/12**(관리 API 6종 + /blocks 4카테고리 응답 실물에 4값 · 생성 응답
  `created_by == admin` · **A2A 카드 감사키 0** 누출 핀) + **VERIFY344_UI_OK 3/3**(목록 셀에 실제
  actor · 상세 메타 줄 · 백필 행 `unknown`/배경 작업 `system` 렌더). lint/mypy/tsc 클린.
- **거짓 통과를 하나 잡았다**: A2A 카드 누출 핀의 첫 경로가 틀려서(`/a2a/{공개id}` → 404) "감사키
  없음"이 **통과처럼 보였다**. 카드가 진짜 카드인지(`name`·`capabilities` 존재) 먼저 단언하도록
  고쳐, 404가 무죄 증명으로 둔갑하지 못하게 했다(부재 단언은 **대상이 실재함을 먼저 확인**해야 한다).
- **UI 정돈 2건**(스샷 실측으로 발견 — 기능 통과 후에도): 새 컬럼이 폭을 뺏어 `사용` 컬럼이
  "0개 에이전 트"로 깨짐 → nowrap+폭 조정 · 감사 텍스트가 고정 액션 컬럼 아래로 밀려 잘림 →
  말줄임 + 폭 190.
