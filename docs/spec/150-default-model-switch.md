# 150 — 기본 모델 전환 UI/API (실사용 버그 #1)

## 문제 (사용자 보고 2026-07-03)
기본 chat/embedding 모델을 바꾸려면 삭제 후 재등록해야 한다(등록 모달에만 기본 스위치).
메모리 검색이 mock embedding에 묶여 있는데, mock 모델은 컬렉션이 참조(RESTRICT)해 삭제도
불가 → 기본 전환이 사실상 막힘. 백엔드 PUT /models는 is_default 이양을 이미 지원하나 UI 공백.

## 설계
- **API**: `PUT /models/{id}/default`(신설) — 그 모델을 kind의 기본으로 지정(같은 kind의 기존
  기본은 자동 해제 — 기존 `_clear_other_defaults` 재사용). 전체 PUT을 프론트가 재구성하지 않게
  전용 액션으로(부분 데이터로 full PUT을 짜면 필드 유실 위험).
- **UI(프로바이더·모델 화면)**:
  - 상단에 **현재 기본 요약 배너**: "기본 Chat: {이름} · 기본 Embedding: {이름|미설정}" —
    "지금 뭐가 기본인지"가 안 보이던 것이 혼란의 절반.
  - 등록된 모델 행에 kind 태그(Chat/Embedding) + **"기본" 태그** + 기본이 아니면
    **"기본으로 지정" 버튼**(클릭 → 전용 API → 배너/태그 즉시 갱신).
- 삭제 차단(컬렉션 RESTRICT)은 그대로 — 전환에 삭제가 필요 없어지므로 보고된 막힘 해소.
