# 165 — 다디바이스 UI 오버플로 감사 하네스 (검증 축2 파일럿)

## 배경
기능 고도화로 일관된 UX 검증이 필요. 자가검증은 관대(같은 저자 사각 + 합격선 없음 → 재량 → 스킵).
처방: **수치 임계 + 적대적 타자**. 축2(다디바이스 UI)는 가장 수치화가 쉬워 파일럿으로 선정.

## 원칙
- **오버플로는 눈대중이 아니라 숫자**: 페이지 가로 스크롤 px + 요소별 넘침 px를 스크립트가 측정.
  "괜찮아 보인다"가 불가능 — pageScroll>임계 또는 offender 존재면 **FAIL**.
- **육안 페어 병행**(회고 133): 정량 지표는 flex 내부 압착(텍스트 뭉갬)을 못 잡는다 → 스크린샷도 캡처.
- **전수**: 모든 화면(14) × 뷰포트(360/768/1280) = 42캡처. 스펙 단위 스폿 체크가 아니라 전 화면 스윕.
- **재실행 가능**: 파라미터화된 하네스(화면·뷰포트 배열) → 표준 감사로 반복(향후 커맨드화).

## 하네스: tests/browser/ui-audit.mjs
- 로그인 1회(기존 shot-*.mjs 패턴 재사용) → 뷰포트별로 각 화면 네비(`data-menu-id$=key`)·대기·측정·캡처.
- **오버플로 측정(in-page JS)**:
  - `pageScroll = documentElement.scrollWidth - clientWidth` (>임계 = 페이지 가로 스크롤 = 대죄).
  - offenders: `overflow-x: visible`인데 `scrollWidth - clientWidth > 임계`인 요소(의도적 스크롤
    컨테이너 auto/scroll/hidden은 제외 — 넓은 표·코드블록은 허용). 넘침 큰 순 상위 12(tag·class·text·px).
  - 임계 4px(서브픽셀 노이즈 컷).
- **출력**: `out-ui-audit/scorecard.json`(화면×뷰포트별 pageScroll·offenders) + `{vp}/{key}.png`(fullPage) +
  콘솔 스코어카드(FAIL 우선). 종료코드 = FAIL 있으면 1.

## 검증(이 하네스 자체) — 실행 결과
42캡처(14화면×3뷰포트). 판정 기준을 오탐 대조로 다듬음(육안 페어로 매 단계 확인):
- 모바일 내비 실패(Sider 오버레이 기본 닫힘) → 헤더 햄버거 열기 추가(선택 시 자동 닫힘).
- 판정 = `rect.right > vw`(우측 경계 실제 초과)로 전환(scrollWidth>clientWidth는 좌측·화면밖 오탐 다수).
- 오탐 컷: 화면밖 시작(`left>=vw`, 닫힌 드로어)·antd 탭 넘침(`.ant-tabs-nav`=⋯로 처리).
- **일반 스크롤 조상은 제외하지 않음** — 한때 넣었다가 batch 버튼(진짜 잘림)까지 삼켜서 뺌(회고 133:
  도구가 진짜 문제를 숨기면 안 됨). 도구는 좁히고, 애매한 소수는 육안 판정.
- 결과: 42→진짜 깨짐 **1건**(mobile/batch 액션 버튼행 +6px, "지금 실행" 잘림) → `<Space wrap>`로 수정
  → 재실행 **0 FAIL**. 육안 재확인(버튼 줄바꿈).

## OUT
- 드로어·상세·모달 오버플로(현재 top-level 화면만 — 후속 축 확장). 세로 스크롤/잘림. 축1(시나리오)·
  축3(문구) 감사(별도 스펙). 하네스의 스킬/커맨드화(파일럿 검증 후).
