# 170 — 평가 도구 정직성 (평가 통과 ≠ 도구 호출)

## 배경
개발자 관찰: "평가는 통과하는데 도구 호출은 실제 대화에서 잘 안 된다." 근인 = **거짓 초록이
출제 시점에 태어난다.** 평가 프레임워크엔 `trace_has`/`trace_lacks`(실제 호출 도구 채점)가
이미 있고 UI도 노출하지만(닫힌 집합·"필수/금지 도구/노드"), 케이스 기본 assert가 `no_error`+
`output_nonempty`뿐이고 아무도 도구 검사를 넣으라 찔러주지 않는다. 그래서 모델이 도구를 안 부르고
자기 지식으로 그럴듯한 답만 내도 통과 → "초록인데 도구 미호출". 진단 정직성 패턴(158/162/164:
실패/빈/미설정을 제 이름으로)을 **평가 표면**에 아직 적용 안 한 자리.

## 딜리버러블 (둘 다 admin `EvalView.tsx`만, 백엔드 무변경 — 성적표가 이미 케이스별 `obs.trace_nodes` 보유)

**① 성적표 "도구 미사용" 신호 (소급):** 통과 케이스인데 `trace_nodes`에 도구 흔적(`rag:`/`mcp:`/
`memory:`)이 하나도 없으면 중립 태그 "도구 미사용"(툴팁: 통과했지만 도구를 하나도 안 불렀다·꼭 필요한
질문이면 '필수 도구/노드' 추가). 상단에 집계 "통과 N건 중 M건 도구 미사용". **기존 시험 결과에도
바로 뜸**(다시 출제 불필요). 버그 단정 아님(순수 대화 케이스는 정상일 수 있음) — 사실만 표면화.

**② 출제 안내 (예방):** agent 문제집 케이스에 도구 검사(`trace_*`)가 하나도 없으면 편집기에 부드러운
안내 한 줄(막지 않음 — 모든 케이스가 도구를 써야 하는 건 아니니 과잉 강제는 독).

## 판정 규칙
도구 흔적 = `trace_nodes` 중 `rag:`/`mcp:`/`memory:` 접두 하나라도. `firedTool(nodes)`=any-startswith.
도구미사용통과 = `case_passed && obs 존재 && !firedTool`. (obs 부재=미판정, 표시 안 함.)

## 검증
브라우저로 실제 성적표 캡처(내가 먼저) — 배지·집계가 도구 미호출 통과 케이스에만 뜨는지 육안. 판정
predicate 경계(도구 흔적 있으면 미표시·순수 그래프 노드만 있으면 표시). 자가검증 지양 → 브라우저 실측.

## OUT
- 도구 호출 신뢰도 자체(모델 능력·프롬프트 유도)는 별개 축. 저장 차단(막지 않음). 백엔드 집계 필드
  추가(프론트 파생으로 충분). 에이전트 배선 게이팅(중립 태그라 불필요 — 사실 표시).
