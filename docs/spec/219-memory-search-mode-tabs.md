# 스펙 219 — 메모리 [일치/유사도] 검색 모드를 Segmented→Tabs로 통일

## 배경 (사용자 지적 2026-07-07)

"메모리 메뉴에서 '일치검색', '유사도 검색'의 탭도 다른 탭과 동일한 UI/Style이어야 하지 않을까?"
메모리 뷰 상위는 Tabs(에이전트 메모리/유저 메모리)인데, 하위 [일치|유사도]만 **Segmented**라 시각 불일치.

## 판단 (규칙으로도 Tabs가 맞음 — 재분류)

스펙 212 규칙은 "같은 목록의 필터·모드=Segmented"라 일치/유사도를 Segmented로 뒀었다. 그러나 실제로 이
둘은 **같은 목록의 표현 차이가 아니라 서로 다른 도구/화면**이다:
- 일치 = 서버 페이지네이션 **편집 가능 목록**(행 수정·삭제 + 추가 입력).
- 유사도 = **회상 시험 패널**(RecallPanel — 질의 입력·관련도·진단).
"내용/도구 자체가 바뀜" → **Tabs가 규칙에도 부합**. 원 분류(Segmented)가 미스핏이었다. 회고 204에서
사용자가 확립한 시각 일관 선호(자매 화면 형태 일치 > 규칙 순수성)와도 합치.

## 변경

- **AgentMemoryPanel·UserMemoryPanel**(자매 둘 다): `<Segmented>` → `<Tabs>`(activeKey/onChange 스위처,
  내용은 아래 조건부 렌더 — eval 패턴). 안내문은 탭 아래로 이동.
- **admin/CLAUDE.md 규칙 갱신**: 일치/유사도를 Tabs 예시로 재분류(다른 도구), Segmented 예시는 세션 상태
  필터만 유지. "상위 탭 안 자식 Tabs 허용(언더라인이라 안 무겁다)" 명시.

## 검증
- 브라우저: 에이전트 선택 후 [일치 검색/유사도 검색]가 role=tab로 상위 [에이전트/유저 메모리]와 동일
  언더라인 스타일 렌더. Segmented 잔재 0. 탭 전환 시 목록↔회상 패널 전환. tsc 0.

## OUT
- 세션 상태 필터는 계속 Segmented(진짜 같은 목록 부분집합).
- RecallPanel/PagedMemoryList 내부는 불변(스위처만 교체).
