# 205 — 인스펙터 정직성 3건 (전송 프롬프트·토큰·턴 번호)

## 배경 (회고 191의 부수 발견 → 사용자 "순서대로" 승인 후보 ①)
인스펙터가 세 군데서 실제와 다른 값을 표시한다:
1. **전송 프롬프트 거짓**: `_build_sent_messages`가 실제 모델 입력이 아니라 "플랫폼 페르소나+대화"를
   재구성(스펙 131 — 당시엔 직접형뿐이라 일치). 커스텀 impl(플랜)의 자체 구성 프롬프트(계획·도구)·
   203 디스커버 힌트가 안 보임.
2. **토큰 추정치**: `estimate_tokens(len(user_text), len(reply))` = 글자수÷4, 질문·최종답만(시스템
   프롬프트·도구 왕복 무시). 실측 usage 미사용. "입력 토큰 4" 같은 비현실 값.
3. **턴 배지 인덱스**: `턴 {selectedTurn+1}` = 메시지 배열 인덱스 → 질문 1개가 "턴 2", 2개가 "턴 4".

## 설계

### A. 모델 콜백 캡처 계층 (1·2를 한 핸들러로 — 정공)
- `TraceCaptureHandler(BaseCallbackHandler)` 신설(api): 그래프 실행 config의 callbacks에 병합
  (observability.with_trace 옆).
  - `on_chat_model_start`: 그 턴의 **각 모델 호출 메시지 배열**을 기록(호출 수 캡, 메시지당 자수 캡
    + 비밀 마스킹 — 131 캡·마스킹 재사용). trace.sentMessages를 **마지막 호출**(최대 맥락 — 계획·
    도구 결과 포함) 기준으로 대체, `modelCalls` 수 병기.
  - `on_llm_end`: `usage_metadata`(입·출력 토큰) **합산**. 모델이 usage를 안 주면 기존 추정 폴백.
- trace.tokens에 `estimated: bool` 추가 — UI 헤더는 실측이면 그대로, 추정이면 "≈" 접두+툴팁("모델이
  사용량을 제공하지 않아 글자 수 기반 추정").
- 폴백 정직화: 콜백 미발화(예외 경로)면 기존 재구성 유지하되 UI 라벨을 "전송 프롬프트"→실측/재구성
  구분 표기.

### B. 턴 번호 (프론트 소폭)
- `턴 N` = 그 어시스턴트 메시지까지의 **user 메시지 수**(질문 순번). Playground에서 계산해 Inspector에
  전달(표시만 — 선택 로직 무변경).

## 검증
1. 단위: 핸들러 — 다회 모델 호출 턴에서 마지막 호출 메시지 캡처(계획·도구 힌트 포함)·usage 합산·
   usage 부재 시 estimated=true·캡/마스킹.
2. e2e(실모델): 플랜 에이전트 위키 턴 → 인스펙터 전송 프롬프트에 "# 작업 계획"·도구 안내 노출,
   토큰이 실측(수백대) 또는 "≈" 라벨, 턴 배지=질문 순번(1문답="턴 1").
3. 무회귀: 131 캡·마스킹 계약(비밀 미복제), 기존 e2e 스모크.

## RBAC 경계
- 비트리거: 표시·계측만. 마스킹은 기존 `_sanitize` 재사용(오히려 실제 전송분에 마스킹이 걸려 강화).

## 경계
- Langfuse 쪽 계측(118)은 무변경 — 이 캡처는 인스펙터 표시용 별도 핸들러.
- 호출별 전문 브라우징 UI(모든 호출 나열)는 OUT — 마지막 호출+호출 수 병기까지.
