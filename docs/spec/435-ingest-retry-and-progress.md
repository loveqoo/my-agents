# 스펙 435 — 인제스트 재시도 + 진행률(334·335 OUT 씨앗 부분 마감)

## 발단

백로그 씨앗(스펙 334·335 OUT) 네 항목 중 **실사용 통증이 큰 둘**을 집는다:

1. **실패 문서 재시도** — 인제스트가 실패하면 문서는 `status=error`로 남고 사용자는 **파일을 다시
   업로드**해야 한다. 그런데 원본 blob은 이미 보존돼 있다(`DocumentBlob` — 편집·재인덱싱의 근거).
   즉 **재업로드는 불필요한 마찰**이고, 실패 원인이 일시적(모델 서버 재기동·회로 열림 등)일수록 흔하다.
2. **진행률** — 지금은 `parsing`/`embedding` 태그만 보인다. 20MB 문서가 30초 도는 동안 "얼마나 됐나"를
   알 수 없다(스펙 431이 스위트에 준 것과 같은 결핍).

나머지 둘(이벤트 버스 합류·영속 알림함)은 OUT — 아래 경계 참조.

## 결정

### A. 재시도 라우트 — `POST /collections/{cid}/documents/{doc_id}/reingest`

- **전제 검사**: 문서 `status == "error"`(성공/진행 중 재시도 금지 — 중복 적재 방지), blob 존재,
  컬렉션이 `reindexing` 아님(스펙 312 배타), 소유·관리 권한(기존 업로드와 동일 게이트).
- **동작**: `status="parsing"`·`error=None`으로 되돌리고 blob에서 `_execute_ingest`를 **spawn**
  (업로드와 **같은 경로 재사용** — 세마포어·배치 흘려보내기·재료 관문 전부 그대로 승계, 스펙 432/433).
  엔티티 컬렉션이면 업로드와 동일하게 `_parse_entity_rows` 재수행.
- **응답**: 갱신된 `DocumentOut`(status=parsing) — UI는 기존 폴링으로 진행을 이어 본다.
- **원자성**: 재시도는 새 인제스트라 기존 실패분 청크가 남아 있으면 안 된다 → 실패 문서는 이미 청크가
  0이지만(부분 적재는 432가 전체 롤백), **방어적으로 그 문서 청크를 지우고 시작**(멱등).

### B. 진행률 — 인메모리 맵 + 문서 응답 필드

- `ingest_core`에 프로세스-로컬 `_PROGRESS: dict[doc_id, tuple[done, total]]`. `_embed_persist_batched`가
  배치마다 갱신, 종료(성공·실패) 시 삭제.
- **DB 컬럼을 안 쓰는 이유**: 인제스트는 단일 트랜잭션이라 진행 중 상태를 커밋할 수 없고(별도 세션
  쓰기는 락·복잡도만 늘림), 진행률은 **재시작 시 유효하지 않은 휘발 정보**다(431 진행 파일과 같은 성격).
- `DocumentOut`에 `progress: {done, total} | None` 추가 — `list_documents`가 맵에서 채운다(라우트 계산
  필드 선례=`editable`). 없으면 None(무회귀).
- FE: 문서 상태 태그 옆에 `임베딩 중 (3,200/21,000)` 표기 + 실패 행에 **"재시도" 버튼**(Popconfirm 불요 —
  비파괴).

## OUT(경계)

- **이벤트 버스 합류(재인덱싱·평가 런)**·**영속 알림함**(씨앗 나머지 둘) — 사용자 가시 통증이 위 둘보다
  작고, 알림함은 저장·재생 설계가 별개 규모.
- 진행률의 **행 단위 %**(백로그 원문) 대신 **청크 단위 done/total** — 청킹 후에야 총량을 알 수 있고
  임베딩이 지배 비용이라 그게 정직한 단위(파싱 구간은 진행률 없음, status=parsing으로만 표시).
- 재시도 시 **원인 자동 진단·재시도 정책**(회로 열림이면 대기 등) — 사용자가 버튼을 누르는 수동 재시도만.
- 멀티 인스턴스에서의 진행률 공유(프로세스-로컬 — k8s 백로그와 합류).
