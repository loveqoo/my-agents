## 재현·원인(확정 기록)
첨부(+thinking) 세션 재로드 시 내부 주입 프롬프트(선언문+⟦첨부⟧ 문서 전문)가 유저 말풍선·세션
칩에 노출, 질문이 밀림(재현 스샷 r424-bug-repro.png). 원인=주입본 영속(스펙 415 보안 계약,
불변)과 표시 경로의 비대칭 — 라이브는 입력 텍스트, 재로드는 원문 4표면(Playground 로드·승인
폴링·SessionsView·세션 미리보기)이 `m.content` 원문 렌더.

## 수리(관문 한 곳)
- `chat_attachments.split_display_content(text) → (본문, [파일명])` — 펜스 문법 정본 옆에 신설
  (strip_attachment_blocks 재사용·이름 캡처). FE 정규식 이중화 없음.
- `GET /sessions/{id}/messages`: user 메시지에 마커가 있으면 `content=본문`,
  `attachments=[파일명]`(MessageOut 필드 신설). assistant·원문 저장 무변경. 원문 확인 통로는
  인스펙터(trace.sentMessages — 모델이 받은 진실)로 유지.
- `_session_previews`: 동일 정본으로 걷은 머리 = 세션 라벨.
- FE(Playground 2·SessionsView 1): 받은 `content` + `attachments`를 라이브 관례(`질문+📎 이름`)로
  조립만 — 파싱 없음.
