## 주 과업 (설계 순서 ①집중 ②가림 ③배치 — 회고 224)

→ 목록 행 = 판정에 필요한 요약만(권한·요청·에이전트·시각·액션). 인자 JSON 등 상세는 3층(클릭 시).

## 변경

### 백엔드 — 페이지 API (기존 소비처 무회귀)
- `GET /approvals/page`: `status`(pending|resolved)·`q`(요약/에이전트 부분일치)·`limit`·`offset` →
  `{items, total}` (세션 페이지와 같은 계약). 정렬: pending=요청 오래된 순 아님 — **요청 내림차순**
  (기존 pending_first+desc 유지, 페이지 내 일관). resolved=처리 시각 내림차순.
- 기존 `GET /approvals`(전건)는 유지 — 사이드바 배지(pending 카운트) 등 기존 소비처 무회귀.
  배지는 total만 필요하므로 추후 `/page?limit=1`의 total로 전환 가능(이번엔 손대지 않음).

### 프론트 — PagedListShell 재사용 (스펙 128)
- Tabs 대기(카운트)/처리됨 유지(성격 다른 도구: 판정 큐 vs 감사 기록 — 212 규칙의 Tabs 측).
- 카드 그리드 → **DataTable 행**(모바일=카드 스택 내장):
  - 대기: 권한 태그 | 요약(+에이전트·체크포인트 2차 텍스트) | 요청 시각 | [승인 및 재개][거부]
  - 처리됨: 결과 태그(승인/거부·본인/관리자) | 요약(+에이전트) | 처리 시각
- **인자 JSON·상세 = 행 클릭 드로어**(3층 위계) — 드로어에서도 대기 건이면 판정 가능.
- 검색(q)·페이지네이션·지속 오류·total 상시 = 셸이 제공.
- resolve 후 ctl.reload() + 배지 onPendingChange(서버 total 기준 — 로컬 배열 조작 제거).
