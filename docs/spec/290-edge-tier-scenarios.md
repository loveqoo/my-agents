# 290 — 조합 스위트 엣지 티어: 한계·경계·오류 경로 (실패의 품질 검증)

## 배경

사용자 지적(2026-07-11): "성공만 하니까 성공을 위한 테스트를 한 게 아닌가." 정당함 — 288/289
스위트(36개)는 "기능이 발동하는가" 축이고, "망가뜨리려는 입력에서 어떻게 실패하는가"(한계·경계·
오류 경로) 축이 없다. verify_* 120여 개가 개별 가드의 단위 검증을 갖고 있으나, **조합 상태에서
한계를 치는** 자리는 비어 있다.

## 원칙

**엣지 티어의 단언은 "성공"이 아니라 "실패의 품질"이다** — 한계 입력에서 시스템은 ① 명확히
거절하거나(4xx·error 프레임) ② 정직하게 축소 동작하되(형 가드 폴백 등) ③ 절대 조용히 오동작
(500·빈 초록·다른 모델로 실행)하지 않아야 한다. 단언은 기존 원칙 그대로 기록 기반.

## 완료 기준

1. 엣지 시나리오 **14개+**(아래 5축), `--tier edge`로 선택 실행·기본(전체)에 포함.
2. 프로브에서 발견된 **조용한 오동작 1건 수리**: 무효 모델 **오버라이드**가 기본 모델로 조용히
   폴백(실측) → 명시 오버라이드는 400으로 시끄럽게 거절(저장 설정의 미지정 폴백은 유지 — 범위 밖,
   백로그). learning 092(broken config → refuse loud).
3. core+edge 전판 초록(연속 1회 이상 — core는 289에서 연속 2회 기실증).

## OUT (정직 기록)

- **프롬프트 인젝션(위임 데이터 채널) 시나리오**: 관측 가능한 캔ary 설계가 안 됨 — 위임 결과에 지시를
  심어도 "종합이 지시를 따랐다"와 "데이터로 인용했다"를 기록으로 구분할 수 없다(실모델 판정 필요 =
  LLM-judge/평가 하네스 영역). 채널 격리 자체는 순수함수 단위 검증(codex 100/115)이 보유.
- 저장 설정의 미등록 모델 기본 폴백(오버라이드 아님) 재설계 — 백로그.
- 모델 서버 다운 중 채팅(프로세스 밖 장애 주입) — 수동 절차로만.

## 검증

- core+edge 전판 실행 초록, 수리 1건(모델 오버라이드 400)은 시나리오가 회귀 핀.
