# 175 — RAG 생성 폼: 임베딩 모델 상위 이동 + 기본 모델 프리셀렉트

## 배경 (구남님 요청)
"RAG의 임베딩은 한 번 정하면 수정할 수 없다. 등록할 때 모델 설정이 상위로 올라가야 한다. 또한 임베딩
기본 모델이 선택되어 있어야 한다."

임베딩 모델은 차원이 고정되므로 **생성 후 불변**(learning: 컬렉션 모델·dims 변경 불가). 그런데 생성
모달에서 임베딩 모델 선택이 **거의 맨 아래**(식별이름·별명·종류·[스키마]·설명 다음)라, 가장 되돌릴 수
없는 결정이 가장 안 보였다.

## 딜리버러블 (프론트만 — CollectionsView `CreateModal`)
1. **상위 이동**: 폼을 "불변 결정 3인방(식별이름 → 종류 → 임베딩 모델)"을 위로, 편집 가능(별명·설명)을
   아래로 재배치. 엔티티 스키마는 종류/임베딩 뒤, 청크는 맨 아래(문서형만).
2. **불변 강조**: 임베딩 모델 라벨에 "(생성 후 변경 불가)" 빨강 힌트 + 설명 보강.
3. **기본 프리셀렉트**: `useEffect`에서 `models.find(m => m.is_default)`를 우선 선택(없으면 모델이
   하나일 때만 그걸로). `Model.is_default`(ModelOut 노출, kind별 기본)를 사용. 옵션 라벨에 기본 모델은
   "· 기본" 표기.

## 안전성
- 순수 UI 재배치·초기값 — 제출 페이로드(CreateFormData)·백엔드 무변경. `is_default`는 이미 API에 있음.
- 기본이 없고 모델이 여럿이면 종전처럼 빈 선택(사용자가 고름) — 회귀 없음.

## 검증
- tsc clean. 브라우저: 생성 모달 열면 임베딩 모델이 별명·설명보다 위, 기본 모델이 프리셀렉트(값 채워짐),
  라벨에 "· 기본"·"(생성 후 변경 불가)" 노출.

## OUT
- 임베딩 모델을 사후 변경 가능하게(불변이 의도 — 재임베딩은 별도 축). 기본 모델 지정 UI(프로바이더·모델
  뷰에 이미 `setDefaultModel` 있음).
