# 407 — 첨부-메모리 축 분리 + 깨진 PDF 정직화(404 후속 버그)

> 상태: **완료** · 2026-07-19 (P1~P4 + codex P1 3건 완성형 반영)
> 발단: 개발자 실사용 발견 — 회상 쿼리에 첨부 주입본(펜스+깨진 PDF 텍스트)이 통째로 노출.
> 실측 확증: 회상(_memory_inputs)·자동 기억 저장(_bg_memory_add) 둘 다 주입된 user_text 소비.

## 버그 2겹

- **B1 메모리 축 오염(우리 버그)**: 첨부 주입이 마지막 user 메시지를 재작성 → 회상 쿼리가
  문서 3만자로 오염(임베딩 검색 품질 저하) + **자동 저장 유저 기억에 문서 내용 혼입**.
  메모리 축(회상·저장)은 **유저의 실제 발화**만 봐야 한다 — 문서는 지식(RAG) 축이지 기억 축이
  아니다. (모델·영속·히스토리 재구성은 주입본 유지 — 404 설계 그대로.)
- **B2 깨진 PDF를 성공으로 통과(정직성)**: 한글 PDF의 ToUnicode 매핑 부재 시 pypdf가 타 문자권
  글자(구르무키 등)로 오추출 — 현재는 이를 정상 텍스트로 수용해 쓰레기가 주입·(B1과 겹쳐)
  기억까지 오염된다.

## 처방

- **P1 메모리 축 분리**: chat()이 주입 **전** 원발화를 `ctx.memory_user_text`로 캡처 —
  `_memory_inputs`(회상 쿼리)와 `_final_frames`의 자동 저장이 이를 우선 사용(부재 시 기존
  user_text 폴백 — 무첨부 턴 무회귀). 인스펙터 "회상 쿼리"도 자동으로 원발화만 표시.
- **P2 추출 품질 게이트(정직 오류)**: extract 시 **문자권 일관성 휴리스틱** — 허용 문자권
  (ASCII·한글 음절·CJK·라틴 확장·문장부호·공백) 밖 문자 비율이 임계(30%) 초과면 400
  "PDF 텍스트가 깨진 형태로 추출됩니다(폰트 매핑 문제) — 텍스트 저장본(txt) 또는 다른 PDF로
  시도하세요." 깨진 쓰레기를 성공 위장하지 않는다.
- **P3(선택, 승인 항목)**: pdfminer.six 폴백 — pypdf 추출이 게이트에 걸리면 pdfminer로 재시도
  (CMap 처리가 더 견고한 경우가 있음), 그것도 걸리면 400. **의존성 1개 추가**(pdfminer.six,
  MIT) — 추가 여부는 개발자 결정. (pymupdf가 품질 최고지만 AGPL — 회사 이식 리스크로 기각.)
- **P4 검증**: verify_404 확장 — E8 첨부 턴의 trace 회상 쿼리=원발화(펜스·문서 토큰 부재)·
  자동 저장 입력 무오염(monkeypatch 또는 trace memorySaved 검사), E9 오추출 모사 텍스트(타
  문자권 과다) 400. 기존 E1~E7·make test·metrics 무회귀.

## OUT

- OCR·스캔 PDF 지원(C안 계열). 임계값 튜닝 UI.
