# 134 — 턴 트레이스에 적용 오버라이드 기록 (설정 이력의 영구화)

## 배경 / 왜
사용자 점검 질문: "오버라이드로 테스트한 세션에 다시 들어가 입력하면 그 설정으로 되나?" 진단 결과 —
오버라이드는 **세션 속성이 아니라 UI 적용 상태**(에이전트별, 매 요청 동봉): 적용 중이면 이어지고,
새로고침/해제/타 기기면 원래 설정. 문제는 **한 세션에 서로 다른 설정의 턴이 섞이는데 턴별 기록이
없어** 나중에 구분 불가(모델/temperature/도구 오버라이드는 인스펙터 어디에도 안 남음 — systemPrompt만
131 전송 프롬프트로 간접 확인).

## 설계
1. **백엔드**: 적용 오버라이드가 있으면 `trace["overrides"]` 기록 — 허용 키(model/temperature/
   historyDepth/mcps/memories/capabilities/systemPrompt) 중 **실제 온 것만**. 값 정화(131 프레임 재사용):
   문자열=_sanitize+캡 300, 리스트=항목별 캡+개수 20, 숫자 통과. 헬퍼 `_overrides_trace(overrides)`.
   경로: 메인+승인대기. 재개는 경계 명시(승인 재개는 ctx 재구성 시 overrides 미보존 — 기존 동작,
   OUT: 재개 시 오버라이드 재적용 여부는 별도 논의).
2. **프론트**:
   - Trace 타입 `overrides?` + 인스펙터 "오버라이드" 섹션(적용 턴만 표시 — 키·값 행, 리스트는 태그).
   - 오버라이드 적용 중 **과거 세션 로드 시** 안내 토스트 1회("이 세션의 이전 턴들과 설정이 다를 수
     있음") — 영구 기록은 트레이스가 담당, 토스트는 순간 주의 환기.

## 검증
- verify_134: `_overrides_trace` — 허용 키만·비밀 마스킹(systemPrompt에 키 주입)·캡·빈 오버라이드는
  필드 없음(무회귀).
- 브라우저(fast-worker): 오버라이드(temperature 등) 적용→전송→인스펙터 "오버라이드" 섹션 값 표시,
  새로고침 후 세션 재선택해도 표시(영속), 미적용 턴은 섹션 없음, 오버라이드 중 과거 세션 로드 토스트.
- codex 간이: 비밀/캡 우회·무회귀.

## 비목표 (OUT)
- 오버라이드를 세션에 영속(속성화)하거나 재개 시 재적용 — 현행 "요청 동봉" 모델 유지(별도 논의).
- 과거 세션 경고의 영구 배너화(토스트로 충분 — 진실은 턴 트레이스).
