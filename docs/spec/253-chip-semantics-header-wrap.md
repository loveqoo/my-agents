# 스펙 253 — 트레이스 칩 시맨틱 교정 + 헤더 줄바꿈 (사용자 실기기 발견 2건)

## 배경 (2026-07-09, 라이브 모델 장애 중 관찰)
1. 조율형이 RAG 검색을 **시도했다 실패**(broker error)했는데 칩은 "1 rag" — 시도 기준 +1이라
   "검색을 썼다"로 읽히는 거짓 신호(직접형 mcp status=error도 동일 문제).
2. 인스펙터 병행 등 좁은 폭에서 헤더 칩들이 짜부·밀림(고정 height 64·no-wrap).

## 변경
1. **칩 = 성공만 카운트, 실패는 빨간 별도 칩**: rag = 직접(mcp server='rag' status≠error)+브로커
   (rag:* !error) 성공 합산. 실패 건수>0이면 "rag 실패 N"(빨강) 병기 — 실패 신호는 지우지 않고
   승격(정밀 디버그 채널: 시도·실패가 성공보다 중요한 신호). mcp 칩 동일 원리.
2. **데스크톱 헤더 줄바꿈**: height 64 고정 → minHeight 64 + flexWrap(좁으면 둘째 줄).

## 검증
- e2e 3/3: 성공 rag 집계 유지(mock 트리거 1 rag)·성공 경로 실패 칩 무출현·1024px+인스펙터 병행
  오버플로 0.
- 실패 칩 렌더: 성공 필터의 여집합(코드 대칭) — mock 환경은 rag 실패를 강제하기 어려워(임베드
  mock 무장애·삭제 차단) e2e 미포함. **실검증 = 사용자 실기기(현재 라이브 장애 중) — 같은 턴이
  "0 rag + rag 실패 1"로 표기되는지 확인 요청.**
