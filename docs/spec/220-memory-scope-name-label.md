# 스펙 220 — 메모리 '스코프'를 이름 위주로 + 중복 제거

## 배경 (사용자 지적 2026-07-07)

1. "메모리의 '스코프'는 무슨 뜻?" — 총계 줄 `스코프 <UUID>`가 원본 식별자라 뜻이 안 통하고 사람이 읽기 불편.
2. 이름으로 바꾼 뒤: 유저 패널은 안내문이 이미 이메일을 말해서("…admin@example.com에게만 회상됩니다")
   스코프까지 이메일이면 **같은 이메일 2회 노출**. 사용자: "중복이 이상하다, 아이디어?"

## 결정 (사용자 선택 = 옵션 3)

**스코프 줄을 신분(누구의 기억)의 단일 표기처로** 삼고, 유저 안내문에서 이메일을 뺀다.
- 스코프 = 사람이 읽는 이름(에이전트명/유저 이메일), 원본 UUID는 **툴팁(호버)**으로(진단 보존).
- 유저 안내문: "…admin@example.com에게만 회상됩니다" → "…이 유저에게만 회상됩니다"(이메일 제거).
- 에이전트 안내문은 원래 이름을 안 써서 중복 없음 — 그대로.

## 변경

- **PagedMemoryList**: 총계 줄 `스코프`를 `scopeLabel`(이름)으로 표기 + `scopeKey`(UUID)를 Tooltip에.
  code 폰트 제거(이름이므로). prop 주석 갱신(scopeLabel=사람이 읽는 이름).
- **AgentMemoryPanel**: `agentLabel?` prop 추가 → `scopeLabel`로. MemoryView가 `agents.find(id).name` 전달.
- **UserMemoryPanel**: `scopeLabel={label ?? userId}`(기존 userLabel 재사용). 안내문에서 이메일 제거.

## 검증
- 브라우저 유저 패널: 이메일 1회만(스코프 줄), 안내문엔 이메일 없음. 에이전트 패널: 스코프=에이전트명·
  총계 줄 UUID 없음. tsc 0.

## OUT
- 스코프 개념(에이전트/유저 단위 mem0 저장·회상) 자체는 불변 — 표기만.
- RecallPanel(유사도) per-hit `h.scope` 태그는 백엔드 반환값이라 별개(이번 범위 아님).
