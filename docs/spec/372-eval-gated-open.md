# 372 — 평가 게이트 배포 (스펙 367-E: 임계 통과해야 오픈)

## 왜 (구남님, 367 기획 시점 예고)

> "에이전트가 평가 점수와 평가 회수가 정해진 수치 이상이 되어야 배포가 된다는 룰을 만들겁니다."

367~371로 토대가 완성됐다: 에이전트 버전은 **불변 복합 아티팩트**(pins)이고, 평가는 **버전 단위**로
귀속·집계되며(스펙 240/244 — 버전별 성공 점수·회수), 오픈 전 스크래치도 버전 지정 실행으로 평가
가능(스펙 242). 따라서 "평가한 것 == 배포하는 것"이 성립하고, 게이트를 걸 자리는 단 한 곳 —
**오픈(activate)** 관문(스펙 370이 예약).

## 설계

### 1. 룰

오픈 요청된 버전 v에 대해, 게이트가 켜져 있으면:

```
성공 평가 회수(v) ≥ min_runs  AND  점수(v) ≥ min_score   → 오픈 허용
아니면 → 400 (현재 성적 vs 임계를 사유로 명시 — "평가 N회·점수 S%, 필요: M회·T%")
```

- **회수** = `EvalRun` status=ok 런 수(에러 런 미포함 — 실패한 평가는 실적이 아님).
- **점수** = 성공 런들의 **평균**(구남님 확정 2026-07-16 — 우연한 1회 고/저점에 안 덩샘).
- 집계는 스펙 244 `_collect_eval_aggregates`와 같은 귀속(agent_pk+agent_version) — 산식만 게이트용.

### 2. 임계 저장 — 전역 설정(AppSetting, 닫힌 키 집합)

- `eval_gate_min_runs`(int, 기본 **0**) · `eval_gate_min_score`(0~1 float, 기본 **0**).
- **기본 0 = 게이트 꺼짐**(무회귀 — 기존 플로우 그대로). 관리자가 설정 화면에서 올리는 순간 발효.
- 에이전트별 오버라이드는 OUT(전역부터 — 필요해지면 후속, YAGNI).

### 3. 적용 경계

- **source=ui + 스크래치(미오픈) 버전의 첫 오픈만** 게이트.
- **롤백(ever_opened 재오픈)은 면제**(구남님 확정): 이미 게이트를 통과해 배포됐던 버전 —
  긴급 롤백을 게이트가 막으면 사고 대응이 잠긴다.
- code/external 에이전트는 이 상태기계 밖(370 경계 유지).
- **우회 없음**(구남님 확정): 급하면 관리자가 설정에서 임계를 낮추는 명시 행위로만(감사 가능).
  force 플래그는 두지 않는다 — 룰의 의미 보존.

### 4. 구현 지점

- `version_routes.activate_version`: target.ever_opened=False && source=ui && 게이트 on이면
  집계 조회 → 판정 → 미달 400(사유 명시). 통과 시 기존 흐름(오픈+자동 회귀).
- 설정: `app_settings._KEYS`에 2키 추가(+검증기). 설정 UI(SettingsView)에 노출.
- UI: 오픈 400 사유를 그대로 표시(안내 문구는 긍정형 — "N회·T% 이상이면 오픈할 수 있습니다").
  에이전트 상세 버전 행에 이미 성적 칩(244)이 있어 사용자는 현재 성적을 본다 — 추가 표시 최소.

## 완료 조건 (수치)

- **C1** 게이트 on(runs=2·score=0.8 예): 미달 스크래치 오픈 → **400**(사유에 현재/필요 수치),
  평가 2회(ok·점수 충족) 후 같은 요청 → **200 오픈**. HTTP 실측.
- **C2** 기본(0/0) = 무게이트: verify_370·e2e 39/39 그대로(무회귀).
- **C3** 롤백 면제: 게이트 on + 임계 미달이어도 ever_opened 버전 재오픈은 200.
- **C4** 에러 런은 회수 불산입(error 3회·ok 0회 → 미달 400).
- **C5** 설정 왕복: PUT 설정 → GET 반영 → 게이트 즉시 발효(재시작 없이).
- **C6** make test SUITE_OK · make e2e green · tsc 0.

## 검증 결과 (2026-07-16 — done, verify_372 ALL PASS)

- **C1** 게이트 on(2회·80%): 실적 0→400(사유에 현재/필요 수치·긍정형)·1회→400(회수 미달)·
  평균 70%→400(점수 미달)·3회 평균 80%→**200 오픈**. **경계값 부동소수 가드**: (0.9+0.5+1.0)/3이
  이진 표현상 0.7999…로 떨어져 80% 임계를 미달 판정하던 것 → 판정에 1e-9 엡실론(회귀 핀 고정).
- **C2** 기본 0/0=무게이트(기존 오픈 자유 — SUITE_OK·e2e 39/39 무회귀).
- **C3** 롤백 면제 실측(임계 미달이어도 ever_opened 재오픈 200).
- **C4** error 런 3회는 실적 불산입(400). **C5** 설정 왕복·재시작 없이 즉시 발효.
- **UI**: 설정 화면 "평가 게이트" 카드(회수·점수 %·긍정형 안내·롤백 항상 가능 명시) 브라우저 실측,
  게이트 발동 400 사유 확인. tsc 0.

이로써 **367 로드맵(A 측정 → B 블록 버전화 → C 복합 버전 → D 캐시 → E 평가 게이트) 완주**.

## OUT

- 에이전트별 임계 오버라이드 — 전역부터(후속).
- 평가 자동 실행 스케줄(게이트용 평가를 자동으로 채워주는 것) — 별개(지금은 수동/자동회귀 결과 사용).
- 점수 산식의 데이터셋 가중치 — 단순 평균부터.
