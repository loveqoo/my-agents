# 166 — 사용 시나리오 감사 (검증 축1)

## 배경
축2(UI 오버플로) 파일럿(스펙 165)의 골격을 축1에 적용: 전수 순회 + 측정 가능 판정 + 아티팩트 +
적대적 실행. 축1은 "가상의 사용자가 목표를 완수할 수 있나 — 어디서 막히고 헷갈리고 기능이 없나".

## 원리(관대함 제거)
- **여정 아티팩트가 재량을 없앤다**: 페르소나 + 목표 + 단계 + **기대결과**를 파일로 박제(`scenarios.md`).
  "이게 되나?"의 합격선이 미리 글로 고정 → "그럭저럭 되네" 불가.
- **적대적 실행이 사각을 없앤다**: 실행자는 "내부를 모르는 비개발자"로 페르소나를 연기. 각 단계에서
  완료/마찰/막힘을 기대결과 대비 판정. 스크립트가 하드 결과(요소 나타남·응답 옴·콘솔 에러 0)를 측정하고,
  스크린샷을 남겨 **소프트 마찰(헷갈림·군더더기)은 육안**으로 본다(축2와 같은 분업).
- **핵심 가치 경로 우선**(why-build: 저마찰 생성·영속 재사용·A2A 협업) — 거기서 막히면 치명.

## 하네스: tests/browser/scenario-audit.mjs
- 로그인 1회 → 여정별로 단계 순차 실행(navigate/click/fill/select/waitFor) → 단계별 기대 assert +
  스크린샷 → 생성 엔티티는 접두어(`scn-<ts>`)로 만들고 **끝에 API로 정리**(dev DB 오염 방지).
- 출력: `out-scenario/scorecard.json`(여정×단계 pass/fail·blocked) + 단계별 png + 콘솔 스코어카드.
  종료코드 = blocked/fail 있으면 1.

## 여정(v1) — scenarios.md 참조
- **J1 저마찰 생성→사용** (페르소나: 비개발자 비서봇 운영자): 새 에이전트 생성(이름·모델·페르소나) →
  **대화해서 응답 받기**. 기대: 만든 뒤 막힘 없이 대화 도달·응답 옴. **감시**: 생성=v1 초안이라
  "만들었는데 활성화 안 하면 대화가 안 되나?"가 마찰/막힘이면 발견.
- **J2 지식 붙이기** (페르소나: RAG 관리자): RAG 컬렉션 생성 → 에이전트 편집 폼에서 그 컬렉션 선택
  가능한지. 기대: 생성한 컬렉션이 폼 선택지에 나타남.

## 검증(이 하네스)
하네스 실행 → scorecard + 스크린샷. blocked/fail을 **적대적 트리아지**(진짜 기능 공백·버그 vs 스크립트
셀렉터 문제). 진짜만 수정하고 재실행해 수렴. 소프트 마찰은 육안으로 추려 별도 기록(후속 스펙 후보).

## OUT
- 더 많은 여정(복제·A2A 협업·승인 게이트·평가 실행). 다중 페르소나 동시. 소프트 마찰의 자동 판정
  (LLM judge — 후속). 축3(문구·평이함) 감사.
