# 180 — 대화 내 인라인 승인(본인 승인은 그 자리에서)

## 배경·문제
본인(self) 승인을 실습해보니 이상했다: **요청자=승인자**인데도 승인하려면 대화를 떠나 **승인 메뉴**로
가야 했다. 남의 것을 검토하는 관리자에겐 큐가 맞지만, *자기 요청을 자기가* 승인하는데 화면 이동은
불필요한 마찰이다. 게다가 단일 브라우저에서 승인하러 이동하면 Playground가 언마운트돼 폴링이 끊겨
채팅 자동 갱신도 안 됐다(스펙 179 P3의 구조적 한계).

## 목표
**지금 이 사용자가 그 승인을 처리할 수 있으면, 대화의 승인 대기 자리에서 바로 승인/거부**한다.
- self → 요청자 본인이 항상 처리 가능(요청자=소유자).
- admin → 현재 사용자가 슈퍼유저일 때 처리 가능.
- 처리 불가(일반 유저가 admin 승인 대기) → 기존대로 "관리자 승인 대기" 안내(승인 메뉴는 그대로 유지).

곁효과: 인라인 승인은 화면 이동이 없어 **폴링이 유지**되므로, 승인 직후 채팅이 그 자리에서 갱신된다
(179 P3 단일 브라우저 한계 해소).

## 비목표
- 승인 메뉴(ApprovalsView) 제거 아님 — 남의 것(관리자 검토)·전체 조망용으로 유지.
- 새 인가 경계 도입 아님 — 인라인 버튼은 **UX 편의**, 실제 인가는 서버 `_may_resolve`(스펙 066/177)가
  그대로 강제. 권한 없는 자가 버튼을 눌러도 403(클라이언트 게이트는 표시 여부만).

## 설계(5파일 배선)
1. **chat.py** — 승인 프레임에 `approver` 실어 보내고, `wait_msg`의 "관리자 승인" 하드코딩을 approver
   반영으로 정정(self→"본인 승인", 그 외→"관리자 승인"). approver는 `interrupted.get("approver")`.
2. **api.ts** — `onApproval?: (approvalId, approver?)`; handleFrame이 `parsed.approver`를 함께 넘김.
3. **Playground.tsx** — `meIsSuperuser` prop 수용. `pendingApproval`에 approver 저장. `canResolve =
   approver==='self' || meIsSuperuser`. `resolvePending(decision)`: `resolveApproval` 호출 후 —
   approve는 기존 폴링이 완료 턴 반영·해제, **reject는 재개가 없으므로**(새 메시지 무) 대기 버블을
   "🚫 거부됨"으로 갱신하고 즉시 해제.
4. **DebugChat.tsx** — awaitingApproval && canResolve면 입력 위에 **인라인 승인 바**(거부/승인 및 재개,
   처리 중 로딩). 불가면 기존 "관리자 승인 대기" 안내 유지.
5. **AdminShell.tsx** — `<Playground meIsSuperuser={user.is_superuser} />`.

## 검증(완료 조건)
- **e2e(본인 승인, member)**: member가 "레코드 삭제"→대화에 **인라인 승인 바**("본인 승인")가 뜨고→
  거기서 **승인**→승인 메뉴 안 가고 그 자리에서 재개 응답 표시(폴링 유지). 큐도 자동 비워짐.
- **e2e(거부)**: 인라인 **거부**→대기 버블이 "거부됨"으로, 채팅 이어감 가능.
- **회귀**: 일반 유저가 admin 승인 대기면 인라인 바 없이 기존 안내(승인 메뉴 경로 무회귀).
- **회귀**: 승인 대기 아님/도구 미바인딩 평상 채팅 무영향.

## 발견·수정 — 폴링 baseline 레이스(빠른 승인)
인라인 승인 e2e에서 서버는 재개·영속했는데(status=approved, 메시지 2건) 채팅이 안 갱신됐다. 원인:
179 P3 폴링이 완료 감지를 "세션 메시지 수 > baseline"으로 하는데, **baseline을 첫 틱(2.5s 뒤)에서
포착**했다. 인라인 승인은 프레임 도착 직후 바로 승인하므로 첫 틱 시점엔 *이미 완료*라 baseline이
완료-후 카운트(2)를 잡아 `2>2=false`가 영영 참이 안 됐다. 2브라우저는 승인이 느려(다른 사람이
큐에서) 첫 틱이 완료 전이었기에 우연히 초록이었다. **수정**: 첫 틱을 즉시(0ms) 발화해 baseline을
*대기 시점*(완료 전)에 포착. 곁효과로 179 P3의 단일 브라우저 한계(승인하러 이동→언마운트)도 인라인
승인엔 무관(화면 이동 없어 폴링 유지)해져 해소.
