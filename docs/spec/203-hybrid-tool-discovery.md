# 203 — 도구 다수 시 디스커버 전환 (하이브리드 도구 접근)

## 배경 (스펙 202 논의 → 사용자 승인 "바로 구현")
직접 바인딩은 도구 수에 비례해 프롬프트가 커진다(사용자 지적). 조율형의 디스커버 사상("프리로드
없이 검색")을 **부품으로만** 빌려온다 — 에이전트 종류 불변(디스커버=부품, 조율형=형태: 위임·fold·
신뢰경계. 사용자 문답으로 확정).

## 설계

### A. 하이브리드 게이트 (packages/agent/src/agent/toolbox.py 신설)
- `effective_tools(tools) -> (tools, discovery: bool)`: 도구 수 ≤ 임계(기본 10, env
  `TOOLS_DISCOVER_THRESHOLD`)면 그대로(무회귀), 초과면 **메타 도구 2개로 대체**:
  - `search_tools(query, limit)`: 주입 도구를 어휘 랭킹(이름 가중+설명)으로 검색 — 이름·설명·인자
    요약 JSON. 프롬프트에는 이 창구만 실림 → 도구가 늘어도 컨텍스트 일정.
  - `call_tool(name, args)`: 찾은 도구를 이름으로 호출(args=JSON 문자열). 미존재 이름은 후보 제안과
    함께 에러 JSON(graceful).
- **브로커 경유가 아님**: 브로커는 per-user RBAC(capabilities 축)라 직접형의 권한 의미(에이전트
  배선=사용)를 바꾼다. 메타 도구는 **이미 주입된 도구 목록 위** 래퍼라 권한·HIL·트레이스 래핑이
  그대로 통과.

### B. 적용 지점 (둘)
- **직접형** `build_agent`(main.py): effective_tools 적용 + discovery 모드면 시스템 프롬프트에 사용
  안내 1줄("search_tools로 찾고 call_tool로 호출").
- **플랜형** `PlanExecuteAgent`: 같은 헬퍼. 계획 문구 분기 — discovery면 "필요하면 도구 검색으로
  알맞은 도구를 찾아 사실을 확인한다"(202의 이름 나열 대신).

### C. UI 안내 (사용자 요청 — 생성·수정 폼)
- AgentForm 직접 응답 '도구' 영역에 문구: "도구를 많이 연결하면(10개 초과) 컨텍스트 보호를 위해
  도구를 검색해 쓰는 방식으로 자동 전환됩니다 — 기능은 동일합니다."
- 임계값은 FE/BE 상수 미러(주석 상호 참조, v1은 API 노출 없이).

## 검증
1. 단위(verify_203): 임계 경계(10=직통·11=메타 2개)·검색 랭킹(키워드→해당 도구 상위)·call_tool
   정상/미존재/args 파싱 오류 graceful·plan 문구 분기.
2. 무회귀: 089(T 포함)·086(plan 결정적). 도구 ≤임계 경로는 코드 경로 동일.
3. live: 임계=1로 서버 기동 → research-assistant(도구 2+)가 discovery 모드 → 위키 질문 →
   search_tools→call_tool→wiki_* 실호출 체인 인스펙터 확인 → 임계 원복.
4. UI: tsc0 + 폼 문구 스샷.

## RBAC 경계
- 비트리거: 새 입구 0. 메타 도구는 주입 목록의 재표현(권한 의미 불변 — 브로커 미경유 명시).

## 경계
- 검색은 어휘 랭킹(브로커 rank와 동사상) — 벡터 검색은 카탈로그 확대 시 후속(백로그 기존 항목).
- 승인 게이트 도구가 call_tool 내부에서 interrupt하는 HIL 재개는 검증 밖(202와 동일 경계).
- 오버라이드 드로어 문구는 밖(생성·수정 폼만 — 사용자 요청 범위).
