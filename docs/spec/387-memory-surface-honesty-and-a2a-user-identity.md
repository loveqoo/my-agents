# 387 — 기억 표면 정직화 + A2A 유저 정체성 전달

> 상태: 초안(AI 작성 → 인간 검토). 발단: 구남님 3문(중복 저장·캐시 범위·"단기(세션)")과 후속 추궁.
> 참고: 스펙 020(카탈로그=실동작)·032(userId 클라이언트 제거)·safe-flag 계열 회고 385/389

## 배경 — "단기(세션)" 추궁이 드러낸 세 겹

1. **죽은 선택지**: 에이전트 폼의 "장기 기억" 드롭다운에 "단기(세션)" 옵션이 떴다(스크린샷).
   실체 = 옛 데모 카탈로그의 memory_types 레거시 행(자기 설명부터 "mem0 아님"). 런타임 판정은
   `memory_enabled()` = `"장기 기억 (mem0)"` 문자열 멤버십뿐이라 **골라도 무동작**(조용한 no-op).
   seed는 정리됐지만(020) 라이브 행은 잔존 — seed_if_empty는 삭제하지 않는다.
2. **머신 경로의 기억 상실**: user_id는 인증 주체에서만 도출(032가 클라이언트 제공 userId를 보안상
   일괄 제거) → 머신 토큰/A2A는 무조건 None → mem0가 세션 축에만. **A2A 호출자가 자기 시스템의
   유저를 대신해 부르는 정당한 유스케이스를 막았다**(머신=owner 전권이라 권한 모순도 없는데).
3. **문구 화석**: 시드 블록·폼 도움말이 여전히 "**요청** userId 유무로 자동 결정"(032 이전 문구).

## 결정(구남님)

- ① 죽은 "단기(세션)" 행 삭제 — **승인·집행 완료**(참조 에이전트 0 확인 후 정식 라우트 DELETE 204,
  잔여 memory_types = "장기 기억 (mem0)" 단일).
- ③ **"외부에서 A2A로 유저아이디 전달 가능, mem0 설정했다면 사용 가능"** — 방향 승인. 아래 설계.
- ② 저장 시 기억 이름 존재 검증 + memory-type 삭제 참조 가드 — **포함 승인**.

## ③ 설계 — 머신 호출자의 유저 정체성

**원칙**: 032의 보안 목적(브라우저 유저가 임의 userId로 타인 기억 접근 금지)은 보존하고,
머신(owner 전권) 경로에만 정체성 전달을 연다.

- **입구 A — `POST /agents/{id}/chat`**: `ChatRequest.userId: str | None` 재도입.
  - principal이 **머신 토큰일 때만 수용**. 쿠키 유저가 보내면 **422 거부**(자기 정체성 위조 금지 —
    조용한 무시가 아니라 명시 거부, 스펙 383 결).
  - 수용되면 mem0 add/recall의 user 축으로 그대로 흐름(변경점은 chat 핸들러의 user_id 결정부 한 곳
    — [[policy-at-the-chokepoint]]).
- **입구 B — A2A 서빙(`exposed_agent_a2a`)**: `params.message.metadata.userId` 수용(A2A 표준
  metadata 자리). 서빙 인증은 이미 머신급 토큰이라 같은 규칙. `stream_local_reply`에 user_id 전달.
- **효과**: 에이전트에 "장기 기억 (mem0)"이 설정돼 있으면, 외부 호출자의 유저 X가 세션·호출을
  가로질러 기억을 갖는다(로그인 유저와 동일 메커니즘).

**결정(구남님): (a) 그대로 수용** — 외부 시스템이 내부 유저와 같은 정체성을 대신 쓸 수 있다
(머신=owner 전권, 의도된 위임). 충돌 성질은 문서·폼 도움말에 명시.

## 문구 정정(포함)

- 폼 도움말(MemoryFields)·시드 블록 설명: "요청 userId…" → 실동작 서술. 긍정문 구조
  ([[prefer-positive-phrasing]]): "로그인 사용자와의 대화는 유저 단위로 세션을 넘어 기억합니다.
  머신/A2A 호출은 userId를 함께 보내면 동일하게 기억하고, 없으면 이번 대화에만 유지합니다."

## ②(포함) — 저장 시 기억 이름 존재 검증 + 삭제 참조 가드

`assert_node_refs_exist`(스펙 316) 규칙을 memories에 적용: 에이전트 저장 시 각 이름이 실제
memory_types에 존재해야 저장(422). 형제 조치: memory-type **삭제 라우트에 참조 가드 추가**
(현재 prompt와 달리 무가드 — 삭제하면 참조 에이전트가 조용히 no-op).

## 완료 조건(측정 가능)

- C1: 폼 드롭다운에 죽은 옵션 없음(memory_types = 실동작 블록만) — ① 완료분.
- C2: 머신 토큰 + userId로 2세션 왕복 — 세션 A에서 저장한 사실이 세션 B에서 회상(user 축 증명).
- C3: 쿠키 유저 + userId → 422(032 보안 보존의 여집합).
- C4: A2A message/send에 metadata.userId → 같은 회상 왕복.
- C5: 씨앗 그물 SUITE_OK·suite 기억 시나리오(51/51) 무회귀.
- codex 적대 리뷰(인가 경계 변경이라 필수).
