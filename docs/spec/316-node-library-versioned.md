# 316 — 노드 라이브러리: 등록 노드 + 버전 고정 참조 (노드형 확장 1/3)

## 배경 / 동기

노드형(스펙 259 계보)의 노드는 지금 에이전트 `impl_config.nodes`에 **인라인 JSON으로만** 존재한다.
잘 만든 노드를 다른 에이전트에서 쓰려면 복붙해야 하고, 개선해도 전파할 방법이 없다.

사용자 요구(2026-07-13): 잘 만든 노드를 **1급 자산으로 등록·관리**하고, 노드형에서 노드를
(a) 직접 설정 또는 (b) 등록 노드 참조, 2가지 방식으로 쓸 수 있게 한다. 이후 코드로 작성해 등록하는
노드(UI로 못 만드는 복잡 로직)와 노드에서의 에이전트 호출까지 확장한다.

**3분할**(합의): ① 본 스펙 = 라이브러리 + 버전 고정 참조(kind=config만). ② 코드 노드(스펙 317 예정,
공통 노드 인터페이스 + 신뢰 레지스트리). ③ 노드에서 에이전트 호출 도구(스펙 318 예정).

## 합의된 설계 결정 (2026-07-13)

1. **버저닝 — 참조는 버전 핀 고정.** 라이브 참조는 잘 테스트해 온/출시된 에이전트를 등록 노드 수정이
   소리 없이 바꾸는 위험이 있다(사용자 지적). 따라서:
   - 등록 노드는 `(name, version)` 단위로 존재하고, **발행된 config 버전은 불변**(수정 API 없음).
   - 수정 = **새 버전 발행**. 참조 에이전트는 자기가 핀한 버전에 머물고, 옮겨 타기는 에이전트 편집에서
     버전을 **명시적으로** 올릴 때만.
   - 예외(② 코드 노드): 코드 재등록으로 **동일 버전 덮어쓰기 허용** — 같은 버전을 쓰는 모든
     에이전트에 일괄 전파하는 의도된 탈출구(핫픽스). 본 스펙은 kind 컬럼만 예약한다.
2. 에이전트 호출은 도구 방식(③) — 이름은 ID 기반(별명은 중복·혼동 위험). 상세는 ③ 스펙에서.
3. 에이전트 호출 재귀 가드는 ③ 필수 항목.

## 설계

### 1) 엔티티 `NodeTemplate` (테이블 `node_templates`, 마이그레이션 1개)

- `id`(uuid PK), `name`(식별 이름 — 에이전트 name 규칙 준용), `version`(int ≥1),
  `kind`("config" 고정 — "code"는 ②에서), `config`(JSON — 에이전트 저장 스키마의 노드 화이트리스트
  `_normalize_node`와 **동일 검증**을 통과한 형태), `description`(선택), `created_at`.
- **unique(name, version)**. 발행 후 불변 — update 라우트를 만들지 않는다(구조로 강제).
- 마이그레이션은 손수 순번 ID 충돌 주의([[hand-authored-migration-ids-collide-silently]]) —
  헤더 그래프 검증(단일 head·중복 0) 포함.

### 2) API (공유 카탈로그 — McpServer와 동일하게 owner 없음, admin 관리)

- `GET /node-templates` — 이름별 그룹(최신 버전·버전 수·사용 에이전트 수).
- `GET /node-templates/{name}` — 버전 히스토리 + 버전별 사용 에이전트 목록.
- `POST /node-templates` — 새 노드(version=1) 또는 새 버전 발행(기존 이름 + 다음 버전 자동).
  config는 `_normalize_node`와 동일 화이트리스트·상한으로 검증(드리프트 0 — 검증 함수 재사용).
- `DELETE /node-templates/{name}/{version}` — **참조 에이전트가 있으면 409 차단**(스펙 093 선례,
  차단 사유에 에이전트 이름 표면화). 참조 0이면 삭제 허용.
- 사용처 산출: agents.config JSON의 `nodes[].ref` 스캔(에이전트 수가 작아 앱 사이드 스캔으로 충분,
  단일 헬퍼로 통일 — usage 표시와 삭제 차단이 같은 함수를 쓴다).

### 3) 참조 표현 + 해석 (엔진 무변경이 원칙)

- `impl_config.nodes` 항목의 새 변형: `{"ref": {"name": str, "version": int}}`.
  저장 스키마 `_normalize_node`가 ref 변형을 허용(ref면 인라인 키는 받지 않음 — 혼합 금지) +
  **저장 시 존재 검증**(없는 참조는 저장 거부 — 이른 실패).
- **단일 해석 헬퍼** `resolve_node_refs(db, nodes) -> list[dict]`: ref 항목을 해당 버전 config의
  **사본**으로 치환(순서 보존, 원본 템플릿 비오염). **미해결 참조(그새 삭제 등)는 명확한 설정
  오류**로 실패 — 조용한 드롭·폴백 마스킹 금지(스펙 089 패턴).
- 해석 위치는 **엔진 앞단(API 층)** — pipeline.py는 해석 결과(인라인과 동일 형태)만 받는다(085 U2:
  impl은 DB 미접촉). 사용처(입구 열거 — 전부 이 헬퍼 경유인지 검증 항목):
  1. 채팅 로드(chat_context, `_resolve_node_models` **앞**) — 플레이그라운드·A2A 로컬 서빙·eval이
     같은 로드 경로를 타는지 확인하고, 다른 입구가 있으면 그 입구에도 배선.
  2. `derive_pipeline_pool`(스펙 289) — 풀 파생은 해석 **후** 도구·기억 합집합(참조 노드의 도구가
     조용히 미바인딩되지 않게).
  3. 플레이그라운드 오버라이드 — **해석 → 병합** 순서(`_merge_node_overrides`는 해석된 리스트 위에
     기존 화이트리스트 그대로). `_NODE_OVERRIDE_FIELDS`에 `ref`를 넣지 않는다 — 세션 오버라이드로
     참조 자체를 갈아끼우는 것은 범위 밖(구조 변경 금지 원칙, 스펙 287과 일관).

### 4) Admin UI (전부 antd)

- 새 메뉴 **"노드 라이브러리"**: 목록(이름·최신 버전·kind·사용 에이전트 수) / 상세(버전 히스토리,
  버전별 설정 읽기 전용 + 사용 에이전트) / 작성·새 버전 발행 폼(기존 NodeListEditor의 노드 편집
  표면 재사용 — prompt·model·tools·context·format·fields·memories·memoryQuery·historyDepth) /
  삭제(차단 시 사유 표면화).
- 에이전트 폼 NodeListEditor: 노드별 **"직접 설정 | 라이브러리에서"** 선택. 참조 선택 시
  이름@버전 픽커 + 해석된 설정 읽기 전용 미리보기(무엇이 실행되는지 가리지 않음 —
  [[beauty-equals-trust]]).
- 플레이그라운드 오버라이드 패널: 참조 노드도 **유효(해석된) 설정**을 보여주고 그 위에 세션 패치.
  패널이 유효 설정을 얻도록 에이전트 조회 응답에 `resolvedNodes`(읽기 전용 파생)를 추가.

## 범위 밖 (OUT)

- 코드 노드(② 317)·에이전트 호출 도구(③ 318).
- 참조의 최신 자동 추종(floating latest) — 명시적으로 하지 않는다(버전 핀이 이 스펙의 존재 이유).
- 버전 간 diff UI·draft(미발행) 상태·노드 라이브러리의 per-user RBAC 세분(공유 카탈로그 — 기존
  McpServer와 동일 수준).
- 노드가 노드를 참조(중첩) — 구조상 없음(순환 참조 클래스 자체가 발생 불가).

## 검증 (사다리 3런)

- **단위(결정적)**: `tests/verify_316_node_library.py` —
  ① resolve_node_refs: 치환·순서 보존·사본 격리(치환 결과 변형이 템플릿 원본 비오염)·미해결 참조는
  명확 오류(조용한 드롭 0), ② 저장 스키마: ref 변형 수용·ref+인라인 혼합 거부·없는 참조 저장 거부,
  ③ 삭제 차단: 참조 존재→409·참조 0→삭제, ④ 오버라이드: 해석→병합 순서·`ref`는 오버라이드 불가,
  ⑤ 새 버전 발행 후 기존 핀 참조의 해석 결과 불변(버전 고정 시맨틱).
- **실 인프라(통합)**: 등록→참조 에이전트 생성→채팅 왕복(참조 노드 실행이 트레이스 노드명으로 확인)
  → 새 버전 발행→기존 에이전트 응답 경로 무영향(핀 유지)·버전 올린 에이전트만 변화.
  UI는 브라우저로 실제 동작 수행→효과 단언([[ui-verification-must-be-functional]]).
- **적대(codex)**: 보장 목록의 여집합 — 저장 검증↔채팅 해석 사이 TOCTOU(삭제 차단이 막는지),
  오버라이드/직접 API 등 폼 밖 입구로 ref 주입 시 검증 우회 여부, usage 스캔이 놓치는 참조 입구,
  resolvedNodes 파생이 비밀(model_cfg의 api_key 등)을 에코하지 않는지.

## codex 적대 검증 → 수정 (P0 0 · P1 4 수정 · P2 2 = 1 수정 + 1 경계)

- **P1 impl 비대칭**: 저장 검증이 `derive_pipeline_pool`(pipeline 전용)에만 있어 비노드형 에이전트는
  없는 참조를 저장할 수 있었다(실행 시 422 시한폭탄). → `assert_node_refs_exist`를 생성/수정 라우트에
  **impl 무관**으로 배선(verify H5b). "비노드형의 inert ref도 삭제를 409로 막음"은 **의도된 보수적
  가드**로 유지(impl을 나중에 pipeline으로 바꿔도 참조가 살아 있어야 함 — 스펙에 명시).
- **P1 삭제 가드 TOCTOU**: usage 스캔↔삭제 커밋 사이에 새 참조가 저장되면 dangling ref. →
  이름 단위 `pg_advisory_xact_lock`을 발행·삭제·에이전트 저장(ref 검증)이 공유(직렬화, JSONB라
  FK 없음 — 잠금이 유일한 직렬화 수단).
- **P1 변이 게이트 부재**: 공유 실행 자산의 발행/삭제가 인증만으로 가능했다. →
  `require_node_manage`(특권: 머신·superuser·admin만, member 403 — model_registry와 동일 패턴).
  읽기는 인증만(에이전트 폼 참조 픽커가 소비).
- **P1 usedBy 가시성 누출**: private 에이전트 이름이 모든 인증 사용자에게 노출. →
  `visible_used_by`(may_use_agent 필터 + 숨김 개수 `usedByHidden`), 목록은 개수만. 삭제 409의
  이름 표면화는 특권 게이트 뒤라 유지.
- **P2 clone/activate/revert 입구(경계 수용)**: 버전 스냅샷/복제 원본의 참조는 usage 스캔이
  agent_versions까지 세므로 삭제 가드가 보호하고, TOCTOU는 잠금으로 닫혔다. 잔여는 직접 DB 보정
  뿐 — 그 경우도 실행 시 422로 정직 실패(verify H5). 라우트별 재검증은 과잉으로 판단, OUT 기록.
- **P2 동시 발행 409 → 수정**: 발행도 이름 잠금을 지나 직렬화 — 경합 시 한쪽 409 대신 순서대로
  vN+1·vN+2 발행(unique 제약은 최후 방어로 유지).

## 완료 조건

- 노드 등록→노드형에서 참조→실행 왕복이 동작하고 트레이스에 노드명이 뜬다.
- 새 버전 발행이 기존 핀 참조 에이전트에 **무영향**(측정으로 확인), 버전 변경한 에이전트만 반영.
- 참조 중 삭제는 409 + 사유 표면화, 미해결 참조는 명확한 설정 오류(마스킹 0).

  계열) 무회귀.
