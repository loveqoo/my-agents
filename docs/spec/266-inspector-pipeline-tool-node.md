# 266 — 인스펙터가 노드형 도구 노드(`X__tools`)의 조회 카드를 안 붙이던 버그 (사용자 보고)

## 배경
사용자 보고(2026-07-09): "RAG를 조회했는데 인스펙터에는 안 나와. 예전처럼 조회 결과가 나와야 하는데."
— 265에서 RAG 실발화는 검증했지만(트레이스 mcp 기록), **인스펙터 표면**은 확인 안 했다. 백엔드는
정상적으로 기록했는데(칩 "1 rag"도 정상) 실행 흐름의 도구 노드에 RagCall/McpCall 카드가 안 붙었다.

## 근인
Inspector.tsx의 호출 카드 귀속 술어 3곳이 **`node === 'tools'` 정확 일치**(기본 ReAct·plan_execute의
도구 노드 이름 관례)로 고정 — 노드형(259)의 도구 노드는 `<노드명>__tools`(예: `문서답변__tools`)라
전부 탈락 → 카드가 어느 노드에도 귀속 안 됨. learning 149 동형(형제 노드 이름의 닫힌 집합 가정):
새 그래프 위상이 들어오면 노드명 기반 귀속 술어도 소비자로서 정렬돼야 한다.

## 수정 (Inspector.tsx, 표시만)
- `nodeMeta`: `X__tools` → "도구·문서 검색 실행 · X"(tools와 같은 시각 계열).
- `nodeEventContent`: `node === 'tools' || node.endsWith('__tools')`로 카드 귀속.
- 타임라인 다회 귀속(`toolsTotal`/`toolsIdx`): `isToolNode` 술어로 일반화 — t.mcp(턴 전체 실행 순)와
  도구 노드 전역 등장 순번 1:1(202/203 도시락 방지 로직 그대로 승계).

## 검증
- **기능 e2e**(`shot-pipeline-rag-inspector.mjs`, 필수 단언): 노드형 RAG 에이전트 → 플레이그라운드 UI
  대화 → 칩 "1 rag" → 인스펙터에 도구 노드 라벨("도구·문서 검색 실행 · 문서답변") + RagCall 카드
  (search_documents · 3건 · 검색어 에코 · 유사도 척도 · 히트별 카드/본문 보기) ALL GREEN + 육안(스샷).
- tsc 0. 기존 'tools' 경로는 술어 확장이라 무회귀(정확 일치 여전히 참).

## 교훈
- 축 검증의 완결은 **기록 + 표면**: 265는 "호출 기록"을 단언했지만 사용자가 보는 표면(인스펙터 귀속)은
  별개 소비자였다. 새 그래프 위상(노드형)을 들이면 그 위상을 소비하는 표면(귀속 술어·노드 라벨)까지
  정렬 목록에 넣어라(238 hide-surface ③과 같은 결 — 소비 표면 전수).
