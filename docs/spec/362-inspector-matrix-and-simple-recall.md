# 362 — 단순 에이전트 회상 표시 봉합 + 에이전트유형×능력×인스펙터 매트릭스

## 왜 (실물 확증 — 사용자 버그리포트 스샷)

personal-secretary(단순/표준 에이전트)에서 "내가 과거에 무엇을 검색했지?" 물으면 모델은 회상된 4건으로
답하는데(정상 실행), **인스펙터 실행흐름엔 회상이 안 보인다** — 트레이스 칩은 "4 mem"인데 실행흐름은
`시작 → 모델 호출 → 종료`뿐(스샷 확증).

**근인**: 단순 에이전트는 회상을 그래프 실행 *전에* 프롬프트로 선주입한다(스펙 268 주석 "회상은 플랫폼이
턴 시작에 1회 수행해 페르소나에 합침") → 실제 관측 그래프엔 `retrieve_memory` 노드가 없다
(`build_graph_path` 합성 경로만 그 노드를 넣지만 정상 턴은 실 관측 그래프 사용). 인스펙터는 `t.memories`를
**`retrieve_memory` 노드에만** 렌더하므로(Inspector.tsx:349), 그 노드가 없으면 회상 4건이 어디에도 안
붙는다. 스펙 359(노드형 memoryRecalls)의 **단순형 형제**.

## 설계

### P1 — 단순 에이전트 회상 표시(위상 독립)

NodeTimeline에서 실 그래프에 `retrieve_memory` 노드가 없으면, 회상을 **맨 앞 합성 스텝**("메모리 회상 ·
턴 시작 회상")으로 넣어 `t.memories`를 보인다. 기존 `retrieve_memory` 렌더(nodeEventContent)를 재사용
(drift 0) — 쿼리·스코프·MemoryRow 그대로. `retrieve_memory` 노드가 실제로 있으면(합성 폴백 등) 중복
없이 그 노드가 렌더(hasRecallNode 가드).

### P2 — 에이전트유형 × 능력 × 인스펙터 매트릭스 (사용자 지시, 전수조사 편입)

반복된 회상 표시 버그(359 노드형·362 단순형)의 근본은 유형마다 mem/rag/mcp를 **다른 메커니즘**으로
처리하는데 인스펙터 표시가 유형별로 따로 배선돼 한 곳 고쳐도 다른 유형이 조용히 빠지는 것. 매트릭스로
상시 회귀에 편입한다:

- **셀 = (에이전트유형 × 능력)**: 유형 {단순(ui)·노드형(pipeline)·조율형(orchestrator)} × 능력 {memory·rag·mcp}.
- **각 셀 단언**: (a) 능력이 실제 **실행**(SSE trace 실측: memories/memoryRecalls·rag hits·mcp calls),
  (b) 인스펙터가 **내용까지 표시**(브라우저: 실행흐름 페이지 텍스트에 회상 본문·검색 히트·도구 결과가
  보임 — 카운트만 아님).
- code/external은 원격·불투명(인스펙터 제한) → 매트릭스 밖(별도 기록).
- 스펙 288 조합 스위트는 실행 축만 → **인스펙터 표시 축**을 이 매트릭스가 담당.

## 완료 조건 (수치)

- **P1-C1** 단순 에이전트(회상 있음) 인스펙터 실행흐름에 "메모리 회상 · 턴 시작 회상" + 회상 본문(MemoryRow) 표시. tsc 0.
- **P1-C2** 무회귀 — `retrieve_memory` 노드가 실제 있으면 합성 스텝 중복 없음(hasRecallNode 가드).
- **P2-C1** 매트릭스 브라우저 감사: memory 행(단순·노드형) 실행+표시 초록(359·362 검증).
- **P2-C2** 매트릭스가 run_suite(전수조사)에 편입돼 상시 회귀.
- **P2-C3** rag·mcp 행, 조율형 유형은 후속 확장(셀 추가) — 미확인 셀은 매트릭스 로그에 명시(은폐 금지).

## OUT

- code/external 인스펙터 표시(원격 불투명) — 별개.
- rag·mcp 전 유형 셀 완성은 후속(이 스펙은 memory 행 + 매트릭스 골격 + 단순형 봉합).
