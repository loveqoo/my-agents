# 389 — 테스트 위생 묶음: 격리 축소·환경 독립화·리퍼 확장

> 상태: 초안(AI 작성 → 인간 검토). 성격: 회귀망 위생(소형 4건 일괄).
> 참고: 회고 389(mock 전제 158)·390(옛 이름)·391(리비전 중복 의심)·384(리퍼=agents만)

## 항목과 결과

1. **verify_158 환경 독립화** — "기본 threshold서 회상 0" 단언은 mock 임베더 전제였는데
   default_mem_cfg를 써서 실모델 기본값에서 깨졌다(회고 389). V2 레그의 mem_cfg를 mock 모델
   (mock-llm/mock-embed) 명시 조립으로 고정 → 환경 무관 결정적. **그린 복귀·격리 해제.**
2. **격리 판정 3건**(반복 "격리인데 통과" 신호):
   - verify_059·345 = 본질이 **virgin-DB 검증**("fresh DB 부팅 수렴"·"처녀 DB unknown 0건") →
     `_throwaway_db.py` 마커 승격(스펙 370 규약 — run_suite가 자동 격리 실행). **둘 다 해제,
     라이브 DB 상태와 영구 무관.**
   - verify_068 = 해제 시도했으나 **실측 재실패** → 재격리(사유 갱신: 초기화 후에도 D6 재현,
     asyncpg 커넥션 수명 조사 유지). 해제는 관찰이 아니라 실측으로.
3. **옛 카탈로그 이름 정리** — verify_268의 "단기(세션)" 4곳→"장기 기억 (mem0)"(단위 mock이라
   의미 동일, 죽은 이름 제거). **verify_020은 오판 정정: 손대지 않음** — 그 옛 이름들은 dangling이
   아니라 **마이그레이션(c1d2 카탈로그 흡수) 로직의 입력**이다(백로그 메모가 틀렸음).
4. **리퍼 확장** — clean_test_agents가 agents만 스윕하던 것을 모델/프로바이더/컬렉션 누수
   (_verify*·v###-·ui###-)까지 확장(모델→프로바이더→컬렉션 순서, 정식 라우트 경유 — 참조 가드가
   안전핀). suite-kb·실모델은 KEEP(상주 픽스처/실자산 — 첫 dry-run이 suite-kb 오인을 적발해 정정).
5. **suite 픽스처 reused 자가검사**(회고 389 함정 봉합) — "텍스트 존재=reused"가 임베더 교체 시
   무효 벡터를 재사용하던 것을, **회상 실증**(search에 PREF 히트) 실패 시 삭제+재시드로 교정.
6. **리비전 ID 중복 의심(회고 391 덤 관찰) = 오경보 확정** — 52파일/52 고유 ID. 앞선 "50/54"는
   내 정규식이 `revision = "..."`(타입 주석 없는 구형식 4파일)을 못 읽은 파싱 오류.
