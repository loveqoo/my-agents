# 스펙 238 — 에이전트 폼 UX 재정비 (사용자 리뷰 5건, 2026-07-08)

## 배경 (사용자 UI 리뷰)

235~237의 비영속 UI를 보고 받은 지적 5건:
1. **영속/비영속은 매우 큰 변화** — 부가정보(세부 설정)가 아니라 **상단 1급 정보**. 기본값=영속.
2. **비영속 선택 후 금지 도구를 고를 수 있게 두는 건 잘못** + 큰 경고로 놀래키는 것도 나쁜 경험 —
   **disabled 처리**가 맞다.
3. **에이전트 종류가 단순 선택박스** — 설명이 든 rich 선택박스 또는 하위 설명/종류별 컴포넌트 그룹.
4. **플레이그라운드 오버라이드 폼과 긴밀 연동** — 폼이 바뀌면 오버라이드도. 바꿀 수 있는 것/없는 것 구분.
5. **플그 추천 명령어가 고정** — 에이전트 설정에서 추천 명령어 등록(옵셔널) → 플그에 노출.

## 변경

### P1 — 영속/비영속 1급 승격 (AgentForm)
- 세부 설정의 "비영속(1회성)" 토글 제거 → **기본 영역**(종류 아래)에 `Segmented` [영속 | 비영속(1회성)],
  기본 영속. 선택별 한 줄 설명. 세부 설정 "저장·영속"(히스토리·대화저장)은 비영속 시 disabled 유지.

### P2 — 경고 대신 disabled
- PickerGroups `PickerItem`에 `disabled?/disabledHint?` 추가(체크박스 disabled+회색 사유).
- 비영속이면 "기억에 저장" 항목 **disabled**(숨김·큰 Alert 제거). 비영속 **전환 시 이미 선택된 금지
  항목은 자동 해제**(disabled+checked 모순 방지 — 전환은 명시적 사용자 행동이므로 결과를 조용히 반영).
- 236의 mock+도구 warning Alert도 **작은 보조 문구**로 강등(놀래키지 않기, 정보는 유지).

### P3 — 에이전트 종류 rich select
- Select `optionRender`로 옵션마다 굵은 라벨+설명 줄. 선택 후 하단 설명 유지. 종류별 하위 섹션
  분기(직접/조율/산출물)는 기존 구조 유지(이미 종류가 설정면을 가름 — 스펙 108).

### P4 — 오버라이드 폼 연동 (OverridePanel)
- **바꿀 수 없는 것 명시**: 영속/비영속은 오버라이드 불가(서버 allowed 키에도 없음) → 패널에 read-only
  모드 태그("비영속(1회성) — 세션에서 변경 불가").
- 비영속 에이전트: 기억 그룹 disabled(런타임이 무시 — 235)·capabilities의 memwrite/memedit disabled
  (편집 폼과 동일 규칙, 스펙 122의 "편집폼만 고치고 오버라이드 빠뜨림" 재발 방지).
- 서버는 이미 안전(ephemeral은 오버라이드 키 불허·memwrite는 런타임 필터) — UI 정합만.

### P5 — 에이전트별 추천 명령어 (옵셔널)
- `config.suggestedPrompts: list[str]`(기본 [], **캡: 최대 8개·각 200자**, 서버 검증 — 신뢰경계 리셋
  learning 075). 다배선 미러링(schemas 2곳·serializers·admin 타입·매핑 — persistHistory/ephemeral 선례).
- 폼: 세부 설정에 태그 입력(Select mode=tags). 플그 DebugChat: 등록돼 있으면 그걸로 프롬프트 카드
  렌더, 없으면 기존 고정 3종 폴백(무회귀).

## 완료 조건 (충족)
- 영속/비영속이 상단 1급. 금지 항목은 경고 아닌 disabled(+전환 시 자동 해제, 미선택-잠금으로 해제
  어포던스 보존). 종류 선택에 설명 내장. 오버라이드 폼이 편집 폼 규칙과 정합(불변 항목 명시 + 기억/
  memwrite 동일 잠금). 에이전트별 추천 명령어가 플그에 뜬다(미등록 시 기본 3종 폴백).

## 설계 노트
- **미선택-잠금 패턴**: 금지 항목은 `disabled = 조건 && !선택됨` — 새 진입은 잠그되 기존 상태의 탈출
  (해제)은 항상 허용. "숨김→해제 불가"(237)·"disabled+checked 고착"(238 codex #2)을 모두 피하는 형태.
- 저장 방식은 세션 오버라이드 불가(서버 allowed 키에 없음) — 오버라이드 폼은 read-only 태그로만 표시.

## 후속 수정 (사용자 지적 2026-07-08 — "비영속인데 대화 저장이 ON 고정")
- **대화 저장**: disabled인데 표시값이 저장값(persistHistory=true)이라 **켜짐 고정**으로 보였다(모순).
  → 표시값=실효값: 비영속이면 꺼짐으로 표시(`checked={!ephemeral && persistHistory}`), 저장값은 보존
  (영속 복귀 시 원복 — 브라우저로 원복까지 검증).
- **채팅 히스토리(검토 중 발견, 반대 방향 오류)**: "적용 안 됨"으로 잠갔지만 런타임 `_window`는
  비영속에도 적용된다(요청에 담긴 대화를 모델에 몇 개 넣을지 — 저장이 아니라 **모델 컨텍스트** 설정).
  → 모델 동작 구역으로 이동·활성 + 안내 문구("비영속에서도 요청에 담긴 대화에 적용됩니다").
- 검증: 브라우저 8/8(기본 ON→비영속 OFF+disabled→영속 복귀 시 ON 복원, 히스토리 활성+문구).
