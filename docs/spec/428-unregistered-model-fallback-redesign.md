# 스펙 428 — 저장 config 미등록 모델의 조용한 폴백 재설계(불변식 우선)

## 문제

learning 092: **"선언했는데 깨진 설정은 크게 거절한다"**(폴백은 실패를 가린다 — 호출자가 다른 모델로
실행된 걸 모른 채 지나감). 스펙 401이 **오버라이드**엔 적용(실명 미등록 → 400). 그러나 **저장 config**
(`agents.config.model`)가 미등록 모델을 가리키면 `_resolve_model`이 여전히 **조용히 기본 폴백**한다 —
092 원칙과 어긋난 잔여 불일치.

## 근인(증상 아닌 원인) — 깨진 상태를 만드는 두 입구

"거절 vs 경고"는 증상 처리다. 저장 config가 미등록 모델을 가리키게 되는 **원인**은 둘:

1. **모델 이름 변경(PUT /models)에 참조 가드 없음** — 삭제(delete_model)는 3중 가드(라이브 에이전트·
   버전 스냅샷·컬렉션 FK, 409)로 막혀 있는데, **rename은 `m.name = body.name`만 하고 참조를 안 본다**.
   이름을 바꾸면 그 모델을 쓰던 에이전트들의 `config.model`이 옛 이름으로 남아 전부 고아가 된다.
   ([[installed-guard-isnt-covering-guard]] — 삭제 가드의 미덮인 형제 경로 · [[move-breaks-references-both-directions]])
2. **에이전트 저장 시 모델 등록 검증 없음** — API로 미등록 모델명을 박아 저장해도 받는다(UI 드롭다운만
   등록 모델로 제한).

## 결정 — 방향 A(불변식 우선, 구남님 승인)

[[find-invariant-before-mechanism]]: 깨진 상태를 *다루는* 메커니즘보다 *못 만들게* 하는 불변식 우선.

### P1 — 쓰기 시점 차단(깨진 상태를 못 만들게)

- **① rename 참조 가드**(`model_registry.py` PUT /models/{id}): 이름을 바꾸려는데 **옛 이름을 참조하는
  라이브 에이전트**(`Agent.model` 또는 `Agent.config["model"].astext`)가 있으면 **409로 차단**("먼저
  에이전트의 모델을 바꾸세요") — 삭제 가드의 라이브 검사와 대칭(**block**, 구남님 승인).
  - 이름 외 필드(kind·params·capabilities 등) 변경은 무영향 — **이름이 바뀔 때만** 검사.
  - 버전 스냅샷(AgentVersion.config.model)의 롤백-후-깨짐은 P2의 resolve 거절이 **미등록으로 남은
    경우엔** 안전망으로 잡는다(라이브만 막고 버전은 ③으로 늦게 잡는 비대칭을 의도적으로 택함 —
    쓴 모델을 사실상 개명 불가로 막으면 과함). **단, 이름이 재사용되면 이 안전망이 성립하지 않는다**
    (아래 OUT '이름 재사용 identity drift' — codex 428 적대검토가 짚음).
- **② 에이전트 저장 모델 검증**(`agents/crud_routes.py` create_agent·update_agent, source=ui):
  `config.model`이 **비어있지 않은데 등록된 chat 모델이 아니면 거절**(400). 미설정(빈값/None)은 폴백
  대상이 아니라 정상(092의 "미선언"=default) — 건드리지 않는다.

### P2 — resolve 시점 정합(092)

- **③**(`chat_context_models._resolve_model`): `config.model`이 **선언됐는데(비어있지 않음) 미등록**이면
  **크게 거절**(400, 오버라이드와 동일 문구 계열) — 조용한 폴백 제거. 미설정은 여전히 기본 폴백(무회귀).
  P1이 입구를 봉하므로 ③은 **직접 DB 편집·버전 롤백**의 잔여 엣지만 잡는 안전망.

## 착수 전 필수 — 기존 깨진 config 감사

P2(loud reject)를 켜면 **이미 미등록 모델을 가리키는 기존 에이전트가 하드 실패**한다(과거 rename 흔적).
착수 첫 단계로 `agents`·`agent_versions`의 `config.model`이 등록 모델에 없는 행을 **측정**하고, 있으면
구남님께 보고(정리 방법 합의) 후 진행. 없으면 바로.

## OUT(경계)

- rename cascade(참조 자동 갱신) — block 채택(대칭·단순). 필요 시 후속.
- 버전 스냅샷 rename 전수 차단(라이브만 막고 버전은 ③ 안전망).
- 폴백+UI 경고(C안) — 092의 "크게 거절"과 반대라 기각.
- **노드형 노드 모델**(`_resolve_node_models`의 노드별 model)은 본 스펙 밖 — 에이전트 층 `config.model`
  (직접 경로)만 다룬다. 노드 모델도 미등록 시 default_cfg로 조용히 폴백하는 같은 축이 있으나 별개 후속.
- **이름 재사용 identity drift**(codex 428 적대검토 [높음]): 모델 X를 Y로 개명 후(라이브 참조 없어 허용)
  X라는 이름의 **새 모델**을 등록하면, 옛 X를 참조하던 버전 스냅샷의 롤백이 이제 **다른 정체성**의 X로
  조용히 실행된다. resolve 거절은 "미등록"만 잡지 "재사용된 이름"은 못 잡는다(등록돼 있으니). 근인은
  에이전트가 모델을 **이름으로** 참조(learning 042 — FK 없음, 의도적 설계). 닫으려면 이름이 아닌
  불변 ID 참조로 바꿔야 해 대규모(별개 스펙). 드문 관리자 조작(개명+동명 재등록)이라 경계로 둔다.
- **메모리 CRUD 경로의 폴백**(codex 428 [중간]): `resolve_agent_mem_cfg`는 `_resolve_model`이 아니라
  `_default_chat_model` 폴백을 쓴다 → 선언-broken 에이전트도 메모리 처리(검색·추가)는 기본 모델로 계속.
  P1이 저장·rename 입구를 봉하므로 broken 행은 직접-DB 편집으로만 생겨 잔여 엣지. 채팅 실행(값비싼
  경로)은 400으로 막히니 (b)의 핵심은 성립. 메모리 경로 통일은 별개 후속.
