# 367 — 에이전트·블록 버전 모델 재설계 (불변 단조 버전 + 오픈 포인터)

## 왜 (성능 우려가 드러낸 진짜 토대)

노코드(UI) 에이전트가 **채팅 메시지마다** 그래프를 새로 짓는다(`chat.py:406 impl.build_graph()` — 매턴
MCP 실연결·모델 클라이언트 신규·compile). 캐시로 분할 상환하려면 캐시 키가 **불변 아티팩트**여야 하는데,
지금은 그렇지 못하다:

- **에이전트는 버전화됨**(`AgentVersion`, active_version 포인터) 하지만 **config가 블록을 "이름"으로 참조** —
  `cfg["prompt"]`·`cfg["model"]`·`cfg["mcps"]`가 **가변 블록 행**을 가리킨다.
- **블록은 버전화 안 됨**(`Prompt`·`MemoryType`·`McpServer`·`Model`·`Provider` = `AuditMixin` 가변 행).
- 드리프트를 **스냅샷+경고**로 땜질(`serializers.py:107 promptStale` — 저장 본문 vs 현재 원본). 이 stale-note가
  "블록 미버전화"의 증상이고, 그나마 프롬프트 본문 하나뿐(MCP·모델은 런타임에 live 해석).

→ 에이전트 "버전"이 밑에서 흔들리므로 **캐시·평가·배포·롤백이 모두 근거를 잃는다**. 성능 문제가
평가 게이트 배포에도 어차피 필요했던 토대(블록 버전화 → 복합 불변 버전)를 앞당겨 드러냈다.

## 결정된 버전 모델 (개발자 확정, 2026-07-15)

**핵심: 에이전트·블록 모두 불변 단조 버전. 차이는 에이전트에만 "오픈(라이브) 포인터" 하나.**

### 블록 (prompt·memory-type·mcp·model·provider)
- **append-only 단조 불변 버전**(v1·v2·v3…). 편집 = 새 버전 append. **무상태**(draft/active/archived 없음).
- 라이브 포인터 없음 — 어느 버전을 쓸지는 **에이전트가 못박아** 정한다.
- "더 새 버전 있음" 배지 = 못박은 버전 < 최신. (기존 promptStale의 승격 — "채택" 버튼.)
- **RAG 컬렉션은 버전 제외**(복구 난이도 — 내용=적재 문서). live 참조 유지. 결과: 그래프 구조는 여전히
  캐시 가능(RAG 도구는 호출 시점 live 검색 = 매턴 입력, 메모리 회상과 동급). **구멍 = 평가 재현성**(RAG
  지식이 평가 후 바뀔 수 있음) — 수용된 경계로 명시.

### 에이전트
- **불변 단조 버전 + 오픈 포인터 하나 + 오픈이력 플래그(ever_opened)**. draft·archived **폐기**.
- **편집 = 오픈된 버전 기준 다음 버전**. v2 오픈 상태서 편집 → v3.
- **충돌 규칙**: 다음 슬롯(오픈+1)이 —
  - 비었거나 **한 번도 오픈 안 된 스크래치 버전**이면 → 그 슬롯을 **대체**(작업 중 버전이 안 쌓임).
  - **한 번이라도 오픈됐던 버전**이면 → **불변 보호**, 새 버전은 `max(버전)+1`로. (롤백 후 편집 시 오픈됐던
    v3 보존 → v4 생성.) → **`ever_opened` 기록 필수.**
- **오픈 = 라이브 포인터 이동**. **롤백 = 포인터를 예전 오픈 버전으로**. (activate/revert가 포인터 이동으로 통합.)

### 복합 버전 (캐시·평가·배포·롤백의 단위)
- 에이전트 버전이 **생성 시점에 블록 버전들을 freeze**(`{block: version}` 못박음) → **불변 복합 버전**.
- config 참조 (블록 이름) → (블록 이름, 버전).
- **캐시 키 = `agent_version_id`**(오픈되면 불변). 콘텐츠 해시 불필요(단조 버전 번호로 충분).

### 이관
- 전 블록의 현재 내용을 **v1**으로 시드, 에이전트를 v1에 못박음.

## 현재 → 목표 (무엇을 바꾸나)

|---|---|---|

## 로드맵 (A→B→C→D→E) · 완료조건은 수치

- **A. 측정 베이스라인 + 하네스** (지금·병행, 자산) — 핫패스 단계별 계측(MCP 연결·모델 클라이언트·compile을
  **구성 비용 vs 호출 비용**으로 분리). 반복 하네스: mock + "MCP 0개 vs N개", 순차 vs 동시 부하.
  - **완료**: 현재 턴당 빌드 ms·왕복 수를 표로 고정(N∈{0,1,4}, 동시성∈{1,8}), 재실행 재현. `make` 타깃 1개.
- **B. 블록 버전화** — 블록별 append-only 버전 이력 스키마(공유 메커니즘 1개). 편집=새 버전. RAG 제외.
  - **완료**: 블록 편집 시 새 버전 행 생성·기존 불변(단위+마이그레이션 실측). promptStale 은퇴, "채택" 대체.
- **C. 복합 에이전트 버전** — 에이전트 버전이 블록 버전 freeze, 참조 (이름)→(이름,버전), 오픈 포인터+
  `ever_opened`+충돌 규칙. draft/archived 폐기.
  - **완료**: 오픈된 버전 밑 블록을 고쳐도 그 버전 동작 불변(freeze 실측). 롤백 후 편집이 오픈됐던 버전 보존
    (충돌 규칙 단위 테스트). 캐시 키로 쓸 불변성 단언.
- **D. 복합 버전 키 캐시** — 그래프+MCP 도구목록 캐시(키=agent_version_id)·모델 클라이언트 풀. **핵심 리팩터**:
  매턴 입력(회상·브로커·대화)을 그래프 **구성**에서 **호출**로 분리(현재 회상을 시스템 프롬프트에 구움).
  - **완료**: A 하네스로 캐시 前/後 턴당 빌드 비용·MCP 왕복 감소를 수치로. 동일 버전 재요청 시 재빌드 0.
- **E. 평가 게이트 배포** (추후·개발자 주도) — 오픈(배포)은 eval 점수 ≥ 임계 **AND** 평가 회수 ≥ 임계일 때만.
  C(불변 아티팩트)+기존 eval 인프라(eval_runner)에 의존.

## OUT / 경계

- **E 구현은 추후** — 이 스펙은 그 토대(불변 복합 버전)까지.
- **RAG 버전화 제외**(복구 난이도) — 평가 재현성 구멍은 수용된 경계.
- **명시적 블록 버전 선택 UI 없음**(YAGNI) — 에이전트는 못박고, "새 버전 채택" 배지로만.
- 마이그레이션은 손번호 금지·프로그램적 생성([[hand-authored-migration-ids-collide-silently]]).
