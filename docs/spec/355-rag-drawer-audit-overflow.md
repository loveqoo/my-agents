# 355 — RAG 문서 드로워 audit 컬럼 오버플로

## 왜 (실물 확증)

RAG 컬렉션 행을 클릭해 문서 관리 드로워를 열면 **파일명이 한 글자씩 세로로 짜부라졌다**
(`g/u/i/d/e/./m/d`). 스샷으로 확증.

**근인**: 스펙 343/344가 문서 테이블에 audit "수정" 컬럼(190px)을 추가하며 `hideBelow: 'lg'`("좁으면
감춤")를 달았는데, 이 `hideBelow`는 `Grid.useBreakpoint()` = **뷰포트** 브레이크포인트 기준이다. 정작
테이블이 갇힌 건 **드로워(size=640)**다. 넓은 화면(1500px) + 좁은 드로워 조합에서 뷰포트가 lg 이상이라
audit 컬럼이 표시되고, 그게 640px을 넘쳐 파일명 컬럼 폭을 0으로 밀었다. 파일명은 `wordBreak:
break-all`이라 폭 0에서 세로로 흘렀다.

## 설계

드로워 문서 테이블에서 **audit 컬럼을 뺀다**. `hideBelow`의 의도("좁으면 이름·상태 우선, 스펙 344")를
드로워(항상 좁은 640) 폭에 실현하는 것 — 드로워는 뷰포트와 무관하게 좁으므로 audit은 감춘다. 컬렉션
목록 뷰(넓은 메인, 별도 columns)의 audit 컬럼은 그대로 유지한다(거기선 잘 보인다). 문서별 수정정보는
편집 맥락에서 확인.

## 완료 조건

- **D1** 드로워에서 파일명이 **한 줄로 온전히** 보인다(세로 짜부라짐 0).
- **D2** 다양한 해상도로 확인(개발자 지시): wide(1500)·mid(1100) 드로워 정상 · narrow(768) 카드 뷰 정상.
- **D3** 컬렉션 목록 뷰의 audit "수정" 컬럼은 무회귀(유지).
- **D4** tsc 0.

## 결과 (2026-07-15)

- `CollectionsView.tsx` DocsDrawer columns에서 audit 컬럼 제거(목록 뷰 audit은 유지).
- **다해상도 스샷 확증**: wide/mid 드로워에서 파일명(`guide.md`·`v331-84e3a6.pdf`) 한 줄 정상, audit
  컬럼 사라짐. narrow는 카드 스택으로 전환돼 정상. tsc 0.

## OUT
