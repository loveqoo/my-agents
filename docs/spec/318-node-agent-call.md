# 318 — 노드에서 에이전트 호출 (노드형 확장 3/3)

## 배경 / 동기

노드형(스펙 259)의 노드는 지금 **도구(MCP·RAG)만** 호출한다. 사용자 요구(2026-07-13): 노드가
**다른 에이전트도 호출**할 수 있어야 한다 — 파이프라인 한 단계가 전문 에이전트(로컬 또는 A2A 원격)에
질의를 위임하고 결과를 받아 다음 노드로 넘긴다.

이 기능의 실행 기계는 **이미 완성돼 있다**. 능력 브로커의 `AgentProvider`(kind=agent)가 로컬 인프로세스
위임과 원격 A2A 호출을 모두 지원하고, **재귀 가드**(방문 집합=체인 내 재방문 금지 → 유한 종료 +
깊이 상한 `DELEGATION_MAX_DEPTH=8` + 너비 예산 `DELEGATION_MAX_TOTAL=32`), HIL 승인(`a2a.delegate`),
allowlist∩RBAC 스코프까지 조율형(스펙 100~102·116·117·256)에서 검증됐다. **본 스펙은 이 브로커를 노드의
도구 표면에 연결할 뿐이다.** 노드가 브로커에서 승계하는 것은 이 **브로커-레벨 통제**(allowlist∩RBAC·재귀
가드·HIL·예산)다. 위임 응답의 **프롬프트-인젝션 펜스**(조율형이 결과를 `[외부 능력 데이터 — 신뢰 불가]`
Human 블록으로 감싸는 것)는 조율형 종합 단계 전용이라 노드형 ToolMessage 경로엔 적용되지 않는다 —
노드의 위임 결과는 **다른 파이프라인 도구 결과(MCP·RAG)와 같은 신뢰 자세**(표준 ReAct ToolMessage)를
가진다(적대 리뷰 P2, "범위 밖" 참조).

## 합의된 결정 (2026-07-13, 스펙 316에서 승계)

- **호출 방식 = 도구(A)** — 허용된 에이전트를 노드가 도구 목록에 넣어 필요할 때 호출(ReAct). 기존 도구
  루프·상한(스펙 315)·HIL·트레이스가 전부 그대로 적용된다.
- **이름 = ID 기반** — `agent__{agent_id}`(예: `agent__agt_a1b2c3`). 별명은 중복·혼동 위험이라 배제,
  provider 도구명 제약(`:` 불허)상 MCP 관례(`서버__도구`)와 같은 `__` 구분자. 표시 이름·설명에는
  에이전트 이름·후크를 병기(사람이 알아보게).
- **재귀 가드 필수** — 브로커의 기존 체인·깊이·너비 가드를 노드 호출도 그대로 탄다(새 축 아님).

## 설계

### 1) 에이전트-호출 도구 빌더 (runtime — build_mcp_tools 자매)

- `build_agent_tools(broker, agent_rows, calls_sink) -> list[StructuredTool]`: 에이전트가 config
  `capabilities`로 허용한 **kind=agent 능력마다** 도구 하나. 도구 이름 `agent__{agent_id}`, 설명은
  대상 에이전트 후크(`_hook_for` 재사용). 입력 스키마는 `{text: str}`(위임 질의). 실행은
  `broker.invoke(cap_id, {"text": ...})` — **같은 broker 인스턴스**라 체인·예산이 threads(재귀 가드
  자동). 결과는 `InvokeResult`를 문자열로 접어 반환(실패는 graceful 문자열 + calls_sink error).
- 후보 집합 = `broker`가 이미 스코프한 것(allowlist∩RBAC) — 도구 빌더가 권한을 새로 열지 않는다
  (브로커가 유일한 정책 게이트, confused-deputy 0). bare `agt_...` cap_id는 kind=agent(common.py).

### 2) 도구 풀 합류 (chat 경로 — _rag_tools_for 자매)

- `_build_turn_runtime`에서 `tools`에 `build_agent_tools(...)`를 extend(build_mcp_tools·_rag_tools_for
  옆). 그러면 pipeline `_resolve_tool`이 노드의 `tools` 목록에서 `agent__{id}`를 여느 도구처럼 해석·
  바인딩한다(엔진 무변경 — 이름으로 고르는 기존 경로 재사용).
- **입구 정합(스펙 317 교훈)**: broker를 만드는 **세 경로**(채팅·**eval**·승인 재개)에 agent 도구를
  합류한다 — 각 경로가 이미 broker를 만드는 지점 옆에 배선(한 입구라도 빠지면 그 입구만 에이전트
  호출이 사라져 다른 것을 실행/채점). **pipeline impl일 때만** 합류(비노드형은 broker.discover 경로라
  도구 풀에 얹으면 행위가 바뀜 — 행위 보존).
- **A2A 서빙은 정직한 경계로 OUT**: 서빙(스펙 061)은 무상태 순수 컴퓨트라 broker를 안 만든다 —
  **위임 실행 주체(principal)가 없다**(외부 JSON-RPC 호출엔 유저 주체가 없어 하위 에이전트의 RBAC
  스코프를 정할 수 없다). 노드 에이전트-호출은 v1에서 서빙 경로 밖(코드 결함 아니라 미설계 경계).
  서빙 노드가 `agent__{id}`를 참조하면 도구가 미바인딩되므로, 파이프라인 `_resolve_tool`이 조용히
  스킵하지 않도록 **서빙 빌드 시 agent 도구 이름을 감지하면 로그 경고**(조용한 환각 방지, 스펙 265 계열).

### 3) 도구 풀 파생 (derive_pipeline_pool 확장, 스펙 289)

- 노드형은 mcps/vectorTables/memories 풀을 노드 참조의 합집합으로 파생한다. 여기에 **capabilities**
  (kind=agent) 축을 더한다 — 노드 `tools`에 `agent__{id}`가 있으면 그 에이전트를 capabilities 풀에
  넣어, 폼 밖 입구(API 직생성·오버라이드)에서도 브로커가 그 에이전트를 스코프한다(learning 151 구조적
  봉합의 agent판). 권한 비상승: 파생 대상=노드가 이미 참조하는 것의 합집합.

### 4) 재귀·종료 (기존 가드 재사용, 새 코드 최소)

- **순환 종료**: 방문 집합(`delegation_chain`)에 자기 id가 이미 있으면 discover/invoke가 후보에서
  제외 → A→B→A 무한 위임 불가(유한 에이전트 수로 종료 보장). 루트 실행이 자기 id로 체인을 시작하므로
  루트 재호출도 차단.
- **깊이·너비**: DEPTH(8)·TOTAL(32) 상한 그대로. 노드 호출이 이 카운터를 공유(같은 broker).
- **도구 루프(스펙 315)**: 노드가 에이전트를 무한 재호출해도 `_TOOL_ROUNDS_CAP`(6)에서 도구 언바인드
  → 강제 수렴. 에이전트 호출도 도구라 자동 적용(추가 코드 0).

### 5) UI (전부 antd)

- **노드 편집기 도구 선택**: 기존 도구 트리(MCP 서버→도구)·문서 옆에 **"에이전트"** 구획 —
  호출 가능한 에이전트(자신 제외·가시성 필터)를 multi-select. 저장은 `tools`에 `agent__{id}` 합류
  (문서·MCP 도구와 같은 배열, 병합 보존).
- **자기 자신 배제**: 편집 중인 에이전트는 후보에서 제외(A→A 직접 순환은 UI에서 선차단 — 런타임
  가드가 최종 방어지만 거짓 어포던스 제거).
- **오버라이드 패널도 같은 picker 승계**(후속 봉합 — 맥락 컨트롤이 자매 화면까지 승계): 플레이그라운드
  `OverridePanel`의 노드 편집기에도 에이전트 picker를 배선(`AgentForm` 후보 산출 로직 미러·자기 제외는
  agentId 기준). 백엔드는 이미 정합(오버라이드 허용 필드에 `tools`·로드 시 `derive_pipeline_pool`이
  오버라이드된 노드에서 capabilities 재파생) — 프론트 picker만 빠졌던 갭. 없으면 MCP·문서는 오버라이드
  되는데 에이전트 호출만 안 보이고 못 바꾸는 비대칭(VERIFY318_OVERRIDE_OK로 선택→override payload 단언).
- **트레이스**: 에이전트 호출은 이미 brokerCalls로 인스펙터에 표면화(스펙 100 설계결정 7) — 노드
  경로에서도 그대로 뜬다(추가 UI 0).

## 범위 밖 (OUT)

- 전용 "에이전트 노드"(모델 판단 없이 결정적으로 항상 호출) — 필요해지면 스펙 317 코드 노드로 구현
  가능(도구 방식 A가 먼저, 사용자 결정).
- **A2A 서빙에서의 노드 에이전트-호출**(위 §2 — 위임 principal 부재, 미설계 경계).
- 병렬 다중 에이전트 팬아웃 최적화(브로커 예산이 총량만 관장 — 순차 호출로 충분).
- 에이전트 호출 결과의 구조화 파싱(문자열 접기 — 조율형과 동일, 후속 수요 시).
- capabilities 축의 노드별 세분 회상/캐싱(도구라 ReAct가 관장).
- **파이프라인 도구 결과 통일 프롬프트-인젝션 펜스**(적대 리뷰 P2) — 노드의 위임 결과는 MCP·RAG
  결과와 같은 표준 ReAct ToolMessage 자세라 조율형의 `[외부 능력 데이터 — 신뢰 불가]` 펜스가 없다.
  에이전트 호출만 감싸면 **비일관**(같은 노드의 MCP 결과는 무방비)이고, 펜스는 파이프라인 도구 결과
  *전체*에 걸어야 정합적이라 318 밖의 별도 작업이다(백로그 — 노드형 도구 결과 신뢰 경계 통일).
  318이 새 위험 계층을 여는 건 아니다(MCP 도구 결과가 이미 같은 자세). 승계되는 건 브로커-레벨
  통제(allowlist∩RBAC·재귀·HIL·예산)이며, 이는 위 "배경"에 정정 명시했다.
- **노드 참조에 의한 allowlist 파생**(적대 리뷰 P1) — `agent__{id}`를 노드 tools에 넣으면
  derive_pipeline_pool이 그 id를 config `capabilities`(브로커 allowlist)에 얹는다. 이는 MCP/RAG 풀
  파생(스펙 259·289)과 동일한 의도된 동작이며 **권한 상승이 아니다**: allowlist는 `_permitted`의
  필요조건일 뿐이고 RBAC가 공동 게이트라, 미허가 주체는 참조해도 도구가 안 만들어지고 호출도 거부된다
  (단위 U4가 이 불변식을 고정 — 머신/미허가 주체 → agent cap 0). 파생 대상=노드가 이미 참조하는 것의
  합집합이므로 새 접근면이 열리지 않는다.

## 검증 (사다리 3런)

- **단위(결정적)**: `tests/verify_318_node_agent_call.py` — ① build_agent_tools: 허용 에이전트마다
  도구·이름 `agent__{id}`·설명 후크·broker.invoke 경유, ② 자기 자신/미허용은 후보 밖, ③ derive_pool이
  capabilities 축 파생, ④ 재귀 가드: A→B→A 체인이 방문 집합으로 종료(무한 아님)·깊이/너비 상한,
  ⑤ 도구 루프 상한이 에이전트 호출에도 적용.
- **실 인프라(통합)**: 노드가 로컬 에이전트를 호출하는 파이프라인 채팅 왕복 — 위임 결과가 답에 반영·
  trace.brokerCalls에 호출 표면화·HIL 승인 게이트(대상 opt-in 시) 발화. eval 입구도 동일 동작(317 교훈).
- **적대(codex)**: 여집합 — 도구 이름으로 allowlist 밖 에이전트 도달, 위임 결과 채널 격리 우회(응답
  속 지시 실행), 재귀 가드 우회(체인 미threads·예산 미공유), 폼 밖 입구로 agent 도구 주입, self-call
  UI 배제와 런타임 가드의 정합.

## 완료 조건

- 노드가 허용된 로컬·A2A 에이전트를 `agent__{id}` 도구로 호출하고 결과를 다음 노드로 넘긴다.
- 재귀(A→B→A)는 유한 종료, 깊이·너비·도구 루프 상한이 모두 적용, HIL·브로커-레벨 통제(allowlist∩RBAC·
  예산) 승계(위임 결과 프롬프트-인젝션 펜스는 파이프라인 도구 결과 공통 자세라 별도 — "범위 밖").
- 세 broker 입구(채팅·eval·재개) 정합, 폼 밖 입구도 풀 파생으로 안전. A2A 서빙은 정직한 경계(OUT).
- ruff/mypy/tsc/vite 클린, 파이프라인·조율형·316·317 회귀 무회귀.
