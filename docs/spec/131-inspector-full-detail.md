# 131 — 턴 인스펙터 상세화: 전송 프롬프트 전문·도구 결과 본문·노드 값

## 배경 / 왜
사용자 요구 3건: (1) 시스템 프롬프트 말고 **실제 LLM에 전달한 프롬프트 전체**, (2) 메모리/RAG/MCP
**도구 호출 결과를 구체적으로**, (3) LangGraph 노드 요약이 `query: <17자>` 식이라 **내용 불가독**.
+ 필요 시 **리치 컴포넌트** 적극 활용.

### 조사로 확정 (deep-reasoner — 가림의 원래 이유)
- #1은 가림이 아니라 **미수집**: trace에 조립본(persona+회상 주입)·히스토리 본문이 애초 없음.
  인스펙터 "시스템 프롬프트"는 정적 persona(회상 미포함)라 실제 전송본과 다름.
- #2: 직접 MCP는 이미 args(마스킹·500캡)+result(2000캡) 노출 중 — 진짜 공백은 **브로커 경유**
  (InvokeResult.text 폐기, 130은 메타만)와 **RAG 직접**(result가 "N건 반환" 카운트 문자열).
  087의 "원문 누출 0"은 그 스펙 스스로 위협 과대평가를 교정(defense-in-depth+캡으로 격하)한 것 —
  같은 마스킹·캡 계약을 브로커/RAG에 적용해도 계약 위반 아님.
- #3: 086 F2 "값-비밀 fail-closed"가 옥석 없이 가린 것. 가려지는 키(query/route/delegated)는 출하
  그래프의 닫힌 상태 키로 **전부 비-비밀**(유저 질의·분류 라벨·위임 결과). 086이 남긴 확장 관문
  ("절대 비밀 아님을 보증하는 키만 allowlist") 그대로 사용.
- 트레이스는 Message.trace JSONB로 영속·세션 재로드 시 복원 — 회상 본문(memories[].text)·MCP
  result(2000캡)는 **이미 영속 중**(신규 민감도 아님). 130 교훈: 신규 필드는 3경로(메인/승인대기/재개)
  대칭 필수.

## 설계

### 백엔드
1. **전송 프롬프트 전문(#1)**: `trace["sentMessages"] = [{role, content}]` — 그래프에 넣은 messages
   배열(조립된 system(persona+회상 주입) 포함)을 **메시지당 2000자 캡**으로. 충실도가 목적이므로
   프런트 재구성이 아니라 백엔드 조립 시점 캡처(chat.py — messages 확정 직후).
   경로: 메인+승인대기(둘 다 messages 보유). **재개는 N/A 명시**(체크포인트 재개라 chat.py에 조립본이
   없음 — 트레이스에 사유 필드 없이 생략, 스펙에 경계 기록).
2. **도구 결과 본문(#2)**:
   - 브로커: invoke 이력에 `resultPreview = _cap(res.text, 2000)`(+125 `_sanitize` 마스킹 백스톱)
     추가, `_broker_calls_trace` 화이트리스트에 키 1개 추가(3경로 자동 대칭 — 헬퍼 단일 출처).
   - RAG 직접: calls_sink result를 카운트 문자열 대신 `_cap(format_rag_hits(hits), 2000)` 스니펫으로.
3. **노드 값(#3)**: `_VALUE_SAFE_KEYS`(runtime.py)에 `query`·`route`·`delegated` 추가 — 값은 300자
   캡으로 노출. **미지 키는 여전히 길이만**(086 F2 fail-closed 유지 — 커스텀 플로우가 임의 키에 비밀을
   담아도 안전). allowlist 키를 커스텀 그래프가 비밀 용도로 재사용하는 경우는 문서화된 경계(OUT).

### 프론트 (리치 컴포넌트 — 사용자 요청)
4. **"전송 프롬프트" 섹션 신설**: antd Collapse — 메시지별 패널(role 태그 색 구분), 내용은 코드
   스타일(monospace·pre-wrap) 블록, system 패널 기본 펼침. 기존 "시스템 프롬프트" 섹션은 이 섹션으로
   대체(정적 persona 표시는 혼동 원인이었음). **user 입력은 표시 생략**(후속 사용자 요청 — 채팅 버블과
   중복; 데이터(sentMessages)는 보존, 생략 안내문 표기).
5. **도구 결과**: 브로커 호출 행에 확장 토글(Collapse) — resultPreview 본문. RAG 스니펫도 동일.
6. **노드 요약**: 값 노출로 `query: 옵시디언 노트...` 식 실내용 표시(300캡, 기존 GraphPath 유지).

## 검증
- verify_131: sentMessages 캡·조립본에 회상 블록 포함, resultPreview 마스킹·캡(비밀 주입 케이스),
  _VALUE_SAFE_KEYS 노출 3키+미지 키 여전히 길이만(F2 무회귀), 3경로 대칭(brokerCalls 확장 키).
- 기존 무회귀: verify_086(그래프 요약)·087(MCP 재분별)·130(브로커 가시성) + tsc/ruff.
- 브라우저(fast-worker): 옵시디언 매니저 실 대화 → 인스펙터에 전송 프롬프트 전문(회상 블록 포함)·
  RAG 결과 본문 확장·`query:` 실값 표시. 세션 재로드 후에도 동일(영속 확인 — deep-reasoner 지적).
- codex 적대: 캡/마스킹 우회·JSONB 비대·F2 재개방 여부·3경로 대칭.

## 비목표 (OUT)
- 커스텀 플로우의 임의 상태 키 값 노출(정규식 백스톱) — 별도 스펙(F2 재개방은 적대 회부 필요).
- 재개 턴의 sentMessages(체크포인트 내부라 조립본 부재 — 경계 명시).
- 결과 전문 별도 저장소/온디맨드 조회(현행 인라인 캡 일관성 유지).
