# 363 — 도구 무발동 박스, 능력을 쓴 턴에는 억제(메모리 회상 턴 오탐 봉합)

## 왜 (실물 확증 — 사용자 버그리포트 스샷 IMG_1770)

단순 에이전트에 "지난 번에 무엇을 질문했었지?"(기억 질문)를 물으면 인스펙터 실행 흐름은
**메모리 회상 4건**(도시락·Redis 등) → 시작 → 모델 호출 → 종료를 보여준다(정상 — 회상으로 답함).
그런데 흐름 하단에 **"도구 2개가 연결됐지만 이 턴에서 호출되지 않았습니다"** 박스가 뜬다. 회상이
분명히 일어났는데 "도구 호출 안 됨"이라 모순처럼 읽힌다(사용자: "도구호출이 되었음에도").

**근인**: 도구 무발동 진단 박스(스펙 236)의 발동 조건이 `toolDiag.called === 0 && !brokerCalls`
뿐이라 **메모리 회상 여부를 안 본다**(Inspector.tsx:695·772). 원래 이 박스는 "흐름이 텅 비어
보이는데 왜 도구가 안 떴나"를 설명하려던 것. 그런데 스펙 359(노드형 회상)·362(단순 회상 합성
스텝)로 **회상이 이제 흐름에 렌더**되어 흐름이 더는 비어 있지 않은데, 박스는 옛 조건 그대로라
회상 턴마다 오탐한다. 메모리가 주 능력인 에이전트(personal-secretary)는 기억 질문마다 이 박스를
본다. RAG·브로커 경유는 이미 `called>0`(rag는 calls_sink 적재)·`brokerCalls`로 억제되므로, 남은
구멍은 **프롬프트 선주입이라 calls_sink에 안 잡히는 메모리 회상**뿐이다.

## 설계

박스는 **진짜로 아무 능력도 안 쓴 맨 턴**에서만 뜨게 한다 — 도구·RAG·브로커에 더해 **메모리 회상**도
발동 억제 신호에 넣는다. 회상이 일어난 턴은 능력을 실제로 썼으니 "왜 텅 비었지?" 설명이 불필요.
박스의 원래 목적(도구를 기대했는데 mock이 키워드 없이는 안 부른다는 안내)은 맨 턴에서 그대로 유지.

- **회상 신호**: `(t.memories?.length ?? 0) > 0`(단순·표준 경로) 또는 `t.memoryRecalls`에 내용 있는
  회상 존재(노드형). 단일 파생값(`recalledThisTurn`)을 `t` 스코프에 둔다.
- **대상 = 실행 흐름 탭 Alert(772) 한 곳**. 프롬프트·설정 탭 "연결된 도구" 섹션 안내문(695)은
  **그대로 둔다** — 거기는 도구 섹션 맥락이라 "이 도구들은 안 불렸다"가 사실이고 톤도 보조(3차 색),
  게다가 그 분기의 else가 "브로커 경유" 문구라 회상 턴을 그리로 보내면 되레 틀린 문구가 나온다.
  사용자가 본 오탐은 흐름 하단에 크게 뜨는 Alert 하나다.
- 백엔드 무변경 — toolDiag는 그대로(MCP 도구 무발동 사실은 정확). 표시 게이트만 조인다.

## 완료 조건 (수치)

- **C1** 메모리 회상이 있는 턴(단순·노드형): 실행 흐름 탭의 "도구 호출 안 됨" Alert **미표시**(스샷 시나리오 재현).
- **C2** 맨 턴(도구 바인딩 있으나 회상·RAG·브로커·도구 전부 0): 박스 **그대로 표시**(스펙 236 목적 보존).
- **C3** tsc 0. 도구 실제 호출 턴(called>0)은 기존대로 미표시(무회귀).

## OUT

- 박스 문구 재작성 — 이 스펙은 발동 조건만(맨 턴에선 기존 문구가 정확).
- toolDiag 백엔드 계측 — 무변경(MCP 무발동은 사실).
