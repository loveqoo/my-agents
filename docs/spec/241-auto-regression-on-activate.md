# 스펙 241 — 버전 활성화 시 자동 회귀 (AgentOps 루프 B)

## 배경 (로드맵 B — 240 다음)

비교 화면(138)과 버전 귀속(240)은 있지만 **트리거가 수동**이다. 새 버전을 활성화하는 순간 그 에이전트의
문제집을 자동 실행해야 "바꾸면 재는" 루프가 잠긴다.

**정직한 경계**: 평가 러너는 서빙 config로 실행(eval_run_agent→_load_context)하므로 **초안(배포 전)
평가는 불가**(오버라이드 화이트리스트로 impl·페르소나·artifactSpec 차이를 주입 못 함). 따라서 B는
"활성화 **직후** 자동 실측 → 회귀 발견 시 revert가 대응 경로"다. 외부 제안의 "배포 전 확인"과 다름을
명시(사전 게이트가 필요해지면 초안 평가 러너가 별도 스펙).

## 변경

### 백엔드
- `eval_routes.trigger_auto_regression(agent_pk, actor)`:
  - 후보 문제집 = kind=agent 중 (이 에이전트로 실행된 적 있는 것 ∪ `source_agent_pk`=이 에이전트인
    수확 문제집), 최근 순 **최대 3개**(비용 캡 — 실모델일 수 있음).
  - 케이스 0개·이미 running인 문제집은 건너뜀(기존 가드 존중). 비특권 실행자는 비용 가드
    (_member_run_guard) 적용 — 거부되면 그 문제집은 조용히 스킵+로그(활성화를 막지 않음).
  - 각 런은 240의 버전·env 박제 + **`env.trigger="activate"`**(자동 회귀 식별 — 새 컬럼 불요).
- `agents.activate_version`·`revert_version`(승격 분기) 성공 후 백그라운드로 위 함수 호출
  (fire-and-forget — 회귀 실행 실패가 활성화를 깨지 않음).

### UI (EvalView)
- 실행 이력에서 `env.trigger==="activate"`면 **"자동 회귀"** Tag — 수동 런과 구분.
- 회귀 확인 동선은 기존 자산 재사용: 문제집 추이(138)+런 비교("v3 → v4", 240). 버전별 집계 화면은
  D에서.

## 검증
- 실측: 에이전트+문제집 베이스라인 런 → 버전 활성화 → 자동 런 생성(trigger=activate·새 버전 박제)
  확인. 문제집 없는 에이전트 활성화 → 자동 런 0(무해). revert 승격도 트리거.
- verify_240 무회귀. codex 적대(중복 실행·비용 폭주·활성화 실패 경로).

## 완료 조건
- 버전을 활성화하면 사람 손 없이 그 에이전트의 회귀 자산이 재실행되고, 이력에서 "자동 회귀 · vN"으로
  식별·비교 가능하다. 문제집 없으면 조용히 무동작(무회귀).
