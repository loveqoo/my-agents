# 스펙 236 — 도구 무발동 진단성 + mock 모델 한계 표면화

## 배경 (실사용 2026-07-07, 백로그 접수)

사용자가 다른 기기에서 web-fetch(위키) 도구를 공개·허용호스트·배선 전부 맞게 연결했는데도 **조용히**
무발동. 근인은 모델 층: (1) mock-llm은 `_TOOL_TRIGGERS` 2개(delete_record·search_documents) 키워드에만
tool_call을 내 임의 도구는 영영 무발동, (2) 해당 배포엔 실 도구모델이 없어 mock 강제. **핵심 갭 = 진단성**:
세 게이트를 다 통과해도 "왜 안 되는지" 신호가 0이라 사용자가 한 세션 내내 엉뚱한 층(공개·배선)을 추적.
회상 진단(스펙 158)·검색 진단(스펙 125)과 같은 결로 "왜"를 화면에 표면화한다.

## 변경 (3부)

### P1 — 턴 트레이스 도구 진단 (핵심)
- 도구가 바인딩된 턴(direct 경로: build_mcp_tools+rag tool)인데 이 턴 도구 호출 0회면 trace에
  `toolDiag` 추가: `{bound: [도구명…(캡)], called: N}`.
- 인스펙터(DebugChat)가 called=0 && bound>0일 때 렌더: "도구 N개 연결됨 · 이 턴 호출 0회 — 모델이
  도구를 호출하지 않았습니다(모델이 도구 호출을 지원하지 않거나, 질문이 도구와 무관할 수 있습니다)".
- 정상일 수도 있으므로(도구 무관 질문) **경고가 아니라 정보성 진단**(회색/보조 톤).

### P2 — mock 모델 한계 표면화 (폼·플레이그라운드)
- mock-llm은 데모용 키워드 트리거만 냄 → "mock 모델 + 도구 연결" 조합이면 사전 경고:
  "이 모델은 데모용이라 대부분의 도구를 호출하지 못합니다 — 도구를 쓰려면 실제 모델이 필요합니다."
- 감지는 레지스트리 데이터로(learning 026 — 런타임 분기 금지): 시드가 mock-llm 모델 meta에 한계 플래그를
  박고, 폼은 meta를 읽는다(이름 하드코딩 지양).

### P3 — mock 트리거 일반화 (실습성)
- 기존 2개 키워드 트리거 유지 + **일반 트리거** 추가: 사용자 문장에 바인딩된 도구의 base 이름이 언급되면
  그 도구를 호출(예: "wiki_search로 파이썬 검색해줘" → wiki_search). args는 tools 스키마(parameters)의
  required string 파라미터에 문장을 채우는 휴리스틱(캡 200자).
- 우선순위: 기존 키워드 트리거 먼저(결정적 테스트 보존) → 일반 트리거.

## 완료 조건 (충족)
- 무발동 턴이 더 이상 조용하지 않다(인스펙터에 "왜" 후보 표시). mock+도구 조합이 사전에 경고된다.
  mock으로도 임의 등록 도구 실습이 가능하다(이름 언급 트리거). 기존 테스트 무회귀.

## 비고 / 경계
- 승인 게이트 없는 파괴적 도구도 이름 언급으로 mock 발동 후보가 됨 — 기존 키워드 트리거("삭제")와 동급
  데모 동작이며, 승인 게이트 설정 도구는 여전히 게이트됨(우회 없음, codex #5 후단 확인).
- eval 러너 등 mock 의존 테스트: 케이스 문장에 도구 base 이름을 그대로 쓰면 이제 tool_call이 난다
  (의도된 실습성 — 기존 키워드 트리거 우선이라 결정성 보존).
