# 349 — `accesstoken` 회수 (로그인마다 1행, 만료돼도 영구 잔류)

## 왜 (실측)

- 로그인 1회 = `accesstoken` **1행**(실측: 로그인 3회 → 3행).
- 세션 수명은 7일(`AUTH_SESSION_LIFETIME`). **만료된 뒤에도 행은 영원히 남는다** —
  `fastapi_users`의 `DatabaseStrategy`는 읽을 때 `created_at >= max_age`로 **거를 뿐**, 지우지 않는다.
  삭제는 **로그아웃 시 1행**뿐(브라우저를 그냥 닫으면 안 지워진다).
- 유저 1명이 하루 테스트한 DB에 이미 **24행**. 사람이 여럿 쓰면 로그인 횟수만큼 자란다.

만료 토큰은 **쓸모가 없는 데다** 남아 있으면 안 되는 것이다 — 인증에 못 쓰는 자격증명 조각이
DB에 무한히 쌓이는 건 위생·보안 양쪽에서 부채다.

## 설계

**배치 잡 `token-cleanup`** — 만료된 토큰 행을 지운다(스펙 348로 이제 배치가 **실제로 돈다**).

- **판정**: `created_at < now() - (lifetime + grace)`. lifetime은 `AUTH_SESSION_LIFETIME`(기본 7일)과
  **같은 출처**를 읽는다(드리프트 0 — 두 곳에 상수를 두면 한쪽만 바뀐다).
- **유예(grace)**: 기본 1일. 만료 직후 경계에서 지우지 않는다(시계 오차·진행 중 요청 보호).
  → 실제 삭제 대상: **8일 이상 된 토큰**.
- **살아 있는 토큰은 절대 안 지운다**(로그인 상태를 끊는 건 파괴적 부작용).
- **파괴적 노브엔 바닥**(learning 037): lifetime을 0/음수로 만들 수 있는 경로가 없어야 한다 —
  env가 이상하면 **잡을 비활성**(전량 삭제로 매핑 금지).
- dry-run 지원(스펙 050) · cron 기본 매일(`0 4 * * *`).

## 완료 조건 (수치)

- **T1** 만료 토큰(8일+)만 삭제 — 살아 있는 토큰은 **0건** 삭제(로그인 세션 유지).
- **T2** dry-run은 대상만 세고 **삭제 0**.
- **T3** `AUTH_SESSION_LIFETIME`이 비정상(0/음수)이면 잡 **비활성**(delete-all 금지).
- **T4** 실제 로그인 → 그 토큰으로 API 호출 성공(청소 후에도 **내 세션은 살아 있다**).
- **T5** 게이트(347): `accesstoken`이 `leaking` → `reclaimed`로 이동, **스코어보드 6 → 5**.
