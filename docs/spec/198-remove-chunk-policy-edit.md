# 198 — 청크 정책 수정 기능 제거 (재청킹 폐기)

## 배경
청크 크기·겹침을 **수정**해도 기존 문서엔 소급 적용되지 않는다(이후 업로드 문서에만) — "수정했는데 왜
기존 문서가 안 바뀌지?"라는 혼란을 낳는다. 소급 적용하려면 **재청킹**이 필요한데, 시스템은 원본 텍스트를
저장하지 않고 청크(겹침 포함)만 보관해 정확한 재청킹이 불가하다(청크를 이어붙이면 겹침 중복·경계 소실).
- 참고: AI 출제는 **청크 텍스트를 그대로** 읽어 질문을 만들므로(`_sample_chunks`→`Chunk.text`) 원본 없이
  동작한다. "조각 그대로 쓰기(출제)"는 되고 "조각 붙여 다시 자르기(재청킹)"만 원본이 필요하다.

## 사용자 결정 (2026-07-06)
- 재청킹은 **만들지 않는다**(원본 미저장 + 복잡도). 대신 **혼란의 원인인 청크 정책 수정 기능을 제거**한다
  → 청크 정책은 **컬렉션 생성 시 고정, 이후 불변**(임베딩 모델·차원과 동일 취급). 별명·설명 수정은 유지
  (소급 문제 없음).

## 설계
### 프론트 (CollectionsView EditModal)
- `chunkSize`/`chunkOverlap` 상태·프리필·저장 payload·입력 필드(문서형 청크 크기/겹침 InputNumber) 제거.
  별명·설명만 편집.
- 안내 문구: "청크 정책 변경은 이후 업로드…" → **"청크 정책·식별 이름·모델·차원은 생성 후 변경할 수
  없습니다."**
- `updateCollection`(api.ts) body에서 `chunk_size`/`chunk_overlap` 제거.

### 백엔드 (API 우회까지 차단 — 프론트만 막으면 샌다)
- `schemas.py` `CollectionUpdate`에서 `chunk_size`/`chunk_overlap` 필드 제거(불변 계약을 스키마로).
- `rag.py` `update_collection`에서 청크 설정 대입 제거. 주석 "임베딩 모델·dims·kind·**청크 정책** 불변".
- `CollectionIn`(생성)·`CollectionOut`(표시)의 청크 필드는 **유지**(생성 시 설정·조회는 그대로).

## 검증
- **단위/왕복**: `update_collection`에 chunk_size/overlap을 보내도(구 클라이언트) **무시**되고 값 불변
  (스키마에서 필드 없어짐 → Pydantic이 무시). 별명·설명 수정은 정상.
- **e2e**: 컬렉션 편집 모달에 청크 필드 없음 · 별명·설명 저장 정상 · 안내 문구 갱신. 무회귀(생성 시 청크
  설정은 유지).
- tsc0 · 기존 컬렉션 e2e 무회귀.

## RBAC 경계 (트리거 판정)
- **비트리거**: 컬렉션 소유자 게이트(`assert_may_manage`) 무변경 — 수정 **범위 축소**(필드 제거)일 뿐
  입구·소유 판정 불변. 새 쓰기 입구 0. 오히려 변경 표면이 줄어 안전.

## 경계
- 이미 만든 컬렉션의 청크 정책은 그대로 고정(마이그레이션·소급 없음).
- 청크 정책을 바꾸려면 컬렉션을 새로 만들어 문서를 다시 올린다(모델·차원과 동일 운영).
