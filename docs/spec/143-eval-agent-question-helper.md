# 143 — 평가 7탄: 에이전트 문제집 AI 출제 (평가 도우미 1탄)

## 배경 / 왜
사용자: "문제를 사람이 직접 쓸 수도 있지만, 에이전트가 10개쯤 넣어주고 사람이 수정하는 게 낫다.
메뉴별 도우미 에이전트의 시작 — 우선 평가부터." RAG 문제집은 142가 해결 — 이번엔 **에이전트
문제집**. 도우미 가용성 = 기본 chat 모델이 실모델일 때(mock이면 정직하게 비활성).

## 설계
1. **출제 재료 = 대상 에이전트의 구성**: 페르소나 + 능력(RAG 컬렉션·MCP·메모리) 조회.
   능력별 출제 전략(결정적 뼈대 + LLM은 질문 문장만 — 142 검증된 방식 재사용):
   - **RAG 능력 있음** → 그 컬렉션 청크 기반 골든 질문(142 generate_golden_cases 재사용) +
     기준: `trace_has "rag:"`(도구를 실제로 쓰는가) + `no_error` + `output_nonempty`.
     (rag_* 기준은 agent 런에서 무의미 — 137 관측 union의 trace 축을 쓴다.)
   - **페르소나 기반** → LLM이 "이 역할이라면 받을 법한 질문" 생성 + 기준: `no_error` +
     `output_nonempty` + `llm_judge "역할(…요약)에 맞게 충실히 답했는가"`(139 재사용).
   - 배분: 요청 count를 능력 있는 전략에 안분(RAG 있으면 반반, 없으면 페르소나 전량).
2. **API**: `POST /eval/datasets/{id}/suggest-cases` {agent_id, count(1~10)} — kind=agent 전용,
   admin. 기존 문제 있어도 **추가**(덮지 않음 — 사람 작성분 보존). 백그라운드 + description
   상태 박제(142 패턴 그대로: 진행/완료/실패·좀비 sweep은 기존 sweep_zombie_datasets가
   "생성 중" prefix로 함께 커버). 기본 chat 모델이 mock/미설정이면 400("도우미 사용 불가" 정직).
3. **UI**: 에이전트 문제집 드로어에 **"AI로 문제 채우기"** 버튼(대상 에이전트 선택 시 활성) →
   개수 선택(5/10) → 생성 후 목록 갱신, 각 문제는 기존 편집기로 수정. mock 기본 모델이면
   버튼 비활성+사유 툴팁.
4. **mock 판별**: 기본 chat 모델의 base_url이 자기 서비스 mock(예: model_id에 "mock" 포함 또는
   provider가 내장 mock)이면 도우미 비활성 — 구현 시 실제 판별 기준을 코드에서 확정(추측 금지).

## 검증
- 단위: 능력별 안분·mock/미설정 400·count 범위·기존 문제 보존(추가만).
- 통합(실 옵시디언 매니저): suggest 4 → RAG형(trace_has rag:)+페르소나형(llm_judge) 혼합 생성,
  질문 형식·기준 build_asserts 통과. **생성 문제집 실행 → 통과율 ≥ 1/2**(자기일관 — RAG형은
  도구를 실제로 쓰는가까지 검증됨).
- e2e(fast-worker): 버튼→생성→문제 혼합 확인→실행→성적표. codex 간이.

  (버튼식 1탄 — 채팅형은 플랫폼 도우미에서), expected 정답 생성.
