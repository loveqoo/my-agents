# 스펙 249 — 오버라이드 서랍 단계형 개편 (생성폼 기조 이식)

## 배경 (사용자 지정, 2026-07-09)

U 손잡이 서랍(스펙 248)의 내부가 세로 전개 나열 — "생성폼(239)의 기조를 그대로" 적용하기로.
단, **요약 단계는 생략**(사용자 결정: "단계를 나누되 요약은 없어도 됩니다") — 오버라이드는 빠른
실험 루프라 요약 게이트가 과함.

## 구조

- **Steps 2단계**: ①모델·프롬프트(모델, 페르소나 블록 채우기, 시스템 프롬프트) ②도구·지식·세부
  (이 대화에서 쓸 것/맡길 것, Temperature, 채팅 히스토리 — Collapse 해제해 평면 나열).
- **하단 고정 푸터**(모든 단계 공통): 좌 [기본값으로] [오버라이드 해제(적용 중일 때만)] /
  우 [이전][다음][적용 — 새 대화](항상 노출 — 요약 없음의 대가로 적용을 어디서나).
  모바일은 기존 "∧ 닫기"를 푸터 우측 끝에 병합.
- 단계 클릭 이동 자유(2단계뿐·둘 다 항상 유효 — 생성폼의 maxVisited 게이트는 불필요).
- 서랍을 열 때마다 1단계부터. code/external 에이전트는 기존 안내 Alert 그대로(단계 없음).

## 검증
- e2e: 단계 표시·다음/이전 이동·2단계에서 적용(새 대화 리셋)·기본값으로·모바일 푸터(닫기 병합)·
  양 뷰포트 오버플로 0. 기존 U 손잡이 12종 무회귀.

## 완료 조건
- 한 화면 스크롤 나열 소멸 — 단계당 한 관심사, 적용은 항상 한 클릭.

## 검증 결과 (2026-07-09)
- e2e 12/12(데탑·모바일 × 단계 표시/이동·2단계 즉시 적용→서랍 닫힘·적용 중 배지·오버플로 0) +
  U 손잡이 12종 무회귀. tsc 0. 육안(데탑 가로 Steps·모바일 세로 Steps).

  Steps가 스크롤 위로 숨음(destroyOnHidden — 매번 1단계·스크롤 0에서).

  가로를 활용해 세로 축소. 모바일은 1열+스크롤 유지.
- 게이트 추가: O3b "2단계 세로 안 넘침"(scrollHeight≤clientHeight 실측 — 519/519). e2e 13/13.
