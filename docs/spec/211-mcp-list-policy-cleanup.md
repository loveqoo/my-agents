# 스펙 211 — MCP 리스트·정책 정리 (사용 공유 제거 + 컬럼 분리 + 자물쇠 + 중복/상태 제거)

## 배경 (사용자 요청 2026-07-07, 항목 2·3·4·5·6)

- 서버 컬럼에 이름+별명+유형태그+소유태그가 뭉쳐 과밀(항목 2).
- 외부 등록 MCP가 private로 고정되고 바꿀 방법이 없음 → 사용자 결정: **RAG(스펙 172)처럼 사용
  공유 게이트 제거**, 단 커스텀 MCP **외부 서빙 게이트(보안, 스펙 156)는 유지**(AskUserQuestion).
- 승인 필요 여부가 리스트에 안 보임(항목 4) → 🔒 이모지.
- 상세 드로어 상단 이름 2회 중복(항목 5, 공용 드로어라 전 블록 공통).
- status는 자동 갱신 경로가 없어 사실상 정적(항목 6) → 리스트·드로어에서 제거, DB 유지(AskUserQuestion).

## 변경

### A. 사용 공유 게이트 제거 (항목 3 — 정책)
- `ownership.agent_may_wire`: published 기반 비소유 배선 게이트(rule 4) 제거 → **등록된 MCP는 모든
  에이전트가 배선 가능**(172 동형: 사용=공용, 관리=소유자만 유지).
- chat.py `effective_pub` 게이트 정리(배선 경로).
- `published`의 의미를 **"커스텀 MCP 외부 서빙"으로 축소**: UI 토글은 source=custom에만 "외부 서빙"
  라벨로 노출, external/local에선 숨김(external 재공개 봉인 152 불변).
- OwnerTag의 public/private 라벨을 MCP에서 제거(소유 표시는 유지).

### RBAC/소유권 체크리스트 (트리거: ownership 헬퍼 변경)
1. **입구 열거**: 배선 입구 = chat 런타임 배선(chat.py)·플레이그라운드 오버라이드 주입·A2A 경유 세션.
   관리 입구(수정/삭제/재탐색/publish) = blocks.py — **무변경(소유자 게이트 유지)**.
2. **입구별 소유권**: 사용(배선)=전부 허용으로 완화(이번 변경), 관리=`assert_may_manage` 불변,
   서빙(/_served)=published+custom 불변.
3. **단일 헬퍼**: agent_may_wire가 계속 단일 판정처(규칙만 제거, 헬퍼 유지).
4. **존재 비노출**: 목록은 원래 전체 반환(무변경).
5. **검증 사다리**: ①단위(비소유 배선 성공·external 서빙 404·custom 미공개 404) ②실서버 통합
   ③codex 적대 — "완화가 열면 안 되는 문의 여집합"(external 서빙 우회·custom 미공개 노출·관리 경로 완화 여부).
6. **자가-잠금 핀**: 소유자 본인 배선·관리가 여전히 됨을 단언.

### B. 리스트 컬럼 재구성 (항목 2·4·6)
- "서버" → **"이름"**: name만(210 정책, 별명 제거) + Tooltip 설명.
- **"유형"** 컬럼 분리: 외부/커스텀/로컬 태그.
- 소유 표시 별도 컬럼(OwnerTag, public/private 라벨 없이).
- **🔒**: 승인 필요 도구(tools_meta approval.required) 1개 이상이면 이름 옆 🔒 + 툴팁 "승인 필요 도구 N개".
- "상태" 컬럼 제거. "공개" 컬럼 → custom만 의미 있는 "외부 서빙" 표시로.

### C. 드로어 (항목 5·6)
- 공용 드로어 본문 헤더의 이름 텍스트 제거(Drawer title만 유지) — 전 블록 카테고리 공통 수정.
- 드로어의 status 표시 제거.
