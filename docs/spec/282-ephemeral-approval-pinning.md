# 282 — 비영속 승인 상태 고정('승인 없음') + 승인 목록 폰트 정합

> 사용자 지적 2건: ①"'승인 없음' 상태의 도구만 실행할 수 있다"고 말했으면 **각 도구를 '승인 없음'
> 상태로 고정해야** 한다(문구의 약속을 UI가 이행) ②승인 오버라이드 목록의 도구 폰트가 다른 곳과
> 다르다(`<code>` 서버명 — 트리는 평문 13px).

## 변경
1. **비영속 승인 고정**: 비영속이면 승인 오버라이드 각 행의 Select를 **'승인 없음' 값으로 고정**
   (disabled — 문구가 말한 상태를 UI가 만듦). 저장 시 finalize가 배선 도구 전부에
   `{approval:{required:false}}`를 기록(폼 상태의 toolPolicy는 불변 — 영속 복귀 시 원래 값 복원).
2. **폰트 정합**: 행 라벨 `<code>{server}</code> · {tool}` → 평문 13px(`{server} · {tool}`) —
   트리·다른 목록과 동일 서체.

## 경계 (정직)
- '승인 없음' 자동 기록 = **완화의 자동화**. 백엔드 완화 게이트(스펙 177 P2, 관리자만 저장)는
  무변경으로 계속 강제 — 비-admin이 비영속+도구 에이전트를 저장하면 서버가 403(fail-closed).
  결과적으로 "비영속+도구 에이전트 저장은 관리자 전용"이 됨(승인이 기본인 도구를 무승인으로 여는
  결정은 여전히 관리자의 명시 저장 행위 안에 있음 — 새 우회 경로 없음, UI 고정은 노출 표시).
- 위험 기본값 도구(예: delete_record)도 비영속 저장 시 무승인이 되지만, 비영속의 대안은 "실행
  자체 불가"(237 fail-closed)였으므로 관리자가 비영속을 고르는 행위가 곧 그 트레이드오프 선택.

## 완료 조건
1. 비영속: 승인 행 Select='승인 없음'·disabled(e2e). 영속 복귀: 원래 값·활성 복원.
2. 비영속 저장 왕복: `toolPolicy[capId].approval.required === false`(e2e).
3. 승인 행에 `<code>` 소멸 — 평문 13px(grep + 육안).
4. tsc 0 + verify-281 갱신 GREEN.

### 후속(실행 중 추가, 사용자 지적)
헤더 `(n개 · 선택)`도 비영속에선 거짓 어포던스(고를 수 없는데 '선택') → **`(n개 · '승인 없음' 고정)`**
으로 상태별 전환(직접형 아이템·조율/노드형 독립 Collapse 두 곳).
