# 269 — 기억 어휘 정리: 단기 기억(히스토리) / 장기 기억(mem0)

> 3부작 중 1/3. **269 어휘 → 270 단기 기억 프록시(노드별) → 271 공용 설정 컴포넌트.**
> 목표 그림은 271(에이전트=노드=같은 "프롬프트 구성 단위", 완전 대칭). 269는 그 **첫 벽돌 = 어휘**다.

## 배경 (사용자 관찰)

개발자 정리:
- **단기 기억** = 채팅 히스토리 N개 사용
- **장기 기억** = 메모리(mem0) 사용

지금 UI는 이 둘이 **서로 다른 두 곳에 흩어져** 있고, 그중 하나는 **죽은 선택지**다:

| 개념 | 현재 위치 | 실효 |
|---|---|---|
| 단기 기억 | 세부 ③ "모델 동작"의 **채팅 히스토리** Select(historyDepth) | ✅ 진짜 스위치 |
| 단기 기억(중복) | "기억" 그룹의 **"단기(세션)"** 선택지(memories 배열) | ❌ 코드가 안 읽음(죽은 라벨) |
| 장기 기억 | "기억" 그룹의 **"장기 기억 (mem0)"** 선택지 | ✅ `memory_enabled()`가 이것만 확인 |

즉 `memories` 배열의 `'단기(세션)'` 문자열은 **아무 동작도 안 한다**(백엔드 `memory_enabled`는
`'장기 기억 (mem0)'`만 True). 실제 단기 기억 스위치는 **채팅 히스토리(historyDepth)**다. 사용자가
"단기(세션)이 뭐냐"고 물은 것 자체가 이 중복이 만든 혼란의 증거(회고 243 P3에서 경고 문구로 임시 봉합).

## 이 스펙의 범위 (어휘만 — 구조 이동은 271)

**최소·무회귀·프론트 전용.** 데이터 모델(`historyDepth: number` + `memories: string[]`)은 **불변**.
바꾸는 건 **표면 어휘와 죽은 선택지 노출**뿐이다. 스텝 배치 재구성(하나의 "기억" 섹션으로 통합)은 271.

### P1. 죽은 선택지 제거 — "단기(세션)"를 선택 대상에서 뺀다

- **에이전트 폼 "기억" 그룹**(`AgentForm.tsx` `pickerGroups` `key:'기억'`, ~248): `blocks.memory.items`에서
  `단기(세션)`을 필터링 → **장기 기억(mem0)만** 선택지로 노출.
- **노드 편집기**(`nodeMemoryOptions`, ~284): 동일하게 `단기(세션)` 제외 → 장기만.
  - 결과: NodeListEditor의 `RECALL_BLOCK` 경고(회고 243 P3 봉합)가 **자연 소멸**한다 — 고를 수 없는
    선택지에 대한 경고가 필요 없어짐. (경고 코드는 남겨도 무해하나, 죽은 코드이므로 함께 정리.)
- 필터 기준: `name !== '단기(세션)'`. (백엔드 memory_types DB 행은 **그대로** — MemoryView 문서 표시는
  유지. 이번엔 *선택 노출*만 막는다. 서버·마이그레이션 무변경.)

### P2. "채팅 히스토리" → "단기 기억" 어휘 통일

historyDepth를 노출하는 **모든 표면**에서 라벨을 `단기 기억`으로 통일하고, 부제로 원 메커니즘을 밝힌다:

- `AgentForm.tsx` ~695: `Field label="채팅 히스토리"` → `단기 기억`; 설명에 "최근 N개 대화를 모델에
  넣습니다(채팅 히스토리)".
- `OverridePanel.tsx` ~470: 동일.
- `AgentDetailPage.tsx` ~176 / `detail/CodeAgentDetail.tsx` ~111: 상세 표시 라벨 `채팅 히스토리` →
  `단기 기억`, 값은 그대로(`최근 N개 메시지` / `기억 안 함`).
- 옵션 라벨(`기억 안 함 (0개)` / `최근 N개 메시지`)은 유지 — 이미 명확.

### P3. 장기 기억 어휘 정합(표시만)

- 장기 기억 선택지 라벨은 이미 `장기 기억 (mem0)` — 유지.
- 에이전트 요약(`SummaryRow k="기억"`)·상세 표시가 `단기/장기`를 **함께** 읽히도록 문구만 손질
  (예: 요약에 "단기 최근 N개 · 장기 mem0 {on/off}"). 저장값·파생 로직 불변.

## 완료 조건 (측정 가능)

1. `blocks.memory.items`에 `단기(세션)`이 있어도 **에이전트 폼·노드 편집기 어디에도 선택지로 안 뜬다**
   (셀렉트 옵션 텍스트에 "단기(세션)" 0건 — 브라우저 e2e로 단언).
2. historyDepth 노출 4표면(AgentForm·OverridePanel·AgentDetailPage·CodeAgentDetail) 라벨이 **"단기 기억"**
   (grep으로 "채팅 히스토리" 잔재 = 설명 괄호 안 외 0건).
3. NodeListEditor의 `RECALL_BLOCK` 경고 분기 제거(장기만 선택 가능하니 경고 무의미) — 죽은 코드 0.
4. `historyDepth`·`memories` 데이터 모델·백엔드 무변경(저장 왕복 동일 — 회귀 e2e).
5. `tsc` 0, 모바일 오버플로 0(ui-audit 관련 화면).

## 무회귀·경계

- `memories` 배열에 이미 `'단기(세션)'`이 저장된 기존 에이전트: 선택지에서 안 보여도 **저장값은 보존**
  (finalize가 기존 배열을 안 건드리면 그대로). 어차피 백엔드가 무시하므로 동작 영향 0. — **검증 필요**:
  finalize/toggle이 안 보이는 값을 실수로 떨구지 않는지(회고 "재탐색 통째 교체가 관리자 필드 파괴" 계열
  경계). 표시만 필터, 저장 배열은 손대지 않는다.
- MemoryView(메모리 콘솔)의 `단기(세션)` 문서 행: 이번 스펙 **범위 밖**(선택 노출만). 271에서 재검토.

## 검증 (사다리 3단)

- **단위/타입**: 옵션 필터 순수함수 단언(입력에 단기(세션) 포함 → 출력에서 제외, 장기 보존).
- **실인프라 e2e**: `tests/browser/` — 에이전트 폼·노드 카드에서 기억 선택 열어 옵션 텍스트 단언(단기(세션)
  없음·장기 있음), 라벨 "단기 기억" 확인, 기존 에이전트 저장 왕복(memories 배열 불변).
- **적대(codex)**: 필터가 장기까지 삼키지 않는지, 저장 왕복이 안 보이는 값을 떨구지 않는지, 4표면
  어휘 누락 없는지.
