# 404 — 플레이그라운드 파일첨부(A안: 1회성 대화 주입)

> 상태: **완료** · 2026-07-19 (P1~P4 + codex P1 2건·P2 완성형 반영)
> 발단: 개발자 요청 "플레이그라운드의 파일첨부 기능" — 검토 결과 신설(기존 흔적 0), 3갈래 중
> A안(문서→그 턴 컨텍스트 주입) 선택. 추가 인프라 불요(모델 무관 — mock·실모델 동일 동작).

## 사용자 경험

입력창 옆 클립 버튼 → txt·md·pdf(텍스트류) 선택 → 첨부 칩 표시(파일명·글자수) → 전송하면
그 턴의 유저 메시지에 문서 내용이 함께 실려 에이전트가 읽고 답한다. 인스펙터에 "무엇이
주입됐나"(파일명·글자수·프리뷰)가 표면화된다.

## 설계(결정 사항 포함)

- **P1 추출 엔드포인트** `POST /chat/attachments`(multipart, 인증): 기존 `rag_ingest.extract_text`
  재사용(txt/md=UTF-8, pdf=pypdf — 이미지 PDF·docx는 정직한 400 "텍스트를 추출할 수 없습니다").
  반환 `{filename, text, chars}` — **무상태**(서버 보관 없음). 캡은 raw 바이트에서 누적 검사
  (cap-the-raw-source).
- **P2 주입 운반**: 클라이언트가 추출 텍스트를 `ChatRequest.attachments:[{filename,text}]`로
  되보내고, 서버가 유저 메시지 앞에 **경계 블록**으로 주입:
  `[첨부 문서: <파일명>]\n<본문>\n[첨부 끝]` — 첨부는 **데이터(지시 아님)** 원칙의 경계 표기
  (인젝션 펜스 계열). 주입된 최종 유저 메시지가 그대로 세션에 영속 → 히스토리 재구성(스펙 289)·
  재개가 공짜(별도 저장소·TTL 없음).
- **P3 표면화**: trace에 `attachments:[{filename,chars,preview(캡+비밀마스킹)}]` — 인스펙터 칩.
  플레이그라운드 UI: 클립 버튼·첨부 칩(제거 가능)·전송 시 조립.
- **P4 검증** `verify_404`: 추출 왕복(txt·pdf)·이미지 PDF 400·캡 초과 413·mock 채팅에 주입
  반영(첨부 본문 속 토큰을 에코로 확인)·trace 표면화·영속 왕복.

## 설정값(승인 항목 — 사용자 가시 한계)

| 항목 | 제안값 | 근거 |
|---|---|---|
| 파일 크기(raw) | **5MB/파일** | pypdf 처리·업로드 체감 |
| 추출 텍스트 캡 | **30,000자/파일**(초과 시 앞부분+"(잘림)" 명시) | 로컬 35B 컨텍스트 예산 보호 |
| 동시 첨부 수 | **3개/턴** | 컨텍스트 예산·UI 단순 |
| 허용 형식 | txt·md·pdf + UTF-8 디코드 가능한 텍스트류(csv·json 등) | extract_text 현 능력 그대로 |
