# 397 — 진단 프로브는 "실패와 같은 시점·같은 채널"이어야 증거다

## 사건(2026-07-19, suite 8045 오진)

suite 2건이 "Connection error"(base_url=localhost:8045)로 실패 → 몇 시간 뒤 내가 **키 없이**
8045를 찔러 401("API key required")을 받고 "서버가 API key를 새로 요구하게 됐다(키 변경)"고
보고. 실제로는: ①실패 시점엔 서버가 **꺼져** 있었고(Connection error가 그 증거) ②지금은 살아
있으며 ③키는 원래부터 필요했고 우리 provider에 **유효한 키가 저장돼 있었다**(저장 키 호출=200).
사용자가 "키가 변경됐다는 것인가요?"라고 되물어 재실측하고서야 정정.

## 두 겹의 오류

1. **시점 불일치**: 실패 시점의 증거(Connection error=연결 불가)와 나중 프로브(401=인증 거절)는
   **다른 상태의 관측**이다. 이걸 한 서사("키를 요구하게 바뀜")로 접합하면 존재하지 않은 사건이
   만들어진다. 오류 메시지의 *종류*가 다르면(연결 vs 인증) 이미 상태가 변한 것.
2. **채널 불일치**: 앱은 저장된 키를 실어 보낸다 — 키 없이 찌른 401은 앱 경로의 재현이 아니라
   무자격 요청의 정상 거절이다. 진단 프로브는 **앱과 같은 자격증명·같은 경로**로 해야 증거가 된다
   (이번 정정도 저장 키를 복호화해 실어 보낸 200으로 확정).

## 처방

- 과거 실패를 진단할 때: 실패 로그의 오류 *종류*를 먼저 분류(연결/인증/타임아웃/4xx) — 지금
  프로브와 종류가 다르면 "상태가 변했다"가 1차 결론이지, 지금 관측을 과거 원인으로 소급하지 말 것.
- 외부 의존 실패의 원인 후보를 보고하기 전에 **앱 저장 자격증명 그대로** 재현 1회 필수.
- 사용자 결정을 요구하는 보고("키를 넣을지 정해달라")는 위 재현이 끝난 뒤에만 — 안 그러면
  잘못된 결정지를 들이밀게 된다.
