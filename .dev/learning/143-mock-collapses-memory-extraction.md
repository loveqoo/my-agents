# 143 — Mock LLM은 메모리 추출을 무너뜨려 "메모리≠히스토리"를 안 보이게 한다

**언제**: "메모리가 그냥 기록만 하고 채팅 히스토리와 차이를 모르겠다"는 체감을 다룰 때, 또는 mock
호스트에서 메모리를 시험할 때.

**사실**: mem0 장기 메모리는 대화를 통째 저장하는 게 아니라 **LLM이 사실을 추출(infer=True)**해 저장하고,
매 턴 **user 스코프로 의미 회상**한다. 기본 provider가 **Mock LLM**이면 추출 프롬프트에 canned 응답만
돌아와 **저장되는 사실이 0** → 회상도 0 → 빈 새 세션의 히스토리와 구별 불가. 사용자의 "차이 모르겠다"는
느낌은 틀린 게 아니라 **약한 모델에서 추출이 무너진 정직한 증상**이다.

**메모리 vs 히스토리 3축(실 모델이면 드러남)**: ①스코프 — 히스토리=세션(run_id, 새 세션이면 0),
메모리=사람(user_id, 세션 가로지름, chat.py recall_scope). ②형태 — 원문 최근 N턴(`_window`) vs 뽑아낸
사실. ③회상 — 항상 최근 N vs 질문과 의미 유사 top-k.

**관측 도구**: 플레이그라운드 트레이스 칩 `N mem · N rag · N mcp · Ns`가 그 턴의 **회상 건수**를 보인다
(=메모리가 매 턴 *조회*됨을 증명; 히스토리엔 조회 행위 자체가 없음). 새 세션에서도 `0 mem`이 뜨면
배선은 세션을 가로지르나 내용이 비었다는 뜻. 재현 데모=`tests/browser/demo-mem-vs-history.mjs`
(세션A 진술→"새 대화"→세션B 질문, 실 모델서 세션B가 `1 mem`이면 크로스세션 회상 실증).

**함의**: mock 호스트에선 메모리의 *구조*(스코프·조회 배선)만 실증 가능하고 *가치*(증류·회상)는 실
추출 모델이 있어야 보인다. 데모/평가에서 "메모리 미작동"으로 오판하기 전에 provider가 mock인지부터 볼 것.
