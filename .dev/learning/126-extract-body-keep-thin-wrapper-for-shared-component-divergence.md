# 126 — 공유 컴포넌트가 한 소비자만 달라질 때: 본문 추출 + 기존 래퍼 얇게(0-드리프트)

## 트리거
여러 화면이 **공유하는 컴포넌트**(드로어·모달·카드 셸 등)인데, **한 소비자만 표현이 달라져야** 할 때
(예: A는 드로어 유지, B는 인라인 페이지). 셸을 통째로 바꾸면 다른 소비자 계약이 깨진다.

## 사례 (스펙 126)
메모리 "조회 시험"을 넓은 상세 페이지로 바꾸려는데, `RetrievalTestDrawer`가 **컬렉션 검색과 공유**.
- 처방: 드로어 **본문을 `RetrievalTestPanel`(공용 알맹이)로 추출**. `RetrievalTestDrawer`는 그 패널을
  antd Drawer로 감싼 **얇은 래퍼**(open/title/onClose만 추가)로 축소하고 **타입을 재노출**해 기존 import
  경로 보존 → 컬렉션 CollectionsView는 한 줄도 안 고침. 메모리는 같은 패널을 인라인으로 렌더.

## 배운 것 ① (본질)
**"한 소비자만 다르게"는 셸 분기(if kind)가 아니라 본문 추출로 푼다.** 공유 컴포넌트를 (a) 표현-중립
**본문 패널**과 (b) 소비자별 **얇은 래퍼**(드로어/카드/인라인)로 가르면, 새 표현은 래퍼만 추가하고
기존 소비자는 **원래 래퍼 그대로** 쓴다(0-드리프트). 로직(상태·async·검증 계약)은 본문에 한 번만 있어
[[move-breaks-references-both-directions]]식 이중 유지가 안 생긴다. 핵심 보존 장치 셋: **props 계약을
한 타입으로 고정**(prop 드리프트를 tsc가 잡음), **타입 재노출**(import 경로 불변), **본문 통째 이동**
(로직 무변경 — 옮기되 고치지 않는다).

## 배운 것 ② (검증 이동 — UI 바꾸면 그 UI 짚던 테스트도 같은 턴에)
UI 구조를 바꾸면 그 구조를 짚던 브라우저 shot(예: "조회 시험 버튼→드로어")이 **다음 실행서 조용히
red**가 된다(learning 121 "silent red" 부류의 UI판). 바꾸는 턴에 shot도 새 레이아웃(인라인 카드)으로
갱신·대체하라. 안 그러면 커밋된 테스트가 깨진 채 방치된다.

## 배운 것 ③ (레이아웃 지시는 먼저 합의)
"상세 페이지로 넓게" 같은 지시는 좌우2단/위아래스택 등 **뜻이 여러 개**다. ASCII 미리보기로 **빌드 전에
합의**하면 헛빌드가 없다(추측 금지·[[explain-plainly-not-one-sided]]).

## 다음에 할 일
- 공유 컴포넌트 한 소비자만 분기 → **본문 패널 추출 + 기존 래퍼 얇게 + 타입 재노출**(0-드리프트).
- UI 구조 변경 턴에 그 UI를 짚던 브라우저 shot도 갱신(silent red 방지).
- 모호한 레이아웃 지시는 미리보기로 먼저 합의.
