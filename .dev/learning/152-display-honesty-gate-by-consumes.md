# 152. 화면 표기 정직성은 실행 코드가 판정한다 — consumes 단일 출처로 게이트

## 맥락 (2026-07-10, 스펙 284/286 후속 연쇄)

사용자가 "노드형인데 파운데이션 모델을 하나만 보여주네? 거짓 아닌가?"라고 지적. 목록·상세를
점검하니 세 겹의 같은 결함이 나왔다:

1. **목록 모델 부제** — 노드형은 노드마다 모델이 다른데 최상위 model(폴백값)을 대표처럼 표시.
2. **노드형 상세** — 개요 실행 행·구성 탭 "모델/페르소나" 행이 최상위 값을 표시. `pipeline.py`를
   읽으니 실행은 노드별 `model_cfg`, 최상위 persona는 **아예 미참조**.
3. **조율형 상세** — 구성 탭이 도구·문서 상설 행을 노출하는데 `orchestrate.py`의
   `consumes=("capabilities","memories")` — 도구·문서를 **소비하지 않는다**.

## 배운 것

- **표기가 정직한지는 화면 코드가 아니라 실행 코드로 판정한다.** "이 값이 저장돼 있나"가 아니라
  "실행이 이 값을 읽나"를 flow 소스(`consumes` 선언, ctx 사용처)에서 확인해야 거짓 표기가 드러난다.
  저장값 표시는 셋 다 사실이었지만 실행 사실과 어긋났다.
- **소비 표면 선언(consumes, 스펙 206)이 이미 단일 출처로 존재하면 화면도 그걸 먹어라.** 폼은
  consumes로 표면을 숨기는데 상세는 impl 문자열 하드코딩으로 갈라져 있었다 — 상세도
  `listAgentImpls().consumes`로 게이트하니 폼·상세가 자동 정합(새 impl 추가에도 무수정).
- **한 군데서 나온 거짓 표기는 자매 표면에 반드시 또 있다.** 목록→상세(노드형)→상세(조율형)로
  같은 질문("실행이 진짜 읽는 값인가")을 반복하자 매번 새 결함이 나왔다. 사용자의 "같은 기준으로
  점검해줘"가 이 확장을 시켰지만, 다음부턴 첫 발견 시점에 자매 표면 스윕까지가 한 단위.

## 적용

- 설정 요약·상세 행을 추가할 때: 그 값을 **실행이 소비하는지** flow 소스에서 확인, 소비 선언이
  있으면 그 선언으로 게이트(하드코딩 분기 금지). 미선언(null)=전부 노출(무회귀).
- 검증은 "미소비 표면에 데이터를 심고 화면 부재 단언"(verify-286 ⑩ 패턴).
