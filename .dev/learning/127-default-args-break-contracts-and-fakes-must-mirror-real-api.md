# 127 — 라이브러리 기본 인자가 계약을 조용히 깬다 + 계약 테스트의 가짜는 실제 API를 미러링하라

## 트리거
외부 라이브러리(mem0 등)를 어댑터로 감싸 "전부/모든" 계약(list_all 등)을 구현할 때. 그리고 그 어댑터를
가짜(fake) 라이브러리 객체로 계약 테스트할 때.

## 사례 (스펙 127)
- **버그**: `Mem0Backend.list_all`이 `get_all(filters=...)`을 top_k **미지정**으로 호출 → mem0 기본
  top_k=20 적용 → **21번째 기억부터 목록·소유권 판정(user_owns)에서 조용히 사라짐**(수정·삭제 오거부
  가능). "모든 기억" 계약을 어댑터가 기본값에 맡겨 깬 것. 처방: `top_k=_LIST_ALL_CAP`(10000) 명시.
- **가짜 드리프트**: verify_040(계약 테스트)의 fake `get_all(self, filters)`가 top_k 인자를 안 받음 →
  (a) 기본 20 잘림을 계약 테스트가 **원리적으로 못 잡았고**, (b) top_k를 명시한 *수정*이 TypeError로
  fake에서 red가 됨(고친 코드가 테스트에서 깨짐). 처방: fake를 실제 시그니처로 미러링 —
  `get_all(self, filters, top_k=20)` + `[:top_k]` 슬라이스(기본값의 잘림 시맨틱까지 재현).

## 배운 것 ① (기본 인자는 계약 위반의 은신처)
**어댑터가 "전부"를 약속하면 라이브러리 호출의 상한/페이징 인자를 반드시 명시하라.** 기본값은 문서에만
있고 코드 리뷰에서 안 보인다 — N+1번째 항목이 조용히 사라지는 버그는 데이터가 쌓인 뒤에야 드러난다
(우리는 12건이라 아직 안 밟았고, 조사(deep-reasoner)가 소스에서 먼저 캤다). 심하면 **소유권/보안 판정**
(user_owns가 잘린 목록과 대조)까지 오염된다.

## 배운 것 ② (fake는 실제 API의 시그니처·기본값 시맨틱까지 미러)
계약 테스트의 가짜가 실제보다 **관대하면**(인자 안 받음, 잘림 없음) 두 번 배신한다: 버그를 통과시키고
수정을 떨어뜨린다. fake에는 실제의 (a) 시그니처(키워드 인자), (b) **기본값이 만드는 시맨틱**(top_k=20
잘림)을 넣어라 — 그래야 "인자를 명시했는가" 자체가 계약 테스트의 검증 대상이 된다. learning 124(GREEN이
버그를 굳힘)의 fake판.

## 곁다리 (127에서 함께 확인)
- e2e 시드 시 **노출 목록의 출처 ≠ 데이터 저장소**일 수 있다: 메모리 유저 드롭다운은 sessions.user_id
  distinct, 기억은 mem0_memories — 둘 다 심어야 화면에 뜬다(fast-worker가 발견).
- offset 페이지네이션 방어 셋: limit 상한 + offset 상한(극단값 DoS) + 정렬 캐스트 가드(포맷 이탈 행
  `'9999'`가 텍스트 정렬 깨는 것 → 정규식 가드 후 timestamptz 캐스트·NULLS LAST). codex 여집합이 잡음.
