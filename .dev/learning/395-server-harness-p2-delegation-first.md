# 395 — 격리 하네스 P2: 첫 위임 성공과 "virgin 서버가 사유를 다시 쓴다"

## 맥락

http 층 66개를 virgin DB+전용 uvicorn(_throwaway_server, 임시 포트)로 격리(스펙 390). 치환
45파일은 **fast-worker에 첫 위임** — 38파일·55줄, ast 0실패, 잔존 11줄 사유표, 애매 3건은 집행
전 보고. 결과: **비격리 52개 전원 virgin 서버 그린**·라이브 DB 무접촉(행수 전후 동일)·369 해제·
"오염" 사유 9건이 "노후/실드리프트"로 재판정(101/102는 virgin에서도 재현 = 환경 아닌 실제 결함
후보로 상향).

## 교훈

- **위임 지시서의 핵심은 "완료 기준=측정"과 "애매하면 보고"였다.** fast-worker가 규칙의 문자
  밖 5줄(guard 얇은 래퍼 경유)을 추측 집행하지 않고 사유와 함께 보고해 와서, 검토-승인이 5분에
  끝났다. 지시서에 ①측정 명령 자체를 적고 ②"추측으로 바꾸지 말고 보고"를 명시하는 게 위임
  품질을 결정한다. 210k 토큰의 기계 작업이 메인 컨텍스트 밖에서 처리됨 — 위임 갭 교정 실증.
- **자기참조 시드가 서버 격리의 숨은 관문이다.** 앱은 자기 URL(mock LLM·served MCP·A2A)을 DB에
  시드하는데, 이게 8000 고정이면 임시 포트 서버가 **라이브 서버를 다시 부른다**(교차 오염).
  다행히 seed가 이미 env 오버라이드를 지원(MOCK_LLM_BASE_URL 등) — served_url만 env 추가.
  서버를 복제·격리할 때는 "이 서버가 자기 자신을 부르는 주소" 전수부터.
- **치환은 3분류다: 클라이언트 주소·자기참조 등록값(치환)·판정 입력 데이터(금지).** URL 리터럴을
  일괄 치환하면 SSRF 가드 테스트(guard_url 입력)의 의미가 깨진다 — 데이터로서의 URL과 주소로서의
  URL을 가르는 게 이 작업의 판단 전부였다.
- **virgin 서버는 격리 사유를 다시 쓴다(387 재현+상향).** "라이브 환경/데이터 차이"라던 101/102가
  virgin에서도 재현 — 오염 탓이 소거되니 실제 드리프트로 판정 상향(별도 조사 후보로 승격). 노후
  양파(093: status→이름규칙→MissingGreenlet 순차 노출)는 켜풀 두 겹까지만 수선하고 개별 재활
  후보로 남김 — 하네스 스펙에서 개별 재활을 다 하려는 유혹은 두더지잡기(384 교훈).
