# 389 — "전체 그린" 선언 뒤에 숨은 두 층: 실모델 행 소실과 임베더 교차 오염

## 맥락

개발자 "최근 테스트에 모두 성공하지 못했습니다" — 맞았다. suite(실모델 조합)가 PREFLIGHT부터
막혀 있었는데 나는 "환경 차단"으로 옆에 치워놓고 그린을 선언했었다. 다시 전수 실행:
metrics-fast ✅ → test-all SUITE_OK ✅ → suite는 3층의 문제를 차례로 파냄:

1. **실모델 행 소실**: dev DB에 mock 3행뿐 — 과거 51/51을 돌리던 MLX provider(qwen3.6-35b·
   e5-large-mlx) 행이 통째로 사라짐(.env에 구성은 남아 있었다). 정식 라우트로 재등록.
2. **기본값 미지정**: 재등록만으론 mem_cfg가 여전히 mock 기본값 → mock 임베딩은 해시라 의미
   유사도 0, 회상 5개 전 유형 실패(`memories=[]`). `PUT /models/{id}/default`로 복원.
3. **임베더 교차 오염**: 기본값 복원 후에도 4개 실패 — 픽스처가 mock 시절 심은 PREF 기억을
   "이미 있음(reused)"으로 재사용했는데 그 **벡터가 mock 공간**. e5 쿼리와 어긋나 top-k 밖.
   mem0 잔해 4행(전부 테스트/프로브 스코프 확인 후) 정리 → 재시드 → 50/51 → 마지막 1개는
   단독 통과(순서 플레이크) → 전판 재실행 **51/51**.

## 교훈

- **"환경 차단이라 스킵"은 그린이 아니다 — 사용자가 맞았다.** suite를 PREFLIGHT 실패로 옆에
  치우고 "대체 증거로 판정"했지만, 막힌 게이트 뒤에 실제 3층 문제(행 소실·기본값·벡터 오염)가
  숨어 있었다. 게이트가 안 돌면 "미검증"이지 "통과"가 아니다 — 차단 원인을 뚫는 것까지가 검증.
- **임베더 교체는 mem0도 재임베딩이다([[rag-edit-is-whole-doc-reindex]]의 기억판).** 벡터 저장소에
  남은 행은 저장 당시 임베더 공간에 묶인다. 임베더(기본값)를 바꾸면 기존 행은 검색 불능 쓰레기 —
  "텍스트가 있으니 reused"는 함정(텍스트 매칭 ≠ 벡터 유효). 픽스처·재사용 로직은 임베더 지문을
  함께 확인하거나, 교체 시 스코프 재시드가 필요하다.
- **회상 실패는 층을 갈라 진단하라: 행이 없나 → 기본값이 mock인가 → 벡터 공간이 맞나.**
  `memories=[]`(회상 0)와 "회상은 되는데 그 사실만 없음"(top-k 밀림)은 다른 층의 신호다.
  전자=임베더가 의미를 못 만듦(mock)·후자=공간 불일치/순위 오염. add는 성공하는데 search가
  빈 것도 정상 신호일 수 있다(list는 벡터 무관, search만 벡터 의존).
- **진단 프로브 자체를 의심하라** — 내가 처음 잡은 "AttributeError 근인"은 파사드 인자 순서
  (scope, query)를 뒤집은 **내 프로브 버그**였다. graceful 삼킴(타입명만 로그)은 프로브 실수도
  앱 결함처럼 보이게 한다. 원시 백엔드를 올바른 시그니처로 다시 불러 반증했다.
- **dev DB의 "행 소실"은 미해결 미스터리로 남김** — 무엇이 MLX provider/모델 행을 지웠는지
  (테스트 정리? 수동? DB 재생성?) 이력(block_versions)에도 실모델 흔적이 없다(mock만). 재발 시
  단서: 실모델 등록도 라우트 경유라 이력이 남아야 하는데 없음 = 이력 도입(스펙 369) 전에 등록·
  삭제됐거나 raw 삭제. 백로그에 관찰 항목으로.
