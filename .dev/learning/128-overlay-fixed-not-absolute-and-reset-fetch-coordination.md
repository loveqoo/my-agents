# 128 — 오버레이는 스크롤 컨테이너에 absolute 금물 + 리셋·조회는 한 효과에서 조율

## 트리거
(a) 드로어/모달 오버레이를 스크롤되는 컨테이너 안에 둘 때. (b) 목록 컴포넌트에서 필터/스코프 전환이
"page 리셋 + 재조회"를 유발할 때(stale 가드가 있어도). (c) 공용 컴포넌트가 소비자 클로저(fetch 함수)를
props로 받을 때. (d) 목록 UI를 브라우저로 검증할 때.

## 사례 (스펙 128)
1. **오버레이 absolute 버그(사용자 신고)**: 공용 Drawer가 `position:absolute; inset:0`으로 스크롤
   컨테이너(Content) 좌표계에 붙음 → 목록을 아래로 스크롤한 채 열면(마지막 세션 클릭) 오버레이가 위로
   밀려 **하단 행들이 드로어 밖으로 노출**(화면 깨짐). absolute inset:0은 컨테이너의 *보이는 박스*
   크기로, 스크롤 콘텐츠를 안 덮는다. 처방: `position:fixed`(뷰포트 기준) — antd Drawer(portal)와 동일
   거동. **오래된 잠재 버그가 목록이 길어지자 표면화** — 이 Drawer를 쓰는 모든 화면이 대상이었다.
2. **과도기 요청(codex)**: reqSeq stale 가드는 "다음 요청이 시작된 후"에만 낡은 응답을 폐기한다 —
   필터 전환 렌더에서 `setPage(1)`은 예약만 되고 같은 flush의 load 효과가 **구 page+새 필터**로 요청,
   빠른 응답이면 잠깐 커밋. 처방: **리셋과 조회를 한 효과에서 조율** — 리셋이 필요한 렌더에서는 fetch를
   스킵(state 정착 후 deps 변경으로 재실행), 과도기 요청 자체를 없앤다.
3. **클로저 identity 루프 차단(설계)**: 셸이 fetchPage(소비자 인라인 클로저, 필터 캡처)를 effect deps에
   넣으면 onExtra→setState→부모 재렌더→새 identity→재조회 무한 루프. 처방: **ref에 고정**(매 렌더 갱신,
   deps 제외) — 항상 최신 클로저를 읽되 재조회 트리거는 명시 키([q,page,scopeKey,refreshKey,
   pageResetKey])만.
4. **브라우저 검증 두 함정(fast-worker 발견 포함)**: ① antd Drawer/Modal은 **portal(body 직속)** —
   `#root` 스코프 체크는 내용을 조용히 놓치고, 무스코프 `tbody tr` 카운트는 배경 테이블 행이 새어
   오카운트. 체크는 해당 portal 루트(`.ant-drawer-section` 등)로 스코핑. ② 지금까지 shot은 **첫 행·
   무스크롤만** 클릭해 스크롤-상태 버그(1번)를 못 잡았다 — 목록 검증에 **마지막 행·스크롤 끝**을 포함.

## 배운 것 (본질)
- 오버레이의 좌표 기준은 "덮어야 할 것"과 일치해야 한다 — 뷰포트를 덮을 거면 fixed/portal, 스크롤
  컨테이너 안 absolute는 스크롤 순간 계약이 깨진다.
- 경합 가드(reqSeq)는 **늦은 응답**을 막지 **이른 요청**을 막지 않는다 — 리셋이 걸린 렌더에서는 요청을
  안 내보내는 게 근본(가드 한 겹 더가 아니라 발생 자체 제거).
- 공용 컴포넌트의 재조회 트리거는 **명시 키 목록**으로 — 함수 prop identity는 트리거로 쓰지 말 것.
