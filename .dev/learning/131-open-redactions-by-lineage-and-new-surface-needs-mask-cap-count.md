# 131 — 의도된 가림은 계보를 추적해 열고, 새 노출 표면엔 마스킹·캡·개수상한 셋 다

## 트리거
(a) 디버깅/관측성을 위해 **의도적으로 가려둔 데이터**(redaction·요약·미수집)를 열어달라는 요구.
(b) 트레이스/로그에 **새 노출 표면**(본문 프리뷰·프롬프트 캡처)을 추가할 때.

## 사례 (스펙 131)
"전송 프롬프트 전체·도구 결과 상세·노드 값"을 인스펙터에 — 기존 가림 3종을 열어야 했다.
- **계보 추적이 먼저**: 각 가림의 출처 스펙(086 F2 값-비밀 fail-closed / 087 원문누출0 / 미수집)과
  적대 리뷰 근거를 추적 → 086은 "비밀 아님을 보증하는 키만 allowlist 확장" 관문을 스스로 남겼고,
  087은 위협 과대평가를 자기 교정한 선례가 있어 — **그 관문대로 열면 계약 위반이 아님**을 사전 판정.
  무엇을 보호하던 장치인지 모르고 열면 보안 회귀, 알고 열면 정당한 완화.
- **새 표면의 3종 세트(codex가 잡은 구멍들)**: ①마스킹 — untrusted 본문(delegated fold)·사용자 저작
  텍스트(페르소나 오버라이드에 적힌 API 키)는 노출 전 _sanitize 백스톱(캡은 크기 방어일 뿐 비밀 방어가
  아니다). ②자수 캡 — 메시지/필드당. ③**개수 상한** — 캡×무제한 개수 = 여전히 무한(historyDepth
  오버라이드로 10,000개 메시지가 JSONB에 통째 영속될 뻔). 셋 중 하나라도 빠지면 구멍.
- **마스킹은 캡 이전에**: 마스킹 함수의 자체 캡으로 잘림까지 맡기면 기존 "…N자 생략" **정직 잘림 표기
  불변식**(086 U2)이 깨진다 — 역할 분리: 마스킹(비밀)→_cap(잘림+정직 표기).
- **부분 표면화 재발**(130 교훈 그대로): resultPreview를 모든 브로커 호출에 실었는데 UI는 rag:*만
  렌더 → 비-RAG 위임 호출 섹션 신설. 백엔드가 싣는 필드는 프론트가 **전 종류** 렌더하는지 대조.
- **영속 복원까지가 기능**: 트레이스 신규 필드는 스트림+저장(JSONB)+재로드 세 지점 대칭 — 새로고침 후
  세션 재선택 e2e(D6)로 실측해야 "스트림에서만 보이는 반쪽"이 아님을 안다.

## 다음에 할 일
- 가림을 열자는 요구 → 그 가림을 만든 스펙·리뷰를 먼저 찾고, 남겨진 확장 관문에 맞춰 연다.
- 노출 표면 추가 체크리스트: 마스킹(untrusted+사용자 저작 텍스트) / 자수 캡 / 개수 상한 / 마스킹→캡
  순서 / 모든 종류 렌더 / 3경로(메인·승인대기·재개) / 재로드 복원 e2e.
