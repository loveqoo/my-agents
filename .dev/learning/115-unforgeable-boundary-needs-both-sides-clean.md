# 115 — 위조 불가 경계는 "비밀 구분자"로 만들되 *경계의 신뢰 구성요소도* 정규화해야

스펙 115(위임 결과 attribution 견고화)에서 배운 것.

## 1. 위조 불가 구분자 = untrusted 측이 절대 못 보는 요청별 랜덤 nonce

텍스트 채널에서 신뢰 표식(출처 라벨)을 데이터와 섞으면 데이터가 표식을 스푸핑한다(가짜 `## 능력:`
헤더 주입). 방어: 각 데이터를 `⟦BEGIN {nonce}⟧…⟦END {nonce}⟧`로 감싸고 **nonce를 요청별 랜덤 생성 +
untrusted 측에 절대 노출 안 함**. 그러면 데이터는 nonce를 몰라 펜스를 조기 종료하거나 새 구획을 못 만든다
→ 진짜 경계가 **위조 불가**. 정적 구분자(고정 문자열)는 데이터가 흉내 낼 수 있으니 무의미 — 핵심은
**비밀성 + 요청별 유일성**. (LLM이 이를 완벽 준수하는지는 별개 모델 품질 문제 — 이건 *경계 자체*를
위조 불가로 만든 구조적 하한.)

## 2. 경계는 그 **신뢰 구성요소까지 정규화**해야 성립한다 (codex P1)

콘텐츠를 펜스로 가둬도, 펜스 *밖*의 라벨을 `cap.name`으로 raw 보간하면 헛일이다 — name이 자원명
(MCP/RAG/agent, 소유자가 정함)이라 개행 + `## 능력:`을 심어 **라벨 줄 자체를 위조**할 수 있다. 경계는
**가장 약한 구성 부분만큼만 강하다**: 데이터를 가두는 것과 별개로, 신뢰 측 구조를 이루는 모든 값
(라벨의 name/id)을 한 줄로 접고 펜스 브래킷을 제거해야 한다. **"신뢰 측"이라고 믿은 값이 실은
attacker-영향 자원명이었다** — 무엇이 진짜 신뢰 소스인지 끝까지 따져라.

## 3. 방어 지침은 **실제 데이터 모양과 일치**해야 (codex P2)

모델에 "출처는 `⟦BEGIN⟧` 앞 라벨"이라 지시하면서 단일 결과는 fence 없이 raw로 흘리면, 악의적 단일
결과가 심은 **가짜 `⟦BEGIN⟧`을 진짜 출처로 오인**시킨다. 지침이 설명하는 구조가 실제로 존재할 때만
그 지침을 내라(펜스가 있을 때만 펜스 규칙). 그리고 단일도 펜스해 지침을 항상 정확히 유지. **방어
설명과 데이터 형식이 어긋나면, 그 틈이 새 공격면이 된다.**

## 4. 순수 함수에 랜덤을 넣지 말고 주입한다

`fold_results`는 순수 유지(단위 검증 결정성) — nonce는 인자로 받고 **생성은 노드(부수효과 경계)가**
담당. 랜덤/시각을 순수 함수에 넣으면 테스트가 비결정이 된다. 조작적 검증: 고정 nonce로 세그먼트를
파싱해 "주입 콘텐츠가 진짜 경계를 못 만든다"를 단언(위조 불가의 조작적 정의).

## 적용
- 신뢰/비신뢰를 텍스트로 섞을 땐 요청별 랜덤·비노출 nonce 펜스로 경계를 위조 불가로.
- 경계의 *신뢰 측* 구조를 이루는 모든 값(라벨·헤더)도 정규화 — 그게 attacker-영향인지 끝까지 확인.
- 방어 지침은 실제 데이터 형식과 일치시키고, 형식을 균일화(단일도 펜스)해 어긋난 틈을 없앤다.
- 랜덤은 순수 함수 밖(노드)에서 주입, 함수는 결정적으로 유지.
