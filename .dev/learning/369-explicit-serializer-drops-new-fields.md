# 369 — 스키마에 필드를 더해도 명시적 직렬화 생성자는 조용히 떨군다

**맥락**: 블록 버전화(스펙 369)에서 5종 Out 스키마에 `version: int = 1`을 추가했는데, 검증에서
mcp-server만 편집해도 v1로 표시. 근인 = 응답 생성 경로가 둘로 갈라져 있었다:

- **ORM 모드**(`model_config = ORM` + ORM 객체 반환): 스키마에 필드를 추가하면 자동으로 실림
  (Prompt·MemoryType은 그래서 바로 동작).
- **명시적 생성자**(`mcp_to_out`·`provider_to_out`·`model_to_out`처럼 필드를 손으로 나열): 스키마에
  필드를 추가해도 **기본값으로 조용히 채워진다** — 컴파일·검증 다 초록인데 값만 틀림.

## 교훈

1. **Out 스키마에 필드를 추가할 땐 "이 스키마를 만드는 생성자가 몇 곳인가"를 먼저 grep** —
   `SchemaOut(` 호출부 전수. ORM 모드가 아닌 곳은 각자 명시 전달이 필요하다.
2. 이 함정은 **기본값이 있을 때만** 조용하다(기본값 없으면 생성자에서 즉시 ValidationError).
   응답 스키마 신규 필드에 기본값을 줄 땐 "명시 생성자가 떨궈도 초록"이 되는 대가를 인지할 것.
3. 잡는 방법은 **round-trip 검증**(값을 바꾸고 응답에서 그 값을 다시 읽기) — verify_369 C1이
   "편집→version 증가"를 응답 값으로 단언해서 잡았다. 표시-레벨 확인(스키마에 필드 있음)만 했으면
   놓쳤다. [[ui-verification-must-be-functional]]의 API판.

관련: 폴리모픽 이력 테이블은 FK cascade가 없어 삭제 정리를 앱 레벨 동일 tx로(스펙 369 §1),
콘텐츠/운영 경계는 payload 함수가 단일 출처(§2 — SQL 백필로 중복 정의하지 않기).
