# 회고 192 — admin 전면 antd 전환 (스펙 204, 교체 18건)

## 무엇을 했나
사용자 지시("모두 antd로, 하나하나 지시 없이 일괄") → Explore 전수 조사(교체 18·래퍼 무변경·
논의 5 보류) → 3배치 교체(하 11: Badge/Card/List/Collapse/Progress/Typography, 중 4: Drawer×2/
Table/Tag, 상 3: **Splitter 도킹**/Dropdown 콤보×2). 규칙은 admin/CLAUDE.md에 명문화. 매 배치
tsc+ui-audit 3종 FAIL 0, 도킹·피커는 기능 e2e로 확인.

## 배운 것

### 1. "전부 X로" 지시는 규칙 명문화 → 전수 조사 → 분류가 먼저다
교체를 바로 시작하지 않고 (a) admin/CLAUDE.md에 규칙을 박고(미래 작업이 자동 준수), (b) Explore로
전수 조사해 교체/래퍼/대응물없음/애매 4분류를 만들었다. 분류가 있으니 "어디까지 했나"가 측정
가능했고, 논의 5건을 사용자 결정(보류)으로 깔끔히 분리했다. **교훈: 일괄 전환 지시 = 규칙
명문화(재발 방지)+조사 분류(진척 측정)+사용자 결정 지점 분리(애매 건)의 3단 — 교체 자체는 그
다음이다.**

### 2. 대량 문자열 수술은 앵커 assert가 안전벨트 — 그리고 잔재는 tsc가 아니라 앵커가 잡는다
python 문자열 치환으로 JSX를 수술할 때 assert(원문 존재·개수)를 걸었는데도 EvalTrend에서 이른
`})}`에 매칭해 잔재 5줄이 남았고(JSX 구조 깨짐), Inspector에선 치환 범위에 codeBox 상수가 딸려
지워졌다. 둘 다 tsc가 잡았지만, **범위 산정은 "다음 고유 앵커"(함수 시그니처 등)로 하고 치환 후
잔재 검사(옛 마커 grep)까지 해야** 한 번에 끝난다. JSX 주석은 삼항 표현식 자리에 못 온다는 것도
실측(TS1005).

### 3. 포털 전환은 e2e 셀렉터 계약을 바꾼다 — 스코프 없는 getByText가 오탐한다
수제 드롭다운(인라인 DOM)→antd Dropdown(포털)으로 바꾸자, 스코프 없는 getByText 클릭이 "실패"로
보였다(실제론 다른 요소 매칭). `.ant-dropdown` 스코프로 클릭하니 정상 — 기능은 멀쩡했고 테스트가
DOM 위치 가정에 결합돼 있던 것. **교훈: 인라인→포털 전환을 하면 기존/신규 e2e의 텍스트 셀렉터를
포털 컨테이너로 스코프해야 한다 — "전환 후 실패"는 먼저 셀렉터 오탐을 의심.**

### 추기(같은 날) — 내 스샷을 보고도 놓친 레이아웃 불변식, 사용자가 잡았다
Splitter 도킹 스샷에서 입력창이 화면 중간에 떠 있었는데(패널=블록 컨테이너라 DebugChat의 flex:1이
높이를 못 받음), 나는 "Splitter 렌더+드래그바"만 확인하고 지나쳤고 사용자가 스샷에서 발견했다.
flex 래퍼 복원으로 수리. **교훈: 컨테이너 교체 후 스샷 육안은 "렌더됐나"가 아니라 그 화면의 레이아웃
불변식(입력창=바닥 고정, 헤더=상단 고정, 스크롤 영역=중앙)을 명시적으로 대조해야 한다 — 회고 183
(배치는 스샷이 잡는다)에 "스샷을 보되 불변식 체크리스트로"를 더한다.**

## 다음에 적용
- 일괄 전환 = 규칙 명문화+조사 분류+결정 분리 후 배치 실행(1).
- 문자열 수술은 고유 앵커+치환 후 잔재 grep(2).
- 포털化 후 e2e는 포털 스코프 셀렉터로(3).
- 컨테이너 교체 스샷 확인은 레이아웃 불변식(바닥 고정 등) 체크리스트로(추기).
