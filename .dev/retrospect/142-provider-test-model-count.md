# 142 — 프로바이더 연결 테스트가 항상 "모델 미발견" (스펙 164)

실사용: 프로바이더 연결 테스트가 잘 붙었는데도 "연결됨 · 모델 미발견". 등록 화면엔 모델이 주르륵.

## 근인
프로바이더 레벨 테스트는 `_probe(base_url, key, "", "chat")`로 **빈 model_id**를 넘긴다(프로바이더
도달성 확인, 특정 모델 아님). 그런데 `_probe`는 `available = model_id in ids if model_id else False` —
빈 model_id를 무조건 False로 판정 → 항상 "미발견". "특정 모델이 목록에 있나" 함수를 빈 이름으로
재사용한 게 화근.

## 배운 것
- **스펙 158 계열의 또 다른 얼굴: 정상을 실패처럼 표시**. 158은 실패를 0건으로 위장, 162는 빈 상태를
  실패로 위장, 164는 "확인 안 함(빈 질의)"을 "미발견(실패)"으로 위장. 공통 처방=**모호한 입력을
  실패로 뭉개지 말고 그 입력의 의미대로 판정**(빈 model_id=프로바이더 확인이지 모델 확인이 아님 →
  목록 개수로). 진단 정직성은 "실패/빈/미지정"을 각각 제 이름으로 부르는 것.
- **한 함수를 빈 인자로 재사용할 때 그 인자 부재의 의미를 재검토**. `_probe`는 "특정 모델 검사"용인데
  빈 model_id로 "프로바이더 검사"에 재사용 → 부재 케이스를 새 의미로 분기했어야 했다. 재사용 시
  인자 부재가 조용히 fail-closed로 떨어지는 footgun.
- **프론트 무변경으로 고쳐짐**: ProbeRow가 detail 문자열+ok만 표시(modelAvailable/텍스트 특수분기
  없음) → 백엔드 detail만 정직해지면 화면도 정직. 표시 로직이 얇으면 백엔드 한 곳 수정으로 끝.

## 검증
verify_164 4/4 — 로컬 stub /models 서버로 실제 _probe 호출: 빈 model_id+모델2개→"2개 발견"·True,
빈+0개→"비어있음"·False, 지정·존재→"사용 가능", 지정·부재→"미발견"(회귀 유지). 인증·데이터 경로
없는 표시 문자열이라 codex 생략(브랜치 전수 단위 테스트가 검증).

## OUT
- 테스트가 발견한 모델 목록을 응답에 담아 UI 드롭다운 채우기(현재 /available-models 담당).
- embedding 프로바이더 테스트(현재 chat 고정).
