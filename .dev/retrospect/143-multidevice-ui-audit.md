# 143 — 다디바이스 UI 오버플로 감사 하네스 (검증 축2 파일럿) (스펙 165)

사용자 문제제기: 기능 고도화로 일관 UX 검증 필요. **자가검증이 관대**(많이 스킵). 전문 에이전트가
필요한가? 어떻게 꼼꼼히?

## 진단(관대함의 구조)
자가검증이 관대한 건 의지가 아니라 구조: (1) 같은 저자=같은 사각, (2) 명시적 합격선 없음=재량=스킵.
처방=**측정 가능한 기준 + 적대적 타자**. 축2(UI 오버플로)는 가장 수치화가 쉬워 파일럿.

## 배운 것
- **꼼꼼함 = 도구가 좁히고, 육안이 소수를 확정**. 하네스가 42캡처를 훑어 진짜 깨짐 1건으로 좁혔다.
  "다 스캔해" 대신 "이 1곳을 봐" — 육안의 부담이 42→1이 되니 관대할 여지가 없다. 이게 자가검증
  관대함의 진짜 해법(더 열심히가 아니라 대상 축소).
- **도구가 오탐 줄이려다 진짜를 삼키면 관대함 재발**. 노이즈(닫힌 드로어·antd 탭 ⋯)를 줄이려 "스크롤
  조상이면 흡수" 필터를 넣었더니 **batch 버튼 잘림(진짜)까지 0건으로 만들었다**. 육안 페어로 잡음
  (회고 133 재확인: 정량이 flex 내부 압착·버튼 잘림을 못/잘못 잡음). **필터는 증명된 안전 패턴만
  좁게**(off-screen `left>=vw`, `.ant-tabs-nav`), 애매하면 표면화해 눈에 맡긴다. 도구의 과잉 억제 = 새 관대함.
- **판정 기준 선택이 신호대잡음을 좌우**. 첫 시도 `scrollWidth>clientWidth`는 좌측·화면밖 요소까지 잡아
  오탐 폭주. `rect.right > vw`(우측 경계 실제 초과)로 바꾸니 "화면서 잘리거나 삐져나온 것"만 남았다.
  측정은 "무엇을 세느냐"가 절반 — 사용자가 겪는 증상(화면 밖으로 나감)에 정렬.
- **하네스가 곧 자산**: `ui-audit.mjs`(화면×뷰포트 배열 파라미터)는 재실행 가능한 표준 감사. 축1(시나리오)
  ·축3(문구)도 같은 골격(전수 순회+측정 가능 판정+아티팩트)으로 복제 가능. 스폿 체크→표준 감사 승격.
- **측정 가능 → 자율 반복**: 수치 판정이 서니 향후 Ralph/커맨드로 사람 없이 상시 감사 가능
  ([[numeric-verification-unlocks-autonomy]]) — 사용자의 "지속적 발견" 요구에 정렬.

## 검증
ui-audit.mjs 실행: 42캡처, 판정 다듬으며 오탐 대조(모바일 내비·off-screen 드로어·antd 탭). 진짜 1건
(mobile/batch +6px 버튼 잘림)→`<Space wrap>`→재실행 0 FAIL·육안 재확인(줄바꿈). tsc 0.
