# 회고 223 — "복잡한 데이터를 인정한다"의 실행형: 3층 위계 문법 (스펙 246)

## 무엇을 했나
사용자 통찰("데이터를 줄이는 단계는 끝 — 이제 잘 보여줄 고민") → 정보 3층 위계를 서비스 문법으로
합의하고 에이전트 상세에 1차 적용: 1층=상태 배지 줄(항상), 2층=관심사 탭 하나만 렌더, 3층=빈 값
접기·식별자 복사 강등. 개요=요약 대시보드(각 관심사 한 줄+점프 — 지도).

## 배운 것

### 1. "구분"과 "필요한 것만"은 다른 처방이다 — 245는 전자만 했다
245(섹션 분류)로 구분은 됐지만 전부 항상 렌더라 노출량이 그대로였다. "필요한 것만"은 세 가지가
따로 필요: ①탭(한 번에 한 관심사) ②빈 값 접기(없음을 알리는 행도 비용) ③요약층(개요=상세 반복이
아니라 어디를 볼지 가리키는 지도). 분류 다음 단계는 항상 노출 제어다.

### 2. 개요는 "첫 번째 상세"가 아니라 "지도"여야 한다
개요 탭에 모델·페르소나를 나열하면 그냥 또 하나의 상세 화면. 각 탭의 요약 한 줄("도구 2 · 메모리 1",
"서빙 v3 · 초안 v4 대기")+클릭 점프로 바꾸니 첫 화면이 "무엇이 있고 어디를 볼지"만 말한다.
행동 필요한 알림(페르소나 stale)만 개요에 남긴다 — 요약층의 입장 기준은 "행동 또는 방향".

### 3. 위계는 화면 하나의 수선이 아니라 문법으로 남겨야 복리가 된다
1층 항상/2층 탭 하나/3층 요청 시 — 이 규칙을 스펙에 문법으로 박아 다음 개편(승인 화면 등)이 같은
틀을 쓰게 했다. 화면마다 새로 논쟁하지 않는 게 이 스펙의 진짜 산출물.

## 다음에 적용
- 화면 설계 순서: 분류(관심사) → 노출 제어(탭·접기·요약층) — 분류만 하고 끝내지 말 것.
- 요약층 입장 기준: 행동 필요하거나 방향을 가리키는 것만.
- 다음 적용 대상: 승인 화면(복잡도 1위), 평가 문제집 드로어.
