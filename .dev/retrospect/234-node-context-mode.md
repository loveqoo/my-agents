# 234 — 노드별 맥락 모드: 사용자 질문이 설계를 끌어올렸다 (스펙 260)

## 맥락
259 노드형을 낸 뒤, 노드 간 전달을 두고 사용자와 설계 대화. 내가 A/B/C(누적/파이프/템플릿)를
전역 선택으로 물었더니, 사용자가 되물었다: *"형식을 고정한 노드에선 쌓인 대화를 제거하는 방식이
필요하지 않을까?"* — 이 한 질문이 답을 전역 토글에서 **노드별 토글**로 끌어올렸다.

## 무엇을 배웠나

### 1. 사용자의 "되묻기"는 내 프레이밍의 결함을 드러낸다
나는 "전역으로 하나 고르기"로 좁혀 물었다. 사용자는 그 프레임을 안 받고 *구체적 실패 사례*(형식 고정
노드)를 던졌다. 그 사례는 전역 선택으로 안 풀린다 — 대부분 노드는 이어받기가 맞고 *일부* 노드만
격리가 필요하니까. 정답은 **노드별**이었다. 내가 A/B/C를 강요했으면 틀린 걸 만들 뻔했다. 사용자가
옵션을 안 고르고 되물으면, 내 선택지 집합 자체를 의심할 것(옵션 밖에 답이 있다).

### 2. 데이터 흐름은 이미 됐지만 "제어"가 없었다
259는 누적 대화라 결과가 *이미* 다음 노드로 흘렀다(사용자 걱정 일부 해소). 하지만 흐름을 *끊거나
정제할* 수단이 없었다. "전달되나?"의 진짜 질문은 "전달을 *제어*할 수 있나?"였다. 기능이 되는 것과
사용자가 통제하는 것은 다르다.

### 3. 격리는 입력만이 아니라 도구 루프까지 (재진입 재-오염 함정)
clean을 "입력만 앞 결과로 바꾸기"로 얕게 짜면 도구 루프에서 샌다: 노드가 도구를 호출→ToolNode가
결과 append→노드 재진입 시 `[sys, *전체 messages]`로 다시 옛 대본을 봄. 진짜 격리는 첫 진입에서
`RemoveMessage`로 이전 대화를 **실제 제거**하고 앞 결과를 새 입력으로 심어 *격리 buffer*를 만들어야
한다 — 그러면 도구 루프 재진입이 그 buffer 위에서 돌아 재-오염이 없다. 재진입 판별=마지막이
ToolMessage인가(그래프 위상이 보장). 이 함정을 단위(U4)로 못 박았다 — clean 노드가 2회 호출되고
2회차에도 USER_IN이 안 보이고 도구 결과만 격리 buffer에 뜬다.

### 4. 동작 검증은 "받은 메시지"를 기록하는 가짜 모델로
`build_graph`가 실 ChatOpenAI를 만들어 검증이 어렵던 걸, `_model_from_node`를 몽키패치해 각 노드가
*실제 받은 메시지 목록*을 sink에 기록하는 가짜로 교체 → carry/clean이 무엇을 보는지 직접 단언(구조가
아니라 동작). 스크립트 응답(도구콜→최종)으로 도구 루프까지 결정적으로 태웠다. 259는 그래프 구조만
봤지만 260은 *흐르는 데이터*가 핵심이라 동작 계측이 필요했다.

### 5. 필드 하나가 대부분의 입구를 공짜로 통과했다(088의 밝은 면)
`context`는 `_resolve_node_models`가 `{**n}`이라 자동 보존, 저장/재로드도 노드 통째라 자동 왕복.
실제 손댈 입구는 pipeline.py(정규화+실행)+프론트(타입+토글) 둘뿐. learning 088은 "새 필드는 모든
입구서 다뤄질 때까지 죽은 것"인데, 여기선 통과-보존 구조(spread·통째 저장) 덕에 입구가 적었다 —
*그래도 입구를 세어 확인*하고 넘어간 게 핵심(공짜여도 열거는 한다).

## 결정 사항 (기록)
- 형식 **강제**(JSON 파싱·검증)는 미루고 프롬프트 유도만 — 사용자와 합의(파서·에러 계약 별도).
- 템플릿 표현식(`{{...}}`) 미도입 — 노드별 토글이 실수요를 덮음. 여러 앞 노드 조합 요구가 실제로
  생기면 후속.

## 다음에 다르게
- 설계 옵션을 좁혀 물을 때, 사용자가 옵션을 안 고르고 사례로 되물으면 *선택지 집합*을 재검토.
- "전달되나?"류 요구는 "제어 가능한가?"로 한 겹 더 파기.
- 누적 상태(대화·버퍼) 위 "격리/리셋" 기능은 도구 루프·재진입까지 위협모델에 넣고 동작 계측으로 검증.
