사용자 요구 3건(전송 프롬프트 전체·도구 결과 상세·노드 값 가독) + "플레이그라운드=정밀 테스트 통로,
디버깅 막강하게"(메모리에 보존한 제품 철학). 조사(deep-reasoner)로 세 가림의 원래 이유를 특정 —
#1은 미수집, #2는 브로커/RAG만 과보수(직접 MCP는 이미 노출), #3은 086 F2 fail-closed가 옥석 없이
가림. 처방: sentMessages 캡처(캡+마스킹+개수 상한)·resultPreview(마스킹+캡)·안전 키 4개 확대
(미지 키는 계속 가림) + 리치 컴포넌트(역할별 Collapse·코드 블록·본문 접이식).

## 잘된 것
- **가림의 계보 추적이 스펙을 정확하게 만듦**: "왜 가렸나"를 각 스펙(086/087/092)과 적대 리뷰 근거까지
  추적해, 여는 범위가 기존 보호 계약을 깨는지 여부를 사전 판정 — 087 스스로 위협 과대평가를 교정한
  선례를 근거로 브로커/RAG에 같은 계약(마스킹+캡)을 적용.
- **codex가 새 노출 표면의 구멍 4개를 정확히 짚음**: delegated 무마스킹(캡은 크기 방어일 뿐)·페르소나
  무마스킹(오버라이드에 적은 API 키 복제)·개수 무상한(historyDepth 오버라이드로 JSONB 비대)·비-RAG
  resultPreview 불가시(130 부분 표면화 교훈 재등장). 전부 수정+회귀 핀(V6/V7).
- **마스킹·캡 순서의 불변식 충돌을 테스트가 잡음**: _sanitize(cap)로 대체하자 086 U2("…N자 생략" 정직
  잘림 표기)가 red — 마스킹은 캡 이전에, 잘림은 기존 _cap이 담당하도록 교정. 정직 표기 자체가
  불변식이었다.
- **영속 복원까지 e2e**: fast-worker가 새로고침→세션 재선택→트레이스 복원(D6)까지 검증 —
  deep-reasoner가 지적한 "스트림 전용 필드는 재로드서 누락" 함정을 실측으로 봉인.

## 아쉬운 것 / 리스크
- 새 노출 표면을 만들며 마스킹·상한을 **처음부터 전부 넣지 못하고** codex가 3건을 보완 — "노출 표면
  추가 = 마스킹·자수 캡·개수 상한 셋 다"를 체크리스트로 다음부턴 선반영.
- sentMessages는 히스토리를 trace JSONB에 중복 영속(캡 후에도 최대 ~60KB/턴) — 디버깅 가치와의 의도적
  교환(사용자 철학 반영). 대량 세션에서 실측은 후속.
- 재개 턴 sentMessages N/A 경계(체크포인트 내부) — 인스펙터는 구 트레이스 폴백으로 처리.
