# 359 — 스펙 436 회고(소형): 발행 한 줄 붙이러 갔다가 죽은 오류 경로를 발견

## 무엇을 했나

재인덱싱·평가 런을 이벤트 버스에 합류(publish 5곳+FE 알림 분기). 그 검증이 **선재 실결함**을 적중:
재인덱싱 실행 내부 실패 시 rollback 후 이력 기록이 만료 ORM 속성에 접근해 MissingGreenlet — 이력
누락+오류 누출(스펙 312 이래 잠복). 434의 스칼라 스냅샷을 오류 경로에 재사용해 수리.

## 배운 것

1. **실패 경로는 테스트가 없으면 "동작한 적이 없어도" 무증상이다** — 이 오류 경로는 312 이래 한
   번도 제대로 돈 적이 없었을 가능성이 높다(성공·사전가드 테스트만 존재). 새 기능(발행)을 얹으며
   실패 경로를 처음 실행해본 것이 발견 계기. **경로에 코드를 얹을 때가 그 경로를 처음 걸어볼 기회** —
   얹기 전에 그 경로의 기존 테스트 유무를 확인하라.
2. **rollback 후 같은 세션의 ORM 속성 접근 = 만료 지뢰** — 434(취소·새 세션)와 이번(오류·같은 세션)
   이 한 부류: 세션 상태가 뒤집힌 뒤(취소·롤백)의 정리/기록은 **박제해 둔 스칼라만** 써야 한다.
   두 번 반복됐으니 부류 규칙으로: "except 블록 안에서 ORM 속성 금지 — 스냅샷 사용".
3. **주입 층을 정확히**: 실패 유도를 사전 가드(blob 삭제→400)에 걸었더니 발행 지점을 안 탔다.
   실패 경로 테스트는 **어느 except가 목표인지** 특정하고 그 안쪽에 주입해야 한다.
