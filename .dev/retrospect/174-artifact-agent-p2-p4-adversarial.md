# 회고 174 — 산출물형 에이전트 뼈대 P2~P4 + 적대 검토 (스펙 188)

## 무엇을 했나
P1(뼈대+ask+스텝캐시+slot-fill) 위에 **폼 프레임(P2)·targeting 데모(P3)·artifact 카드(P4)**를 얹어
스펙 188을 완주했다. 사용자의 두 설계 기둥 — (1) produce→artifact→sink **뼈대**(알맹이는 유저 정의),
(2) **이중 입력 일급**(채팅 텍스트 AND 폼이 같은 슬롯에 씀, 병합은 뼈대 소유) — 을 `ProduceContext.form`
+ union 재개봉투 + `_PENDING_ARTIFACT`(formId)로 구현. 둘째 구현(TargetingDemoAgent)이 뼈대 파일 무변경으로
붙어 **누수 0** 측정. 마감은 codex challenge 적대 검토로, 5×P1·2×P2를 실제 코드에 대고 판정해 2 고침·1 하드닝·
3 문서화 경계로 정직화.

## 배운 것 (다음 Context에서 상기·적용될 것)

### 1. "이중 입력"의 진짜 어려움은 **입력 종류가 아니라 확정 시점**이다
텍스트/폼 두 입력을 union 봉투로 받는 배관은 쉬웠다. 어려운 건 **텍스트가 슬롯을 언제 확정하느냐**.
codex가 짚은 "서울 말고 부산" → '서울' 채움은 결정적 substring 병합의 본질적 한계. NLP 부정어 파싱은
범위 밖. 해법은 병합 알고리즘이 아니라 **확정 게이트**: `confirm=True`면 텍스트로 값이 바뀐 뒤 곧장
확정하지 않고 **갱신 프리필로 재제시** → 폼 제출만 최종 확정 경로. 텍스트는 폼을 *돕는* 채널이지
*확정하는* 채널이 아니게 만들면, 퍼지한 텍스트 병합의 오판정을 사람이 잡는다. **교훈: 다중 입력
경로를 지원할 때 "누가 쓰나"보다 "누가 확정하나"를 먼저 설계하라 — 확정 권한을 한 경로(명시 제출)로
좁히면 나머지는 보조 채널로 안전해진다.**

### 2. 적대 검토의 P1이 다 코드결함은 아니다 — **여집합 성공을 경계/결함으로 가르는 판정 노동**이 본체
codex가 5개 P1을 냈지만 실제 코드 대조 후 실결함은 2개(P1-3 pending 소실·P2-2 무확인 확정)뿐. 나머지 3개는
**문서화된 경계**였다: P1-1/2(broker가 호출자 RBAC로 *더* 제약 — 완화 아님, e2e가 publication 강제 확인),
P1-4(스텝캐시 재실행은 프리미티브 멱등성 계약으로 안전 — 서빙 MCP가 강제), P1-5(produce는 신뢰 코드라
닫힌 집합은 규율이지 샌드박스 아님). **판정 방법이 핵심**: 정적 추론만으로 "게이트 없음"을 결함이라 못
박는다 — P1-2의 "publication 미강제"는 내 e2e가 카탈로그 미발행 시 도구 미도달을 **경험적으로 반증**했다
(적대자는 런타임을 못 봐서 정적으로 최악을 가정한다). **교훈: 적대 findings는 (a)실코드 대조 (b)경험적
증거(e2e)로 검증하고, 안전위반 아니면 "경계 문서화(주석+안전불변식 테스트+스펙 OUT)"로 정직화하라 —
고치지도 기각하지도 않는 제3의 처분.** (memory: complement-attack-can-be-honest-boundary 재확인)

### 3. 확정 시점을 바꾸면 **기존 e2e/단위의 완료 흐름 가정이 깨진다** — 테스트도 새 시맨틱으로
P2-2 수정(텍스트→재제시)은 targeting e2e B케이스·verify_188 T케이스가 "텍스트로 곧장 완성"을 단언하던
걸 깼다(초록→빨강). 이건 회귀가 아니라 **의도된 시맨틱 변경**이라, 테스트를 "텍스트 보완→재제시→폼 제출→
artifact"로 갱신했다. **교훈: 확정/완료 조건을 바꾸는 수정은 그 조건을 단언하는 모든 테스트를 함께
갱신해야 한다 — 테스트 빨강이 곧 회귀는 아니다. 어느 게 옳은지(테스트 vs 수정)를 설계 의도로 판정하고,
테스트를 새 계약의 인코딩으로 다시 쓴다.** (스펙 170 default-props-first-render 트랩의 확정-시점 판)
