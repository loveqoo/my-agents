# 238 — 노드형 폼 UX 재검토: 숨긴 기본값이 요약에 떠 거짓 확인 (스펙 263)

## 맥락
사용자: "노드형 설정 UI/UX 다시 검토. 고칠 게 없으면 없다고 해도 됨." — 정직한 판정 여지를 준 요청.
상태 트리(retrospect 229 방식)로 5상태(정체성/빈/채움/요약/모바일360) 캡처 + 오버플로 수치로 검토.

## 무엇을 배웠나

### 1. 표면을 숨겨도 값은 남는다 — 숨김의 짝은 "모든 소비 표면 정렬"
결정 #2로 노드형에서 모델/페르소나 **입력 그리드**를 숨겼지만, `form.model`/`form.persona`엔
blankForm 기본값이 그대로 남아 **요약 카드**(다른 소비 표면)에 1급 정보처럼 재등장했다. 사용자는
정한 적 없는 "모델 mock-llm·페르소나 calm-sre"를 확인 화면에서 보게 됨 = 거짓 확인. 233의 교훈
(숨긴 표면의 데이터는 하위 합집합에서 재구성)과 합치면 **hide-surface 3종 세트**가 된다:
① 입력 표면 숨김 ② 그 표면이 공급하던 계약 재구성(도구 풀 파생) ③ **그 값을 표시하던 하류 표면
(요약·상세·목록)도 같은 분기로 정렬**. ③을 빠뜨렸다 — 메모리 context-control-propagates-to-affordances
("맥락 컨트롤은 하위 어포던스까지 승계")의 표시판 버전.

### 2. 안내 문구는 원인 필드 아래에(인과 순서), 기존 설명과 겹치면 합류
"노드형은 노드마다…" 문구를 옛 모델/페르소나 그리드 자리(종류 필드 **위**)에 뒀더니, 원인(종류 선택)
보다 결과 설명이 먼저 오는 어색한 인과 + 종류 아래 typeDesc와 중복. 처방: 문구 제거하고 고유 정보
("다음 단계에서 추가")만 typeDesc 뒤에 합류. 빈자리를 문구로 채우지 말고, 안내는 그 원인 컨트롤에
붙인다.

### 3. "없으면 없다고 해도 됨"은 부분 판정을 정직하게 하라는 뜻
전부 좋음/전부 나쁨이 아니라 "대부분 양호(근거: 상태별 스샷·오버플로 0 수치) + 결함 2건"으로 판정.
양호 판정에도 근거를 남겨야 재검토가 안 돈다(ui-audit "clean pass도 정직한 산출물" 규율).

### 4. 검토는 상태 트리로 — 요약 상태가 아니면 못 봤다
결함 1은 **요약 단계**에서만 보인다. 채움 상태만 캡처했으면 놓쳤다(229: 화면 목록 1층 순회의 사각).
위저드는 단계마다 별개 상태 — 전 단계 + 모바일까지 도는 게 검토의 최소 단위.

## 결과
AgentForm 3곳 수정(표시만): 요약 정직화(모델·프롬프트=노드마다 설정 + 처리 단계에 노드별 모델 병기),
안내 문구 합류. 재캡처 육안 + 왕복 무회귀 그린 + tsc 0.
