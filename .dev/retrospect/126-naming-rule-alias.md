# 126 — 스펙 148: 네이밍 규칙 + 식별 이름/별명 분리 회고

## 무엇을 했나
5종(에이전트·RAG·페르소나·권한·MCP)에 name=식별 이름(규칙 `^[가-힣a-z0-9.\-]+$`, 참조 키)·
alias=별명(자유 표기) 분리. 마이그레이션이 기존 데이터 자동 변환+config/casbin 참조 재작성.
원격 유래는 거부 대신 slugify+원문 별명. 검증 verify 45/45·e2e 6/6·codex High3/Med3/Low2 중 6건
수정. 이후 사용자 요청으로 데이터 초기화(스키마 드롭→재시드→샘플 재적재→qwen 재등록).

## 설계가 사용자에게서 왔다 (147에 이어 반복되는 패턴)
원래 스펙은 "이름 하나에 규칙"이었다. 구현 착수 직후 사용자가 "잠깐만요" 후 식별/별명 2원화를
제시 — 규칙과 한글 표기의 긴장("옵시디언 매니저"를 버려야 하나?)을 스펙이 강제 개명으로 풀려던
것을, 사용자는 축 분리로 풀었다. **규칙이 기존 이름과 충돌할 때 선택지는 '개명 강제/grandfather'
둘만이 아니다 — 축을 쪼개면 둘 다 산다.** 열린 질문(한글 공백)을 스펙에 남겨둔 것이 이 재설계를
불러온 트리거였다(질문을 지웠으면 강제 개명으로 밀고 갔을 것).

## 핵심 결정: 별명을 새 컬럼으로, name은 그대로 참조 키
에이전트 config가 자원을 **이름 문자열**로 참조하므로, 표시명을 새 컬럼으로 빼고 name에 규칙을
걸면 (1) 참조 해석 코드 무변경 (2) 자유 개명(별명)이 참조를 못 깨게 됨 — 기존 취약이 오히려 해소.
반대 방향(name=표시, slug 신설)이면 참조 해석 전부를 이중화해야 했다.

## codex가 잡은 것 — "이름 규칙 스펙"은 사실 "참조 무결성 스펙"
- **마이그레이션 dedupe 순서**: "docs_kb"/"docs-kb" 공존 시 collation에 따라 비준수 행이 준수 행
  이름을 선점 → 참조가 엉뚱한 행으로. 준수 행 우선 처리로 수정. (우리 DB엔 충돌 케이스 없음을
  실측했지만 로직은 바로잡음 — 순서 의존 변환은 순서를 명시하라.)
- **페르소나·권한 rename/삭제 무가드**: MCP만 가드(093)가 있었다. 규칙 위반 이름을 *개명으로
  교정*하는 흐름이 생기는 순간, 개명이 참조를 깨는 경로가 주 경로가 된다 — 규칙 도입이 기존
  구멍의 위험도를 올린 것. references.py 닫힌 집합에 permissions·persona(스칼라) 추가.
- **capabilities 축 구조적 누락**: 조율형은 mcps가 비고 capabilities("mcp:서버/툴")로 참조 —
  가드·usedBy가 둘 다 못 봤다. 닫힌 집합을 만들 때 **같은 자원을 가리키는 모든 표기법**을 세야
  한다(스펙 124의 "rag: 이중 배선"과 동형 — 같은 함정 세 번째).

## e2e 함정: 스펙끼리 상호작용
K1 첫 FAIL — e2e fixture(신규 super 계정)에게 "옵시디언 매니저"는 *타인 private*(147 정책)라 기본
숨김. 검증 대상(148)이 아니라 직전 스펙(147)이 원인. fast-worker가 DB 실측으로 원인을 찾고 필터
opt-in으로 보정 — 미검증 가설 없이 실측 먼저 원칙이 서브에이전트에도 이식됐다.

## 데이터 초기화가 드러낸 것
ingest_rag_samples.py가 스펙 128(문서 목록 페이지네이션) 이후 응답 모양 변화를 반영 안 해 죽어
있었다 — **가끔만 도는 스크립트는 API 모양 변화에 조용히 썩는다**. 초기화·재구축 같은 통합 rung을
실제로 밟아야 이런 drift가 드러난다(verification-ladder의 통합 rung 역할 재확인).
초기화로 함께 날아간 것 중 시드가 복원 못 하는 것(qwen provider·기본 모델)은 .env 값으로 API 재등록
— **초기화 전 "시드 밖 상태" 목록**(provider/모델·업로드 문서·casbin 부여)을 먼저 세는 게 맞았다.

## 다음에 적용
1. 이름/식별자 스펙은 참조 무결성 체크리스트(RBAC 스펙의 입구 열거처럼)로 시작: 이 이름을 담는
   필드 전부(배열·스칼라·접두 표기·정책 저장소)를 닫힌 집합으로 먼저 센다.
2. 순서 의존 데이터 변환은 정렬 기준을 코드에 명시(암묵 collation 금지).
3. 초기화/재구축 전에 시드가 복원 못 하는 상태를 목록화하고 복원 계획을 같이 낸다.
