# 250 — 노드 카드 접기: 선례가 설계 결정을 다 미리 내려줬다 (스펙 275)

## 맥락
사용자 요청("노드를 아코디언처럼 접고 펼 수 있으면, 접으면 헤더에 설정 요약") → 노드가 2~3개만
돼도 카드가 길어 파이프라인 전체 흐름이 안 보이는 문제. antd Collapse(노드당 1아이템)로 접기,
접힘 헤더에 이름+요약(모델·도구/문서/기억 수·비기본값·프롬프트 앞부분)+미완성 "작성 필요" 태그.

## 발견과 교훈

### 1. 축적된 선례가 새 기능의 설계 결정을 선결해 준다 (복리의 설계판)
이번 기능의 결정 대부분이 **기존 자산에서 바로 나왔다**: 접이식 컴포넌트 선택 → admin/CLAUDE.md
규칙(접이식=Collapse), 헤더 클릭 오토글 위험 → 스펙 123 함정이 `collapsible="icon"`을 즉시 지목,
요약 줄 오버플로 → 모바일 감사 규율이 ellipsis+측정을 기본값으로, e2e 셀렉터 → 249의 v6 DOM 교훈.
설계 고민 시간이 거의 0 — **회고·규칙이 쌓이면 새 기능은 "결정"이 아니라 "조회"가 된다.**

### 2. 접힘은 정보를 숨기므로, 게이트 원인은 접혀도 보여야 한다
저장 게이트(pipelineValid)가 프롬프트/모델 빈값을 막는데, 접힌 노드는 그 error status가 안 보인다
— 접기 기능이 **기존 게이트의 가시성을 깨는 부수효과**. 처방: 접힘 헤더에 "작성 필요" 빨간 태그.
**규칙: 정보를 접는 기능을 넣을 때, 접히는 것 중 "사용자가 지금 행동해야 하는 신호"(검증 오류·
경고)가 있는지 스캔하고 헤더로 승격하라.** (요약은 편의, 오류 승격은 필수.)

### 3. 펼침 상태 같은 UI 로컬 상태는 인덱스 키의 이동/삭제 재매핑까지가 한 세트
노드 식별자가 없어 인덱스 키로 펼침을 관리 — 이동(스왑)·삭제(시프트) 시 키 재매핑을 같이 안 하면
"3번을 접었는데 2번이 접힌다". add/remove/move 각각에 setOpen 재매핑을 붙였다. **배열 인덱스를
UI 상태 키로 쓰면 배열을 바꾸는 모든 연산에 키 변환을 페어로** — 하나라도 빠지면 조용히 어긋난다.
