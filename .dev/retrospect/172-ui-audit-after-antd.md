# 172 — antd 통일 후 전수 UI 감사 (+하네스 닫기 견고화)

**스펙**: docs/spec/187 후속 검증 · **관련**: 169(감사 하네스)·169-회고(Drawer 채택)·166(셀렉터 함정)

## 무엇을 했나
사용자 요청("UI 테스트 해봅시다")으로 스펙 169 전수 감사 3축 실행. 최종: **화면 42/0 · 오버레이
14/14(NAV 0) · 시나리오 7/0 — FAIL 0**. 중간에 오버레이 하네스의 닫기 로직이 구 커스텀 Drawer에
결합돼 있던 걸 발견·견고화.

## 무엇이 잘못됐고 무엇을 배웠나

### 1. "종합 ok"에 커버리지 붕괴가 숨어 있었다 — NAV 실패는 통과가 아니라 미검사
첫 실행 종합은 초록("기계 감사 3종 중 FAIL 0")이었지만 상세에 "오버레이 14건 중 **NAV 실패 11**" —
11개는 열지도 못해 검사 자체가 안 됐다. FAIL 0의 분모가 3이었던 것. 오케스트레이터는 navOk=false를
fail로 안 세서 침묵 통과.

- **처방**: 스코어카드를 읽을 때 **분모(실제 검사 건수)**를 확인하라. "실패 0"은 "전부 통과"가 아니라
  "검사된 것 중 실패 0"이다. NAV/스킵/타임아웃 카운트가 있으면 그게 곧 미커버리지.
  [[no-silent-caps]]·[[probe-deeper-before-concluding]]의 감사판.

### 2. 하네스가 구 구현의 **부수 성질**에 결합돼 있었다 — Escape의 리스너 위치
근인: 하네스는 오버레이를 Escape 연타로 닫았는데, 구 커스텀 Drawer는 **document 레벨** keydown
리스너라 포커스 무관하게 닫혔다. antd Drawer는 **패널 포커스 기준**이라, 모달 닫힘 애니메이션·포커스
복원(300ms 대기와 경합)이 끝나기 전 두 번째 Escape가 body로 새면 드로어가 살아남는다. 페이지를 전
뷰포트가 재사용해 잔여 `.ant-drawer-mask` 하나가 이후 11건을 전부 막았다(오염 전파).
**앱 버그 아님** — 실사용자는 포커스가 드로어 안에 있고 마스크 클릭 닫기도 있다.

- **처방**: 컴포넌트 구현 교체 후 테스트/하네스의 **상호작용 가정**(Escape 리스너 위치·포커스 의존·
  애니메이션 타이밍)을 재점검하라. 수정은 타이밍 튜닝이 아니라 **의존 제거**로: 포커스 무관한
  "닫기 버튼 클릭 루프"(잔여 오버레이 0까지, 최대 5회)로 교체. [[suspect-selector-not-app-when-screenshot-ok]]의
  자매 — 이번엔 셀렉터가 아니라 키 이벤트 전달 모델.

### 3. 상태 공유 하네스는 실패 하나가 뒤를 오염시킨다
한 페이지를 14개 오버레이 × 2 뷰포트가 공유 → persona-edit 하나의 닫기 실패가 나머지 11건의 NAV를
연쇄로 죽였다. 실패 지점(1건)과 증상 지점(11건)이 달라 근인 추적이 한 겹 더 필요했다(첫 증상인
"close 아이콘이 햄버거 가로챔"은 원인이 아니라 잔여 드로어의 그림자).

- **처방**: 공유 상태 하네스에서 다발 실패가 나오면 **첫 실패 지점**부터 보라(이후는 오염일 수 있음).
  설계 시엔 항목 간 "깨끗한 상태 복구"(닫기 루프)를 항목 종료 조건으로 넣어 오염을 차단.

## 복리 포인트
- antd 통일(186·187)이 전수 감사 3축 그린으로 종결 — 회귀 3종+감사 3축의 이중 그물 확립.
- 하네스 닫기 루프가 구현 무관(antd/커스텀/Inspector 폴백)이 되어 다음 컴포넌트 교체에도 견딤.
