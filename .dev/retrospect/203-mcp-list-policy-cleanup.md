# 회고 203 — MCP 리스트·정책 정리: 사용=공용 + 컬럼 분리 + published 축소 (스펙 211)

## 무엇을 했나
사용자 UI 배치 2·3·4·5·6번. (1) MCP "사용(배선)" 게이트(agent_may_wire·_wiring_owner_privileged·
stored_mcps confused-deputy 분리) 제거 → 등록 MCP는 누구 에이전트든 배선(사용=공용, RAG 172 동형).
(2) published를 "커스텀 외부 서빙" 전용 축으로 축소(생성/수정/publish 3입구 non-custom=400). (3) 리스트
컬럼 분리(이름+🔒/유형/소유/외부 서빙, 상태 제거)·드로어 이름 중복·status 제거(fast-worker 위임).
검증=verify_211 15/15(사용=공용·publish 3입구·서빙 불변·자가잠금)·verify_152 11/11(계약 갱신+부채 2건)·
verify_156 9/9 무회귀·codex 적대(P2 1건 수리)·브라우저 10/10.

## 배운 것

### 1. 정책 완화는 "완화가 여는 새 표면"을 적대 검토로 먼저 봐야 한다 — codex가 크레덴셜 유출을 짚음
"사용=공용"은 RAG(172)에서 안전했지만 MCP엔 **auth 토큰**이 있어 의미가 달랐다: 타인이 크레덴셜 MCP를
배선해 "토큰 에코"류 도구로 토큰을 회수(codex P2). 나는 RAG 선례를 그대로 적용하며 이 차이를 못 봤다.
**교훈: 같은 정책을 다른 자원에 복제할 때, 그 자원만의 속성(크레덴셜·부수효과)이 만드는 새 공격면을
따로 센다. 적대 검토(codex)를 "완화가 열면 안 되는 문의 여집합"으로 돌려 사용자 결정 전에 표면화.**
사용자에게 트레이드오프를 물어(전부 공용+마스킹 택함) 직접 MCP 결과에도 _sanitize_preview 적용(브로커/
RAG와 한 경로로 통일 — 구 _cap은 마스킹 없었음).

### 2. 계약을 뒤집는 스펙은 "그 계약을 검증하던 자산"을 완료 기준에 넣어야 한다 (회고 202 재확인)
게이트 제거로 verify_152의 V1c(local publish 정상)·V6(external 오염 행 배선 차단)가 구계약이 됐다.
V6는 특히 **사용자 요청 #3(외부 등록 MCP 공동 사용)이 명시적으로 제거를 원한 게이트**를 지키고 있었다 —
"stale 테스트"가 아니라 "정책이 바뀐 테스트". 갱신하며 백로그에 있던 부채(V4 code→400, 스펙 154로 낡음)도
같이 청소해 11/11. **교훈: 실패한 구계약 단언은 "버그 vs 정책변경"을 코드로 판별하라(자가판단 금지) —
V6는 사용자 의도가 진실원이라 '차단'을 '허용'으로 뒤집는 게 옳았다.**

### 3. 재공개 봉인은 "서빙"과 "사용" 두 축 — 하나를 열어도 다른 하나는 닫힌 채로
152의 external 재공개 봉인은 **서빙**(_is_served=custom 전용)에서 유지하고, **배선(사용)**만 공용으로 열었다.
codex도 서빙·관리 게이트는 "없음(안전)"으로 확인. **교훈: "공개"가 여러 역할을 겸하면(사용 공유 vs 외부
서빙) 축을 분리해 하나만 완화한다 — 둘을 한 플래그로 묶으면 하나 풀 때 다른 하나가 딸려 열린다.**

## 다음에 적용
