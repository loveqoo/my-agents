# 회고 224 — 설계 순서는 집중→가림→배치: 레이아웃 진단부터 시작한 두 번의 헛발 (스펙 247)

## 무엇을 했나
사용자 "복잡한 UI 개선, 어디로 예상?" → 승인 화면 예측(측정 근거) → 빗나감(플레이그라운드).
스샷 진단 6건 제시 → 다시 빗나감. 사용자 교정: "레이아웃은 가장 나중 문제 — 먼저 무엇에 집중,
다음 무엇을 가림." 자료 학습(NN/g progressive disclosure·visual hierarchy·Apple HIG 초점 1개) 후
집중 모델 합의: 대화 모드=주 과업(개선 루프 작업대), 계측은 상시 유지, 헤더는 에이전트만 노출.
구현: 설정 6종을 "대화 설정" 팝오버로, 신호 배지(미리보기·오버라이드·A2A)만 헤더에.

## 배운 것

### 1. UI 진단의 순서는 ①이 화면의 주 과업은 무엇인가 ②그것을 방해하는 게 무엇인가 ③배치 — 역순은 두 번 빗나간다
복잡도 수치(측정)로 승인을 예측했고, 스샷에서 밀도·정렬(배치 층)을 짚었지만 둘 다 사용자의 문제
의식과 어긋났다. 사용자가 본 것은 "초점 없음"(대화와 계측·설정이 항상 동시에 켜져 경쟁). 측정과
스샷은 증상을 주지만, **주 과업 정의 없이는 어떤 증상이 문제인지 판정할 수 없다.**

### 2. 도메인 표준 자료를 먼저 읽는 게 논의를 압축한다 — 사용자가 시킨 이유
NN/g(위계 없는 화면=과업 시간 2배, "무엇이 처음부터 필요한지 알아야 숨길 수 있다")·HIG(화면당
초점 1개)를 읽고 나니 사용자의 두 문장이 정확히 그 문헌의 요약이었고, 이후 논의가 두 번의
AskUserQuestion으로 끝났다. UX류 개편은 구현 전에 표준 문헌 한 바퀴가 싸다.

### 3. 내 추천이 기각된 두 지점이 사용자 모델을 드러낸다 — 기록 가치가 높다
①계측 숨김 추천 기각 → "계측 상시"(플그=정밀 디버그 채널, 확인이 루프의 절반). ②런처 개편 기각 →
"상단 설정 유지, 노출만 좁히기"(구조 변경 최소·가림 우선). 기각된 제안은 실패가 아니라 사용자
설계관의 측정값 — 다음 제안의 사전 확률을 바꾼다.

## 다음에 적용
- UI 개선 요청 → 첫 질문은 "이 화면의 주 과업이 무엇인가"(측정·스샷은 그 다음).
- UX 개편 전 표준 문헌(NN/g 등) 선행 학습을 관행으로.
- 기각된 추천을 회고에 기록(사용자 설계관 축적).

## 추기 2 (사용자 교정 — "자동 선택은 노출되어야, 인지의 관점")

### 4. 컨트롤 가림과 상태 가림은 다른 문제다 — 자동화가 늘수록 상태 표시는 오히려 늘어야
설정을 팝오버로 가리면서 "기본과 다를 때만 배지"로 상태까지 가렸다. 사용자 교정: 스마트 자동 선택
(에이전트·버전·경로·세션)이 많아질수록 **무엇이 선택됐는지가 항상 보여야** 한다 — 숨은 상태는 인지
불확실성("지금 뭘로 대화 중이지?"). 처방=상시 조건 표시줄(조용한 텍스트, 이상값만 색, 클릭=변경 입구).
**규칙 정정: "다를 때만"은 경고의 규칙이고, 현재 유효 상태는 항상 조용히 표시한다.** 자동화 기능을
넣을 때마다 "이 자동 결정이 어디에 보이나"를 짝으로 설계할 것.
