# 128 — 스펙 150: 기본 모델 전환 회고 (자율 루프 1건차)

## 무엇을 했나
실사용 버그 #1: 기본 chat/embedding 전환이 "삭제 후 재등록"으로만 가능(등록 모달에만 스위치,
mock 임베딩은 컬렉션 RESTRICT로 삭제 불가 → 사실상 잠김). PUT /models/{id}/default 전용 라우트 +
기본 요약 배너 + 행별 "기본으로 지정". verify 12/12·e2e 4/4·codex High2/Med3/Low1 → 6건 수정.

## 버그의 실체는 "상태 비가시 + 전환 동선 부재"
백엔드는 처음부터 전환을 지원했다(PUT is_default 배타 처리). 사용자가 겪은 "어려움"은 (1) 지금
뭐가 기본인지 어디서도 안 보이고 (2) 등록 이후엔 누를 버튼이 없다는 것. 기능 부재가 아니라
**가시성 부재가 버그로 보고되는** 패턴 — 배너(상태 표시)가 수정의 절반이었다.

## codex가 잡은 것 두 겹
- **불변식은 앱 로직이 아니라 DB에**: `_clear_other_defaults`는 배타를 "노력"할 뿐 동시 요청이면
  기본 2개가 가능. 부분 유니크 인덱스(kind WHERE is_default)로 봉인 — 그런데 **인덱스는 문장
  단위 검사**라 해제→지정이 한 flush에 섞이면 자기 트랜잭션과 충돌한다(verify가 즉시 잡음).
  해제를 먼저 flush해서 해결. *DB 불변식을 추가하면 정상 경로의 문장 순서도 재점검하라.*
- **신설 라우트만 잠그면 우회가 남는다**: 기본 전환에 게이트를 달자는 지적의 본질은 "기존
  PUT /models로도 is_default를 바꿀 수 있다"는 것. 게이트는 **표면(라우트)이 아니라 능력(기본
  변경)** 단위로 — models/providers 변이 전체에 관리 게이트(installed-guard≠covering-guard의
  라우트판).

## 자율 루프 1건차 관찰
사람 개입 없이 스펙→구현→verify→e2e(fast-worker)→codex→수정→재검증→회고까지 완주. e2e는
실 DB 기본을 왕복시키므로 **원복을 검증 항목으로 명시**(K4)한 것이 주효 — 파괴적이지 않아도
전역 상태를 만지는 e2e는 원복까지가 스펙이다. 수정 후 e2e 재실행도 스크립트 재활용으로 3분.

## 다음에 적용
1. "X가 안 된다" 보고는 기능 부재 전에 **상태 가시성**부터 의심(배너/표시가 반).
2. 배타·유일 불변식은 DB 제약으로 + 정상 경로 문장 순서(flush) 동반 점검.
3. 전역 상태를 만지는 e2e는 원복을 검증 항목(K)으로 명시.
