# 254 — 폼 흐름 3종: 사용자 확인 질문이 지시를 정정했고, "같은 Collapse"의 뜻을 한 번 틀렸다 (스펙 279)

## 맥락
사용자 UI 집중 수정 3건: ①종류를 이름·설명 바로 뒤로(종류가 모델·페르소나의 위치를 결정) ②비영속이면
단기/장기 모두 잠금+제거 ③도구·문서를 같은 Collapse로+승인 오버라이드를 사이에(도구 선택 시 노출).

## 발견과 교훈

### 1. 사용자가 "제가 오해한 것 같다"고 물으면 — 지시보다 사실이 우선이다
②를 구현하던 중 사용자가 "비영속일 때도 최근 메시지 N개를 제공할 수 있나? 오해한 것 같다"고 확인
질문. **측정으로 답**: 단기(historyDepth)는 요청에 담겨 온 body.messages를 자르는 실행 창
(chat.py:1114 `_window`)이라 DB 저장과 무관 — 비영속에서도 동작(스펙 238의 원 결정이 옳았음).
직전에 넣은 단기 잠금을 되돌리고 장기만 잠금+제거로 확정. **교훈 두 겹**: ⓐ지시가 도메인 오해에
기반했을 수 있음을 사용자 스스로 알아챌 수 있게, 이상하면 근거를 되물을 여지를 남겨라(이번엔
사용자가 먼저 물었지만, 내가 238 주석과 상충을 알아채고 먼저 확인했어야 — 옛 주석이 "비영속에도
활성"이라 적혀 있었다). ⓑ**지시 이행 중에도 코드의 기존 결정과 충돌하면 멈추고 사실 확인** —
251 ①("사용자 단정을 코드로 반증")의 지시판.

### 2. "같은 Collapse로 묶어라"의 두 가지 해석 — 구조 요구는 스케치를 받아라
③을 "Collapse 패널 하나에 세 구획을 다 넣기"로 구현했더니 반려 — 원한 것은
**`Collapse(Item, Item, Item)`**(형제 아이템, 각자 접힘·아코디언 그룹으로 밀착). 별개 Collapse 쌓기
=뉴라인, 한 패널=구획 소실, 형제 아이템=정답. 사용자가 처음 메시지에 이미 `- 도구 / - 승인 / - 문서`
불릿 구조를 그려줬는데 내가 "한 덩어리"로 뭉뚱그렸다. **구조(레이아웃) 지시는 항목 나열이 곧
스펙** — 불릿 하나 = 컴포넌트 아이템 하나로 읽어라.

### 3. 순서 변경은 위치-의존 셀렉터를 깬다 (252 ③의 순서판)
①로 종류가 모델 앞에 오자, `div-has('모델')...first()` 패턴이 **바깥 컨테이너**(첫 Select=종류)를
집어 세 테스트(279 자신·276·277)가 종류 드롭다운을 오클릭. div-has 패턴에서 `.first()`=최외곽,
`.last()`=최내곽 — **필드용은 항상 `.last()`**. 위젯 교체(252)뿐 아니라 **순서 변경도** 형제
셀렉터를 깬다.

### 4. antd v6 클래스 표본 추가: Collapse 패널 = `.ant-collapse-panel`
`.ant-collapse-content`가 v6에 없다(빈 배열) — 249(단일 Select=.ant-select-content)에 이어 두 번째
표본. **v6 셀렉터는 관례 말고 outerHTML 프로브로 확정**이 이제 규칙.
