# 회고 216 — 근본 모드는 1급으로, 금지는 경고가 아니라 disabled로 (스펙 238)

## 무엇을 했나
사용자 UI 리뷰 5건 일괄 반영: 영속/비영속 상단 Segmented 승격(기본 영속)·금지 항목 disabled(큰 Alert
제거)·종류 rich select(optionRender)·오버라이드 폼 정합(read-only 태그+동일 잠금)·에이전트별 추천
명령어(config.suggestedPrompts, 캡 8×200). codex 5건 중 2건(편집폼 기억 그룹 누락·stale disabled+checked)
을 미선택-잠금 패턴으로 봉합.

## 배운 것

### 1. 설정의 "무게"가 배치를 정한다 — 근본 모드를 부가 설정에 묻으면 그 자체가 UX 버그
비영속은 에이전트의 존재 방식(세션·이력·기억 전부)을 가르는 모드인데 세부 설정 접힘 속에 넣었다.
사용자: "매우 큰 변화 → 상단 1급 정보". 필드를 어디 둘지는 구현 편의(관련 필드 옆)가 아니라 **결정의
영향 반경**으로 정해야 한다. 기본값 명시(영속 (기본))도 1급 정보의 일부.

### 2. 금지는 사후 경고가 아니라 사전 어포던스 잠금 — 놀래키는 UI는 실패한 설계의 자백
"선택하게 해놓고 큰 경고로 막기"는 (a)무효 상태를 만들 수 있게 한 개발 실수 + (b)사용자를 놀래키는
경험, 두 번 나쁘다. 올바른 순서: **불가능한 조합은 아예 선택 불가(disabled+한 줄 사유)**, 경고 Alert는
어포던스로 못 막는 경우의 최후 수단. 236의 mock Alert도 같은 원칙으로 보조 문구로 강등.

### 3. 미선택-잠금 패턴 — disabled는 "새 진입"만 막고 "기존 상태 탈출"은 열어둔다
금지 항목을 그냥 `disabled: 조건`으로 하면 이미 선택된 항목이 disabled+checked로 고착(해제 불가 —
237의 "숨기면 해제 불가"와 동형 함정, codex가 오버라이드 stale applied에서 적발). 처방:
`disabled = 조건 && !선택됨`. 새로 켜는 건 잠그되 남은 선택은 언제나 해제 가능. 상태 전환(자동 해제)과
조합하면 정상 흐름에선 잠금만 보이고, 비정상 잔존 상태에서도 탈출구가 있다.

### 4. 같은 규칙은 같은 턴에 모든 표면으로 — 편집 폼을 고치면 오버라이드 폼이 따라와야
스펙 122(편집 폼만 kind-aware로 고치고 오버라이드 누락)의 재발을 사용자가 선제 지적("긴밀하게 연동").
게이트/잠금/표시 규칙을 바꾸면 그 설정이 노출되는 **다른 폼(오버라이드·복제·상세)**을 체크리스트로 —
그리고 "바꿀 수 있는 것/없는 것"을 오버라이드 폼에 명시(read-only 태그)하는 것까지가 연동이다.
codex #1도 정확히 이 축(편집 폼 안 직접형 기억 그룹만 누락)을 짚었다. [[context-control-propagates-to-affordances]].

### 5. 고정 UI 조각(추천 명령어)은 에이전트 데이터로 — 폴백을 남기면 무회귀 확장
하드코딩 3종 카드를 config.suggestedPrompts로 대체하되 미등록 시 기존 폴백 유지 — 기존 에이전트 무영향.
새 config 필드는 이제 3번째 반복(persistHistory→ephemeral→suggestedPrompts): grep으로 배선점 열거가
루틴으로 정착(스키마 2·직렬화·타입 2·매핑 3·blankForm).

## 다음에 적용
- 새 설정 필드 배치: 영향 반경 큰 모드는 상단 1급, 파생 세부만 접힘 속으로.
- 무효 조합은 disabled(+미선택-잠금)로 사전 차단, Alert는 최후 수단.
- 폼 규칙 변경 시 오버라이드·복제 등 자매 표면 동시 반영 + 불변 항목 read-only 명시.
