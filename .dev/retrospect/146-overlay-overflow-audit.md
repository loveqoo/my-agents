# 146 — 드로어·모달 오버플로 감사 (축2 확장) (스펙 168)

백로그 후속: ui-audit(스펙 165)가 top-level만 봐서, 오버플로 숨기 쉬운 오버레이(모달·드로어)로 확장.

## 한 것
`ui-audit-overlays.mjs` — ui-audit의 MEASURE 재사용, 7 오버레이(생성 모달·상세 드로어·페르소나 편집·
컬렉션/프로바이더 생성·오버라이드/인스펙터 패널) × 2 뷰포트(360/1280) 열고 측정·스크린샷. 생성 모달은
열기만(엔티티 0). fast-worker 기계 구동, 메인 트리아지.

## 결과
14/14 열림·**FAIL 0**. 오버레이 전부 반응형(모바일서도 필드 세로 스택·URL 잘림+복사, 가로 넘침 0).
육안 재확인(모바일 생성 모달·상세 드로어 clean). 스펙 167 카피 수정("실제 호출 기능은 준비 중")도
상세 드로어서 실반영 확인(감사끼리 상호검증 연장).

## 배운 것
- **clean pass 연속도 정보다** — 축1(시나리오)·168(오버레이) 둘 다 clean. top-level(165)에서 batch 1건,
  카피(167)에서 12건이 나왔으니 감사가 관대해서가 아니라 **그 축은 실제로 건전**. "어디가 성하고 어디가
  약한지"의 지도가 생긴다(약점=반응형 테이블·카피 누출, 강점=오버레이·핵심 여정).
- **테스트 인프라 함정도 자산화**(learning 142): antd 아이콘 버튼은 접근성 이름이 `"edit 편집"`이라
  `exact:true` 매칭이 깨진다. fast-worker가 우회하며 발견 → 다른 스크립트도 물릴 사실이라 learning으로.
  모바일 DataTable=카드 렌더(table 셀렉터 0건)도 형제 함정. **감사가 제품뿐 아니라 감사 도구의 함정도 노출**.
- **소프트 UX 경계는 코드 수정 대신 보고+백로그**: "모바일서 현재 메뉴 재탭 시 사이더 백드롭 안 닫힘"
  (controlled Menu onSelect가 같은 key 재발화 안 함)은 실동작 경계 — 하네스는 우회, 제품 수정은 사용자
  판단 영역이라 백로그로. 감사가 범위를 넘어 UI를 고치러 들지 않게(과잉 억제의 반대편 규율).

## 검증
ui-audit-overlays 실행 14/14·FAIL 0·엔티티 변동 0(생성 안 함). 스크린샷 육안(모바일 모달/드로어 clean).

## OUT
- 세로 잘림/스크롤. 중첩 드로어. 저장 후 상태 오버레이. 모바일 메뉴 재탭 백드롭(백로그). 감사 커맨드화.
