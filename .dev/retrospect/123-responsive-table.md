# 123 — 회고: 반응형 테이블 (스펙 145 — 144의 오답 교정)

## 무엇을
사용자 재보고: "가로 스크롤이 아니라 **모든 폭에서 잘 보이는 반응형**". 공유 DataTable을
tableLayout:'fixed'(컬럼이 폭을 나눠 갖고 내용이 줄바꿈 — min-content가 표를 못 늘림)로,
카드 스택 전환점 md(768)→lg(992) 상향(컬럼 많은 표가 비좁은 태블릿 구간은 카드),
AgentsView 고정폭 5개 제거. 전 메뉴 표 수혜.

## 잘못한 것 (144의 오독)
- "최대한 다 보여야"를 "컬럼을 숨기지 말라"로만 읽고 **가로 스크롤을 해법으로 착각** —
  스크롤은 "숨겨진 걸 밀어서 보기"지 "다 보임"이 아니다. 사용자가 재보고하고서야 교정.
  **UX 피드백의 명사(테이블·컴포넌트)가 아니라 목적어(다 보임)를 구현 기준으로.**
- 1차 수정(overflowWrap만)도 불충분 — e2e 실측이 즉시 반증(intrinsic 890px: 고정폭 합
  636 + table-layout:auto의 min-content는 텍스트 줄바꿈으로 안 줄어든다).

## 잘된 것
- e2e가 **실측값(scrollWidth/clientWidth diff)** 으로 판정 — "보기에 괜찮음"이 아니라 숫자.
  중간 폭 2건 실패가 근본 수정(tableLayout fixed)을 강제했다.
- fast-worker가 숨은 tabpanel 오검출(거짓 통과)을 스스로 발견·스코프 수정 — 측정기도 검증 대상(136).

## 기술 지식(재사용)
- 표를 컨테이너에 맞추려면: tableLayout:'fixed' + 셀 overflowWrap. auto 레이아웃에선 고정폭
  합과 비텍스트 요소(Avatar/Tag/Switch)의 min-content가 intrinsic 하한을 만든다.
- 반응형 표의 3단계: 넓음=표 / 중간(lg 미만)=카드 스택 / 좁음=카드 스택(동일) — "숨기지도
  밀지도 않는다".
