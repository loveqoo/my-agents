# 회고 215 — "구조적으로 불가"는 추론이 아니라 실측이다: 235의 가정을 237이 밟아서 반증 (스펙 237)

## 무엇을 했나
비영속 도구 경계(사용자 결정: DB 쓰기 도구만 금지 — memwrite/memedit 422, MCP·RAG 허용). 3층 게이트
(저장 422 + 런타임 필터 + 승인 명시 에러)로 구현. 구현 중 승인형 도구를 비영속으로 **직접 트리거**해
보니 235의 "체크포인터 없으면 interrupt 구조적 미도달" 가정이 반증 — Approval·세션 행이 실제로 쓰였다
(계약 위반 실경로). codex 4건 중 1건(버전 승격 게이트 밖) 수정, 3건 문서화 경계.

## 배운 것

### 1. "구조적으로 불가"라는 주장은 그 경로를 실제로 밟아 실측해야 한다 — 추론 일치는 증거가 아니다
235에서 codex도 나도 "체크포인터 없음 → interrupt 불성립 → approval 미도달"에 동의했고, verify_235
E6(approvals Δ0)도 초록이었다. 그러나 E6은 **승인형 도구를 트리거하지 않은** 에이전트로 잰 vacuous 0
(회고 213 배움 2의 함정을 스스로 반복). 237에서 승인형 도구를 직접 쏘자 즉시 반증 — interrupt는
체크포인터 없이도 발생한다. **"불가" 주장 검증 = 그 불가능하다는 행위를 실제로 시도하는 테스트.**
[[probe-deeper-before-concluding]] · 추론이 여럿 일치해도(자기+codex) 같은 근거 위면 같은 사각.

### 2. 부재 단언(Δ0)의 대조군은 "그 신호를 낼 조건"까지 갖춰야 한다 — 세 번째 재발이면 장치로
213(체크포인터 미초기화 vacuous)·이번(승인 도구 미트리거 vacuous). 같은 함정 2연속 = 다음엔 리뷰 관행:
**Δ0 단언마다 "이 카운터를 올리는 조작을 대조군이 실제로 수행하나?"를 테스트 주석에 명기**(verify_237
T5는 트리거를 직접 쏘고 에러 문구라는 양성 신호로 게이트 발화를 증명 — 0 단독이 아님).

### 3. 금지 경계는 "닫힌 입구 목록"으로 — 주 CRUD만 막으면 승격 경로가 샌다
create/clone/update에 게이트를 달았지만 codex가 activate/revert(버전 승격)를 짚음 — 과거 버전 승격이
게이트 밖이면 "저장 상태로 존재 불가" 불변식이 깨진다. RBAC 체크리스트의 "입구 열거(닫힌 집합)" 원칙이
소유권만이 아니라 **모든 저장 불변식**에 적용됨을 확인. config가 서빙 상태로 승격되는 지점 전부에 같은
게이트.

### 4. UI에서 항목을 숨겨서 금지하면, 이미 선택된 항목의 해제 수단도 같이 사라진다
비영속 ON 시 "기억에 저장" 항목을 피커에서 숨겼더니, 먼저 선택하고 나중에 비영속을 켠 경우 해제
어포던스가 소멸(경고는 "해제하라"는데 해제할 수 없는 자기모순). **숨김 조건에 "미선택"을 포함** —
선택돼 있는 동안은 노출해 해제 가능하게. 금지 UI는 (a)신규 진입 차단과 (b)기존 상태 탈출 보장이 별개.

## 다음에 적용
- "X는 구조적으로 불가/미도달" 주장이 나오면 그 X를 시도하는 테스트를 짝으로 요구(추론 금지).
- Δ0 단언 테스트엔 카운터를 올리는 양성 조작+양성 신호(에러 문구 등)를 함께 — 0 단독 단언 금지.
- 저장 불변식 게이트는 config가 승격되는 입구 전수(create/clone/update/activate/revert)에.
- 금지로 항목 숨길 땐 기선택 탈출 경로 확인.
