# 354 — 스펙 431 회고(소형): suite 진행 노출

## 무엇을 했나

장시간 스위트의 비가시성(구남님 제안) 해소 — ProgressWriter(원자적 진행 파일, 실패 무해) +
씨앗 그물 per-test 스트리밍([n/N]·직렬 start·병렬 as_completed) + 배터리 [n/N] 접두.

## 배운 것

1. **"안 보인다"의 근인은 로깅 부재가 아니라 출력 타이밍이었다** — 러너는 이미 다 찍고 있었는데
   그룹 완료 후 일괄이라 직렬 db 그룹 수 분간 침묵. 관측 요구가 오면 "뭘 더 찍을까" 전에 "지금 찍는
   게 **언제** 나오나"부터 볼 것(버퍼링·일괄 수집이 흔한 범인 — flush=True 포함).
2. **관측은 실패 무해가 계약** — 진행 기록(파일 쓰기)이 그물을 깨면 관측이 본업을 해친다.
   ProgressWriter 전 쓰기를 try 흡수 + 원자적 tmp+rename(반쪽 JSON 소비 방지).
3. **소형 작업도 검증은 실물로** — tail 캡처·진행 파일 중간 2회·종료 일치까지 실측. 단 배터리
   라이브 스모크는 중단 지시로 생략 — 스펙에 "컴파일까지·다음 실행이 실증"으로 정직하게 경계 기록
   (검증 안 한 것을 한 척 안 하기).
