# 129 — 스펙 151: MCP 도구 상세 정보 회고 (자율 루프 2건차)

## 무엇을 했나
실사용 버그 #2: MCP 하위 도구의 메타정보(설명·파라미터)가 어디에도 안 보임. discover가 이름만
뽑고 버리던 것을 toolsDetail(설명+args 스키마 파생)로 확장, tools_meta JSONB 스냅샷 저장, 상세
드로어를 도구 카드 화면으로, 재탐색 엔드포인트(백엔드 복호 자격증명) 신설. verify 21/21·
e2e 8/8×2·codex 3건 수정.

## 재탐색을 백엔드 엔드포인트로 만든 이유가 설계의 핵심이었다
프론트에서 discover를 재호출하는 안은 마스킹 토큰 문제(프론트는 •••만 보유)에 막힌다.
"저장된 자격증명으로 재실행"은 본질적으로 백엔드 작업 — 자격증명이 어디 있느냐가 API 경계를
정한다. 공유 코어(_live_discover)로 discover/rediscover 드리프트도 0.

## codex 패턴 2개가 또 반복됐다 (누적 3~4번째)
- **경유 캡 ≠ 경계 캡**: _tool_info의 캡은 discover *경유* 값만 지킨다 — 클라이언트가 tools_meta를
  직접 POST/PUT하면 무제한(149의 metadata 캡, cap-the-raw-source와 동형). 캡은 파생 함수가 아니라
  **입력 스키마(validator)** 에 걸어야 모든 경로를 덮는다.
- **갱신 연산의 참조 대칭**: 재탐색이 enabled_tools를 교집합으로 줄이는 "안전해 보이는" 동작이,
  원격의 일시적 누락 한 번에 에이전트의 툴 단위 능력을 조용히 끊는다. 삭제·rename에만 있던 참조
  가드(093)를 재탐색에도 — **자원 상태를 바꾸는 모든 동사에 같은 참조 질문을 던져라**(삭제만
  특별하지 않다).

## e2e가 남긴 프레임워크 실측 2건

class 덤프 실측으로 확정하고 스크립트에 주석으로 남김. e2e 스크립트 자산이 세대(148→150→151)를
거치며 함정 지식을 축적하는 복리가 실제로 동작 중.
