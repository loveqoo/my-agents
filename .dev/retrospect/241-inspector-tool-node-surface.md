# 241 — 기록은 단언했지만 표면은 별개 소비자였다 (스펙 266)

## 맥락
265에서 RAG 실발화를 "호출 기록 필수 단언"으로 검증하고 완료 선언했다. 사용자: "RAG를 조회했는데
인스펙터에는 안 나와. 예전처럼 조회 결과가 나와야 하는데." — 백엔드 기록(trace.mcp)·칩("1 rag")은
정상이었지만 인스펙터 실행 흐름의 도구 노드에 조회 카드(검색어·건수·히트)가 안 붙었다.

## 무엇을 배웠나

### 1. 축 검증의 완결 = 기록 + 사용자 표면 (트레이스 JSON 그린 ≠ 화면에 보임)
265의 교훈("주장 vs 기록 분리")을 적용해 기록까지 단언했지만, 사용자가 실제로 보는 **표면**(인스펙터
카드 귀속)은 또 다른 소비자였다. 같은 세션에서 두 번 연속 "그린 선언 → 사용자가 한 겹 더"를 겪은 것:
264(발화 자체) → 265(호출 기록) → 266(표면). 검증 사다리를 "행동 발화 → 기록 → **사용자 표면**"
3층으로 완결해야 한다. 특히 새 기능(노드형)이 기존 관측 인프라(인스펙터)를 *재사용*할 때, 재사용이
자동 호환이라 가정하지 말 것.

### 2. 노드명 기반 귀속 술어도 "닫힌 집합" 함정을 탄다 (149의 노드명판)
인스펙터의 카드 귀속이 `node === 'tools'` 정확 일치 — 기본 ReAct·plan_execute의 관례에 고정.
노드형이 `<노드명>__tools`라는 새 이름 위상을 들여오자 술어가 전부 탈락시켰다. learning 149("입구
열거는 grep 전수")의 자매: **새 그래프 위상(노드 이름 체계)을 도입하면, 그 이름을 소비하는 표면
(귀속 술어·라벨 매핑·순번 로직)을 grep해 전수 정렬하라.** 이번 grep: `'tools'` 정확 비교 3곳
(nodeMeta·nodeEventContent·타임라인 tctx) — isToolNode 술어로 일반화.

### 3. 다회 귀속 로직은 승계하며 일반화 (202/203 도시락 방지 보존)
'tools' 다회 라운드의 카드 중복 방지(내용 매칭→순번 폴백)를 노드형에도 그대로 승계 — t.mcp는 턴
전체 실행 순 리스트라 도구 노드의 **전역 등장 순번**과 1:1이 성립(이름이 여럿이어도). 기존 술어만
바꾸고 로직은 재사용해 도시락 버그 부류(231) 재발 없이 확장.

### 4. 표면 수정의 검증은 표면에서 — 플그 UI e2e
수정 후 검증도 트레이스가 아니라 실제 플레이그라운드 UI에서: 칩 "1 rag" → 인스펙터 → 도구 노드
라벨 + RagCall(3건·검색어·유사도·히트 카드) 텍스트 단언 + 육안 스샷. 유사도 0.038이 낮게 뜨는 건
mock-embed 특성(의미 공간 아님) — 검색·표면 검증엔 충분, 실 임베딩 품질과 혼동 금지.
