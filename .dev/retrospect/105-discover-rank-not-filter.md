# 105 — 회고: 조율형이 도구/문서/기억 못 쓰던 버그 (스펙 124)

## 무엇을 / 왜
사용자: "조율형이 도구·문서·기억을 못 쓴다." 근인은 `broker.discover`의 어휘 하드 필터
`q in cap-text`(쿼리⊆능력)가 자연어 쿼리에서 허가된 능력을 전부 떨군 것. 조율형은 discover로 위임
대상을 찾으니 항상 빈 목록. 사용자 결정(필터→랭킹)대로 하드 필터를 토큰 겹침 랭킹으로 바꿨다(게이트 불변).

## 잘된 것
- **레이어 격리로 근인 확정**: 빈 쿼리(능력 나옴) vs 실 쿼리(사라짐)로 "필터가 떨군다"를 분리, 네트워크
  불필요한 memory provider로 MCP 연결 실패와 필터를 격리(가짜 MCP는 연결 0이라 필터를 가렸음). 추측 없이
  실 broker 재현.
- **보안 표면 안 건드림**: allowlist∩RBAC 게이트(discover 위쪽)는 그대로 두고 후처리 필터만 랭킹으로.
  verify_124 D4/D4b로 게이트 무회귀(미허가·빈 allowlist → 공집합) 명시 고정.
- **GREEN 테스트가 버그를 굳힌 걸 정직히 판정**: verify_101 H2·verify_100 P2가 `discover(비매칭)==[]`를
  단언했는데 이는 버그 필터 부수효과였다. 코드를 되돌리지 않고 **진짜 불변식**(미허가 부재·허가 유지)로
  테스트를 교정. 보안 불변식은 별도 확인(web_search 여전히 부재).

## 아쉬운 것 / 리스크
- 랭킹 순서가 "쿼리 토큰 겹침 수"라 단순 — 큰 카탈로그·동의어엔 약함(OUT: 시맨틱/벡터는 후속). 지금
  카탈로그 작아 충분(설계결정 10과 정합).
- 이 버그는 능력 브로커 첫 출하(100)부터 있었을 가능성 — 조율형 실사용(도구 호출)까지 **엔드투엔드로
  돌려본 검증이 없어** 오래 잠복. 다음엔 조율형 데모를 실제 도구 호출까지 e2e.
- codex는 오늘 실행이 불안정(123 hang) — 124도 백그라운드로 걸었으나 무응답 시 레이어 격리 재현 +
  verify_124 7종 + 브로커 verify 7종 무회귀로 대체 검증.
- pre-existing: verify_115가 orchestrate.py 상대경로로 FileNotFoundError(조용한 red, learning 121 부류).

## 다음 작업 Context에서 상기할 것
- 권한 게이트 뒤 후처리는 **필터 아니라 랭킹**(오케스트레이션 소비 시 허가된 걸 버리면 기능이 죽음).
- 버그 수정이 GREEN 테스트를 깨면 **불변식 vs 버그 부수효과** 판정 후 후자면 테스트를 불변식으로 교정.
- 조율형은 discover→delegate로 도는 만큼 **e2e(실제 도구 호출)** 검증을 붙일 것.
