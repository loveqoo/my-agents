# 회고 206 — 빌딩 블록 '수정일' 죽은 값 배선 (스펙 216)

## 무엇을 했나
사용자가 "수정' 열이 편집해도 안 바뀐다"고 지적 → 백엔드가 `"updated":"—"` 하드코딩(전 카테고리)임을
확인. 편집 가능성으로 배선 범위를 갈랐다: 페르소나(updated_at 이미 있음)·MCP(컬럼 추가)는 실제 배선,
메모리(읽기 전용 시스템 enum)는 "—" 유지. 열 이름 "수정"→"수정일"(편집 동작 혼동 제거). 검증=DB 컬럼
실존+head f212 단일+편집 시 updated_at 07-03→07-07 상승(onupdate 발화)+화면 fmtTime 친화표기.

## 배운 것

### 1. 하드코딩 플레이스홀더("—")는 죽은 위젯의 데이터판 — 사용자가 "안 바뀐다"로 잡는다
헤더 검색창(스펙 213)이 "동작 안 하는 컨트롤"이었다면, 이건 "동작 안 하는 *값*". `"updated":"—"`가
전 카테고리에 하드코딩돼 편집해도 불변. 자가검증은 "열이 렌더되나"만 봐서 통과하고, *편집 후 값이
변하나*를 보는 사용자만 잡았다. **교훈: 표시 값이 상수 리터럴("—"·"just now"·"N/A")로 박혀 있으면
그건 미배선 신호다. "데이터가 렌더되나"가 아니라 "액션 후 그 값이 실제로 변하나"를 검증에 넣어라
(편집→재조회→값 상승 왕복). 스펙 213 "죽은 위젯" 교훈의 확장.** ([[205-page-title-dedup-dead-search]])

### 2. 배선 범위는 "편집 가능성"으로 가른다 — 읽기 전용엔 정직한 N/A("—")가 정답, 가짜 날짜 아님
메모리 타입은 빌딩 블록에서 읽기 전용(BLOCK_FORMS={}, 시스템 enum). 여기에 updated_at을 추가하면
전 행이 마이그레이션 시각으로 백필돼 "오늘 다 수정됨"처럼 *거짓 정보*가 된다. 그래서 메모리는 배선 대신
"—"를 **의도적으로 유지**했다(수정 자체가 불가하므로 N/A가 진실). **교훈: "죽은 값을 살려라"가 항상
"실제 값을 채워라"는 아니다. 그 자원이 그 축으로 변하지 않으면(읽기 전용) 정직한 빈 표시가 맞다 —
없는 이벤트에 그럴듯한 값을 지어내면 새 거짓말. 여집합이 정직한 경계일 수 있다.**
([[complement-attack-can-be-honest-boundary]])

## 다음에 적용
- 표시 값이 상수 리터럴이면 미배선 의심 — 액션 후 값 변화까지 검증(렌더 여부로 그치지 말 것).
- 죽은 값 살릴 때 자원의 편집 가능성부터 확인 — 읽기 전용은 정직한 "—", 편집 가능만 실배선.
- 마이그레이션은 헤더-only 그래프검증(단일head·중복0·고아0)+실DB 컬럼 확인([[hand-authored-migration-ids-collide-silently]]·[[reload-reruns-migrations-mid-edit]]).
