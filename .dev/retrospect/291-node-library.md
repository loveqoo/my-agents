# 291 — 노드 라이브러리: 등록 노드 + 버전 고정 참조 (스펙 316)

## 무엇을 했나
노드형 확장 3부작(사용자 제안 2026-07-13)의 1탄. 노드형 파이프라인의 노드를 (name, version) 단위
1급 자산으로 등록·공유하고, 에이전트가 `{"ref": {"name", "version"}}`으로 **버전을 핀 고정** 참조한다.
발행된 버전은 불변(수정=새 버전 발행) — 테스트·출시된 에이전트가 등록 노드 수정에 흔들리지 않는다
(사용자 결정: 라이브 참조의 파급을 버저닝으로 통제). 백엔드(엔티티·CRUD·해석·가드) + admin UI(라이브러리
뷰·폼 참조 픽커·오버라이드 베이스) + 검증 사다리 3런.

## 배운 것 / 복리 포인트

- **참조 해석을 "이미 있는 단일 관문" 앞에 한 지점으로 꽂으면 엔진·오버라이드·풀 파생이 공짜로
  따라온다.** `_load_context`가 채팅·A2A 로컬 서빙·eval의 단일 로드 경로였고, 해석을 오버라이드 병합
  **앞**(해석→병합)에 두니 스펙 287의 노드 오버라이드가 무수정으로 ref 노드에도 동작했다(길이·인덱스
  정렬이 유지되므로). 저장 경로도 기존 `derive_pipeline_pool` 호출점을 지나므로 풀 파생·존재 검증이
  같은 지점에서 해결. **새 기능을 붙일 때 "어느 관문을 이미 모두가 지나가나"부터 찾아라.**

- **저장-측 검증과 실행-측 해석의 게이트 조건이 다르면 비대칭이 샌다(codex P1).** 실행 해석은 "nodes가
  리스트면" 무조건인데 저장 검증은 `derive_pipeline_pool`(impl=pipeline 전용) 안에 있어, 비노드형
  에이전트가 없는 참조를 저장할 수 있었다(실행 시 422 시한폭탄). → 검증을 impl 무관 헬퍼
  (`assert_node_refs_exist`)로 분리해 두 게이트의 조건을 일치시켰다. **한 데이터에 대한 쓰기 게이트와
  읽기 게이트는 같은 술어를 공유해야 한다** — [[gate-on-intent-value-not-mutable-baseline]] 계보.

- **JSONB 참조엔 FK가 없다 — 참조 무결성은 advisory lock으로 직접 직렬화해야(codex P1 TOCTOU).**
  삭제 가드(스캔→삭제)와 에이전트 저장(검증→커밋)이 겹치면 dangling ref. `pg_advisory_xact_lock
  (hashtext('nodetpl:'||name))`을 발행·삭제·저장 검증이 공유해 닫았다(발행도 이 잠금으로 동시 발행
  409→순차 vN+1·vN+2로 개선). **정규화를 포기하고 JSON에 참조를 넣는 순간, DB가 주던 무결성
  (FK·CASCADE)을 앱이 승계해야 한다는 청구서가 온다.**

- **공유 카탈로그의 조회가 남의 자원 이름을 되비추면 열거 오라클(codex P1).** usedBy(참조 에이전트
  이름)를 전 인증 사용자에게 노출하고 있었다 — private 에이전트 이름 누출. `may_use_agent` 필터 +
  숨김 개수(`usedByHidden`)로 정직 표기, 변이는 특권 게이트(`require_node_manage`, model_registry
  패턴). **횡단 집계(usage/카운트)는 만들 때부터 "누구의 시야로 세나"를 물어라** — [[installed-guard-isnt-covering-guard]]의 집계판.

- **외형 검증이 아니라 기능 검증이 프런트 크래시를 잡았다.** tsc·vite 빌드는 초록이었지만, 브라우저로
  "새 버전 발행"을 실제 클릭하니 `undefined.filter` 크래시(템플릿 config는 선택 필드를 생략하는데
  공용 폼 컴포넌트가 `n.tools.filter`로 단정). 서버 화이트리스트가 "미지정 키를 저장 안 함"이므로
  **API가 돌려주는 부분 객체를 폼에 물릴 땐 방어 기본값이 필수.** → [[ui-verification-must-be-functional]] 재확인(이번에도 스샷·컴파일이 아니라 클릭이 잡음).

- **서브에이전트 위임(프런트 9파일)은 규칙 문서+API 계약+완료 기준을 자기완결로 주면 잘 돌아간다.**
  admin/CLAUDE.md(antd 강행)·백엔드 계약·기존 패턴 파일 목록을 브리프에 넣었더니 NodeConfigFields
  추출(단일 출처)·isNodeRef 판별 헬퍼 같은 좋은 구조 결정까지 자체적으로 했다. 단, 위임 후 **메인이
  기능 검증으로 재검증**(위 크래시)이 반드시 필요 — 위임 보고의 "통과"는 컴파일 통과였다.
