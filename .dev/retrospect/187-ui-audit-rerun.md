# 회고 187 — ui-audit 재실행 (스킬 발동, 스펙 165~169의 상시화)

## 무엇을 했나
사용자 요청("오랜만에 ui 체크")으로 ui-audit 스킬 발동. 기계 3종 = screens 42·overlays 20(확장 후)·
scenario 7 — **FAIL 0**. 축3(문구)는 deep-reasoner 일반인 연기로 이번 세션 신규 카피 채점 — 막힘 0·
오탈자 0·경미 3(2건 즉수정: 청크 괄호설명+툴팁, admin/member 병기 / 1건 보류: 도구 docstring은 모델
라우팅 명세라 평이화가 해로울 수 있음). 모바일 신설 표면 3장 육안 확인.

## 배운 것

### 1. "지속적 발견" 장치도 커버리지 목록이 정적이면 신설 표면에 공허 초록
감사 3종이 전부 초록이었지만, 목록을 열어보니 **이번 세션에 만든 표면 3개(능력 부여 탭·컬렉션 편집
모달·문서 드로어)가 목록에 없었다** — 그 초록은 그 표면들에 대해 아무것도 말하지 않는다. 목록에
추가하니 20건 측정으로 늘었고(다행히 다 통과), 스킬 문서에 "**새 화면/탭/모달을 만들면 감사 목록에
추가**" 규칙을 명시했다. **교훈: 상시 게이트의 clean pass를 받으면 첫 질문은 "결과가 좋은가"가 아니라
"**목록이 자산 변화를 따라왔는가**"다 — 커버리지 밖 초록은 [[poisoned-row-plus-double-catch-vacuous-green]]
과 같은 공허 초록의 다른 형태(그쪽은 소스가 죽어서, 이쪽은 목록이 낡아서).**

### 2. 카피 지적도 소비자별로 갈라 처방한다 — 사람용은 보강, 모델용은 보류
축3가 지적한 3건 중 2건(화면 안내문)은 사람만 읽으니 바로 보강했지만, 도구 docstring('스니펫'·
`lang: ko|en`)은 **모델이 도구 선택에 쓰는 명세**이기도 하다(회고 186 "도구 이름·설명=모델 라우팅").
일반인 평이화로 고치면 사람은 편해도 모델 라우팅이 흔들릴 수 있어 보류하고 사유를 기록했다.
**교훈: 문자열 하나에 독자가 둘(사람·모델)일 수 있다 — 카피 처방 전에 "이 문자열을 누가 소비하나"를
먼저 갈라, 모델 소비 문자열은 평이함이 아니라 라우팅 정확도로 판단한다.**
