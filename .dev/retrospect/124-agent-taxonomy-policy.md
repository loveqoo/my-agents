# 124 — 회고: 에이전트 분류 트리 + private 정책 (스펙 146~147, 피드백 연쇄)

## 무엇을
사용자가 "분류가 너무 어렵다"에서 출발해 스스로 계층(internal/external × public/private ×
A2A)을 발견 → 논의로 최소 어휘(태그 public/private/external + A2A 스위치)까지 수렴 →
트리 불변식을 **동작 정책**으로: private=소유자만 사용(채팅·목록·단건·복제·메모리 읽기
404-fold)·A2A 금지(400)·타인 private는 admin에게도 기본 숨김(필터 opt-in).

## 잘된 것
- **사용자의 어려움 → 계층 발견 → 불가능 상태 제거**가 교과서적 설계 과정. AI 역할은 트리를
  현재 축과 대조·경계(external 태그 자명성, private+shared 조합 봉인)와 최소 어휘 제안.
- **codex 적대가 High 3건 우회를 잡음**(단건 조회·복제·메모리 읽기) — "가드 설치≠전체 커버"
  (installed-guard 메모리)의 재실증. 목록·채팅만 막고 안심할 뻔했다. 사용 게이트는 **에이전트를
  만지는 모든 입구**(브로커·A2A 서버·평가 러너까지 codex가 전수 확인)가 대상.
- e2e가 프론트 결함(admin에겐 can_manage 기반 '타인' 판정 불가) 발견 → meId 비교로 교정.
- 404-fold 일관(068): 사용 불가=미존재와 동일 응답(403이면 존재를 알려주는 셈).

## 배운 것
- **개념 태그의 '무표시' 상태는 규칙을 숨긴다** → 전 상태 명시. 단, "정상·기본값 무표시"
  원칙과 공존: 축이 '분류'면 전 상태 명시, 축이 '문제 여부'면 예외만.
- can_manage 같은 파생 불리언은 **특권자 시야에서 축이 뭉개진다** — 타인 판정은 원본
  비교(meId)로.
