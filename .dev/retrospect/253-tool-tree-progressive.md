# 253 — 도구 트리 점진 공개: "리치하게"의 뜻은 더 보여주기가 아니라 필요한 때 보여주기 (스펙 278)

## 맥락
277(트리 위젯) 직후 사용자 피드백 4건: 아코디언 소실·블릿(스위처) 불능·전부 펼쳐져 인지 부담·
**도구 설명 없이 고를 수 없음**. 근인 하나가 두 증상: 277이 `expandedKeys`를 상수(전체)로 고정하고
`onExpand`를 빈 함수로 둠 — 스위처가 죽고(②) 항상 만개(③). 아코디언은 PickerGroups→트리 전환에서
래퍼가 떨어져 나감(①). 설명(toolsMeta)은 카탈로그에 있는데 안 씀(④).

## 발견과 교훈

### 1. controlled prop을 상수로 고정하면 그 상호작용은 조용히 죽는다
277에서 "검색 매칭을 항상 보이게" 하려고 `expandedKeys={전체}`+`onExpand={() => {}}`를 썼다 —
antd Tree는 controlled면 사용자 확장을 콜백이 상태로 되돌려줘야 동작하는데, 빈 콜백이라 스위처
클릭이 무시됐다(에러도 경고도 없음). **controlled 컴포넌트에 상수를 주는 건 그 축의 상호작용을
비활성화하는 것과 같다** — e2e도 "전부 펼쳐져 있으니 리프가 보인다"만 확인해 접기 불능을 못 잡았다
(happy-path 초록: 상호작용 부재는 존재 단언으로 안 잡힘 — 토글 왕복 단언 필요, 이번 verify-278 ③).

### 2. "리치하게"는 정보 총량이 아니라 점진 공개다
사용자가 "리치하게 보여달라"면서 동시에 "한 번에 많이 보여주면 인지 어렵다"고 했다 — 모순이 아니라
**점진 공개(progressive disclosure)** 요구: 초기 1 depth(서버만)→블릿으로 확장→리프에서 설명.
아코디언(0단)→서버(1단)→도구+설명(2단) 세 겹이 각자 정보를 가진다. 274의 "밀도" 논의와 연결:
접근 비용을 계층에 비례시키는 게 리치의 정체(beauty=trust — 정돈이 곧 신뢰).

### 3. 설명 데이터는 이미 있었다 — 표면이 안 실었을 뿐
toolsMeta(도구 설명·파라미터)는 스펙 151부터 카탈로그 API에 실려 상세 드로어가 쓰고 있었다. 선택
표면(트리)만 안 실은 것 — "도구 설명 없이 고를 수 없다"는 지적은 **데이터 부재가 아니라 표면 누락**.
새 데이터 채집 전에 기존 카탈로그가 뭘 이미 아는지 먼저 확인(이번엔 grep 한 번으로 해결).

### 4. 중첩 Collapse는 형제 테스트의 인덱싱·헤더 locator를 이중으로 깬다 (252 ③ 연장)
트리를 Collapse로 감싸자 노드 카드(275, 자신도 Collapse) 안에 Collapse가 중첩 — 275 e2e의
`col(idx)=.ant-collapse.nth(idx)` 인덱싱이 내부 아코디언까지 세서 어긋나고, 헤더 innerText는 strict
위반. 처방: **구분 클래스로 스코프**(노드 카드=collapsible-icon 헤더 보유)+first(). 컨테이너 위젯을
중첩시키면 형제 테스트의 "n번째" 셀렉터부터 의심하라.

## 조치
ToolTree v2: Collapse 래퍼(도구+배지, 선택 있으면 기본 펼침)·expandedKeys 상태화(초기 []=1 depth·
onExpand 갱신·검색 중 매칭 자동 확장)·리프 설명(toolsMeta)·서버 "도구 n개". verify-278 8/8 +
형제(277·276·272·273·109·275) 갱신 GREEN + tsc 0 + 오버플로 0 + 육안. 값·백엔드 무변경.
