# 회고 204 — 탭 UI 통일 + RAG/평가 kind 분리 (스펙 212)

## 무엇을 했나
사용자 UI 배치 8·9·10번. 탭 패턴 기준 명문화(admin/CLAUDE.md): **데이터 집합 전환=Tabs / 같은 목록
필터=Segmented / Radio.Group 탭용도 금지**. 정렬: 승인 Segmented→Tabs(대기/처리=다른 집합)·세션
Radio→Segmented(상태 필터=같은 목록). RAG 컬렉션 문서/엔티티 Tabs(kind 클라 필터·생성 프리셀렉트·
배지 제거). 평가 문제집 에이전트/RAG Segmented(상위 Tabs 안이라 중첩 회피, 백엔드 kind 파라미터로
서버 필터=페이징 정합). 검증=브라우저 6/6·tsc0. fast-worker 2기 병렬(승인·세션·규칙 / RAG 탭).

## 배운 것

### 1. 내 "중첩 회피" 본능보다 사용자의 "시각 일관"이 우선일 수 있다 — 이탈은 스샷으로 물어라
평가는 이미 상위 Tabs(문제집/격자/이력) 안이라 kind를 Tabs로 하면 "탭 속 탭"이 된다. 나는 중첩을
피하려 **Segmented 필터**로 구현하고, 규칙("같은 목록 부분집합=Segmented")으로도 정당화했다. 하지만
사용자는 스샷을 보고 **"탭으로 통일"**을 택했다 — RAG는 Tabs인데 평가만 Segmented면 *개념이 같은데
형태가 다른* 불일치가 더 거슬렸던 것. 실제 중첩 탭은 언더라인 스타일이라 안 무거웠다. **교훈: "중첩은
나쁘다"는 내 기술적 본능이 항상 사용자 우선순위가 아니다. 개념이 같은 두 화면(RAG kind·평가 kind)은
형태 일치가 규칙 순수성보다 중요할 수 있다. 판단이 갈리면 스샷으로 물어 사용자가 값싸게 확정하게 —
스펙에 심어둔 "스샷 확인 체크포인트"가 이 되돌리기를 한 번에 끝냈다(첫 구현 Segmented→확정 Tabs).**

### 2. 서버 페이징 목록의 필터는 클라 필터가 아니라 서버 파라미터로 — 페이징 정합
평가 문제집은 PagedListShell(서버 페이징)이라 kind를 클라에서 거르면 페이지·총계가 어긋난다. 백엔드
list_datasets에 `kind` 쿼리 파라미터를 더해 WHERE로 걸었다(총계·페이징 정합). RAG 컬렉션은 전량 클라
보유(listCollections 무페이징)라 클라 필터로 충분 — **자료 소스의 페이징 여부가 필터 위치를 정한다.**

### 3. 스크린샷 확정 체크포인트를 스펙에 미리 박아두면 판단 이탈을 사용자가 싸게 검수
스펙 212에 "평가 중첩은 스샷 확인 1회"를 미리 적어둬, Segmented로 이탈한 판단을 구현 후 스샷으로
바로 제시할 수 있었다. **교훈: 구현 중 판단이 갈릴 지점을 스펙 작성 시 "여기서 스샷 확인"으로 표시하면,
완료 후 되돌리기 대신 그 지점만 사용자가 검수한다(값싼 확정).**

### 4. 맥락을 만드는 컨트롤을 넣으면 그 맥락에 의존하는 하위 어포던스까지 같은 변경에서 승계 (사용자 지적)
평가에 kind 탭을 넣자 '새 문제집' 버튼에 맥락이 생겼다 — 에이전트 평가 탭의 버튼은 "에이전트 문제집"을
만들어야 하니 모달에서 종류를 또 고를 필요가 없어졌다. 그런데 나는 탭만 넣고 생성 버튼·모달은 그대로
둬(종류 Select가 남음) 사용자가 "이런 건 같이 고려했어야지"라 지적. **RAG 컬렉션 워커는 같은 프리셀렉트를
적용했는데 평가엔 빠뜨려 한 스펙 안에서도 불일치**가 났다. **교훈: 탭/필터처럼 *맥락을 만드는* 컨트롤을
추가하면, 그 맥락을 소비하는 하위 어포던스(생성 버튼 라벨·모달 기본값·중복 선택 제거)를 **같은 변경에서**
승계시킨다. "탭을 넣었다"의 완료 기준은 탭 렌더가 아니라 *탭이 만든 맥락이 아래까지 흐르는가*다. 같은
패턴을 이미 옆(RAG)에서 했다면 그게 체크리스트 — 한 스펙 안 자매 화면의 처리를 대조하라.**

## 다음에 적용
- UI 통일 요청은 컴포넌트가 아니라 역할로 번역 후 규칙 적용(중첩 컨테이너 고려).
- 서버 페이징 목록의 새 필터축은 서버 파라미터로(클라 필터는 무페이징 목록만).
- 판단 갈림 지점은 스펙에 "스샷 확인" 체크포인트로 선표시.
- **맥락 컨트롤(탭/필터) 추가 시 하위 어포던스 승계를 완료 기준에** — 자매 화면(RAG)의 처리와 대조.
