# 154 — 컬렉션 편집 버튼: 발견성 (스펙 176)

구남님: "RAG 별명 수정 기능은 어디 있나요?" — 173에서 별명 편집을 *문서 관리 드로어* 맨 아래에 넣었더니
못 찾음.

## 배운 것
- **"어디 있나요?"는 기능 결함이 아니라 발견성 결함의 신호다.** 별명 편집은 173에서 *구현*됐지만, 행
  클릭→문서 관리 드로어 맨 아래 "컬렉션 설정" 패널에 묻혀 실질적으로 안 보였다. 사용자는 행 클릭=문서
  관리를 예상하지, 거기서 별명 편집을 찾지 않는다. **기능을 "관련 없는 컨테이너"에 넣으면 없는 것과
  같다** — 편집은 *편집스러운 곳*(행의 연필 버튼)에 둬야. [[not-missing-just-unexposed]]의 다음 단계:
  노출은 됐는데 *발견*이 안 됨.
- **편집 진입점은 하나로.** 173의 드로어 패널을 남긴 채 176의 모달만 더하면 *두 곳*에서 같은 필드를
  편집 → 혼란·드리프트. 드로어 패널을 제거하고 EditModal로 일원화(문서 드로어=문서만, 편집=연필 버튼).
- **아이콘 키는 MAP 존재를 확인**(170 info-circle 폴백 재발 방지). `edit: EditOutlined` 확인 후 사용 —
  없는 키면 조용히 엉뚱한 아이콘으로 폴백한다.
- **내 안내 문구가 테스트를 오검출**시킬 수 있다. "식별 이름·모델·차원은 변경 불가" 힌트의 "식별 이름"을
  "불변 필드가 편집 노출됨"으로 오판(V2b). 부재 검사는 *편집 입력*(Select/Input) 기준이지 텍스트 언급이
  아니어야. [[eyeball-catches-what-check-misses]] 역방향(육안이 테스트 거짓양성을 잡음).
