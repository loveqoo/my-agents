# 125 — 회고: 실사용 테스트 1차 (스펙 144~147 배치 — 페이즈 회고)

> 개별 스펙 회고(122~124)와 별개로, "사용자 직접 테스트→보고→교정" 모드 첫 배치 전체를 본다.
> 범위: 에이전트 메뉴 UX(144)·반응형 테이블(145+후속3)·2줄 행/분류 트리(146+후속3)·private
> 정책(147). 커밋 12개, 사용자 보고 ~10회, 모두 당일 반영.

## 이 모드에서 실제로 작동한 리듬
- **보고 1건 = 진단(실측) → 수정 → 픽셀/개수 단위 재측정 → 즉시 커밋** — 평균 왕복이 짧아
  사용자가 테스트 흐름을 안 끊김. 스크린샷 1장이 스펙 문서보다 정확한 요구서였다.
- 실측 판정의 전면화: scrollWidth diff·아바타 정원 px·태그 삐짐 px·행당 tr 수·태그 개수 —
  "보기에 괜찮음"을 한 번도 판정 근거로 안 씀. 이 습관이 오독(144)의 재발을 막았다.

## 잘못한 것 (이 배치의 대표 실수)
- **144 오독**: "리스트 컴포넌트가 불편"의 목적어(다 보임)를 놓치고 수단(스크롤)을 해법으로 —
  재보고 비용 발생. 교정 후 원칙: **피드백의 명사가 아닌 목적어를 수용 기준으로, 그 기준을
  사용자 문장으로 재서술 후 e2e 판정에 사용**(123). 이후 3건에선 재발 없음.
- 145 1차 수정(overflowWrap만)처럼 **첫 가설로 바로 구현** — e2e 실측이 반증해 줘서 회수했지만,
  진단→가설 검증(실측)→구현 순서면 한 사이클 절약.

## 배운 것 (이 배치 고유)
- **사용자의 "왜 어렵지?" 탐구가 최고의 설계 입력** — 분류 트리(146~147)는 사용자가 발견했고,
  AI 역할은 현재 축과의 대조·경계 짚기·최소 어휘 제안·불변식의 정책화였다. "사용자=설계자,
  AI=검증자·구현자" 분업이 이상적으로 돌아간 사례.
- **라벨 질문은 리네이밍 요청이 아니라 설계 신호** — '공유 vs 공개' 질문이 트리→정책→High 3
  보안 수정까지 이어짐. 질문의 뿌리를 파는 게 맞았다.
- 반응형 표의 기술 공식(재사용): tableLayout fixed + 셀 overflowWrap + **가변 내용=비율 폭·
  고정 내용=고정 폭** + lg 미만 카드 스택 + 태그류는 셀 내 줄바꿈 허용(버전처럼 짧은 건 nowrap).
- 파생 불리언(can_manage)은 특권 시야에서 축이 뭉개진다 — 원본 비교(meId)로 판정(124).
