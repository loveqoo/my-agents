# 298 — 가짜 "단기(세션)" 메모리 타입 제거 + mem0 스코프 설명 (스펙 323)

## 무엇을 했나

사용자 지적("장기기억에도 단기(세션)이라는 선택지가 있어" → "그럼 그건 가짜였군요, 당장 지우십시오, mem0
동작 설명 추가")에서 시작. 메모리 타입 카탈로그의 **"단기(세션)"은 죽은 라벨**이었다 — 백엔드
`memory_enabled()`가 무시(진짜 단기는 `historyDepth`가 소유), 프론트는 도처에서
`.filter(m => m !== SHORT_TERM_MEMORY)`로 걸러내며, 카탈로그엔 "타입"으로 떠서 "장기 기억 (mem0)"과
나란히 보여 혼란만 줬다. 세 층(시드+DB+프론트) 전량 제거 + 에이전트 폼 장기 기억 필드에 mem0 스코프
자동결정 설명 추가.

## 핵심 배운 것

### 1) "가짜 선택지"는 걸러내는 코드가 오히려 존재를 지탱한다
`SHORT_TERM_MEMORY`는 백엔드가 무시하는 죽은 값인데, 프론트 ~11곳의 `.filter(m => m !== ...)`가
**그것을 계속 참조**하며 살아있게 했다. 필터가 있으니 화면엔 안 뜨는 듯하나 카탈로그·config엔 남아
사용자가 실제로 마주쳤다. **죽은 개념은 "가려서" 없애는 게 아니라 근원(시드·DB·상수)에서 뽑아야** 걸러내는
코드까지 no-op이 되어 함께 사라진다. 가림 코드가 많을수록 "이미 처리됨" 착시가 커진다.

### 2) 설명은 "정의하는 곳"이 아니라 "켜는 곳"에 있어야 보인다
mem0 스코프 설명은 카탈로그 "장기 기억 (mem0)" body엔 이미 있었다. 하지만 사용자가 실제 설정하는
**에이전트 폼 장기 기억 필드**엔 없어서 "안 보였다". 정보가 시스템 어딘가 존재하는 것과 **사용자가
결정하는 순간 눈앞에 있는 것**은 다르다. 설명은 소비 지점(액션 지점)에 둔다. [[explain-plainly-not-one-sided]]

### 3) 삭제는 세 층 전부 — 시드·라이브 DB·프론트 (전체 정합)
"단기(세션)" 소멸은 (a) `seed.py` MEMORY_TYPES/AGENTS(신규 시드), (b) 현 dev DB의 `memory_types` 행 +
17개 agent_versions.config의 재귀 스트립(기존 데이터), (c) 프론트 상수+필터+import 셋 다 필요. 하나라도
빼면 "grep 0" 완료조건이 안 선다. 특히 (b) 라이브 DB config는 JSONB 재귀 청소라 ORM으로 처리(원시 SQL은
JSONB 인코딩 함정). [[whole-fix-over-minimal-patch]] — 개인용이라 최소수선 대신 전체 교체.

### 4) 스크린샷 boolean이 false여도 PNG가 진실 — 스크립트 판정 ≠ 실제 렌더
검증 스크립트가 `/userId가 있으면 세션을 넘어/` 매칭에 false를 반환했으나, 정작 캡처된 PNG엔 그 문구가
선명히 렌더돼 있었다. 원인은 코드가 아니라 **스크립트의 네비게이션 타이밍**(step ② 렌더 전 캡처)이었다.
자동 판정이 false여도 **산출물(스크린샷) 자체를 눈으로 확인**하면 진위가 갈린다 — 판정 스크립트를 맹신해
"미완"으로 오결론하지 말 것. [[probe-deeper-before-concluding]]

## 검증
- 카탈로그: `단기(세션)` 없음·`장기 기억 (mem0)` 있음(스크린샷 shot-323).
- 폼: 에이전트 생성 step ② 장기 기억 필드에 mem0 스코프 설명 렌더(스크린샷 shot-323-form-memory — 육안 확인).
- DB: `memory_types` 1행(장기 기억 mem0)·config에 남은 FAKE 0(측정).
- 프론트: `SHORT_TERM_MEMORY` grep 0·tsc/build 클린·ruff/mypy 클린.

## 범위 밖(유지)
- historyDepth(진짜 단기) 동작 불변 — 가짜 라벨만 제거.
- mem0 스코프를 명시 선택으로 바꾸기 — 설명만 추가, 동작(userId 자동결정)은 그대로.
