# 167 — AgentsView 분해 Phase B (useAgents 훅)

**스펙**: docs/spec/185 · **관련**: 166(Phase A)·184(useAsyncData)·165(폼시드 훅 부적합)

## 무엇을 했나
AgentsView의 데이터 오케스트레이션(목록·레퍼런스 데이터·12개 뮤테이션)을 `useAgents()` 훅으로 추출.
747→684줄, 데이터 로직은 120줄 훅으로 격리. 컴포넌트는 UI + 성공 토스트·네비게이션만 소유. 로직
수술이라 실 뮤테이션 왕복으로 검증(생성→삭제, 커스텀 토스트 보존 확인).

## 무엇이 잘못됐고 무엇을 배웠나

### 1. "훅이 있다"가 "훅을 써라"는 아니다 — runWithToast를 안 쓴 게 옳았다
스펙 184가 `runWithToast`를 만들었지만, AgentsView는 성공 토스트가 **커스텀 플로팅 Alert**이고 에러만
antd message다. runWithToast(성공·실패 모두 antd message)를 적용했으면 성공 토스트 표현이 바뀌는
**행동 변경**이었다. deep-reasoner가 이걸 사전에 짚어 Phase B 설계에서 배제했다. 훅은 **데이터만**
throw하고, 토스트 표면은 컴포넌트가 소유하게 두는 게 정답.

- **처방**: 공용 훅/유틸이 있어도 소비처의 **표면 계약**(토스트 종류·에러 처리 지점별 상이)을 먼저 확인.
  일괄 적용이 행동을 바꾸면 그 소비처는 예외로 두라. [[hoc-vs-hook-tree-or-logic]]의 자매 — 추상은
  다양성을 죽이면 안 된다.

### 2. 로직 수술은 tsc가 아니라 "실 왕복"으로 검증
Phase A(파일 이동)는 tsc+렌더로 충분했지만, Phase B는 상태/이펙트/뮤테이션을 옮긴 **로직 수술**이라
tsc 0가 행동 보존을 증명하지 못한다. 실제 생성→삭제 왕복을 브라우저로 돌려 (a) list 반영, (b) 커스텀
토스트가 여전히 `.ant-alert-success`(antd message로 안 바뀜), (c) pageerror 0을 확인해야 확증된다.

- **처방**: 리팩터를 "이동(tsc 그물)"과 "수술(실행 검증 필수)"로 구분하라. 데이터/상태 로직을 옮겼으면
  그 데이터가 실제로 흐르는 왕복을 최소 하나는 돌린다. [[decomposition-is-mostly-file-moves]]의 뒷면.

### 3. tr 카운트 ≠ 엔티티 카운트 (subRow 함정) — 또 하네스가 과정밀
"생성 후 행 +1" 단언이 실패(10→12). 정체: DataTable이 subRow(2줄 행, 스펙 146)를 써서 새 에이전트가
2 tr을 만든다. 코드는 정상(특정 행 존재·삭제 후 복원 통과). 하네스가 tr을 엔티티로 오독. "증가"만
판정하고 정확 검증은 고유 이름 행으로.

- **처방**: 리스트 반영을 tr 카운트로 재지 말 것 — 커스텀 행(subRow·확장행)이 있으면 어긋난다. 고유
  식별자 행 존재/부재로 판정. [[suspect-selector-not-app-when-screenshot-ok]]의 재확인(이번엔 카운트 단위 오류).

## 복리 포인트
- 데이터 로직이 `useAgents`로 격리 → 단위 테스트 가능·컴포넌트는 순수 UI 오케스트레이션. 스텝 3 완결.
- 훅 채택 판정 기준 축적: 표면 계약(토스트 종류)을 바꾸면 그 소비처는 훅 밖. "있으니 써라" 금물.
- 검증 등급 구분: 이동=tsc+렌더, 수술=실 왕복. 다음 대형 리팩터에 재사용.
