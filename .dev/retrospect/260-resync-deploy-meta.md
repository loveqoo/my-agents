# 260 — resync 커밋 재보고: 보존 단언에는 경로 판별자가 필요하다 (스펙 285)

## 맥락
사용자 질문("Code 버전 어디서 오나?")→측정 답변(SDK/카드 자기신고 스냅샷, resync는 endpoint·상태만
실측)→"sync 시 커밋도 재보고받자" 결정. resync에 deploy 메타(commit·repo·runtime) 재반영 추가 —
commit 변경 시 버전 행 전이(057 F4 불변식: active_version=실재 active 행, 재왕복은 기존 행 승격).

## 발견과 교훈

### 1. "보존됐다" 단언은 어느 경로로 보존됐는지 판별자가 없으면 거짓 초록
⑤(확장 소실 카드→메타 보존) 테스트가 통과했는데, 실은 몽키패치 함수가 자기 자신을 재귀 호출해
서버가 죽고 **도달 실패 경로**(early return)로 보존된 것이었다 — 내가 검증하려던 확장-소실 보존
로직은 실행조차 안 됨. 처방: 두 경로가 다르게 남기는 흔적(도달 실패=카드 스냅샷 안 만짐)을
판별자로 추가. **부작용 없음을 단언할 땐 "의도한 경로가 실행됐다"는 양성 증거를 함께** — 보존만
보면 no-op·에러·조기 반환 전부 통과한다(245 "내 초록" 계열의 단언판).

### 2. 몽키패치는 원본을 먼저 캡처 — 패치 함수가 전역을 다시 읽으면 자기 재귀
`__main__._card = patched` 후 patched 안에서 `_card()` 호출 = 자기 자신. RecursionError가 서버
스레드에서 조용히 터져 본 테스트는 초록. 원본 참조를 클로저로 캡처하고 나서 바꿔라.

### 3. 공유 경로를 확장하면 그 경로의 라이브 테스트를 돌려라 — 낡은 걸 발견한다
resync를 만졌으니 verify_081_live를 돌렸고, 112(관리 게이트) 이후 principal 없이 직호출이라
**이미 깨져 있었음**을 발견(제 변경 무관). 게이트 추가 스펙이 라우트 직호출 테스트를 안 돌렸던 것
— 같은 턴 수리. 백엔드 라우트 직호출 테스트는 인증·게이트 스펙마다 낡을 수 있는 부류.

## 조치
resync_agent에 code+확장 보유 시 deploy 재반영(merge-preserve: 값 있을 때만·확장 소실 시 보존),
commit 변경 시 버전 전이. verify_285 11/11 + 081 수리 후 8/8. UI 무변경(기존 resync 버튼 그대로).
