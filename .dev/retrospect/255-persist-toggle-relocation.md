# 255 — 대화 저장 이동: "차이가 뭐냐"는 질문은 배치 결함의 신호 (스펙 280)

## 맥락
사용자 질문 "저장 방식의 '영속(기본)'과 세부의 '대화 저장' 토글 차이는?" → 측정으로 답(비영속 ⊃
대화 저장 끔: ephemeral=DB 전면 무접촉, persistHistory=메시지 본문만 스킵·세션/기억/통계 유지) →
사용자 지시 "대화 저장을 저장 방식 아래로 + 간결한 설명".

## 발견과 교훈

### 1. 포함 관계인 두 설정이 다른 스텝에 있으면 관계가 소멸한다
ephemeral(상위)과 persistHistory(하위)는 명확한 포함 관계인데 step ①과 step ③에 떨어져 있어
사용자에게 별개 개념으로 보였다. **"이 둘의 차이가 뭐냐"는 질문이 나오면 답만 하지 말고 배치를
의심하라** — 개념적 부모-자식은 화면에서도 인접해야 한다(273 "개념 편집 표면"의 배치판). 관계
설명도 값 옆에: OFF 문구를 "무엇이 유지되고 무엇만 불가한지"(세션·기억·통계 유지, 재개·소급 열람만
불가)로 구체화 — 사용자가 표로 물었던 바로 그 내용을 hint 한 줄에 압축.

### 2. 답변 끝의 "원하시면 고칠 수 있다" 제안이 다음 스펙이 된다
질문에 사실로 답하면서 "떨어져 있는 것 자체가 신호"라고 덧붙였더니 바로 지시가 왔다. **정보 질문에
답할 때 그 질문이 드러낸 구조 결함을 한 줄로 지적해 두면, 사용자의 판단 비용이 낮아진다**(설계
제안을 억지로 미는 것과 다름 — 신호를 명명만).

## 조치
step ③ '저장·영속' 구획 소멸 → step ① 저장 방식 바로 아래 대화 저장(관계 설명 ON/OFF 전환,
비영속=실효값 disabled 유지). verify-280 6/6 + 279 무회귀 + tsc 0. payload 무변경.
