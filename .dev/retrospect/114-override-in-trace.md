# 114 — 회고: 턴 트레이스에 적용 오버라이드 기록 (스펙 134)

## 무엇을 / 왜
사용자 점검 질문("오버라이드했던 세션에 다시 들어가면 그 설정으로 되나?")을 진단 — 오버라이드는
세션 속성이 아니라 **UI 적용 상태**(적용 중이면 이어지고, 새로고침/해제/타 기기면 원래 설정). 진짜
구멍 = 한 세션에 설정 다른 턴이 섞이는데 턴별 기록이 없음. 처방 = trace["overrides"](허용 키만·
마스킹·캡, 131 프레임 재사용) + 인스펙터 섹션 + 과거 세션 로드 시 안내 토스트(성공 시에만).

## 잘된 것
- **질문 → 진단 → 관측성 처방**의 짧은 사이클(125/130/131과 같은 결 — 이제 패턴이 잡힘).
- codex ①이 **"보낸 값 ≠ 적용된 값" 드리프트**를 잡음: 백엔드는 공백 systemPrompt를 적용 안 하는데
  트레이스는 기록 — **기록은 적용 가드를 미러**해야 "적용된 오버라이드"라는 이름이 정직해진다.
  ②(토스트가 로드 실패에도 뜸)는 선제 수정과 수렴.
- e2e가 1회차 전부 통과 — 축적된 셀렉터 패턴(칩 폴링·꼬리 12자 세션 매칭·슬라이더 키보드 조작)이
  재사용되며 안정화.

## 아쉬운 것 / 리스크
- 재개(승인 재개) 턴은 overrides 미보존이 기존 동작 — 경계만 명시(OUT). 재개 시 오버라이드 재적용
  여부는 별도 논의 필요.
- temperature에 문자열이 와도 그대로 기록(타입 검증은 기존 동작 유지) — 잘못된 요청 값도 "요청된
  대로" 남는 것이 디버깅엔 오히려 정보.

## 다음 작업 Context에서 상기할 것
- **"적용된 X 기록"은 적용 가드를 미러**해야 한다 — 입력을 그대로 기록하면 "적용 안 된 값이 적용된
  것처럼" 남는다(codex 134 #1). 기록 지점은 입력이 아니라 적용 직후/적용 조건과 동일 술어로.
- 상태 안내 토스트는 **그 상태가 확정된 경로(성공)에서만**.
- 참고: 스펙 134, 회고 111/112(관측성 시리즈), learning 130(진단 먼저).
