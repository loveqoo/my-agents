# 107 — 회고: 메모리 조회를 드로어 → 상세 페이지 인라인 (스펙 126)

## 무엇을 / 왜
사용자: "드로워 말고 상세 페이지로 넓게." 메모리 "조회 시험"이 640px 드로어에 갇혀 좁았다. 문제는
검색시험 셸(`RetrievalTestDrawer`)이 **컬렉션 검색과 공유**라 그냥 못 벗긴다 — 메모리만 인라인 하려면
컬렉션 계약을 안 깨야 한다. 처방: 드로어 **본문을 `RetrievalTestPanel`로 추출**, 드로어는 그걸 감싼
얇은 래퍼로 축소(컬렉션 무변경), 메모리 패널은 상단 Card에 인라인 전체 폭 + 목록 아래. 레이아웃은
사용자 선택(위아래 스택, 검색 위).

## 잘된 것
- **공유 컴포넌트 분기를 0-드리프트로**: "한 소비자만 다르게(드로어→인라인)"를 알맹이 추출 + 얇은 래퍼로
  풀어, 컬렉션은 import 경로·prop 계약 그대로(타입 재노출). codex NO ISSUES로 계약 보존 확인. 125의
  diag·실패≠0건·stale-async는 알맹이째 이동이라 로직 무변경.
- **레이아웃을 미리 합의**: "상세 페이지"가 좌우2단/위아래 여러 뜻이라, ASCII 미리보기로 물어 위아래
  스택 확정 후 빌드 — 헛빌드 0([[explain-plainly-not-one-sided]] 결, 추측 금지).
- **바뀐 UI에 검증도 이동**: 125 드로어 shot이 새 인라인서 깨질 걸 알고 126 페이지 shot으로 대체
  (드로어 없음·인라인 카드·진단 지속·비밀 미노출 5/5). 테스트가 UI 변경을 따라가게.

## 아쉬운 것 / 리스크
- 에이전트 메모리 탭은 신규 super에 mem0 에이전트가 없어 셀렉트 비활성 → 브라우저로 직접 못 띄웠다
  (유저 탭만 스샷). 두 패널이 `RecallPanel` 공유 + tsc + 대칭 구조라 수용, 단 에이전트 탭 실화면은 미확인.
- 컬렉션 드로어도 실화면 재확인은 생략(fresh super에 컬렉션 없음) — 래퍼가 알맹이를 그대로 감싸고 tsc·
  codex가 계약 보존 확인이라 저위험으로 판단.

## 다음 작업 Context에서 상기할 것
- 공유 컴포넌트가 **한 소비자만 다른 표현**(드로어 vs 인라인)이 필요하면: **본문 추출 + 기존 래퍼 얇게**로
  다른 소비자 계약을 0-드리프트로 보존(타입 재노출로 import 경로도 유지).
- "상세 페이지/넓게" 같은 레이아웃 지시는 뜻이 여러 개 → **미리보기로 먼저 합의**하고 빌드.
- UI를 바꾸면 그 UI를 짚던 **브라우저 shot도 같은 턴에 갱신**(안 하면 다음 실행서 조용히 red).
- 참고: learning 126, 회고 106(125 diag는 이 알맹이에 실려 이동), [[verify-ui-in-browser-proactively]].
