# 244 — 기억 어휘 정리: 죽은 라벨은 경고 말고 제거, 필터는 원본 소비자 전수 (스펙 269)

## 맥락
사용자가 "단기(세션)이 뭐냐"고 물은 데서 출발. 근인=단기(세션)이 **죽은 카탈로그 라벨**(백엔드
memory_enabled 무시)인데 장기(mem0)와 **같은 선택 표면**에 섞여 있어 혼란. 243 P3는 경고 한 줄로
봉합했었음. 269는 뿌리를 뽑음 — 선택지에서 제거. 3부작(269 어휘 → 270 단기 프록시 → 271 공용
컴포넌트)의 첫 벽돌.

## 발견과 교훈

### 1. 죽은 선택지는 경고가 아니라 제거가 처방 — 그리고 "왜 X냐"는 질문은 X가 잉여라는 신호
243에서 "단기만 고르면 회상 안 됨" 경고를 달았는데, 269에서 **선택지 자체를 빼자 경고가 통째로
소멸**했다. 사용자의 "단기(세션)이 뭐냐"는 이해 부족이 아니라 **UI가 잉여 선택지를 노출한 것의
증상**이었다(회고 243 ④의 다음 단계). **규칙: 무동작 선택지에 경고를 붙이는 건 임시봉합, 선택
표면에서 빼는 게 근치.** 사용자가 개념을 두 번 물으면 그 개념이 UI에 두 번 있는지 의심하라.

### 2. 필터는 카탈로그 원천이 아니라 "저장 배열 원본 소비자"를 전수 덮어야 한다 (codex Medium+Low)
`blocks.memory`(카탈로그) 소비자 3곳(폼 피커·노드 옵션·오버라이드)은 grep으로 잡아 필터했는데,
**저장 배열 `agent.memories`를 직접 렌더하는 소비자**(Inspector 프롬프트 헤더 태그·개요 카운트 2곳·
요약 보존 카운트)는 놓쳤다 — codex가 4건 확증. **선택 표면(옵션 원천)에 필터를 심어도, 이미 저장된
배열을 raw로 그리는 표면은 안 덮인다**("installed guard isn't a covering guard"의 표시판·"move
breaks references both directions"의 형제). 처방: 죽은 값을 숨길 땐 **두 축을 다 grep**하라 —
(a) 옵션 원천(`blocks.*.items`)과 (b) 저장값 원본(`agent.<field>`·`form.<field>`)을 그리는 곳 전부.

### 3. 사용자가 내 asymmetry를 깼다 — 프록시는 "공유 자원 + 소비자별 슬라이스"로 일반화된다
내가 "단기 기억은 대화 단위라 노드에 못 쓴다"고 단정했는데 사용자가 뒤집음: 대화는 공유 자원이지만
**몇 개를 떼느냐(N)는 노드마다 다를 수 있다** — mem0를 노드별 키워드로 조회하는 것과 같은 구조.
프록시(268)가 mem0에 한 일을 히스토리에도 그대로: 원본 한 번 쥐고 소비자별 슬라이스+캐시. **"모델에
넘기는 주체만 다르고 프롬프트 구성은 동일"** 이 진짜 primitive. 내 표의 예외(단기만 ❌)가 사라져
270·271이 더 깨끗해짐. [[probe-deeper-before-concluding]] — 내 단정이 사용자 직관과 어긋나면 단정을
의심(사용자가 밀어붙이기 전에 스스로).

### 4. 유도 필드의 죽은 값 드롭은 방어 이월하지 않는다 (codex High → OUT)
노드형 `memories`는 노드 합집합에서 **유도**(268)라, top-level 구저장 단기(세션)은 저장 시 빠진다.
codex가 High로 짚었으나 — 269 회귀 아님(pre-existing 유도 시맨틱)·단기(세션)은 죽은 값이라 드롭
효과 0. **유도 필드에 죽은 값을 살려두려 방어 코드를 넣는 건 부자연** → OUT으로 정직 기록(고침도
기각도 아닌 경계 명시, [[complement-attack-can-be-honest-boundary]] 계열). 비노드형은 원문 전개로
보존(조건 #4 성립)이라 판별이 갈림 — "보존"의 의미는 필드가 유도냐 원본이냐에 달렸다.
