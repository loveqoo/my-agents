# 325 — 스펙 397 회고: runtime 해체 — 6회전, 적대자가 진리표를 들고 왔다

## 무엇을 했나

캠페인 연장 6회전. runtime.py(738줄·C급 5 최다·MI 31.5 최저)를 파사드 75줄+4형제로 해체.
저장소 C급 47→42(캠페인 누적 61→42). 표적 verify 9종·suite 51/51, codex 적대 P1 0·P2 1
(소스-텍스트 단언 4번째 재현 — 즉시 갱신).

## 배운 것

1. **적대 검증의 질이 회전마다 진화한다.** 이번 codex는 승인 리졸버 분해를 "300조합 진리표
   대조 mismatch 0"으로 검증했다 — 우리가 함정 목록을 선반영할수록 적대자는 더 정밀한 수단
   (전수 진리표·AST 재계수)으로 응수한다. 분해 대상이 순수 함수면 진리표 대조를 우리 쪽
   완료 기준에 먼저 넣는 것도 가능(다음 템플릿 후보).
2. **표면 박제의 grep은 판정 단계가 필요하다.** `runtime.X` 전수 grep 25종 중 4종이 비소비
   (타패키지 참조·부재 단언·주석 텍스트) — 기계 박제는 "수집→판정→검증" 3단계로. 부재 단언
   (`not hasattr`)은 표면의 음화(陰畵)라 재수출을 되레 금지하는 신호.
3. **보안 계약 모듈은 "덜 분해"가 옳다.** _redact_args는 CC 13이지만 scalar 분리만 했다
   (codex 권고 그대로) — 마스킹 정본에서 복잡도 점수보다 상수·로직 동거와 예외 범위 보존이
   우선. 게이트가 요구하는 ≤C는 이미 충족되므로 ≤B를 강행할 이유가 없었다.
4. **소스-텍스트 단언 4번째 재현(054·122·058·재054)** — 이제 리팩터 템플릿의 상시 체크:
   "대상 파일명을 grep하는 테스트" 사전 수색(`grep -rl "파일명" tests/`)을 P1 표면 박제에 포함.
5. **파사드 하강의 연쇄**: rag_runtime이 runtime 파사드를 역참조하던 지연 import 2곳을 정의
   모듈로 내림 — 파사드는 "외부 소비자용"이고 내부 형제끼리는 정의 모듈을 직접 본다는 규칙이
   캠페인 전체에서 일관화됐다.
