# 197 — 피드백 수집(스펙 209 Phase 1): "DPO"를 정직하게 재정의, codex가 read=write 혼동을 잡음

## 맥락
사용자가 "좋아요/싫어요로 개선(DPO 같은 것)"을 원했다. 논의 끝에 방향 확정: 피드백을 **평가 케이스로
수확**(우리 강점=수치 검증), 👍도 함께(에이전트 변경 회귀 지표), 실제 세션까지. Phase 1=수집.

## 무엇을 배웠나
- **"DPO"를 정직하게 재정의**했다. 진짜 DPO=모델 학습인데 우리는 등록 모델을 base_url로 쓸 뿐 학습
  안 한다. 사용자에게 이 경계를 먼저 말하고("우리 안에서 학습은 안 됨") 대안 3길(평가 수확/데이터셋
  export/프롬프트·기억 반영)을 제시해 **평가 수확**으로 합의했다. 요구를 그대로 구현하지 않고 아키텍처
  현실에 맞춰 정직하게 번역한 게 핵심. 👍도 수확은 사용자가 짚은 통찰(변경 안전망).
- **범위를 정직하게 분리**했다. 플레이그라운드 피드백엔 스트림에 message_id 방출이 필요한데 `_persist`
  호출부가 5곳(민감한 스트리밍 영속 경로)이라, Phase 1(세션 뷰=사용자 강조점)과 Phase 1.5(플그)로
  갈랐다. "다 하려다" 민감 경로를 흔드는 대신 사용자 우선순위(실제 세션)를 먼저 완성.

## codex가 잡은 것 (통합 테스트가 못 본 여집합)
verify_209 통합 17건은 **내가 상상한 실패**(타인 세션·머신·assistant-only)를 덮었다. codex 적대 검증이
**read 권한이 write를 넓히는 혼동**을 잡았다(F1, High·설정의존): `_own_scope`가 `sessions:read`(읽기
전용 오퍼레이터)를 admin으로 봐 무스코프를 줘, 그 권한자가 **타인 세션에 피드백을 쓸** 수 있었다.
읽기 스코프를 쓰기 게이트에 재사용한 게 화근. → **쓰기 전용 스코프**(`_own_scope_write`, 진짜 superuser만
무스코프) 분리. 교훈: **읽기 권한과 쓰기 권한의 스코프는 다르다** — 하나로 재사용하면 read가 write를
조용히 넓힌다([[gate-on-intent-value-not-mutable-baseline]]의 친척: 게이트 축을 정확히).
- F2(경합 500): check-then-insert를 PG on_conflict 원자 upsert로. F3(reason 무제한): max_length.
- F4(malformed UUID 422): 수용 — 형식검증은 존재/소유 오라클이 아님(모든 malformed에 균일, 세션
  존재 여부와 무관). "달라 보인다≠오라클"을 구분.

## 다음에 적용
- 소유권 경계 스펙은 **읽기/쓰기 스코프를 별도 함수**로(하나 재사용 금지). 통합 테스트 초록으로
  끝내지 말고 codex 여집합(특히 "권한 X가 의도보다 넓게 작동하나")을 태운다.
- 요구가 아키텍처와 어긋나면(학습 없는 곳에서 "DPO") 정직하게 번역해 대안을 제시하고 합의한다.
- 배관이 민감 경로 다수를 건드리면 사용자 우선순위 기준으로 phase를 가른다(위험 격리).
