# 회고 225 — 헤더 공동 설계 15왕복: 사용자=아트디렉터 협업 패턴 (스펙 248 후속1~15)

## 무엇을 했나
플레이그라운드 헤더를 사용자와 15왕복으로 공동 설계. 최종형: 에이전트 콤보(2줄) · 버전 칩(●상태/vN,
우측 정렬) · 세션 칩(요약/전체 ID, 좌측 정렬, 상태별 3문구) · U 손잡이(경계선에 매달린 탭→위에서
내려오는 오버라이드 서랍). 모바일=3줄 확정(에이전트/버전+세션/손잡이).

## 배운 것

### 1. 사용자 ASCII 스케치는 최고 밀도의 스펙이다 — 받으면 그대로 구현하고 확인은 스샷으로
"(꽉찬 연두 동그라미) 활성 뉴라인 v2", "─────U── 매달린 손잡이" 같은 스케치는 해석 여지가 거의
없어 한 번에 맞았다. 반대로 산문 명세("조건 요약을 보여달라")는 두 번(요약 텍스트→컴포넌트) 틀렸다.
**모호하면 스케치/구체 예시를 요청하는 쪽이 왕복을 줄인다.**

### 2. 중복은 3연발로 반복됐다 — 규칙을 좁게 쓰면 다음 중복이 그물 밖으로 나간다
콤보 초안 태그(상태) → 버전 옵션 초안 라벨(상태) → '+새 대화' 버튼(기능 입구) → 인스펙터 버튼·시스템
프롬프트 버튼(기능 입구). 앞의 둘을 겪고 만든 규칙이 "상태 라벨"에 한정돼 뒤의 셋을 못 잡았다.
일반화: **무엇이든 추가 전에 같은 화면의 동일 상태/동일 동작 지점을 grep, canonical 하나만**(메모리).
중복의 뿌리는 "컴포넌트를 고립적으로 만드는" 작업 방식 — 화면 단위 스캔이 짝이어야 한다.

### 3. 기능이 덜어질수록 그릇도 다시 봐야 한다 — 팝오버가 버튼 하나 남으면 해체
검사 도구 팝오버는 6항목→3→2→1로 줄었는데, 1이 된 순간 팝오버 자체가 간접화 비용만 남는다.
컨테이너는 내용물 수에 따라 존재가 정당화되는 것 — 내용이 줄면 컨테이너 해체를 기본 후보로.

### 4. 오버플로 게이트는 "상태"가 커버리지다
빈 화면만 재던 게이트가 대화 중 상태의 모바일 오버플로 6건을 놓쳤다. 뷰포트 축뿐 아니라
**상태 축(빈/대화 중/드로어 열림)**을 게이트에 넣어야 한다. 신설: overflow-both(대화 중·양 뷰포트).

### 5. 이색 디자인 요청은 은유가 잡히면 쉽다
"U 손잡이 + 위에서 내려오는 드로어"는 서랍이라는 물리 은유가 있어 세부 결정(테두리 이음·둥근
아래 모서리·점등)이 자동으로 따라왔다. 은유를 먼저 명명하면 구현 선택지가 수렴한다.
