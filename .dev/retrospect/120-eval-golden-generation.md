## 무엇을 / 왜

자동 출제하고 자기일관 기준(질문으로 검색하면 출처 문서가 나와야 함)을 부여. 최대 마찰(수제
문제)을 제거. v1=단일 청크(멀티홉·진화 OUT).

## 잘된 것
- **self-consistency가 품질 신호로 작동**: 생성 문제집을 바로 실행하면 점수가 곧 생성 품질
  (최종 5/5·100%). 검증에 ≥2/3 게이트로 박음.
- codex 8건 중 4건 수정(빈 생성=실패 박제·재시작 좀비 생성 sweep·생성 중 실행 409·출제
  프롬프트 인젝션 방어) + 3건 경계 정직화(관대 파싱·짧은 청크 카운트 제외·파일명 캡 오판 —
  docstring 명시). "고침/기각/정직화" 3분류가 자리 잡음.
- **e2e가 실 모델 습관을 실측으로 반증**: qwen이 한국어 의문문을 물음표 없이 종결("…는가") →
  엄격 파서가 절반 이상 거부, 수율 1~2/5. fast-worker가 격리 호출로 원시 응답까지 재현·진단.
  프롬프트 강조+의문형 어미 정규화(평서문은 여전히 거부)로 수율 5/5 복구.
- 작은 컬렉션 실측(문서 1개)이 다양성 상한의 결함을 노출 — **상한은 우선순위지 차단이 아니다**
  (후보 부족 시 예비분 완화).

## 잘못한 것

## 다음 작업 Context에서 상기할 것
- 형식 강제 파서(첫 줄 토큰·물음표 등)는 **실 모델의 언어 습관으로 수율을 실측**하고, 의미 보존
  정규화(어미→물음표)로 관대하게 — 거부는 평서문 같은 진짜 이탈만.
- e2e 실행 중 = 백엔드 동결 구간. 수정 대기열에 쌓았다가 e2e 후 일괄 반영.
- 생성형 기능의 검증 3종: 형식 파서 단위 + 실 생성 수율 + **산출물을 곧바로 소비시키는
  자기일관 실행**.
