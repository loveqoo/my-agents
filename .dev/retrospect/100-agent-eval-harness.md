# 100 — 에이전트 평가 하네스 (스펙 119)

## 무엇을

수치 기반 자율(Ralph)의 전제인 "에이전트가 좋아졌나"의 결정적 수치를 내는 **개발·CI 하네스**(사용자
선택). 방향 3(4개 방향 "모두 차례대로") 3번. 방향 2(Langfuse 관측) 위에 얹힘.

## 어떻게

- `tests/eval_harness.py`: `EvalCase`·`run_eval(cases, run_fn) -> EvalReport`(score=통과율). 결정적 scorer
  (trace_has/lacks·no_error·output_nonempty/contains — 행위·구조 신호 하한). run_fn 어댑터로 실행 경로 분리.
- verify_119: 단위(산술·판별력·경계) + 관통(실 채팅 mock-llm: 능력 조율형 위임·무능력 무위임).

## 잘된 것

- **"조용한 초록"을 대죄로 규정**(learning 119 ①): 신호 도구는 거짓 초록이 신호 없음보다 나쁨(루프가
  거짓을 최적화)→모든 경로 fail-closed 설계. **판별력 실측**(틀린 assertion·실패 관측이 점수를 내리는가)을
  검증에 명시(통과만 초록인 하네스 배제).
- **codex가 조용한 초록 4구멍을 잡음**(신호 도구에 적대 타자가 특히 값짐 — 넷 다 happy-path 통과, 119 ②):
  [P1] 빈 asserts 자동통과(all([])=True)→명시 실패, [P1] passthrough가 HTTP 실패를 error=False로 숨김→
  status 확인, [P2] "예외 후 계속" 검증 1 case뿐→2 case로 continue 증명, [P2] scorer 예외가 전체 중단→
  assert 실패로 접기. 자가검증이면 "통과 초록"에 만족했을 것.
- **결정성 = 자율 전제**(119 ③): LLM 텍스트 비결정→행위(trace 노드)·구조 신호를 하한(110 재사용).
- **재사용 규약**(119 ④): 데이터셋 × run_fn 분리 — 실행 경로만 갈아끼워 재사용, 어댑터가 실패 숨기지 않게.

## 배운 것 / 함정

- **신호 도구는 모든 경로 fail-closed**(119 ①) — 빈 조건·숨은 실패·예외 전부 점수를 내리게.
- **판별력 실측 + 적대 타자에 조용한 초록 맡김**(119 ②).
- **결정적 수치는 행위·구조 하한**(119 ③, LLM 텍스트 채점 지양).
- **데이터셋 × 실행함수 분리, 어댑터가 약한 고리**(119 ④).
