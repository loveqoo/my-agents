# 245 — 단기 기억 프록시: 섞인 두 축을 분리하고, 같은 슬라이스 불변식이 경로마다 다른 데이터에 깨진다 (스펙 270)

## 맥락
269(어휘)에 이어 사용자 설계대로 "프록시가 원본 대화를 쥐고 노드별로 슬라이스"를 구현. 핵심 = 파이프라인
시드가 **대화 히스토리 + 턴내 노드 출력을 한 리스트에 섞어** 노드별 제어를 막고 있던 것을 분리. 3부작 2/3.

## 발견과 교훈

### 1. 섞인 두 축을 분리하니 per-node 제어가 열렸다 — 시드가 이중 역할이었다
파이프라인 그래프는 "에이전트-윈도된 대화 전체"를 시드하고 노드가 그 위에 누적했다. 그래서 한 `messages`
리스트에 **대화(턴 가로지름)와 노드 출력(턴 내)이 섞여** 노드가 "대화만 N개"를 떼려 해도 경계가 없었다.
처방 = 대화를 **누적 상태에서 들어내** 프록시가 쥐고(시드는 현재 턴만), 노드별 슬라이스를 주입. carry/clean은
턴내 흐름만 관장. **규칙: 한 자료구조가 두 축을 겸하면 어느 쪽도 독립 제어가 안 된다 — 제어를 원하는 축을
먼저 분리하라.** 이게 268(mem0 프록시)과 완전 동형("공유 자원 + 소비자별 슬라이스")이라 271 공용화가 열림.

### 2. 같은 슬라이스 불변식(`[:-1]`)이 경로마다 다른 데이터에 깨진다 (codex High)
슬라이스 = `_window(대화, d)[:-1]` — "마지막=현재 턴이니 버린다"는 불변식. **메인 경로**의 `body.messages`는
끝이 현재 턴이라 맞다. 그런데 **재개 경로**의 세션 DB는 현재 턴이 아직 미영속(이전 대화만)이라 `[:-1]`이
**직전 assistant 메시지를 잘못 떨군다**. 같은 코드, 다른 데이터 멤버십. 처방 = `drop_last` 플래그(메인=True·
재개=False). **231·243 "재개는 원 턴 컨텍스트 축을 전수 재구성"의 변주 — 이번엔 축 누락이 아니라 *같은
축인데 데이터 형태가 달라* 불변식이 깨짐. 재개는 항상 "이 가정이 이 경로의 데이터에도 참인가"를 재확인.**

### 3. 무회귀는 "안 persist하고 매번 주입"으로 지켰다 — 도구 루프 재진입
오늘은 시드된 대화가 도구 루프 내내 보였다. 시드를 줄이면 재진입 시 대화가 사라져 회귀. 처방 = 히스토리를
**상태에 누적하지 않고**(노드마다 자기 depth로 새로 주입) **재진입에도 매번 주입**하되 기록은 첫 진입만.
"inject-but-don't-persist"라 clean의 RemoveMessage 격리·노드별 depth 독립이 안 깨진다(268 e2e 실증).

### 4. 내가 안 만든 경로는 내 초록에 안 걸린다 — codex가 재개를 잡았다
단위·메인 e2e는 전부 초록이었지만 **재개 e2e를 안 만들어서** drop_last 버그가 안 보였다. codex가 그 미검
경로(HIL 재개)를 짚음. **초록은 내가 테스트한 경로에 대한 초록일 뿐 — 안 만든 경로의 결함은 적대 타자가
잡는다.** 회귀 검증 사다리 3런의 3번(적대)이 1·2번(내가 짠 테스트)의 사각을 덮는 이유의 실례.
