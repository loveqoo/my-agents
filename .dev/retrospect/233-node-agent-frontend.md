# 233 — 노드형 에이전트 프론트: UI 노하우를 적용해 위저드에 변주 끼우기 (스펙 259)

## 맥락
전 턴에 백엔드(`LinearPipelineAgent` impl + 노드별 모델 해석 + 스키마 왕복, verify_259 15/15)를
끝냈고, 이번 턴은 프론트. 사용자 지시: **"그동안 UI 개선한 것 잘 파악해보시고 그 노하우를 적용해주세요."**
+ 내 노드 카드 UI 계획에 "일단 동의합니다."

## 무엇을 배웠나

### 1. "노하우 적용"은 최근접 형제 변주 + 컨테이너 구조를 먼저 읽는 것
내 초안은 **플랫 폼** 전제였다("종류 고르면 노드 편집기가 뜬다"). 실제 `AgentForm`은 스펙 239
**4단계 위저드**(정체성→하는 일→세부→요약)였다. 이걸 안 읽고 짰으면 배치가 통째로 어긋났다.
- 모델·페르소나는 **정체성 단계**에 있다 → 노드형은 *거기서* 숨겨야 한다(하는 일 단계가 아니라).
- 노드 편집기는 **하는 일 단계**의 `isArtifactForm ?` 분기 옆에 형제로 끼운다.
- 저장 게이트(`stepOk(1)`·`saveDisabled`)·요약 카드까지 변주마다 손봐야 한다.
- **최근접 형제**(`artifact_form`/`ArtifactSpecEditor`, 190)가 전 배선을 이미 보여준다 —
  카드+add/remove+`xxxValid()` 게이트+왕복 3지점(configOf·save·reload). 그대로 계승하니
  드리프트 0. 노하우 = 코드로 이미 존재하는 관용구를 *찾아* 베끼는 것이지 새로 발명하는 게 아니다.

### 2. 표면을 숨기면 그 데이터의 출처를 하위에서 재구성(합집합 파생)
결정 #2 "에이전트-레벨 도구 숨김". 그런데 백엔드 `ctx.tools`는 `cfg.mcps`/`cfg.vectorTables`(풀)에서
빌드된다 — 풀이 없으면 노드가 필터할 대상도 없다. 해법: **`finalizeForm`이 저장 직전 풀을 노드 도구
합집합에서 파생**. 노드가 도구 `add`를 고르면→소유 서버 `calc-tools`를 `cfg.mcps`에 역산. UI 표면을
지우되 계약(풀 존재)은 하위 선택의 합집합으로 되살린다. 부수효과: 풀=합집합이라 노드 도구 ⊆ 풀이
*구조적으로* 보장(권한 상승 불가능 — 필터가 걸 게 없음).

### 3. RAG 단일 도구가 노드별 스코핑을 못 하게 한다(설계 제약을 v1 한계로 정직화)
`search_documents`는 컬렉션 수와 무관한 **단일 도구**(build_rag_tool이 전체 컬렉션 하나로). 그래서
"노드별로 컬렉션 다르게"가 도구 이름 필터로 표현 불가. v1: "문서 검색"을 노드 도구로 제공하되 풀
파생은 전체 컬렉션 → 문서화된 한계로 남김. 인프라 제약을 억지로 우회하지 말고 경계로 기록.

### 4. antd6 셀렉터는 여전히 getByText로 (learning 080 재확인, 2회 미스)
도구·페르소나 Select를 `.ant-select-selection-placeholder`(개명된 클래스)로 2번 잡으려다 타임아웃.
**getByText(placeholder)** 로 바꾸니 즉시 통과 — 클래스 가정 말고 렌더 텍스트로. 이 함정을 이미
learning 080에 적어놨는데도 처음에 클래스로 짰다: *기록해둔 함정도 그 순간 안 떠오르면 다시 밟는다.*
브라우저 하니스는 처음부터 getByText 기본값으로.

### 5. 기능 검증 = 왕복 실측(외형 아님)
브라우저에서 저작→생성으로 끝내지 않고 **브라우저 세션으로 `GET /api/agents` 재조회**해
`impl=pipeline`·nodes 보존·conformance·도구 파생을 단언(메모리 `ui-verification-must-be-functional`).
스샷 한 장이면 "렌더됨"만 보였을 것 — 실제로 저장·직렬화·파생이 도는지는 API 왕복만 안다.
