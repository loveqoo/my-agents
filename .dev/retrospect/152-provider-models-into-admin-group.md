# 152 — 메뉴 감사: 프로바이더·모델을 관리자 그룹으로 (스펙 174)

개발자 질문 "관리자 하위 메뉴는 관리자만 사용하는 게 맞나요?"에서 출발한 감사.

## 배운 것
- **메뉴 감사는 양방향으로 봐야 한다.** (1) 관리자 그룹 항목이 *정말* 서버에서 막히나(UI만 숨김이
  아니라) — 5개 다 `require(...,"manage/run")` 강제 확인, 함정 없음. (2) *역방향* — 상단(전원 표시)
  항목 중 사실상 관리 전용인 게 섞여 있나 — **프로바이더·모델**이 변이 전부 `_manage`(비관리자 403·보기만)
  인데 상단에 있었다. 한 방향만 보면(관리 그룹만 검사) 이 역방향 불일치를 놓친다.
  [[installed-guard-isnt-covering-guard]]의 변주: "게이트 있나"뿐 아니라 "게이트 위치와 메뉴 그룹이
  일치하나"까지.
- **메뉴 가시성 ≠ 기능 게이트.** 프로바이더·모델 메뉴를 숨겨도 에이전트/RAG 폼의 모델 선택은 무영향 —
  목록은 `GET /models`(로그인만)로 읽고 변이만 `_manage`. 읽기/쓰기 게이트가 분리돼 있어 "관리 UI는
  숨기되 참조는 열림"이 가능. 메뉴 이동 전에 이 분리를 확인해 기능 무회귀를 보장.

## 검증
tsc clean·브라우저 사이드바 순서 실측 4/4(관리자 그룹 뒤·상단 없음·도구 앞). 비관리자 미표시는 기존
5개와 동일 `is_superuser` 게이트라 코드 논리로 확인.

## OUT
- 라우트 접근 가드 추가 불요(서버 `_manage`가 이미 강제 — 메뉴 숨김은 방어심화). 빌딩 블록 내
  권한(permissions) 재분류=별도 축.
