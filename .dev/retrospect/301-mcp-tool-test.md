# 301 — MCP 도구 시험 (스펙 326)

## 무엇을 했나

사용자 요청 "MCP 테스트하는 기능" → 범위 결정 3(실호출까지 / 블록 상세 드로어 / 승인 도구=경고 후
허용) → `POST /mcp-servers/{id}/test-tool` + 드로어 "도구 시험" 패널. 회상 시험(084)·검색 시험(072)의
MCP판으로 시험 3형제 완성.

## 핵심 배운 것

### 1) 시험 경로 = 실전 경로 재사용이 곧 기능이다
새 연결 코드 대신 채팅과 같은 `build_mcp_tools`를 재사용하고 결과를 calls_sink에서 회수했다. SSRF
가드·자격증명 복호·어댑터 swallow 해제·마스킹+캡(320)이 전부 공짜로 따라온 것 이상으로, **시험이
보여주는 표면이 채팅이 기록하는 표면과 바이트 단위로 동일**해진다 — 시험 통과=실전 리허설 통과.
별도 경로를 팠으면 "시험은 되는데 채팅은 안 되는" 이중 진실이 생겼을 것.

### 2) 우선순위 사다리 리졸버에서 "끄기"는 키 삭제가 아니라 명시 False
그래프 밖 interrupt()를 피하려 tools_meta에서 approval 키를 **걷어냈더니** 리졸버의 레거시 폴백
(`_APPROVAL_ACTIONS`)이 되살아나 delete_record가 다시 게이트됐다(U5 실패). 폴백이 있는 해석기에서
비활성화는 부재(absence)가 아니라 **명시 값**(`{required: False}`)으로 — 부재는 "다음 단계로 넘어감"
이지 "꺼짐"이 아니다. [[gate-on-intent-value-not-mutable-baseline]]과 동류(의도를 값으로 박아라).

### 3) 래퍼 밖에서 터지는 실패도 시험 결과다
StructuredTool은 인자 스키마 검증을 `_run` **이전**에 하므로 래퍼의 except가 못 잡는다 — 라우트에서
안 잡으면 인자 틀림이 500으로 새 나간다. 시험 기능에선 "인자 틀림"도 정당한 결과(사용자가 형식을
배우는 통로)라 같은 마스킹 규칙으로 error에 실었다. 부수효과 없는 검증 실패와 실행 실패를 한 표면에.

### 4) 테스트 인프라 확장은 이웃 단언을 낡게 한다 (320→151)
스펙 320이 mock에 failing_op를 추가(라이브 등록·시드 제외)한 뒤 verify_151의 "라이브 탐색=3건"
단언이 조용히 낡아 있었다 — 이번 회귀 실행에서야 발견(3→4 갱신). 라이브 자원에 개수 단언을 걸면
그 자원을 늘리는 스펙이 원격지 테스트를 깬다 — 개수보다 포함(contains) 단언이 내구적.
