# 회고 183 — RAG 컬렉션에서 '평가하기' 단축 진입 (스펙 197)

## 무엇을 했나
컬렉션 상세(문서 관리 드로어)에 '이 컬렉션 평가하기' 버튼 추가 → 평가 화면으로 이동 + 이 컬렉션이
프리필된 '새 문제집' 창을 연다(이름만 입력, 문제 자동생성 없음 — 스펙 195 정책 일관). 순수 프론트 배선.
197 e2e 9/9(드로어→버튼→평가전환→모달 rag·컬렉션 프리필→생성 collection_id 고정)·tsc0·스샷.

## 배운 것

### 1. 뷰 간 "진입 파라미터 전달"은 새 메커니즘이 아니라 기존 패턴의 복제다
AdminShell은 라우터 없이 `view` 상태로 뷰를 바꾼다. 뷰A(컬렉션)→뷰B(평가)로 **값**(컬렉션 id)을 넘기는
건 새 배선이 필요해 보였지만, 이미 **똑같은 형태**가 있었다: 에이전트 "테스트"→Playground가
`playgroundAgent` 상태 + `initialAgentId` prop + `onConsumedInitial`(1회 소비) 3종으로 값을 전달한다.
그대로 복제해 `evalCollection` + `initialCollectionId` + `onConsumedInitial`로 배선했다. **교훈: 상태
기반 뷰 전환에서 파라미터를 넘길 땐 "이 앱이 이미 뷰 간 값을 어떻게 넘기나"를 먼저 찾는다 — 대개 동형
패턴이 있고, 복제가 발명보다 일관되다(1회 소비 콜백으로 재진입 시 모달 재열림도 막힌다).**
([[index-layer-for-context-recall]]의 컴포넌트판 — 공용 패턴 재사용)

### 2. "빠르게"의 정도는 최근 정책과 맞춰 사용자와 합의한다
'평가하기'를 "즉시 빈 문제집 생성+드로어 열림"(가장 빠름)으로 할 수도 있었지만, 바로 직전(스펙 195)에
**자동 생성을 없앤** 참이었다 — 즉시 생성은 그 정책과 어긋나고 빈 문제집을 양산한다. 사용자에게 두 방식을
제시하니 "모달 열기(이름만 입력)"를 골랐다. **교훈: "빠르게 해달라"는 요구를 극단(원클릭 자동)으로 풀기
전에, 방금 세운 정책(자동 최소화)과 충돌하는지 보고 사용자와 정도를 합의한다 — 속도와 정책 일관성은
트레이드오프다.**
