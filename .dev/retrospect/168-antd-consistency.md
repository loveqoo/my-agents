# 168 — antd 일관성: 토스트 표준화 + 비-antd 감사

**스펙**: docs/spec/186 · **관련**: 167(커스텀 토스트 보존 경위)·166(shared.Drawer 커스텀 발견)

## 무엇을 했나
사용자가 AgentsView의 커스텀 플로팅 토스트(antd6 포팅 잔재)를 짚어, 표준 `message.success`로 통일.
감사 중 ApprovalsView에서 **같은 패턴**을 추가 발견해 함께 통일. 나머지 비-antd 재구현은 정당/사고로
분류.

## 무엇이 잘못됐고 무엇을 배웠나

### 1. "보존"이 항상 옳은 건 아니다 — 레거시 불일치는 드러나면 정리 대상
스펙 185 Phase B에서 커스텀 토스트를 "행동 보존" 명목으로 지키고 회고까지 썼는데(167), 그건
**리팩터 중엔 옳았으나** 그 토스트 자체가 의도 없는 레거시 불일치였다. 사용자가 "왜 커스텀을 썼냐"
물었을 때 내가 처음에 마치 지켜야 할 설계처럼 답한 게 오해를 불렀다. git blame으로 c9848df(antd6
포팅) 잔재임을 확인하고 정직하게 정정.

- **처방**: 리팩터의 "행동 보존"과 제품의 "그 행동이 옳은가"는 **다른 질문**이다. 보존은 리팩터를
  깨끗하게 하려는 규율일 뿐, 보존한 행동을 정당화하지 않는다. 리팩터 보고 시 "이건 보존했지만 원래
  이래야 하는지는 별개"라고 **레거시 냄새를 함께 표면화**하라. 사용자가 묻기 전에.

### 2. 한 인스턴스를 고칠 땐 같은 패턴을 전수 grep (두 번째가 숨어 있다)
AgentsView 토스트만 고치면 됐을 것 같았으나, 감사에서 ApprovalsView가 **동일 커스텀 토스트**를
갖고 있었다(top:16·center·pointerEvents:none·Alert). 하나를 고치면 같은 패턴의 형제를 grep으로 찾아
함께 고쳐야 불일치가 안 남는다.

- **처방**: 불일치를 고칠 때 그 **시그니처**(여기선 `showIcon message={toast}`·`pointerEvents:'none'`)로
  전 코드베이스를 훑어 형제 인스턴스를 전수 처리. 하나만 고치면 불일치가 다른 곳에 남는다.

### 3. 감사는 "비-antd"를 세는 게 아니라 "정당/사고"를 가르는 것
grep이 6개 후보를 뱉었지만, 5개는 정당(디자인시스템 층·매트릭스·모바일셸·a11y 카드·전파가드 false
positive)이고 사고는 1종(커스텀 토스트)뿐이었다. "antd 안 씀"이 곧 결함은 아니다 — 네이티브
`<button>`은 접근성상 오히려 옳고, DataTable/Drawer/Desc는 의도된 커스텀 층이다.

- **처방**: 일관성 감사의 산출은 "위반 목록"이 아니라 **"정당 vs 사고 분류 + 각 사유"**. 정당한 커스텀을
  기계적으로 antd로 바꾸면 오히려 기능/접근성을 잃는다. 각 건의 존재 이유를 먼저 물어라.

## 복리 포인트
- 앱의 성공 토스트가 전부 표준 `message`로 통일 → 일관성. 커스텀 토스트 패턴 재발 시 grep으로 즉시 포착.
- 비-antd 커스텀 층(DataTable/Drawer/Desc) 존재 이유를 스펙에 기록 → 다음에 "왜 antd 안 씀?" 재질문 방지.
