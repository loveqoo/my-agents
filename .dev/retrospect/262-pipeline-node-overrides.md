# 262 — 스펙 287(노드형 오버라이드) 회고

## 무엇을 했나
노드형 에이전트의 플레이그라운드 오버라이드 지원. 사용자와의 범위 협상(노드 추가/삭제=테스트 범위
밖)을 서버 강제 규칙(길이 일치 merge)으로 번역. 백엔드=화이트리스트 merge+트레이스 표면화,
프론트=폼과 같은 공용 NodeListEditor를 구조 잠금 모드로 임베드.

## 배운 것

1. **"통짜 교체"와 "필드 merge"는 권한 의미가 다르다.** 처음 제안한 통짜 배열 교체는 구현이 가장
   쉽지만 노드 추가/삭제가 부수 효과로 딸려온다 — 사용자가 그 부수 효과를 짚어 범위를 좁혔다.
   전송 형식은 그대로(배열)여도 서버가 **merge로 해석**하면 구조 변경이 원천 불가능해진다.
   "클라이언트가 보내는 것"과 "서버가 받아들이는 것"을 분리해 설계하면 UI 잠금은 UX일 뿐 보안
   경계가 아니게 된다(fixedStructure prop 주석에 명시).

2. **효과 실측 채널을 먼저 찾으면 통합 테스트가 싸진다.** "오버라이드가 진짜 먹었나"를 응답 텍스트
   로 재려면 mock-llm 출력 형식에 결합하게 되는데, trace["mcp"](도구 호출 실측)를 채널로 쓰니
   "노드 도구 제거 → echo 호출 1→0"이 한 단언이 됐다. 086의 ASGI 하네스+SSE trace 파서 재사용으로
   서버 기동 없이 실 DB 통합이 됐다(첫 실행 24/24).

3. **codex 적대는 "동등 표면" 판정에 유용했다.** Medium 2건 모두 "새 구멍"이 아니라 "기존 오버라이드
   시맨틱의 노드형 확장"임을 코드 라인으로 확인해줬고(승인 게이트·enabled_tools 불변), 부수로 기존
   결함(historyDepth 비정수→500)을 찾아 이 참에 봉합했다. 인가 인접 변경은 스스로 "완화 아님"을
   주장하지 말고 적대자에게 여집합을 시키는 게 맞다(기존 결정 재확인).

4. **정책 의존성은 코드 주석+스펙 양쪽에 남겨야 한다.** vectorTables 허용은 "컬렉션=사용 공용"(211)
   정책 위에서만 안전하다. 정책이 바뀌는 순간 이 allowed 키가 구멍이 되므로, 재검토 트리거를
   스펙 검증 결과에 명시했다(complement=정직 경계 계열).

## 아쉬운 것
- 2단계(세부)에 temperature를 숨긴 근거(노드 모델 등록 params 소유)는 코드 추적으로 확인했지만,
  노드별 temperature 오버라이드 요구가 나오면 노드 필드로 추가해야 한다(현재 노드 스키마에 없음 —
  폼과 같은 제약이라 정합).
