# 235 — 노드 출력 형식 강제: "강제"는 보장이 아니라 시도+정직한 실패 (스펙 261)

## 맥락
사용자가 259→260→261 순으로 노드형을 키워왔고, #3=출력 형식 강제를 먼저 하자고 했다. 임의
OpenAI 호환 엔드포인트(mock 포함)라 네이티브 structured-output에 못 기댄다 → 프롬프트 지시 +
파싱·검증 + 1회 보정 + 정직한 폴백의 3중 best-effort로 구현.

## 무엇을 배웠나

### 1. "강제(enforce)"는 신뢰 못 할 생산자 위에선 "보장"이 아니라 "시도+정직한 실패"
mock/미협조 모델은 요청해도 JSON을 못/안 낸다. 그래서 "반드시 JSON"을 코드로 *보장*할 수 없다.
할 수 있는 건: (a) 프롬프트로 유도, (b) 파싱·검증, (c) 1회 보정, (d) 그래도 실패면 **거짓 JSON을
지어내지 않고 원문 통과**. "형식이 안 맞으면 빈 {} 라도 채운다"는 유혹을 물리치는 게 정직 — 소비층이
"이건 형식 위반"임을 알 수 있어야지, 가짜 성공으로 덮으면 안 된다(learning 087/092 결).

### 2. 폴백값은 "보정물"이 아니라 "원래 노드 응답"이어야 한다 (U5가 뒤집음)
처음엔 보정 실패 시 보정 시도의 결과("여전히 산문")를 통과시킬 뻔했다. 테스트를 짜다 깨달았다:
보정은 "이걸 JSON으로 바꿔줘"라는 *변환 시도*일 뿐, 노드의 진짜 답은 **원문**이다. 변환이 실패했는데
변환 산물을 노드 출력으로 삼으면 원래 의미까지 왜곡된다. 폴백은 원문 보존. 테스트 기대값이 틀렸고
코드가 옳았다 — 단위 테스트를 *동작 명세*로 쓰니 이 구분이 드러났다.

### 3. 강제는 "최종 응답"에만 — 도구 루프 중간을 건드리면 깨진다
JSON 강제를 모든 모델 응답에 걸면, 도구를 호출하는 중간 응답(tool_calls 有)까지 JSON으로 강제하려
들어 도구 루프가 깨진다. `_finalize`를 `tool_calls`가 없는 최종 응답에만 적용 — 260의 "clean은 첫
진입에만"과 같은 결: *언제 개입하느냐*를 그래프 신호(tool_calls/ToolMessage)로 정확히 좁힌다.

### 4. 관대 추출은 적대 표면 — codex로 넘길 것
`_coerce_json`이 첫 `{`~마지막 `}`를 슬라이스한다. 관대함은 편의이자 위험(거대 입력·중첩·인젝션).
지금은 json.loads가 방어하지만, "관대 파서=신뢰경계"(learning 075)라 #2 codex에서 자원고갈·보정
무한루프·원문 폴백의 은폐 가능성을 적대 검토 대상으로 명시 기록.

### 5. 세 번째 확장도 입구가 적었다 — 통과-보존 구조의 복리
format/fields도 `{**n}` spread + 노드 통째 저장이라 손댈 입구는 pipeline+프론트 둘. 259에서 노드를
"통째 흐르는 데이터"로 설계한 게 260·261 확장을 싸게 만들었다(자산화의 복리 — 한 번 잘 그은 경계가
세 스펙을 얹게 함).
