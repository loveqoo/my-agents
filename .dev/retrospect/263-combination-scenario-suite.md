# 263 — 기능 조합 시나리오 스위트 (스펙 288)

## 무엇을 했나

기억×도구×세션·영속×오버라이드×impl 6종(직접/pipeline/orchestrate/route/plan_execute/비영속)의
조합 31개 시나리오를 실모델(qwen3.6-35b + e5 임베딩)로 한 명령에 도는 스위트를 만들었다
(`tests/suite/run.py`). 단언은 전부 기록 기반(trace mcp/toolDiag/brokerCalls/graph/memoryRecalls·
recall_diag·DB 행 실측), 픽스처는 `suite-` 접두 멱등 부트스트랩. 프리플라이트=실모델 없으면 exit 2.

## 잘된 것

- **스위트가 첫 실행에서 곧장 값을 했다**: 24/28에서 걸린 4건이 전부 "몰랐던 플랫폼 계약"이었다 —
  ① 히스토리는 클라이언트가 body.messages로 누적 전송(서버는 DB 재구성 안 함), ② 노드형 풀
  (vectorTables/memories)은 폼이 파생하는 책임이라 API 직생성 픽스처가 빠뜨림(조용한 미바인딩),
  ③ 조율형 위임 후보=활성 버전 보유+lexical 발견 토큰 필요, ④ in-process ASGI는 lifespan 미실행이라
  체크포인터 수동 초기화 필요. 문서 어디에도 한 줄로 안 적혀 있던 것들이 시나리오 실패로 드러났다.
- **기록 기반 단언 원칙이 실모델 비결정성을 견뎠다**: 최종 연속 2회 전판 초록(31/31 — 322s·292s),
  flaky는 두 판 합쳐 1건(echo 미호출→재시도 통과, 1차 실패 내용까지 리포트에 노출돼 정직 표기 동작
  실증). 프롬프트를 명령형으로 강하게 쓰면 로컬 35B도 도구 지시를 거의 안정적으로 따른다.
- **적대 리뷰(codex)가 9건(High 4)을 냈고 전부 수용 가능했다**: 특히 "부재 단언은 관측 존재가
  전제"(trace 없으면 전부 공허 통과)는 자가검증으로는 절대 못 봤을 결. learning 119(silent green)의
  스위트판이다.

## 배운 것

- **부재(absence) 단언은 관측 채널의 존재를 먼저 단언해야 한다** — "도구 안 불림"과 "관측 없음"은
  기록상 동형이다. trace 필수 게이트를 기본으로 깔았다(codex #1).
- **재시도는 실패를 삼키기 쉽다** — flaky 통과여도 1차 실패 내용을 리포트에 보존하고 `--strict`로
  게이트화(codex #4). "정직 표기" 원칙은 상태 표기만이 아니라 exit code까지.
- **픽스처 재사용 판정도 실증으로** — chunk_count>0(#5)·description 해시(#6)는 선언이지 실증이
  아니다. 검색으로 토큰 히트를 확인하고(임베딩 딥 핑 겸용), 핵심 필드를 실측 대조.
- **같은 유저 스코프에 자동 추출이 누적되면 회차 간 독립이 깨진다**(#8) — 부트스트랩이 시드 토큰 외
  기억을 청소해 기준선 복원.
- **클라이언트 계약을 러너가 재현해야 한다** — 세션 히스토리(누적 전송)와 세션 재개(DB→messages
  재구성)는 서로 다른 경로라 둘 다 시나리오로 가른다(codex #7).
