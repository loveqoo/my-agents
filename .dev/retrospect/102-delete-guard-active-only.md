## 잘된 것
- **형제 가드 재정렬을 근거로 삼음**: references.py 주석이 스스로 "usedBy 배지(활성만) ↔ 삭제(버전까지)"
  불일치를 적어뒀다. 완화가 그 어긋남을 해소 → 단순 완화가 아니라 일관성 회복으로 정당화.
- **단일 함수라 RAG·MCP 삭제·MCP rename 셋이 자동 일관**(드리프트 0). 완화 범위를 스펙에 명시.
- **검증에서 조용한 red를 발견**: verify_093을 돌리자 전부 404 → 스펙 112가 라우트에 assert_may_manage를
  추가하며 직접호출 테스트를 깼는데 재실행 안 돼 커밋된 채 red였음을 포착. principal 스텁으로 복구.
- codex rung3: P1/P2/P3 전부 "없음" — 활성 참조 누출·범위 누출·principal 스텁 무력화·fixture 정합
  4각도 모두 clean.

## 아쉬운 것 / 리스크
- **직접호출 테스트가 게이트 추가로 조용히 깨졌던 것**은 이번에 우연히 발견. 게이트 스펙(112)이 호출처를
  안 쓸어서 생긴 부채. 완료조건 후보로 "전체 verify 주기 재실행"을 남김([[121-...]] learning).
- 트레이드오프(오래된 버전 롤백 시 자원 없이 동작)는 런타임 degrade에 의존 — 사용자가 수용했으나, 후속
  으로 "삭제 시 과거 버전 config에서 이름 스트립"을 옵션으로 남겨둠(OUT).
