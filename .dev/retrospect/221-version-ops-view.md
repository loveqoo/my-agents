# 회고 221 — 집계 화면의 4대 함정: 누수·노출·조용한 캡·의미 모호 (스펙 244, AgentOps D 마감)

## 무엇을 했나
버전 운영 화면 — GET /agents/{id}/ops(버전별 평가·자동 회귀·피드백 집계)+상세 드로어 버전 행 칩.
"Version 하나가 운영 단위"의 화면 면이자 AgentOps 로드맵(A 귀속→B 자동 회귀→242/243 버전 실행→D)의
마지막 조각. codex 4건 전부 수정.

## 배운 것

### 1. 집계 엔드포인트는 4개 함정을 정례 점검하라 — 이번에 넷 다 걸렸다
(a) **조인 누수**: 중복 FK(feedback의 message_pk와 session_pk)가 불일치할 수 있으면 조인에 일치를
강제(정상 경로만 믿지 말 것). (b) **노출 범위**: 집계=전 유저 데이터의 요약 — 개별 행 권한과 별개로
"요약을 누가 보나"를 다시 정해야(사용 가능≠운영 지표 열람, may_manage로 승격). (c) **조용한 캡**:
"최신 N개 순회"는 편하지만 과소집계 = no-silent-caps 위반 — 집계는 SQL GROUP BY로 전수(DISTINCT ON이
"버전별 최근 성공" 같은 축을 싸게 준다). (d) **지표 의미**: "최근 성공 점수"를 "평가 점수"로 표기하면
최신 실패가 초록 뒤에 숨는다 — 라벨에 의미를 박고(최근 성공) 실패 카운트를 병기.

### 2. 컴포넌트에 훅을 넣을 땐 조기 return 지도를 먼저 본다
ops 조회를 위해 컴포넌트를 분리했다가 프롭 배선 12개가 깨짐 — 되돌리고 훅을 조기 return **이전**
최상단에 두는 게 정답이었다(조건은 훅 내부에서). 분리는 프롭 수가 적을 때만 싸다.

### 3. 로드맵 마감 — 제안 검토(대조)→갭 4개→스펙 5개(240~244)로 AgentOps 루프 완성
피드백→수확→평가(버전 귀속)→초안 평가(배포 전)→활성화→자동 회귀→버전 운영 화면이 한 바퀴.
외부 제안을 기존 자산과 대조해 갭만 구현한 덕에 5스펙으로 끝났다(통째 구현이면 중복 공사).
