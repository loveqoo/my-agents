# 회고 219 — 자동 트리거는 수동 경로의 게이트를 전부 상속해야 한다 (스펙 241, AgentOps B)

## 무엇을 했나
버전 활성화(activate·revert 승격) 시 그 에이전트의 회귀 자산(실행 이력∪수확 문제집, 최근 3개)을
자동 재실행. env.trigger="activate"+240 버전 박제로 이력에서 "자동 회귀 · vN" 식별. fire-and-forget
(실패해도 활성화 무영향). verify 7/7 + codex 2건 수정.

## 배운 것

### 1. 자동화 경로는 수동 경로의 게이트 목록을 체크리스트로 상속해야 한다
수동 start_run에는 assert_may_manage(문제집 소유권)·비용 가드·running 가드가 있는데, 자동 트리거를
새로 쓰면서 소유권 게이트를 빠뜨렸다(codex #1 — 내 에이전트로 남이 실행한 이력이 있으면 남의
문제집을 내 활성화가 실행). **같은 동작의 자동 버전을 만들 땐 수동 버전의 게이트를 열거해 하나씩
상속 여부를 판정**(상속 안 하면 사유 명시). [[installed-guard-isnt-covering-guard]]의 트리거 판.

### 2. 자동 트리거의 비용 축은 "동시성"이 아니라 "반복"이다 — 멱등 키를 설계하라
running 가드(동시 1)는 있었지만 같은 버전을 재활성화하면 매번 새 런 — 반복 축이 뚫려 있었다.
처방=자연 멱등 키(문제집×에이전트×버전×trigger)로 dedupe: 같은 버전은 1회만, 새 버전만 새 런.
자동화는 "몇 번 눌러도 같은 결과"가 기본값이어야 한다.

### 3. fire-and-forget은 계약이다 — 트리거 실패가 본동작을 깨지 않게 전체를 감싼다
자동 회귀의 어떤 실패(후보 조회·가드·태스크 생성)도 활성화를 깨면 안 된다 — try/except 전면 +
스킵은 로그. 대신 실행 자체의 실패는 런 status=error로 이력에 정직하게 남는다(조용한 실패와 다름).

## 다음에 적용
- 수동 동작의 자동화 = 수동 게이트 전수 상속 체크(소유권·비용·중복·검증).
- 자동 트리거엔 멱등 키(무엇×무엇당 1회인지)를 먼저 정의.
