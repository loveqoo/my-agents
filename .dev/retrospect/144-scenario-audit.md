# 144 — 사용 시나리오 감사 (검증 축1) (스펙 166)

축2(오버플로) 골격을 축1에 적용: "가상 사용자가 목표를 완수하나 — 어디서 막히나".

## 한 것
여정 아티팩트(`scenarios.md`: 페르소나+단계+기대결과) + 러너(`scenario-audit.mjs`, Playwright 실행+단계별
assert+스크린샷+생성 엔티티 API 정리). J1 저마찰 생성→대화, J2 지식 붙이기. fast-worker 위임(기계적 구동),
메인이 적대 트리아지.

## 결과
J1/J2 **7단계 전부 ok·막힘 0**. 핵심 감시점(J1: 생성=v1 초안이라 대화 막히나)이 오히려 **잘 처리**돼
있었다 — 초안을 즉시 플레이그라운드서 대화 가능 + "초안/미반영 초안" 배지로 명확히 표시. 저마찰
생성→즉시 사용이 실제로 됨.

## 배운 것
- **clean pass도 정직한 산출물** — 모든 감사가 버그를 내야 하는 게 아니다. 가치는 "적대적 + 기대결과
  글로 박제 + 정직 보고"라서 **믿을 수 있는 통과**라는 것. 관대한 통과(스폿·눈대중)와 다르다. 없으면
  없다고, 근거(스크린샷·단계별 대조)와 함께.
- **clean이어도 육안 검증은 한다**(축2 원리 재적용). fast-worker의 7/7 초록을 그대로 믿지 않고
  스크린샷을 열었다 — J1-4에서 실제 응답+초안 배지 확인, J1-2에서 "모달 잔류" flag 포착.
- **소프트 flag는 손으로 흔들지 말고 코드로 추적**. "생성 후 모달 잔류"를 애니메이션으로 넘기지 않고
  핸들러(`setFormOpen(false)` 무조건 실행) 확인 → 페이드 프레임 타이밍 아티팩트로 확정(실버그 아님).
  적대적이란 = 소프트 flag도 코드까지 내려가 참/거짓을 못박는 것. (fast-worker 판단은 옳았으나 근거를 확정.)
- **위임 분업이 맞았다**: 기계적 브라우저 구동(fiddly 셀렉터·rc-virtual-list 숨김 클론 함정)은 fast-worker,
  판단(기대결과 정의·트리아지·soft flag 코드추적)은 메인. fast-worker가 자기 스크립트 버그(record 인자
  순서·셀렉터)를 스스로 잡고 정직 보고 — 위임이 작동.
- **정리 규율**: 생성 엔티티 `scn-` 접두어+API DELETE+DB 재조회로 0 확인. 감사가 dev DB를 오염시키면
  다음 감사가 오탐. 부수효과 있는 감사는 정리까지가 한 단위.

## 검증
scenario-audit.mjs 실행 7/7 ok·정리 후 DB 잔류 0. 스크린샷 육안(J1-4 응답+초안 배지, J1-2 모달=페이드
아티팩트). 소프트 flag 코드추적으로 실버그 아님 확정. 수정할 코드 없음(핵심 경로 건전).

## OUT
- 더 많은 여정(복제·A2A·승인·평가). 소프트 마찰 자동 판정(LLM judge). 축3(문구·평이함) 감사.
  드로어/모달 오버플로(축2 확장). 상시 자율 감사 루프.
