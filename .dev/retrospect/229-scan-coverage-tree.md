# 회고 229 — 전수 스캔의 커버리지는 "화면 목록"이 아니라 "열 수 있는 상태의 트리" (스펙 250·252)

## 무엇을 했나
중복 전수 스캔(250: 13건 제거·유지 5건 근거 기록) → 승인 개편(251) → RAG·평가 점검(252: 소수술
5+드로어 탭 분리+문제 편집 폼). 3중 검증(deep-reasoner 정독+기계 텍스트 스캔+육안 확정) 체계 정착.

## 배운 것

### 1. 스캔 커버리지의 단위는 화면이 아니라 "도달 가능한 상태"다 — 사용자가 두 번 증명
250에서 14화면+오버레이를 스캔했다고 믿었지만, 사용자가 연달아 사각을 짚었다: 상세 탭 아래 반복
제목(내가 만든 화면인데 열어서 안 봄), 문제 편집 폼(드로어 속 폼 — 오버레이의 오버레이). 화면
목록 순회는 1층만 돈다. **전수라 부르려면 상태 트리(화면→드로어→폼→긴 데이터 상태)를 열거**해야
하고, "긴 값" 시드(60자 파일명)처럼 데이터 축도 상태다. 다음 스캔 준비물: 진입 경로 목록(어느
버튼이 어떤 오버레이를 여는가)을 먼저 만들고 그걸 체크리스트로.

### 2. 판정 기준은 재발마다 넓어진다 — "완전 일치"에서 "같은 말+부연"으로
스캐너(에이전트·기계)가 못 잡은 것들은 전부 기준의 구멍: 후크 붙은 제목(구성 — 무엇을…), 라벨
반복 컬럼(문제집 탭의 문제집 컬럼), flex 스페이서(스타일 선언은 있으나 효과 실측 없음). 잡을
때마다 기준을 스펙에 갱신했고, 2차 스캔은 보강 기준으로 즉시 성과(배치 h4 등 6건).

### 3. "건전 판정 + 근거 기록"이 스캔의 절반이다
수정 13건만큼 가치 있던 것이 유지 9건의 근거 기록(KPI 관용·마스터-디테일·디버그 통로 의도·점진
공개) — 다음 스캔·다음 AI가 같은 후보를 재심하지 않는다. 스캔 산출물 = 수정 + 판례집.

### 4. flex 함정 소수집(이번 주 실측 3건)
①flex:1 값 입력 옆 flex:1 스페이서 = 폭 반분(정렬은 marginLeft:auto로) ②antd Tag는 기본
nowrap — 긴 문장 태그는 whiteSpace:normal 짝 ③드롭다운 폭은 popupMatchSelectWidth 확인.
