# 257 — 비영속 승인 고정: 문구가 약속한 상태는 UI가 만들어야 한다 (스펙 282)

## 맥락
281 문구("'승인 없음' 상태의 도구만 실행할 수 있습니다") 확정 직후 사용자: ①"그렇게 말했으면 각
도구를 '승인 없음' 상태로 고정해야" ②승인 목록 폰트 불일치(<code> 서버명) ③(실행 중 추가) 헤더
"(n개 · 선택)"도 고를 수 없으니 거짓 어포던스.

## 발견과 교훈

### 1. 안내 문구는 상태의 서술이 아니라 UI가 이행할 계약이다
"X 상태만 실행된다"고 써놓고 컨트롤이 X가 아닌 값을 보여주면, 문구와 화면이 서로를 반박한다.
처방: 비영속이면 Select 값='승인 없음'+잠금(표시), 저장은 finalize가 배선 도구 전부에
required:false 파생(폼 상태 불변 — 영속 복귀 시 원래 값 복원, setEphemeral 파괴 대신 저장 직전
파생 패턴). **문구를 고치는 지시를 받으면 "그 문구가 참이 되게 하는 상태 변화가 UI에 있는가"까지
따라가라** — 문구 수정(281 후속)과 동작 수정(282)은 한 세트였다.

### 2. 완화의 자동화는 게이트 위치를 먼저 확인하고 경계를 스펙에 적는다
'승인 없음' 자동 기록 = 완화 자동화 — 177 완화 게이트(관리자만 저장)는 서버가 계속 강제하므로
새 우회는 없고, 결과적으로 "비영속+도구 저장=관리자 전용"이 됨(비-admin은 403). 위험 기본값
도구가 무승인이 되는 트레이드오프는 "비영속의 대안=실행 자체 불가(237)"였으므로 관리자의 비영속
선택이 곧 그 결정. **자동화가 보안 게이트를 지나는 값을 만들면, 게이트가 서버에 있는지 확인하고
그 함의(누가 저장할 수 있게 되는가)를 스펙 경계 절에 명시.**

### 3. 상태에 따라 어포던스 라벨도 뒤집힌다 — '선택'은 고를 수 있을 때만
헤더 "(n개 · 선택)"이 비영속에선 거짓. 라벨/헤더의 동사·명사가 어포던스를 약속하면, 그 어포던스가
죽는 상태에서 라벨도 바뀌어야("'승인 없음' 고정"). 250 ②("접힘은 오류 신호를 승격")·255("배치가
관계를 말함")와 같은 축: **텍스트·배치·상태는 전부 UI의 발화 — 서로 모순되면 안 된다.**
