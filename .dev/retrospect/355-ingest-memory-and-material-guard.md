# 355 — 스펙 432 회고: 인제스트 메모리 유계화 + 재료 관문

## 무엇을 했나

자원감사 ②의 "1.6GB 추정"을 실측(21k 청크 → 피크 Δ+1.75GB·잔류 +0.98GB — 추정보다 나쁨)하고,
배치 흘려보내기(임베딩→flush→expunge, 단일 트랜잭션)+동시 세마포어(2)로 **피크 9배↓·잔류 65배↓**.
codex P0(재인덱싱 완주 창)를 재료 일치 관문으로 봉합.

## 배운 것(전이 가능)

### 1. "추정 → 실측" 순서가 옳았고, 실측은 추정과 다른 그림을 준다

추정(1.6GB)은 벡터만 셌다. 실측은 겹상주(벡터+ORM 사본+커밋 버퍼)로 단위당 2.6배, 그리고 추정이
전혀 못 본 **잔류 1GB**(끝나도 반납 안 됨)를 드러냈다. 처방을 추정 위에 세웠다면 절반만 고쳤다.
[[verify-premise-before-designing]]의 정량판 — 수치 문제는 측정 먼저, 처방은 실측 위에.

### 2. 상태 검사는 "지금 안 하고 있음"만 안다 — 겹침 방지는 재료(내용) 일치로

`status != 'reindexing'`은 재인덱싱이 **진행 중**인 것만 잡는다 — 우리 작업 구간 중 시작·완료까지
해버리면(ready 복귀) 상태 검사는 통과하고 옛 재료 산출물이 새 세계에 섞인다(codex P0 — 이 창의
절반은 종전 코드에도 있었음). 수리=**작업에 쓴 재료를 박제하고 커밋 관문에서 현재값과 대조**
(embedding_model_id·chunk 파라미터). 상태는 가변 순간값, 재료는 작업의 정체성 —
[[gate-on-intent-value-not-mutable-baseline]]의 형제(가변 기준 아닌 의도/재료 값으로 판정).

### 3. flush+단일 트랜잭션 = 메모리 유계와 원자성의 양립점

"배치마다 커밋"은 반쪽 문서를 만들고, "전량 후 커밋"은 메모리를 태운다. flush는 Postgres로 밀되
커밋 전 불가시 — expunge로 파이썬 상주를 버리면서 실패 시 전체 롤백을 유지한다. 대량 적재의
기본형으로 기억할 것. (대가: 트랜잭션이 임베딩 동안 열림 — 연결 점유·FK 경합은 경계로 문서화.)

### 4. 잔류(RSS 미반납)의 주범은 살아있는 참조였다

수리 전 잔류 +977MB를 "파이썬 할당자 특성"으로 반쯤 체념했는데, 상주 객체(벡터 리스트·identity
map)를 없애자 잔류가 +15MB로 떨어졌다 — 할당자 아레나는 참조가 죽으면 대부분 재사용·반납된다.
"GC가 안 돌려줘서"라고 결론 내리기 전에 **누가 아직 쥐고 있나**부터.

## 흠집

말미-이동 설계를 하며 "flush분은 롤백되니 안전"에 만족하고 "재인덱싱이 그새 **완주**하면?"을
안 물었다 — 상태 기반 관문을 만들 때마다 "그 상태가 잠깐 지나갔다 돌아오면?"(ABA 문제)을 질문
목록에. codex가 또 잡아줬다(3연속 스펙에서 P0/P1 적중 — 파괴·경합 부류엔 codex가 확실히 값함).
