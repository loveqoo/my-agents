# 247 — 노드 문서 facet 분리: 공용화 아닌 정렬, 그리고 적대자의 High가 오탐일 때 (스펙 272)

## 맥락
271(기억 공용 컨트롤) 뒤 facet 정렬 연장. 노드가 도구+문서를 **한 셀렉트에 접어** 둔 것을 도구/문서
두 컨트롤로 분리해 에이전트의 개념 구조(도구/문서 별도)와 맞췄다. 저장(`n.tools`)·백엔드 무변경, UI만.

## 발견과 교훈

### 1. 모든 facet이 "공용 컴포넌트"로 가지 않는다 — 정렬과 공용화는 다르다
271은 기억을 **공용 컨트롤**(MemoryFields)로 뽑았다 — 269가 죽은 선택지를 빼 장기가 단일 옵션이 돼
접이식→인라인 무손실 하강이 가능했기 때문. **도구·문서는 카탈로그 스케일**(MCP 서버·컬렉션 수십~수백)
이라 에이전트는 PickerGroups(접이+검색+카운트, 107/109), 노드는 간결 인라인이 각자 맞다. 억지로 단일
공용 컴포넌트로 통일하면 한 surface를 훼손(246 "추출이 결합 드러냄"의 예방판). **그래서 이번 조각은
공용 컴포넌트가 아니라 노드의 facet *구조*를 에이전트와 맞추는 것** — 렌더 방식은 각자 밀도 보존.
**규칙: facet 대칭을 볼 때 "같은 개념"과 "같은 컴포넌트"를 구분하라. 스케일 패러다임이 다르면 개념만
맞추고 렌더는 각자 둔다**(271 안 B 기조의 재적용). 스펙 배경 절에 이 정직을 먼저 적었다.

### 2. 쓰기 병합 보존이 핵심 위험 — 필터의 쓰기판 (244의 대칭)
도구·문서 두 컨트롤이 한 `n.tools` 배열을 나눠 소비한다. 한 컨트롤의 onChange가 담당 부분만 갈아끼우고
**나머지 항목을 보존**하지 않으면 상대 항목을 떨군다(도구 바꾸면 문서 유실). 244 "필터는 원본 소비자
전수"의 **쓰기판**: `onChange={(vals)=>setNode(i,{tools:[...vals, ...n.tools.filter(isDocTool)]})}`처럼
상대 부분을 명시 보존해 합쳐 저장. e2e로 양방향(도구 선택 후 문서 유지·역도) 단언 = 9/9 GREEN.

### 3. 적대자의 High도 오탐일 수 있다 — 측정으로 반증하고 불변식을 못박는다 (정직 경계)
codex가 "서버명 `search-documents`인 MCP → 런타임명이 `search_documents__foo`로 문서 오분류(High),
중복(Medium)"을 주장. **측정으로 미도달 확인**: (a) `safeToolName`은 **대시를 보존** →
`search-documents`→`search-documents__foo`(대시)라 `isDocTool` 접두(`search_documents__`, 밑줄)에 안
걸림, (b) 밑줄로 sanitize되는 이름은 NAME_RULE(`^[a-z0-9\-]+$`)이 **프론트·백엔드 둘 다** 금지
(`blocks.py:46 validate_resource_name`) → 충돌 이름 자체가 생성 불가. 두 보증이 충돌을 원천 차단.
**교훈: 적대 리뷰가 High를 줘도 자동 수용 아님 — 도달 경로를 *측정*해 반증하되, 근거를 남기고
(스펙 검증 절+회고) 불변식을 코드 주석에 못박아 미래 규칙 완화가 이 판정을 깨면 걸리게 한다**
(243 ① 예약 이름공간 규율 + [[complement-attack-can-be-honest-boundary]]: 공격 성공해도 항상 결함
아님, 안전 위반 아니면 정직 경계로 닫되 주석+근거 함께). codex의 착오 근인 = "대시→밑줄 sanitize"를
가정했으나 safeToolName은 대시 보존이고 밑줄명은 애초 금지 = 두 사실을 함께 안 봐야 나오는 결론.
Low(레거시 민이름 드롭)는 폐기 형식+명시 비우기라 OUT.

codex(High/Medium 측정 오탐·Low OUT). 저장 스키마·백엔드 무변경. 남은 facet: 모델(유사)·프롬프트
