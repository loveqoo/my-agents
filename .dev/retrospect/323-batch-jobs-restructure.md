# 323 — 스펙 395 회고: 파괴 잡 해체 — 적대 리뷰 0건에 도달한 4회전

## 무엇을 했나

리팩터 루프 4회전. batch/jobs.py(904줄, 파괴 잡 9종)를 파사드 73줄+7형제로 해체. C급 2→0
(전체 49 — 이번 캠페인 누적 61→49). JOBS 표면 diff 0 기계 확인, 배치 verify 11종+suite 51/51,
codex 적대 리뷰 **발견 0건**.

## 배운 것

1. **적대 리뷰 0건은 "안 잡힌 것"이 아니라 "미리 잡은 것"이다.** 이전 회전들의 P2 유형(관용구
   교체·fake 미러 약화·소스 단언 소비자)을 이번엔 계획 단계에서 자체 검열했다 — 순수 이동은
   바이트 동일 원칙, monkeypatch 소비자는 착수 전에 세고 갱신, "" vs None 접힘 같은 미묘한
   동치도 분해 시점에 확인. 적대자는 그 검열 목록을 그대로 확인만 했다. **루프의 함정 목록이
   회전마다 자산으로 복리**되는 것이 이 캠페인의 실제 산출물.
2. **파괴 잡의 리팩터는 "가드부터 이동"이 옳다**(codex 순서). 가드(전체삭제 패턴·keep-list·
   최후 super·사설망)가 먼저 독립 모듈로 나오면, 이후 잡 본체 이동에서 가드 훼손 여부를 diff
   범위로 즉시 판별할 수 있다.
3. **monkeypatch 대상은 정의 모듈**(3번째 적용 — 061·122 계열에 이어): 파사드 재수출을 패치해도
   내부 호출은 정의 모듈 전역을 읽는다. 이제 분할 전 체크리스트 항목: "이 모듈을 patch하는
   테스트 grep → 정의 모듈로 갱신".
4. **레지스트리는 파사드가 소유하는 게 무전환 최적**: codex의 jobs_registry.py+소비자 단계 전환
   안보다, 파사드가 전 잡을 어차피 임포트하므로 JOBS를 그대로 두면 소비자 전환이 0이다 —
   자문을 그대로 따르지 않고 동작보존 우위로 단순화한 의도적 편차(스펙에 명시).
5. **plan/execute·DeletePlan 같은 "더 나은 설계"는 파괴 경로에선 별도 스펙**: 리서치가 보여준
   성숙형(Terraform plan)이 있어도, 동작보존 리팩터에 얹으면 의미 변경이다. 백로그로 넘겼다.
