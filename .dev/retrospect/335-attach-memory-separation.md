# 335 — 첨부-메모리 축 분리(스펙 407): 실사용 첫 발견이 캔 축 혼선

- **실사용이 가장 좋은 적대자**: 개발자이 인스펙터에서 "회상 쿼리 깨짐"을 봤을 때, 실체는
  ①메모리 축이 첨부 주입본을 통째로 소비(회상 오염+**유저 기억에 문서 혼입**) ②깨진 PDF를
  성공으로 통과, 두 버그의 합성이었다. 404 설계 때 "주입본이 영속·히스토리에 그대로"를 장점으로
  삼으면서 **그 본문을 소비하는 다른 축(메모리)을 열거하지 않았다** — 입구 열거 교훈의 소비자판:
  텍스트를 재작성하면 그 텍스트의 모든 소비처를 열거하라.
- **falsy 폴백의 배신(codex P1①)**: `ctx.memory_user_text or user_text`는 빈 발화("")에서
  주입본으로 폴백 — 의도는 "미설정 폴백"인데 or는 "빈값"도 폴백시킨다. 미설정 판정은 None
  판정으로(found-vs-value 계열 — 회고 131과 같은 뿌리).
- **모드 하나가 관문을 우회한다(codex P1②)**: 노드형 memoryQuery=input 모드는 "노드가 받은
  메시지"를 쿼리로 쓰므로 기본 쿼리만 고쳐선 부족 — 회상 프록시(관문)에서 펜스를 걷는
  정화가 정본(policy-at-the-chokepoint).
- **폴백 경로는 캡도 폴백된다(codex P1③)**: pdfminer maxpages 절단은 pypdf 실패 경로에서
  페이지 캡을 조용히 우회 — 폴백 경로에도 같은 거부(413)를 명시 구현해야 캡이 계약이 된다.
- pypdf 한글 오추출(구르무키 등 타 문자권 매핑)은 문자권 일관성 휴리스틱으로 정직 400 —
  실측 표본(개발자 이력서 깨진 문자열)이 그대로 테스트 픽스처가 됐다.
