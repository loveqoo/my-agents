# 249 — 모델·프롬프트 공용화: 전수 grep이 버그를 선물했고, v6 셀렉터 관례가 거짓 음성을 줬다 (스펙 274)

## 맥락
273 마감 기준("개념 편집 표면 전수 grep")을 남은 facet에 적용하라는 사용자 요청 → 점검에서 모델
3표면 사본+chat 필터 누락 버그, 프롬프트 참조/사본 패러다임 분기 발견 → 274로 모델 공용화(버그
수정 포함)+프롬프트는 사본 페어(노드·오버라이드)만 공용화. 실행 중 사용자가 노드 카드 배치 지시
(프롬프트→모델→기억→도구·문서→받기·형식)를 보내 같은 표면 재작성에 합류.

## 발견과 교훈

### 1. 전수 grep 점검이 잠복 버그를 공짜로 찾는다 (248 ①의 실증)
"공용화됐나"를 grep으로 재는 과정에서 **의도치 않게 진짜 버그**가 나왔다: 에이전트 폼 모델 옵션이
주석("등록된 chat 모델로 옵션 구성")과 달리 `models.map` 무필터 — 임베딩 모델이 노출되고, 저장은
통과하나 런타임 해석이 `kind=="chat"` 조회라 대화 시점에 실패. **같은 개념의 표면들을 나란히 놓고
비교하는 것 자체가 감사**다 — 셋 중 둘만 필터가 있으면 하나가 틀린 것(사본이 많을수록 다수결로
결함이 보인다). 244 "주석만 있고 가드 없음"의 세 번째 표본.

### 2. 관례 셀렉터는 라이브러리 메이저 업그레이드에서 조용히 거짓 음성이 된다
antd v6 **단일** Select는 값/placeholder를 `.ant-select-content`(title=값)에 렌더 —
`.ant-select-selection-item/-placeholder`는 **multi 전용**이 됐다. 이 관례로 짠 e2e가 거짓 음성 2건
(로더가 실존하는데 "미노출" 스킵, ghost 보존이 되는데 "0건" FAIL). innerText 디버그에 값이 보이는데
locator가 0건이면 **셀렉터가 DOM 구조와 어긋난 것** — 추측 수선 말고 outerHTML **프로브로 실구조
확정** 후 고쳐라(probe-select.mjs 1회용). 133 "도구가 좁히고 육안이 확정"의 셀렉터판.

### 3. 실행 중 도착한 배치 지시는 같은 표면이면 같은 턴에 합류
노드 카드를 공용 컨트롤로 재작성하는 중에 배치 지시가 왔다 — 별도 스펙으로 미루면 같은 파일을 두 번
갈아엎는다. **같은 표면의 재작성이면 지시를 그 자리에서 합류**시키고 스펙에 "실행 중 추가" 절로 기록,
e2e에 DOM 순서 단언을 넣어 배치도 회귀 그물에 올린다. (배치 부수 이득: 단기 기억이 받기/형식 사이에
끼어 있던 것이 장기와 나란한 기억 구획으로 — 에이전트 폼 271 구조와 대칭.)

### 4. 프롬프트 facet의 정직한 절반
모델은 3표면 전부 공용화, 프롬프트는 **참조(에이전트 폼) vs 사본(노드·오버라이드)** 저장 시맨틱이
갈려 사본 페어만 PromptField로 — 247 "같은 개념≠같은 컴포넌트"를 이번엔 **한 facet 안에서** 적용
(전부 통일도, 전부 방치도 아닌 시맨틱 경계선까지만). 오버라이드의 "채우기" 별도 Field 2개가 노드식
라벨 줄 콤팩트 로더 1구획으로 줄어드는 부수 정돈도.
