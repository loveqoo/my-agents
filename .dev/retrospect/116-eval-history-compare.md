# 116 — 회고: 평가 2탄 — 성적 추이 + 런 비교 (스펙 138)

## 무엇을 / 왜
137의 성적을 시간축으로 — 문제집 드로어에 추이 차트(단일 계열 SVG, dataviz 스킬 절차 적용:
폼 선택→색 1개→검증기 PASS→마크 규격→호버 툴팁→선택적 라벨), 실행 이력에 문제집 필터+런 2개
비교(회귀 우선 정렬·assert 단위 diff). 백엔드는 dataset_id 필터 한 줄(비교는 프론트 계산).

## 잘된 것
- **dataviz 스킬 절차가 설계를 결정론화**: 색 고민 대신 검증기 실행(프라이머리 블루 PASS), 상태색은
  라벨+아이콘과 함께(색 단독 금지), 마지막 점만 라벨, 런 목록이 표 뷰 역할 — "취향"이 아니라 절차.
- **결정적 회귀 시나리오**: 두 번째 런 전에 불가능 기준(output_contains 불가능 문자열)을 추가해
  100%→0%를 모델 비결정성 없이 재현 — 비교 UI의 전 상태(회귀 태그·Δ%p·diff)를 안정 검증.
- **e2e가 UX 상태 공간의 구멍을 드러냄**: "새로 실패"(기존 기준 깨짐)와 "신규 기준 실패"(기준 강화
  결과)는 다른 상태인데 라벨이 전자만 있었다 — fast-worker가 원인(런 A의 details에 그 assert 자체가
  부재)을 파일:라인으로 특정, 세 번째 라벨("신규 기준 · 실패" orange) 추가로 해소. **diff UI는 "한쪽에만
  존재"를 항상 별도 상태로** 설계할 것(케이스 레벨은 이미 있었는데 assert 레벨에서 빠뜨림).
- codex 3건(50회 캡 명시 — silent cap 금지·공통 문제 0 경고·stale 비교 선택 정리) 즉시 반영.

## 아쉬운 것 / 리스크
- 비교 매칭이 케이스 **이름** 기준 — 개명하면 A/B가 아니게 됨(경고로 완화, 안정 case id 저장은 OUT).
- 추이는 최근 50회 캡(명시로 정직화) — 장기 추이는 후속.
