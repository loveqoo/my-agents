# 248 — 오버라이드 공용 기억 컨트롤: "통합됐다" 선언을 사용자가 검증시켰더니 사본이 나왔다 (스펙 273)

## 맥락
272 마무리 직후 사용자가 "정말 공용 컨트롤로 통합되었는지 확인해주세요" — 자가선언 말고 측정을
요구. grep해 보니 폼 2곳(AgentForm·NodeListEditor)은 진짜 공용이었으나 **플레이그라운드 오버라이드
드로어에 DEPTH_OPTS 사본+자체 단기 Select가 잔존**. 사용자 지시: 최소수선(export/import) 말고 **전체
교체** — "개인용 서비스라 작업 단위를 작게 쪼갤 필요 없음".

## 발견과 교훈

### 1. "공용화 완료"의 스코프는 스펙 범위가 아니라 개념의 전체 소비면이다
271의 완료 조건은 "AgentForm+NodeListEditor"였고 그 범위에선 참. 그러나 **사용자의 질문("정말
통합됐나")은 스펙 범위가 아니라 개념 범위**를 묻는다 — historyDepth를 편집하는 표면은 3곳(폼·노드·
오버라이드)이고 그중 1곳이 사본. 244 "필터는 원본 소비자 전수"·"installed guard≠covering guard"와
동형: **공용화 스펙을 닫을 때 완료 조건에 "그 개념을 편집하는 표면 전수 grep"을 넣어야 한다**(이번
273 완료 조건 1·2가 그 형태 — DEPTH_OPTS 정의 1곳·소비처 3곳을 grep 카운트로). 271 때 이걸 했으면
273이 안 생겼다.

### 2. 사용자의 "작업 단위 지침"도 자산이다
"개인용이니 최소수선보다 전체를 고쳐라, 작업 단위가 너무 작을 필요 없다" — 오픈 서비스가 아니라
호환성 부담이 없으니 과도기·점진 이행 비용을 치를 이유가 없다는 뜻. 앞으로 리팩터 범위 판단 시
기본값을 "전체 정합"으로. (메모리에도 기록.)

### 3. 형제 테스트 노후는 이번에도 — 그리고 이미 낡아 있던 것도 같은 턴에 갱신
246 ④의 세 번째 반복: 273이 피커에서 '기억' 그룹을 빼자 shot-override-109의 "피커=도구·기억" 단언이
낡음. 게다가 109·123은 **249(접이식→Steps) 때부터 이미 깨져 있었다**(시드 에이전트명 의존·'세부 설정'
접이식 클릭) — 회귀 게이트에 안 물려 있어 아무도 몰랐음. 처방: 만지는 표면의 형제 스크립트는 돌려보고
낡았으면 그 턴에 갱신(109는 자가 생성 에이전트로 재작성 — 시드명 하드코딩이 노후의 근인이므로 테스트가
자기 픽스처를 만들게).

### 4. 기능 왕복의 값싼 실증 = 요청 캡처
"UI 검증은 기능적으로"를 오버라이드에 적용하는 최경량 수단: `page.on('request')`로 실제 POST /chat
body를 캡처해 `overrides={"memories":[...],"historyDepth":0}` 배선을 단언 — 모델 응답 품질과 무관하게
(mock-llm) 드래프트→적용→payload 전 경로가 실증된다. 스샷·라벨 검사보다 강하고 실모델 e2e보다 싸다.
