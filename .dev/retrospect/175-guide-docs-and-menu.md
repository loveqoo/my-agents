# 회고 175 — 가이드 문서 2종 + 어드민 가이드 메뉴 (스펙 189)

## 무엇을 했나
개발자용(산출물형 produce 저작)·일반사용자용(노코드, 메뉴·권한·평가·승인·플레이그라운드) 가이드를
쓰고, 스크린샷 9장을 Playwright로 캡처해 삽입, md→HTML 빌더로 `admin/public/guide/`에 정적 서빙,
AdminShell에 "가이드" 메뉴(새 탭)를 달아 e2e로 검증했다.

## 배운 것

### 1. 사용자 문서는 **실물(코드+화면)이 그라운드 트루스** — 스크린샷이 교정 장치다
글로만 쓴 초안은 그럴듯했지만, 캡처한 실제 화면이 오류 2건을 잡았다(빌딩 블록은 3탭인데 "메모리
타입"을 빼먹음, 평가는 "문제"가 아니라 "문제집" 단위). **문서 주장(메뉴 이름·권한 규칙)은 전부
소스에서 grep**(AdminShell menuItems·authz.py 시드 정책·agent_may_wire·완화게이트)하고, **화면
구성은 캡처로 재확인**하는 2중 근거가 문서 정확도를 만든다. 스크린샷은 장식이 아니라 검증 단계다.
캡처 스크립트를 자산으로 남기면(shot-guide-menus.mjs) UI 변경 시 재실행=문서 갱신이 된다.

### 2. 산출 HTML은 **인코딩 선언부터** — 사용자가 "한글 깨짐"으로 발견
md→HTML 변환에서 `<meta charset="utf-8">`을 빼먹어 사용자 브라우저에서 한글이 깨졌다. 파일은
UTF-8로 저장돼 있어도 **선언이 없으면 브라우저가 추측**한다(로컬 파일/단순 서빙일수록 어긋남).
생성기가 HTML을 뱉는다면 doctype·charset·viewport는 본문보다 먼저 챙길 골격이다. 빌더
(build-html.py)에 박아 재발 봉인.

### 3. "메뉴 추가"가 항상 뷰 추가는 아니다 — 정적 문서는 onSelect 가로채기가 최소 수술
가이드를 ViewKey에 넣어 뷰로 만들면 라우팅·타이틀·상태 전부를 건드린다. 대신 onSelect에서
key==='guide'만 가로채 `window.open`(새 탭)하고 return — 기존 라우팅 무접촉, 원래 뷰 유지(e2e
G3로 확인). 콘텐츠가 앱 상태와 무관한 정적 문서면 뷰 통합보다 이 패턴이 회귀면이 좁다.

## 다음에 적용
- 사용자 문서 작업: 소스 grep + 실행 화면 캡처 2중 근거, 캡처 스크립트를 갱신 자산으로 커밋(1).
- HTML 생성기: charset/viewport 골격 먼저(2).
- 정적 콘텐츠 메뉴: 뷰 통합 전에 가로채기+새 탭 검토(3).
