# 259 — 목록 재설계: 태그 계층은 "축마다 다른 표현 수단"으로 푼다 (스펙 284)

## 맥락
사용자: 태그들에 계층이 있어 어렵다 + 6개 지시(출처 탭·내 것 tint·종류 표시·페르소나 제거·탭 내
검색·신호등). "기본 public"은 측정 결과 분리(285) — 현 모델은 공개=owner_id 소멸이라 "기본
public+내 것 tint" 양립 불가, 가시성 축은 147 보안 경계(404-fold·복제·A2A·메모리 게이트)라 생성자
축 분리+RBAC 체크리스트+codex가 필요.

## 발견과 교훈

### 1. 태그 과밀의 처방 = 모든 축을 태그로 두지 않는 것
계층이 다른 6개 축(출처/소유/가시성/종류/상태/예외)을 전부 태그·필로 나열하니 어려웠다. 확정:
**축의 성격에 맞는 표현 수단 배분** — 출처(상호배타 집합)=탭, 소유(이진·전역)=행 배경 tint,
상태(3값 신호)=색 점+툴팁, 종류(명명 필요)=컬럼 Tag, 예외(드묾)=조건부 태그만. 태그는 "예외와
연결"만 남았다. UI 어휘: 같은 위젯(태그)에 다른 계층을 실으면 사용자가 계층을 복원해야 한다.

### 2. 지시의 일부가 데이터 모델과 충돌하면 그 항목만 분리하고 명시한다 (256 ③ 실천)
"기본 public+내 것 tint"는 UI 지시처럼 보이지만 생성자 축이 없는 현 모델에선 자기모순 — 침묵 이행
(둘 중 하나 조용히 포기)이 최악. 측정으로 충돌을 보이고 285로 분리 선언, 284는 나머지 전부 실행.

### 3. 행 배경은 CSS 특이성 전쟁터다
tint를 inline style→클래스로 바꾼 뒤에도 보조행(expanded)이 흰 줄로 남음 — 기존
`.dt-antd-sub … expanded-row > td` 배경 규칙이 더 특이해서. **행 강조를 넣을 땐 그 테이블의 기존
배경 규칙(줄무늬·expanded·hover)을 grep해 특이성을 맞춰라** — 스크린샷 육안이 잡았다(e2e 클래스
단언은 통과했었음: 클래스 존재≠실제 칠해짐, 133 "도구가 좁히고 육안이 확정" 재현).

삭제·탭별 placeholder·신호등 점(파랑/노랑/빨강)·표시 안내 범례 갱신. verify-284 16/16 + 283/276/274
