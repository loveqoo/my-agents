# 회고 205 — 페이지 제목 중복 + 죽은 검색 UI (스펙 213)

## 무엇을 했나
사용자 스샷 지적 2건: (1) 헤더+Page가 제목 이중 렌더 → Page 제목 제거(헤더 단독), (2) 배선 안 된
전역 검색창 → 제거. 둘 다 전역 컴포넌트(shared.Page·AdminShell) 단일 수정이라 전 메뉴 전파. 검증=
브라우저 9메뉴 순회(제목 정확일치 h3 화면당 1개·검색 껍데기 0)+tsc0.

## 배운 것

### 1. 중복은 "두 진실원"의 신호 — 하나를 진실원으로 정하고 나머지를 표시에서 지운다
제목이 헤더(TITLES[view])와 Page(title prop) 두 곳에서 각자 렌더돼 늘 겹쳤다. 둘 다 "맞는" 값이라
자가검증으론 안 걸리고, 실제 화면을 본 사용자만 잡았다. **교훈: 같은 정보를 두 컴포넌트가 각자 그리면
반드시 진실원을 하나로 정하고(여기선 헤더) 다른 쪽은 표시를 지운다 — 값이 우연히 같아 안 보이다가
맥락(라벨 길어짐·번역)에서 어긋난다. 전역 표시 요소는 "한 곳에서만 그린다"를 불변식으로.**

### 2. 껍데기 UI(배선 없는 위젯)는 "곧 만들 것"이 아니라 지금 거짓 약속 — 지우거나 배선하거나
헤더 검색창은 value/onChange 없이 자리만 차지해, 사용자가 "왜 있냐"고 물었다. 목업에서 넘어온
플레이스홀더가 배선 없이 살아남은 것. **교훈: 동작 안 하는 UI는 사용자에게 "여기서 검색 되는구나"라는
거짓 신호다. 목업→실기능 전환 때 미배선 위젯을 남기지 말고 (a)배선하거나 (b)지운다. "나중에"는 그때까지
거짓 약속이 노출된다.** (회고 188 "무시되는 배선"의 UI판 — 폼이 안 쓰는 설정을 받는 것과 같은 결.)

## 다음에 적용
- 전역 표시 요소(제목·배지)는 진실원 1곳 원칙, 두 컴포넌트 중복 렌더 금지.
- 목업 유래 미배선 위젯은 실기능 전환 시 배선 or 제거(껍데기 잔존 금지).
- UI 지적은 스샷이 진실 — 자가검증이 못 보는 "겹침·거짓 약속"을 육안이 잡는다([[verify-ui-in-browser-proactively]]).
