# 회고 191 — 인스펙터 도구 카드 중복 (스펙 202 후속, "도시락" 버그)

## 무엇을 했나
사용자 보고("플랜 에이전트 인스펙터 버그, 도시락 세션 봐라") → 세션이 소유 스코프라 DB 직조회로
실세션 트레이스 확보 → 데이터는 온전(mcp 3건=tools 노드 3개), 렌더가 범인: tools 노드 상세가
t.mcp **전부**를 귀속(192 가정 "직접 그래프는 tools 1개")인데 202 도구 루프로 tools가 N회 등장 →
라운드마다 전체 카드 중복(3호출=9장). 수리=내용 매칭(호출 result 머리 40자가 라운드 summary에
포함)+순번 폴백. 동일 시나리오 재현으로 3=3(중복 0)·라운드별 내용 일치 확인.

## 배운 것
1. **옛 가정은 주석에 있다 — 가정을 깨는 스펙이 그 주석을 찾아야 한다.** Inspector 주석에 "ReAct
   다중 tools는 한 노드로 접힘"이라고 가정이 명시돼 있었다. 202(도구 루프)가 정확히 그 가정을 깼는데
   그래프 쪽만 고치고 소비자(인스펙터)를 안 훑었다. 새 스펙이 기존 불변식을 바꿀 땐 그 불변식을
   언급하는 주석·코드를 grep해 소비자를 전수하는 습관(회고 181 "필드 제거 소비처 전수"의 가정판).
2. **사용자 세션 = 진단 1차 자료.** 재현 시도 대신 사용자가 지목한 실세션을 DB에서 직조회하니
   트레이스(데이터)가 온전함을 즉시 확인 — 데이터/렌더 층 분리가 한 번에 됐다.
3. **진단 중 부수 발견은 백로그로.** 전송 프롬프트 거짓·턴 배지 인덱스·토큰 추정치 3건을 발견했지만
   사용자가 본 버그(중복 카드)만 고치고 나머지는 백로그 — 범위 규율.
