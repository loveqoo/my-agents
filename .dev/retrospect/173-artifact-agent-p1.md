# 173 — 산출물형 에이전트 뼈대 P1 (ArtifactAgentBase)

**스펙**: docs/spec/188 · **관련**: 102(조상 ABC 패턴)·116(재실행 중복)·041(HIL 체크포인트)

## 무엇을 했나
"산출물을 만들기 위해 노력하는 에이전트"의 뼈대(produce→artifact→sink)를 별도 구현체로 출하.
멀티턴 ask(인터럽트 재개)·스텝 캐시·slot-fill 데모까지. 단위+e2e+무회귀 3중 그린, e2e 첫 실행 통과.

## 무엇이 잘못됐고 무엇을 배웠나

### 1. 설계 논의에서 사용자의 추상화 교정이 스펙을 두 번 갈아엎었다 — 갈아엎게 두는 게 맞다
초안(고정 필드 슬롯필) → 유스케이스 반영(타겟팅 파이프라인) → **사용자 교정("구체 로직이 아니라
뼈대를 만들라")** → 최종(ArtifactAgentBase + produce 구멍 + 프리미티브). 각 단계에서 스펙을 통째로
다시 썼는데, 그 비용이 구현 후 재작업보다 압도적으로 싸다. 특히 "타겟팅 에이전트"로 직진했으면
두 번째 산출물 유형이 나올 때 전부 재설계였다.

- **처방**: 설계 논의 중 사용자가 추상화 수준을 교정하면 기존 초안에 덧대지 말고 **그 수준에서
  다시 써라**. 스펙 단계의 전면 재작성은 싸고, 구현 후 추상화 교정은 비싸다. 102의 "뼈대+유일 구멍+
  둘째 구현" 패턴이 이번에도 정답 틀이었다 — 검증된 자기 패턴을 새 축에 재적용(회고 164 §3과 동형).

### 2. LangGraph interrupt의 재실행 시맨틱 → 스텝 캐시(Temporal류 결정성 계약)
produce를 "여러 턴에 걸친 하나의 코루틴"으로 보이게 하는 핵심: 재개 시 노드가 **처음부터 재실행**되고
interrupt()는 기록된 답을 순서로 반환한다. 문제는 ask 이전의 rag/tool/extract가 재개마다 재실행되는 것
(스펙 116이 조율형에서 state 커밋으로 푼 그 문제). produce는 임의 유저 코드라 state 커밋으로 못 풀고,
**스텝 캐시**(스레드별 호출순서 인덱스 로그 — 리플레이는 기록 반환)로 풀었다. 부수효과 중복만이 아니라
**비결정 LLM 재추출로 인한 리플레이 드리프트**(다른 결과→다른 질문 경로→기록된 답이 엉뚱한 interrupt에
매칭)까지 막는 게 요점. 대가로 produce에 결정성 계약(시계·난수 분기 금지)을 문서화 — Temporal 워크플로와
같은 규율.

- **처방**: "재실행되는 실행 모델" 위에 유저 코드를 얹을 땐 (a) 부수효과 재실행과 (b) 비결정 분기로 인한
  리플레이 드리프트 **둘 다**를 막아야 한다. 이벤트 로그+리플레이(스텝 캐시)가 표준 해법이고, 결정성
  계약은 숨기지 말고 구멍(produce)의 docstring에 명시.

### 3. 이어달리기의 열쇠는 "누가 thread를 기억하나" — 기존 설계에서 대응물을 찾아라
thread_id가 턴별 고유라는 chat.py 설계(체크포인트 중복 누적 방지) 때문에 ask가 걸린 thread를 다음 턴이
모른다. 새 테이블을 설계하기 전에 **승인 흐름이 같은 문제를 어떻게 풀었나**를 봤다 — Approval.checkpoint
컬럼이 정확히 이 역할. P1은 세션 keyed 메모리 dict로 동형 구현(영속화는 후속 명시). 노드가 직접 반환한
AIMessage가 "messages" 스트림에 안 잡히는 함정도 updates 델타 캡처로 우회(산출물형에만 게이트).

- **처방**: 새 기계가 필요해 보이면 먼저 "기존 흐름(승인·조율형)이 같은 부류의 문제를 어디서 푸는가"를
  찾아 그 대응물로 구현하라. 이번 P1의 세 기계(재개 포인터·리플레이·kind 분기) 전부 기존 설계의 변주였고,
  덕에 e2e가 첫 실행에 통과했다.

## 복리 포인트
- 프리미티브 닫힌 집합(ask·form·rag·tool·extract)이 곧 보안 경계 — P2(form)·P3(targeting)는 이 계약
  위에 얹기만 하면 됨.
- 검증 사다리 재확인: 단위(그래프 계약 직접)→e2e(플그 실왕복)→무회귀(시나리오+승인 117). 리플레이 캐시
  같은 "보이지 않는" 기계는 단위(호출 카운트)가 아니면 못 잡는다.
