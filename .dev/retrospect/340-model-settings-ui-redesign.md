# 340 — 모델 능력·파라미터 설정 UI 재설계(스펙 412)

## 발단
구남님 "능력(서버가 할 수 있는 것) 개념은 좋았는데 UI가 안 깔끔하다. 예전 UI 개편처럼 외부 사례
공부하며 유저 인지·개념 경계·컴포넌트 조합을 다시." → 411까지 기능은 됐으나 능력(사실)과
파라미터(값)가 한 평면에 뒤섞여 "스트리밍 지원 vs 스트리밍 기본값"이 겹쳐 보였다.

## 무엇을 했나
서브에이전트 디자인 조사(외부 사례+문헌) → 재설계. 두 화면을 각자:
- 모델 폼: ①능력 선언 블록(Switch+Tag, "서버가 할 수 있는 것") ②파라미터 기본값 블록
  (Slider↔InputNumber·고급 Collapse). 사실/값을 다른 시각언어·블록으로 분리.
- 오버라이드 화면: 프리셋 Segmented(정밀/균형/창의/직접)+상속 placeholder+오버라이드 Tag+되돌리기+
  게이트 disabled/사유 툴팁. 공유 조각 ParamNumberField 추출(사본 금지).

## 배운 것 (복리 후크)

- **UI 개편도 조사 먼저**(회고 338 재확인) — 바로 배치 손대지 않고 외부 사례(OpenAI/AI Studio/LM
  Studio·NN/G·VS Code·antd 문헌)를 서브에이전트로 조사하니 검증된 패턴(Slider+InputNumber·기본/고급·
  프리셋·placeholder 상속·disabled+사유)이 즉시 나왔다. [[design-focus-before-layout]]·[[research-prior-art-before-expensive-probing]].

- **인지 경계 = 다른 시각언어** — "정적인 걸 인터랙티브처럼 보이지 않게"(조사 정설). 능력=사실은
  Switch+Tag(선언), 파라미터=값은 Slider/InputNumber(편집). 같은 목록에 섞으면 "지원 vs 기본값"이
  같은 것의 반복처럼 읽힌다. **개념이 다르면 블록·헤더·컴포넌트를 갈라라.**

- **게이트는 숨김 vs 비활성+사유의 판단 기준** — 원천 불가(서버가 못 함)면 숨김, 껐을 뿐이면
  disabled+사유(존재는 인지시킴). disabled 툴팁은 wrapper span으로 hover 확보(조사가 짚은 구현 함정).

- **상속/오버라이드 표준 3요소**(VS Code 정본) — 상속값 placeholder + "오버라이드" 배지 + 되돌리기
  링크. 계층(모델→에이전트→노드→세션)마다 이 표현으로 "무엇을 상속 중/덮음"을 인지.

- **인지 부하는 기본/고급 + 프리셋** — 파라미터 6개+면 핵심만 펼치고 나머지 Collapse(2단까지),
  프리셋으로 개별 이해 없이 일괄 세팅. NN/G: 고급 지연 시 과제 완료 30~50%↑.
