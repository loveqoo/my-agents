# 169 — 커스텀 Drawer를 antd Drawer로 (스펙 187 Phase 1)

**스펙**: docs/spec/187 · **관련**: 186(비-antd 감사)·166(커스텀 Drawer 셀렉터 함정)

## 무엇을 했나
`shared.Drawer`(커스텀 95줄)를 antd `Drawer` 얇은 래퍼로 교체. prop API 유지해 10개 호출부 무변경.
antd가 포커스 트랩·Escape·스크롤락·애니메이션을 제공 → 재구현 삭제. shared.tsx 575→480줄.

## 무엇이 잘못됐고 무엇을 배웠나

### 1. "shared 구현만 교체 + prop API 유지"가 대량 통일의 저위험 경로
70곳(Drawer 10·DataTable 10·Desc 50) 호출부를 antd로 직접 갈아엎으면 대량 churn·위험. 대신 shared
컴포넌트의 **내부만 antd로 바꾸고 겉 API를 유지**하면 호출부 0곳 변경으로 antd 렌더를 얻는다. antd의
스타일·a11y라는 이점은 그대로 취하면서(렌더가 antd) 위험은 shared 파일 하나에 국한.

- **처방**: 광범위한 컴포넌트 통일은 "호출부 일괄 교체"보다 "공유 래퍼 내부 교체 + API 보존"을 먼저
  고려. antd Drawer는 API가 커스텀과 거의 동형(open/title/width/onClose/footer)이라 거의 드롭인이었다.

### 2. 커스텀이 antd의 특정 기능을 이미 흉내내고 있었다 — 그게 교체 신호
커스텀 Drawer의 주석은 "Escape 닫기 — antd Drawer와 거동 통일", "fixed — antd Drawer 동일 거동"이라
적혀 있었다. 즉 **antd의 동작을 손으로 재현**하던 중이었다. 그런 주석은 "원본(antd)을 쓰면 된다"는
직접 신호 — 재구현이 원본을 좇고 있으면 원본으로 돌아가라.

- **처방**: 커스텀 컴포넌트 주석에 "antd처럼", "~와 동일 거동"이 보이면 통일 후보 1순위. 흉내는 원본의
  부분집합일 뿐(포커스 트랩·a11y 등 빠진 게 있다).

### 3. antd 채택은 사소한 시각 변화를 동반한다 — 미리 표면화
닫기 X가 우측→좌측(antd 기본 헤더)으로 옮겨졌다. 기능은 동일하나 UX 위치 변화. antd의 스타일을
취한다는 건 antd의 레이아웃 관례도 따른다는 뜻 — 스펙에 "의도된 결과"로 명시해 나중에 회귀로 오인
안 되게.

- **처방**: 컴포넌트 통일 시 antd 기본과 커스텀의 **시각/레이아웃 차이**(버튼 위치·패딩·기본 크기)를
  검증에서 스샷으로 확인하고 스펙에 의도된 변화로 기록. tsc·기능 테스트는 이 차이를 못 잡는다.
