# 회고 181 — 평가 케이스 등록 UX 4건 (스펙 195)

## 무엇을 했나
케이스 등록이 번거롭다는 실사용 문의 4건: (1) 카드 'N개 기준' 배지=아래 태그와 중복 → 제거, (2) 근거
파일명 직접 타이핑=오타 → 컬렉션 문서 파일명 AutoComplete(자유입력 허용), (3) '문제 이름'을 매번 작성
번거로움 → **이름 개념 제거**(내부 해시 관리·유저 비노출, 성적표엔 질문 표시), (4) AI 자동 출제가 생성
시 강제/버튼이 하단에 숨음 → 드로어 상단 '시험 실행' 옆 'AI 출제' 버튼(agent·rag 공통). tsc0·195 e2e
12/12(name 해시 왕복·update 보존·배지 없음·질문 제목·상단 버튼·파일명 옵션)·194 e2e 무회귀·스샷.

## 배운 것

### 1. "필드 하나 제거"는 그 값의 **소비처를 다 따라가야** 하는 이전 작업이다
'문제 이름'을 UI에서 지우는 건 한 줄이지만, `name`은 (a) CaseIn 필수 검증, (b) 성적표 `case_name` 식별자,
(c) 카드 제목으로 **소비**되고 있었다. 그냥 지우면 성적표에 빈/해시가 뜬다. 그래서 세 곳을 이었다:
CaseIn.name optional→**해시 자동**(생성), update 미전송→**기존 보존**(덮어쓰기 금지), 실행 시
`HarnessCase.name=c.input`으로 **성적표엔 질문 주입**, 카드 제목=input. **교훈: 필드를 제거할 땐 "누가 이
값을 읽나"를 먼저 세고(생성·검증·표시·박제), 각 소비처의 대체를 정한 뒤 지운다 — UI만 지우면 하류에서
빈 값이 샌다.** ([[sync-wholesale-replace-drops-admin-fields]]의 역방향 — 그건 "몰래 덮어씀", 이건 "몰래 비움")

### 2. 새 능력은 새 엔드포인트보다 **기존 엔드포인트의 분기**가 인가 표면을 안 넓힌다
rag AI 출제를 별도 라우트로 만들면 소유자 게이트·비용가드·중복락·404-fold를 **다시** 짜야 했다(스펙 178이
suggest_cases에 심은 것들). 대신 `suggest_cases`에 `kind=="rag"` 분기를 추가해 그 게이트를 **그대로 통과한
뒤** 갈랐다 → 새 인가 입구 0, 비용가드·락 재사용. **교훈: 이미 소유·비용 게이트가 선 엔드포인트에 형제
기능을 얹을 땐, 게이트 뒤에서 분기해 표면을 재사용한다 — 새 라우트는 그 방어를 복제하다 한 겹을 빠뜨린다
([[installed-guard-isnt-covering-guard]]의 예방판).** (대가: `_execute_generation_append`가
`_execute_suggestion`과 description 로직이 겹침 — 케이스 소스만 다른 복제, 후속 통합 여지)

### 3. 사용자의 "없애자"가 내 "자동화하자"보다 나았다
나는 3번을 "AI가 이름을 **생성**"(기능 추가)으로 풀려 했다. 사용자는 "이름을 **없애고** 해시로 관리, 안
보여줌"(기능 제거)을 제안했다 — 후자가 낫다. AI 이름 생성은 LLM 콜·실패 처리·수정 UX를 부르지만, 제거는
그 전부를 없앤다(할 일 자체가 사라짐). **같은 실수를 4번에서 또 했다**: '컬렉션에서 생성'(문제집 만들 때
자동 10개 채움)을 "원하는 사람용"이라며 **남겼는데**, 사용자가 "응? AI가 자동으로 만드는데?"라고 지적해
제거했다 — 사용자는 자동 생성 **자체**를 불필요로 봤다. 내 기본값("옵션으로 남기자")이 또 틀렸다: 없앨
걸 남기면 그 선택지·코드·혼란도 복잡도다. **교훈: "이걸 자동화할까"·"옵션으로 남길까"를 떠올리면 먼저
"이게 필요한가 / 없애도 되나"를 묻는다 — 없앨 수 있는 필드/단계/옵션을 남기거나 자동화하면 복잡도만
는다.** ([[explain-plainly-not-one-sided]]·회고 180 #2와 연속: 사용자 UI 감각을 내 초안보다 신뢰)

### 4. 마커를 bool로 승격한 판정은 그 마커를 박는 **모든 경로**를 커버해야 한다 (후속 버그)
AI 출제 시 Skeleton이 안 떴다. `generating`(스펙 193이 description 마커→구조 bool로 승격)이
`startswith("생성 중")`만 봤는데, 두 진행 경로 중 컬렉션 생성(142)은 "생성 중…"(접두)를, AI 출제
(143/195)는 "… · AI 출제 중…"(접미)를 박는다 → 접미 경로가 판정 밖 → 출제 시 배지·Skeleton·폴링 전멸.
4번에서 AI 출제를 전면에 내세우자 비로소 드러났다(그전엔 하단 버튼이라 눈에 안 띔). **교훈: 문자열
마커를 bool 필드로 승격할 땐 "그 마커를 **박는 곳**"을 전수한다(여기선 생성·출제 두 곳) — 한 경로만
커버한 판정은 형제 경로에서 조용히 false가 된다([[installed-guard-isnt-covering-guard]]의 판정판:
"설치했다"≠"모든 경로를 덮는다").**

## 다음에 적용
- 필드 제거 = 소비처(생성·검증·표시·박제) 전수 후 대체 정하고 지운다(1).
- 형제 기능은 기존 게이트 엔드포인트에서 분기(새 라우트 방어 복제 회피)(2).
- "자동화할까" 전에 "필요한가"(없앨 수 있으면 없앤다)(3).
- 마커→bool 승격은 그 마커를 박는 모든 경로 전수(생성·출제 두 경로 다 봐야 generating)(4).
