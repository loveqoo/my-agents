# 회고 190 — 도구 다수 시 디스커버 전환 (스펙 203)

## 무엇을 했나
toolbox.py 신설(effective_tools: 임계 10 이하 직통·초과 시 search_tools/call_tool 메타 도구) →
직접형(build_agent)·플랜형(plan_execute) 두 지점 적용 + 폼 안내 문구. 단위 16/16·089/086 무회귀·
tsc0. live(임계=1 강제): search_tools(2ms, 6개 중 wiki 1위)→call_tool→wiki_search(672ms)→위키 근거
답변 5.79s 전 체인. 브로커 미경유(권한 의미 보존) 설계.

## 배운 것

### 1. 예약어 충돌은 스키마 경로에서만 드러난다 — 도구 테스트는 ainvoke(스키마 dict)로
call_tool의 인자명을 `args`로 지었더니 LangChain이 예약어 충돌로 스키마를 `v__args`로 둔갑시켰고,
모델이 스키마대로 호출하자 실제 함수와 어긋나 전량 실패했다. **단위 테스트는 `.coroutine(위치 인자)`
로 호출해 초록**이었다 — 스키마 계층을 아예 안 탄 것. live 실모델이 잡았고, 수리 후 테스트를
ainvoke(스키마 dict) 경로로 바꾸고 스키마 인자명 검사(3e)를 박았다. **교훈: LangChain 도구의 단위
검증은 함수 직호출이 아니라 반드시 스키마 경로(ainvoke + dict)로 — 모델이 보는 건 스키마다. 인자명
`args`는 금지어(v__ 접두 둔갑).**

### 2. 개념 문답이 스펙 범위를 벼린다 — "디스커버=부품, 조율형=형태"
사용자와 "디스커버 쓰면 조율형 아닌가?" 문답을 거치며 부품(검색 창구)과 형태(위임·fold·신뢰경계)를
구분했고, 그 구분이 그대로 설계 결정이 됐다: 브로커(per-user RBAC) 미경유·주입 목록 위 래퍼(권한
의미 불변). 문답 없이 갔으면 "조율형으로 전환"을 만들어 권한 축이 흔들렸을 것. **교훈: 사용자의
개념 질문은 구현 전 스펙 경계를 좁히는 공짜 설계 리뷰다 — 합의된 구분(부품/형태)을 스펙·백로그에
그대로 박아 다음 논의 재발을 막는다.**

### 3. 로컬 모델 인프라 flake와 기능 결함을 스트림 오류 문구로 가른다
live 1차에서 최종 답변이 "[오류] peer closed connection…"으로 끝났다 — 체인(검색→호출→실데이터)은
인스펙터에 온전했으므로 기능이 아니라 로컬 모델 서버의 스트림 드랍. 재시도로 5.79s 클린 패스 확인.
**교훈: 실모델 e2e 실패는 "어느 층의 실패인가"를 트레이스로 먼저 가른다 — 도구 체인이 온전하고
최종 스트림만 끊겼으면 재시도 1회가 옳은 대응(기능 재수정 아님).**
