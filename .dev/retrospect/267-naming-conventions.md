# 267 — 네이밍 컨벤션 정밀화 (스펙 292)

## 무엇을 했나

사용자가 broker/core.py를 직접 열람하고 "네이밍·컨벤션 들쭉날쭉" 지적 — 실측으로 확인(정당).
룰 6개(R1 bool 술어·R2 타입 주석·R3 루프 변수·R4 축약 사전·R5 상수/배치·R6 동사 사전)를
명문화하고, **잴 수 있는 것은 전부 기계 게이트로**: `scripts/naming_audit.py`(R1·R3 AST 카운터)
+ ruff ANN(R2) → `make metrics-fast` 편입.

수치: R1 위반 23→0(룰 정밀화 후 진짜 5건 개명) · R3 66→0 · ANN 423→0(파라미터 294·반환 129) ·
mypy 0 유지 · 스위트 51/51. 실행 = R1 판정·개명 메인, R2/R3 벌크 75파일 3기 병렬.

## 잘된 것

- **룰이 측정 중에 진화했다 — 오탐이 룰의 결함을 가르쳐줬다.** 초안 R1(질문형 접두만)이
  `host_is_private`·`user_owns`·`_resume_uses_memory` 같은 주어-동사형(S-V-O — 실은 가장 잘
  읽히는 술어)을 위반으로 꼽았다. "상태동사 토큰이 이름 어디든 단어로 존재 OR 분사·형용사 어미"로
  정밀화하니 위반 23→5로 줄고 남은 5건이 전부 진짜(명사구 bool). 룰은 선험이 아니라 코퍼스에
  맞춰 조정하는 것 — 단, 조정 근거를 스크립트 주석에 박아 자의성 차단.
- **틀린 주석은 mypy가 잡는 이중 게이트 설계가 작동.** 지시서에 "주석 붙였는데 mypy가 새 오류를
  내면 주석이 틀린 것 — 타입을 다시 읽어라"를 박았고, 3기가 전 트리 mypy 0을 유지하며 423건을
  소거했다. Any 도배도 안 나옴(정당화 Any 각 사유 주석 — Protocol row·duck-typing 센티널·재귀 JSON).
- **타입 주석 작업이 또 실버그를 적발.** approvals.resolve의 `resolved_by=str(principal.id)` —
  머신 토큰(str)이 승인 처리하면 `.id` AttributeError 500(스펙 181 유입, 기존 부채). `User | str`
  주석을 붙이는 행위 자체가 유니언의 str 팔을 상기시켜 발견됨. 센티널 "machine" 스탬프로 수리.
  291의 mypy 회귀 적발에 이어, **타입 층은 넣는 과정 자체가 감사(audit)다.**
- **FastAPI 함정 공유가 병렬 3기 사이에 자연 전파.** `-> dict | StreamingResponse` 주석은
  `response_model=None` 없이는 부팅 크래시 — C기가 발견·봉합하고 배정 밖(a2a_server)을 전달,
  B기가 같은 패턴으로 처리. import 스모크를 완료 기준에 넣은 것이 이걸 잡았다.

## 배운 것

- **스타일 일관성은 "리뷰 게이트"로 남기면 반드시 재발한다** — 291에서 네이밍을 리뷰로 두자
  바로 다음 열람에서 지적됐다. 카운터 하나(naming_audit)로 룰이 회귀 핀이 된다. 수치화 불가처럼
  보이는 것도 부분집합은 AST로 잴 수 있다(bool 반환+이름 패턴, 블록 for 한 글자).
- **반환 타입 유니언 주석은 FastAPI에선 코드 동작을 바꿀 수 있다**(response_model 생성 시도) —
  "주석은 무해"가 프레임워크 데코레이터 아래선 거짓. 주석 작업도 부팅 스모크가 게이트여야 한다.
- **상관 튜플(`(row, provider) | (None, None)`)은 mypy가 못 좁힌다** — 정확 표기가 union-attr을
  낳으면 Any+사유가 정직(구조 개편은 별도 판단). 타입 시스템의 표현력 경계를 아는 것도 컨벤션.
