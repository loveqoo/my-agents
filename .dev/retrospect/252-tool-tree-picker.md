# 252 — 도구 트리 위젯: 계층이 데이터에 이미 있으면 위젯이 그걸 드러내야 한다 (스펙 277)

## 맥락
276(도구 단위 배선) 직후 사용자가 "도구 선택을 리치한 컴포넌트로 — [x] some-tools / [x] tool-a /
[x] tool-b". 평면 `서버 · 도구` 나열을 서버(부모)→도구(자식) 체크박스 트리(antd Tree)로. 공용
ToolTree를 직접형 폼·노드 카드·오버라이드 세 표면이 조립(값=런타임명 server__tool, 276 그대로).

## 발견과 교훈

### 1. 데이터에 계층이 있으면 평면 위젯은 그 계층을 숨긴 것 — 위젯이 구조를 드러내야 한다
서버→도구는 원래 계층 데이터(safeToolName=`server__tool`)인데 평면 체크박스로 눌러 담고 있었다.
276이 도구 단위 배선을 열자 "calc-tools · add / calc-tools · multiply / …"처럼 서버명이 반복돼
카탈로그가 커질수록 읽기 어려웠다. **antd Tree는 그 계층을 공짜로 렌더**하고, 부모 체크=전체
선택·부분=indeterminate까지 비-strict 모드가 자동 파생 — 우리는 리프 키(런타임명)만 관리하면
onCheck에서 부모(srv:)를 걸러 값을 얻는다. **데이터가 트리면 트리 위젯을 쓰라**(247 "데이터 모양대로":
도구=계층→Tree, 문서=평면 컬렉션→Select 유지, 억지 통일 안 함).

### 2. 공용 위젯 하나가 세 표면을 한 번에 정렬 — 271~276의 배당금
ToolTree 하나를 직접형·노드·오버라이드가 조립. 값 축이 이미 276에서 런타임명으로 통일돼 있어
(mcps 파생·하이드레이션 규칙도 세 곳 동일) 위젯 교체가 기계적이었다. **앞 스펙들이 값 축을 통일해
두면 UI 리치화는 위젯만 갈아끼우는 일**이 된다(246 "앞 정리가 뒤 설계여지 넓힘"의 반복 — 이번엔
데이터 축 통일이 위젯 공용화를 값싸게 했다).

### 3. 위젯 교체는 형제 테스트를 무더기로 낡게 한다 — 셀렉터는 바뀌어도 불변식은 안 바뀐다 (246 ④ 4번째)
도구 UI가 PickerGroups/Select→Tree로 바뀌자 **다섯 스크립트**(272·273·274·276·109)가 셀렉터
불일치로 빨강. 전부 기능 회귀가 아니라 노후 — 불변식(도구 배선·병합 보존·배치 순서)은 그대로고
셀렉터만 트리로 갱신. 특히 274 배치 순서 검사는 라벨을 '도구 (선택)'→'도구'로 바꾸자 **안내 문구의
'도구'에 걸려** 깨짐 → 순차 커서 탐색(이전 매치 뒤부터)으로 교정. **위젯을 바꾼 턴에 그 위젯을
만지는 형제 e2e를 전부 돌려 셀렉터를 갱신**(안 하면 다음 회귀가 거짓 빨강). e2e 셀렉터가 위젯 구조에
결합돼 있음을 매번 확인.

## 조치
ToolTree.tsx(antd Tree checkable·검색·배지·리프만 onChange) 신설, 직접형 폼(도구 PickerGroup→트리·
setTools mcps 파생)·노드 카드(도구 Select→트리·문서 Select 유지)·오버라이드(도구 PickerGroup→트리·
setDraftTools)가 조립. verify-277 9/9 + 272·273·274·276·109 셀렉터 갱신 후 GREEN + 275·268 무영향 +
tsc 0 + 모바일 오버플로 0. 값·백엔드 무변경(276 런타임명 축 그대로). codex 스킵(위젯 표현만).
