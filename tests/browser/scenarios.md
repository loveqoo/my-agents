# 사용 시나리오 아티팩트 (스펙 166 · 검증 축1)

여정 = 페르소나 + 목표 + 단계 + **기대결과**. 실행자는 "내부를 모르는 비개발자"로 연기하며 각 단계에서
완료/마찰/막힘을 기대결과 대비 판정한다. 이 파일이 합격선의 단일 출처 — 스크립트/에이전트는 여기에 맞춘다.

판정 어휘:
- **완료(ok)**: 기대결과 그대로 도달.
- **마찰(friction)**: 도달은 했으나 헷갈림·군더더기·불필요한 단계(치명 아님, 개선 후보).
- **막힘(blocked)**: 기대결과에 도달 못 함(기능 공백 또는 버그 — 치명, 우선 수정).

---

## J1 — 저마찰 생성 → 사용
**페르소나**: 비개발자 비서봇 운영자. "챗봇 하나 만들어서 말 걸어보고 싶다." 버전·초안·활성화 같은 개념 모름.
**목표**: 새 에이전트를 만들어 대화하고 응답을 받는다.

| # | 단계 | 기대결과 |
|---|------|----------|
| 1 | 에이전트 메뉴에서 "새 에이전트" 클릭 | 생성 폼(모달)이 열린다 |
| 2 | 이름 입력(scn-<ts>), 모델 선택, 프롬프트 선택, 생성 | 에이전트가 만들어지고 목록/상세에 보인다 |
| 3 | 방금 만든 에이전트로 대화 시도(플레이그라운드 등) | **막힘 없이 대화 진입 가능** |
| 4 | 메시지 보내기 | **어시스턴트 응답이 온다**(빈 화면·에러 아님) |

**감시 포인트**: 2에서 생성은 v1 **초안**이다. 3~4에서 "초안이라 대화가 안 된다 / 활성화하라는데 방법이
안 보인다"면 → **막힘 또는 마찰**(비개발자에겐 "만들었는데 왜 안 되지"). 활성화가 필수라면 그 안내가
생성 직후 명확한지가 마찰 판정 기준.

## J2 — 지식 붙이기
**페르소나**: RAG 지식베이스 관리자. "문서 모아둔 컬렉션을 챗봇이 참고하게 하고 싶다."
**목표**: 컬렉션을 만들어 에이전트에 연결한다.

| # | 단계 | 기대결과 |
|---|------|----------|
| 1 | RAG 컬렉션 메뉴에서 컬렉션 생성(scn-<ts>, 임베딩 모델 선택) | 컬렉션이 목록에 보인다 |
| 2 | 에이전트 생성/편집 폼을 연다 | 폼에 "벡터 테이블/지식" 선택 영역이 있다 |
| 3 | 방금 만든 컬렉션을 선택지에서 찾는다 | **생성한 컬렉션이 선택지에 나타난다** |

**감시 포인트**: 3에서 방금 만든 컬렉션이 폼 선택지에 안 보이면 → 막힘(연결 경로 공백). 이름만 있고
어떤 컬렉션인지 구분 어렵거나(alias 미표시 등) 하면 마찰.
