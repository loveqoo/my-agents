# 문구·평이함 감사 루브릭 (스펙 167 · 검증 축3)

UI 문구가 **IT 모르는 일반인**도 이해할 수준인지 판정하는 합격선. 리뷰어(사람 또는 적대적 에이전트)는
이 루브릭을 각 사용자 노출 문자열에 적용한다. 이 파일이 합격선의 단일 출처 — 재실행 시 참조.

## 대상(전수, 사용자 노출만)
- 프롭: `placeholder`·`title`·`label`·`okText`·`cancelText`·`description`·`tooltip` 한글 값.
- 알림: `setToast(...)`·`message.{success,error,warning,info}(...)`.
- JSX 텍스트 노드(버튼·설명·빈상태·배지), 메뉴 라벨, `Alert` message/description.
- **개발자 주석(`//`·`/* */`)은 제외** — 사용자에게 안 보인다.

## 문제 유형
1. **전문용어(jargon)**: 비개발자가 모를 IT/내부 용어가 **설명 없이** 노출.
   예: 임베딩·벡터·차원·스냅샷·브로커·오케스트레이션·페이로드·인제스트·청크·런타임·토큰·프로바이더·A2A·MCP·RAG.
   단, **도메인 필수어 + 툴팁/괄호 설명이 있으면 통과**. 기준 = "이 화면만 처음 본 일반인이 설명 없이 마주치면 막히나".
2. **오탈자·맞춤법·띄어쓰기**.
3. **불명확·비평이**: 문장이 너무 길거나, 내부 개념 전제, 이중부정, 수동태 남발, 모호.
4. **일관성**: 같은 개념을 다른 단어로(예: 지식/컬렉션/벡터 테이블, 초안/미반영 초안, 사용/배선).

## 심각도(관대 금지 — 애매하면 flag 후 심각도로 구분)
- **막힘**: 일반인이 못 알아듣고 진행 불가(우선 수정).
- **거슬림**: 이해는 되나 불친절·비일관(선별 수정).
- **사소**: 취향(보류).

## 발견 형식
`파일:라인 · 원문 · 유형 · 심각도 · 왜 막히나(한 줄) · 개선 제안(구체 대체 문구)`

## 수정 원칙
- **막힘·오탈자 우선**. 도메인 필수어는 배척보다 **괄호/툴팁 설명 추가**를 우선(용어 자체를 없애면 정확도 손실).
- 일관성은 **용어 하나로 통일**(추후 용어 사전으로 상시화 — OUT).
- 취향 과잉 교체 금지(문구 전면 갈아엎기 아님).
