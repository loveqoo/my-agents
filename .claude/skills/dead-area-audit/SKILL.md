# 죽은 영역 감사 (스펙 324·325)

죽은 영역은 능동적으로 속인다 — 걸러내는 코드와 함께 자라 "이미 처리됨" 착시를 만들고(가짜 메모리
타입, 스펙 323), 생산 0인 값 위에 소비 UI가 4층으로 쌓인다(세션 버킷, 스펙 324). 새 기능의 버그는
시끄럽지만 죽은 영역은 조용히 신뢰를 갉는다. 이 스킬은 그 감사를 **재실행 가능한 레시피**로 상시화한다.

## 언제

주기 점검(자산이 한동안 쌓였을 때), 큰 스펙 여러 개 출하 후, "요즘 뭐가 썩었나" 진단, 자율 루프의
위생 사이클. **이 스킬은 식별·보고까지** — 제거는 3급 분류 보고 후 사용자 승인을 받아 별도 진행한다.

## 냄새 축 (A~F)

| 축 | 정의 | 원형 사례 |
|---|---|---|
| A. 배제로만 참조되는 값 | 생성·긍정 사용은 없고 필터·배제에만 쓰이는 enum/라벨/상수 | 단기(세션) — `.filter(m !== C)` ~11곳이 존재를 지탱 (323) |
| B. 써놓고 안 읽는 필드 | config/DB에 기록되지만 어떤 코드도 읽지 않는 키·컬럼 | Chunk.token_count — 쓰기 2, 읽기 0 (324) |
| C. 죽은 코드 | 호출자 0인 함수·export·컴포넌트·라우트 | getA2ASkills·IdRow·AGENT_SOURCE (324) |
| D. 아무것도 안 지키는 가드 | 검사 지점≠부수효과 지점, 또는 조건 항상 참/거짓 | `status.in_(("awaiting",))` — 영구 빈 결과 (324) |
| E. 고아 데이터 | API로 도달 불가능한 DB 행(소유자 소멸·soft 참조 끊김·테스트 잔재) | 센티넬 approvals 226행·데모 화석 세션 (324) |
| F. 버려진 스펙 잔재 | 폐기된 방향의 코드·주석·상수 화석 | 메모리 히트 type="semantic" 상수 — 폐기 분류의 화석 (324) |

## 실행 — deep-reasoner 4기 병렬 (읽기 전용)

메인은 오케스트레이터(계획·종합), 스캔은 deep-reasoner에 위임한다. **4기를 한 메시지에 동시 발사.**
각 프롬프트는 자기완결로: ①대상 경로 ②냄새 정의+원형 사례 ③제외 목록 ④출력 형식을 반드시 포함.

| 기 | 담당 축 | 대상 |
|---|---|---|
| ① 백엔드 | A·B·C·D | `packages/api/src/api/` (도구: `uvx vulture packages/api/src/api --min-confidence 80` + grep 교차검증) |
| ② 프론트 | A·C | `admin/src/` (도구: `cd admin && npx knip`·`npx ts-prune` + grep 교차검증) |
| ③ 시드·스키마 | B·F | `seed.py` 카탈로그 전항목의 런타임 소비 추적 + config JSONB 키 전수 read/write 대조 + 폐기 개념 grep |
| ④ DB 고아 | E | 라이브 DB — **SELECT만**. models.py로 스키마 파악 → 소유자 소멸(`owner NOT IN user`)·soft 참조 끊김·테스트 패턴(`shotfix_%`·`v3xx%`·센티넬 `000000xx`)·FK 무결성 |

- vulture/knip/ts-prune은 미설치라 uvx/npx가 첫 실행 시 받아온다(네트워크 필요) — 실패하면 grep
  기반으로 전환하라고 프롬프트에 명시.
- **④기 DB 접속 레시피**(프롬프트에 그대로 실어줄 것 — psql 없음): `cd packages/api && uv run python`
  스크립트로, `from api.db import SessionLocal`(async) 후
  `async with SessionLocal() as s: (await s.execute(text("SELECT ..."))).fetchall()` 패턴.
  읽기 SELECT는 deep-reasoner의 조회성 Bash 허용 범위 안임을 프롬프트에 함께 명시.

공통 프롬프트 골격(각 기에 축 정의·대상 붙여서):

```
당신은 "죽은 영역 감사자"입니다. <대상 경로>를 스캔해 후보를 찾으십시오. 읽기 전용 — 수정 금지.
[냄새 정의 + 원형 사례]
제외: tests/verify_*.py(일회성 스크립트), alembic 마이그레이션(역사 기록), docs/(인간 영역).
출력(최종 텍스트가 보고서): 후보별로
  [축N] 한 줄 요약 / 증거: file:line+코드 / 왜 죽었는가(반드시 "X grep 0건" 같은 측정 포함) /
  확신도: 확실·유력·관찰 / 제거 시 영향
후보 없는 축도 명시(방법 요약). 마지막에 스캔 커버리지 3줄 + 기각한 가설(오탐 방지용).
확신 없으면 '관찰'로 낮추고 근거를 정직하게.
```

**도구 결과는 반드시 grep 교차검증** — vulture/knip은 데코레이터 등록·문자열 forward-ref·동적
import를 못 봐 오탐한다(FastAPI 핸들러·pydantic validator는 정적 호출자 없어도 살아있음).

## 종합 — 3급 분류 → 승인 → 제거

1. 4기 보고를 **확실**(즉시 제거 가능한 증거) / **유력**(판단 1개 필요) / **관찰**(냄새만)로 종합.
2. **이전 감사와 대조**해 중복을 걷어낸다 — 최신 감사의 "깨끗 확인"·"기각한 가설" 목록은
   `docs/spec/324-dead-area-audit.md`(이후 감사가 갱신). 이미 백로그에 있는 항목(예: raw verify 격리)
   재보고 금지.
3. AskUserQuestion으로 제거 범위 승인(확실분/유력분/보류 분리). **자동 제거 금지.**

## 제거 시 규율 (회고 299 — **승인 받은 뒤에만** 이 절로 진입)

- **측정 완료선언은 값이 사는 모든 장소 열거 후** — 같은 데이터가 두 곳에 살면(agents vs
  agent_versions) 한쪽 "0"은 거짓이 된다.
- **타입을 좁혀 컴파일러를 부려라** — 유니온 축소(tsc)가 숨은 죽은 분기를 대신 찾는다.
- **DB 삭제는 SELECT 분포 확인 먼저**(실사용 흔적 vs 기계 생성 가름), 스테이트먼트별 개별
  트랜잭션, CASCADE 규칙 확인.
- **검증 실패의 귀속은 stash 재현으로** — `git stash` 후 같은 게이트 재실행이 "내 탓인가"를 가르는
  가장 싼 방법(기존 드리프트를 내 회귀로 오인 금지, 역도 마찬가지).
- **제거 후 codex 여집합 공격** — "제거물의 남은 소비자"를 찾게 하라. 잔존 소비자는 삭제한 파일이
  아니라 **옆 파일**에 있어 자가 grep이 안 닿는다(동명 이별 인터페이스 함정 포함).
